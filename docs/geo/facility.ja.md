# 施設管理

`/geo/facility` ページは、温室・育苗ハウス・機械室などの建物について、3Dモデリング、工学計算、センサー・アクチュエーターの割り当て、装置チェックを行う場所です。モデルがウィンドウ全体を使い、施設の設定は **設定** ボタンで開く設定パネル一つに **位置 · 構造 · エンベロープ · 構成要素 · 連携 · レビュー** の6つのタブで並びます。

---

## 画面レイアウト

```
施設設計 · [地図へ戻る] · <施設名> <残り> · [未保存の変更] · [施設を保存]          ← タイトル行
[地図 | 3D]  追加 [選択] [開口部] [設備] [灌水] [センサー]  [表示: 方向 · 透視 | アイソメ · 3Dに表示]  [ツール & エクスポート] [元に戻す]  [設定]   ← ツールバー
┌── ステージ: 3D または地図(一度に一つ、ウィンドウの高さいっぱい) ──┐   ┌── 設定パネル(右側のドロワー、開いてもステージは見える) ──┐
│                                                                    │   │  位置 · 構造 · エンベロープ · 構成要素 · 連携 · レビュー      │
│                                                                    │   │  (選んだタブの内容)                                          │
└── ステータス行(選択中のもの · ツールの案内) ──────────────────────┘   │  [新規施設] [施設を複製] [施設を保存]                         │
                                                                         └───────────────────────────────────────────────────────────────┘
```

- **タイトル行** — **施設設計**、**地図へ戻る**、開いている施設の名前とその横の **残り** のタグ、**未保存の変更** 表示、**施設を保存**。タグはボタンではなく、やることが残っているものだけを示します — **位置 未完了**(名前・地図・配置のどれかがない)、**未接続 3**(装置のない構成要素の数)。終わったものは示さないので、すべて埋めるとタグは消えます。**位置 未完了** にマウスを重ねると、何が足りないかが表示されます(**名前を入力してください**、**地図を選択して施設を配置してください**)。寸法・平面・構造・位置・外皮は **施設を保存** を押したときだけ保存されます。保存済みの施設では、構成要素と **連携** の設定は編集をやめて約1.5秒後に自動で保存され、タイトル行に **保存済み HH:MM** と表示されます。
- **ツールバー** — モデルの上の一行です。右端の **設定** が設定パネルを開きます。**地図 | 3D** でステージを切り替えます。**位置** は地図で、ほかのタブは3Dで開き、手で選んだほうはそのセッションの間タブごとに記憶されます。地図では **配置を消去**・**地図に配置**、3Dでは追加ツール(**選択**、**開口部**、**設備**、**灌水**、**センサー** — **設備 › 地図から追加…** は地図に描いたものを構成要素として追加します)、**表示** メニュー(**方向** — 決まった視点9つ、**透視 | アイソメ**、**3Dに表示** — 種類ごとにモデルで隠す・表示する。隠したものがあると **表示** の横にその数が付きます)、**ツール & エクスポート**(アセットライブラリ · PNG/仕様ファイル/GLB のエクスポート · 仕様ファイル/GLB のインポート · 高品質 / 高速プレビュー · **3Dモデルを再構築**)、**元に戻す** があります。設定パネルを開いてステージが狭くなると、ツールバーが一行に収まるよう **元に戻す** が **もっと見る**(=**ツール & エクスポート**)メニューの先頭に入ります。
- **ステージ — 3D** — モデルがウィンドウの下端までいっぱいに広がり、ページはスクロールしません。モデルの上には何も重ねません。いちばん下のステータス行に、選択中のもの、有効なツールと終え方、マウス操作が表示されます。
- **ステージ — 地図** — **地図に配置** を押し、地図上で施設の中心をクリックします。置いた施設はドラッグで移動でき、寸法・回転は入力に合わせて四角形にすぐ反映されます。
- **設定パネル** — **設定** を押すと右からドロワーのように開き、開いている間もステージはそのまま見えて操作できます — モデルを見ながら値を変えます。3Dで構成要素をクリックしても開き、新しい施設を始めるときは自動で開きます。**閉じる** でステージだけが残ります。いちばん上に6つのタブが一行に並び、選んだタブの内容だけが表示されます。内容をスクロールしてもタブの行は上に残り、矢印キーでタブを移れます。**保存済み施設** はパネル上部の **閉じる** の左にあるボタンです — 押すと一覧がパネルの全高で開き、編集中の施設の位置から始まります。もう一度押すか施設を選ぶと、元のタブに戻ります。
- **構成要素タブ** — すべての構成要素を種類ごとに表示し、装置のない行には **機器なし**・**入力なし** のタグが付きます。上の **追加** の横で種類を選ぶと既定の位置に一つ追加します。行を選ぶと3Dでその構成要素が選択されます。一緒に作られた構成要素(複数棟の天窓のように一つの装置を共有するもの)は **天窓 ×6** のような一行にまとめて畳まれ、その行で装置を選ぶとまとまり全体に一度に入ります。行を押すと展開して一つずつ表示されます。まとまりから外して装置を個別に使うものは展開した一覧に **個別** と表示され、まとまりの装置の選択は届きません。装置を個別に使うものしか残っていないまとまり(例: 側窓の左右)は畳みません。
- **選んだ構成要素** — 3Dや構成要素タブで一つ選ぶと、設定パネルがその構成要素(名前・装置・位置・サイズ・回転・開閉方式・削除)に切り替わり、**施設へ** で戻ります。**連携**・**レビュー** タブは施設を保存するまで押せず、タブの行のすぐ下の一行にその理由が表示されます。
- **スマートフォンでは** — 閲覧と小さな修正だけを行います。タイトル行はなく、メニューの下の一行に **地図へ戻る**・**地図 | 3D**・**設定** だけが残ります(追加ツール・表示メニュー・地図への配置・ステータス行は載せません)。開いている施設の名前は設定パネルのタイトルに表示されます。設定パネルを閉じるとモデルが画面いっぱいになり、**設定** を押すと同じ設定パネルが画面全体を覆い、上のつまみを引くと下がってモデルが見えます。下げている間も上の行のボタンは押せ、**設定** を押すとパネルがまた上がります。パネルの先頭に **配置と平面の編集は広い画面で行います。** があり、タブは **位置**・**構造**(数値・オン/オフ)・**エンベロープ**・**構成要素** だけが表示され(**連携**・**レビュー** は表示されません)、3Dや一覧で選んだ構成要素は名前と装置だけを扱います。進行は **3/4 ステップ · 未接続 2** のような一行です。

タブごとの内容:

| タブ | 内容 |
|------|-----------|
| **保存済み施設**(ヘッダーのボタン) | 一覧(選んで開く · 削除) — **新規施設**・**施設を複製** は列の下部にあります |
| **位置** | **マップとサイト**(名前 · 地図 · サイト)、**位置**(回転) |
| **構造** | **構造**(構造 · 平面 · ベイ数 · 間隔 · ゾーン)、**仕様**(この施設を操作できるグループ · プリセット · スパン · 軒高 · 棟高 · 長さ · 屋根タイプ)、**容量プレビュー**、**ゾーン**(平面を描いたときのそのゾーン) |
| **エンベロープ** | **被覆・換気**、**カーテン** |
| **構成要素** | 構成要素の一覧と **追加**、**灌水**(配管・灌水装置・バルブの自動生成) — ツールバーの **灌水** メニューの自動生成がこのタブを開きます |
| **連携** | **天気**(予報 Input の接続)、**グループ**(同じ種類のアクチュエーターをリーダー・フォロワーにまとめる)、**ラベル色**(測定項目ごとの色区間) — 施設を保存したあとに使えます |
| **レビュー** | **装置チェック**、**IEC 統合サマリー**、区画ページへのリンク行 — 施設を保存したあとに使えます |

各ゾーンで何を育てているかはここではなく区画ページで記録します — **レビュー** タブの最後の行にそのページへのリンクがあります。

## 施設登録の流れ { #facility-registration-flow }

```
/geo/facility を開く  (/geo/design の施設設定の 施設設計 › 開く、地図上の施設、またはアドレスを直接入力)
         ↓
位置 › 名前 · 地図(サイトは任意) → 地図に配置 → 地図上で施設の中心をクリック · 回転
         ↓
構造 › 構造・寸法・屋根 → エンベロープ › 被覆・換気・カーテン → 3Dで確認
         ↓
ツールバー › モデルにセンサー・アクチュエーターを配置 → 一つずつ選んで設定パネルで装置を接続
         ↓
施設を保存
         ↓
連携 › 気象サービス · アクチュエーターグループ · ラベル色 → レビュー › 装置チェック
```

- 施設はこのページの **施設を保存** で作られます — `/geo/design` で先に描く必要はありません。保存すると、選んだ地図に施設の輪郭も置かれます。
- 施設を指定せずに開くと空の新規施設から始まり、**位置** タブが地図とともに開きます。地図から開くとその地図がすでに選ばれています。保存済みの施設は **保存済み施設** の一覧から開きます。このときアドレスに `?facility_uuid=` が付くため、再読み込みやブックマークで同じ施設が開きます。
- 保存には地図と配置が必要です — **地図に配置** をしないと保存は拒否されます。名前は空のままでも保存できますが、タイトル行の **位置 未完了** タグが **名前を入力してください** と表示し続けます。
- **施設を複製** は開いている施設をコピーします。接続されたセンサー・出力は引き継がれません。
- **連携**・**レビュー** タブ — その中の **IEC 統合サマリー**・**装置チェック** も — は施設を保存したあとにのみ使えます。

## 外皮の設定

建物の形と外側は **構造**・**エンベロープ** タブで決めます — 構造・ベイ数・平面は **構造 › 構造**、寸法は **構造 › 仕様**、続いて **エンベロープ › 被覆・換気** と **エンベロープ › カーテン**。回転は **位置** タブにあります。これらの値はすべて冷暖房負荷の計算と3Dモデルの入力になり、モデルは値を変えるたびに追従します。

**エンベロープ** タブにある外皮の設定:

- **被覆・換気**
    - **外皮（全体）** — 外側の被覆です。常にあるので、資材だけを選びます。
    - **内部カバー**（トグル） — 内側の二つ目の被覆: **被覆レイヤー**（資材）と **エアギャップ** (m)。
    - **側壁補強**（トグル） — **被覆レイヤー**、**位置**（X− ・ X+ ・ Y+ ・ Y−）、**深さ** (m、壁から外へ出る距離)。
    - **正面補強**（トグル） — **位置**（Y+ ・ Y−）、**深さ** (m)。
    - **外部側面ベント**（トグル） — 側壁に沿った側窓。**1段** または **2段** で、2段なら段ごとに高さと開始高さ (m) を決めます。
    - **外部屋根ベント**（トグル） — 天窓。**位置** は **中心** または **左右**。
- **カーテン**
    - **天井保温カーテン**（トグル） — **1層** または **2層**。
    - **側壁保温カーテン**（トグル） — 側面ベントの段構成に従います。
    - **遮光カーテン**（トグル） — **透過率**: 完全に閉じたときに通る光の割合（0.30なら10分の3が通る）。空欄なら0.50とみなします。

ここでオンにした換気窓とカーテンは **外皮生成** と付いた構成要素として現れます — 設定パネルの **構成要素** タブと、一つを選んだときの設定パネルで — そこで動かすアクチュエーターを接続します。

### 構造タイプ { #structure-type }

**構造 › 構造** で選びます。

| 画面 | 値 | 説明 |
|------|----|------|
| **単棟** | `single` | 棟ごとに独立した構造物です。二つ以上なら **間隔 (m)** だけ離れて一列に並びます。 |
| **連棟** | `connected` | 複数の棟が側壁を共有して一つの建物になります。間隔の欄はありません。 |

### 棟の設定 { #bay-configuration }

- **構造 › 仕様**
    - **プリセット** — **標準アーチ型**
    - **スパン (m)** — 棟一つの幅
    - **軒高 (m)** — 床から軒まで
    - **棟高 (m)** — 床から棟まで。軒高との差が屋根の高さです。
    - **長さ (m)** — 建物の長さ
    - **屋根タイプ** — **アーチ型**、**切妻屋根**、**切妻 2**（一つの棟に棟木が二つ）、**平屋根**
- **構造 › 構造**
    - **ベイ数** (N) — 1〜20
    - **間隔 (m)** — 棟と棟の間の距離。**単棟** のときだけあります。
    - **ゾーン** — 二つ以上のときに現れます。棟の間の境界をクリックしてゾーンを分けたりまとめたりします。地図ウィジェットとゾーン別の環境制御がこのゾーンを使います。
- **位置 › 位置** — **回転** (°)、0〜359、数値で入力(施設を動かすには地図上でドラッグします)

### 平面を描く { #plan-drawing }

階が二つ以上ある場合や、平面が単純な長方形でない場合は **構造 › 構造 › 平面を描く** を開きます。階が一つの長方形の施設は使わなくてもかまいません。ほかの画面は変わりません。

ステージは上から見た平面に変わります。上が北です。設定パネルには階、ツール、選んだ項目の値が表示され、いちばん下の **平面を閉じる** で平面を終えます。

- **上の階を追加** — 新しい階は空で、下の階の外形が下絵として見えます。**下の階をコピー** を押すと外形・ゾーン・境界が同じ状態で始まります。作物と床の開口はコピーせず、曲面・切妻の屋根は新しい階へ上がります。**階高 (m)** だけ入力すれば、階の高さは下の階から計算されます。削除できるのは最上階だけです。
- **外形を描く** — 向かい合う二つの角を押します。**点で描く** は点を一つずつ打ち、最初の点をもう一度押すと閉じます。点は既存の角、直角、0.5 m の目盛りの順に吸着します。同じ階の外形どうしは重ねられません。L字の温室は長方形二つを並べて描きます。曲面・切妻の屋根は長方形の外形にだけ付けられます。
- **ゾーンを分ける** — 壁を一方押し、反対側の壁を押します。広い方が元のゾーンを引き継ぐので、そのゾーンの区画はそのままです。
- 二つのゾーンの間の線を押すと **壁**、**カーテン**、**開放** を選んだり、**ゾーンを統合** したりできます。接する二つの外形の間の線も同じです。
- **床の開口** — 階段や吹き抜けに使います。2階以上にあり、その階で向かい合う二つの角を押します。
- **元に戻す** で一段階ずつ戻せます。**施設を保存** を押すまで保存されません。開いて見ただけで閉じれば施設はそのままです。

平面を変えても機器の座標は移動しません。ゾーンが変わる機器があれば、保存前に個数をお知らせします。

平面を保存すると、地図の図形は全階の外形から導かれ、上の構造・棟数・スパン・長さ・高さ・屋根の種類はロックされます。平面を描く画面で変更します。**構造 › ゾーン** には描いたゾーンが表示されます。**環境制御はまだこのゾーンを使いません。** 保存された寸法と既存のゾーンでそのまま動作し、容量プレビューの床面積・体積・透光・外皮は平面の値で(ゾーンを合計すると床面積の合計と一致します)、暖房・冷房・換気面積は保存された寸法に基づく参考値です。

上の階に機器を置くには **3Dに表示**(ツールバーの **表示** メニュー)でその階を選び、床に置きます。その階の床の外や床の開口の上には、案内を出して置きません。

コーディネーターと区画は、保存済みのゾーンを通してつながります。

- 分けたゾーンの作物は、その幅を担当する保存済みゾーンのコーディネーターの候補になります。
- 上の階のゾーンと保存済みの幅の外にあるゾーンには、つなぐコーディネーターがありません。**構造 › ゾーン**、平面、保存時の通知、区画のゾーン選択で知らせます。
- 上の階のゾーンの区画は、ゾーンを指定していないコーディネーターにとっても制御の候補になりません。区画の画面に「上階の区画は環境制御の対象外です」と表示されます。
- 上の階の機器は環境制御の入力から外れます。上の階のセンサー値は1階の制御値に混ざらず、コーディネーターは上の階の機器を動かしません。画面と手動操作には引き続き表示されます。
- ゾーンの総量は、分けるときは元のゾーンに残り、統合するときは単位が同じなら合算します。

## 3Dプレビュー { #3d-preview }

ステージを **3D** にすると、Three.jsで描いた建物モデルが表示され、設定パネルで値を変えるたびにモデルへ反映されます。

- **右クリックドラッグ**: 回転
- **左クリックドラッグ**: 平行移動（クリックで選択）
- **スクロール**: ズーム

床の **N 矢印** がこの施設の実際の北です(**位置** タブの回転値を反映)。既定の視点は南から北を見る向きなので、画面の右が東・奥が北となり、北が上の地図と左右・前後が一致します。ツールバーの **表示** メニューの **方向** にある北側の視点は北から見るため、東が左に来ます。

複数階の構造モデルで保存した施設では、**3Dに表示**(ツールバーの **表示** メニュー)に階が上の階から並びます。階を選ぶとその上が隠れ、その階を断面として見られます。階が 1 つの施設には階の行はなく、地図上の 3D は常に建物全体を表示します。

### 3Dアセットモード { #3d-asset-mode }

自動パラメトリック生成の代わりに、カスタムのGLTFモデルを適用することもできます。

1. `/geo/model_assets` でGLTFファイルをアップロードします。
2. ツールバーの **ツール & エクスポート › アセットライブラリ** でモデルを選びます。
3. パラメトリックモデルに戻すには **アセットを解除** をクリックします。

## 工学計算 { #engineering-calculations }

建物の外皮に基づいて、暖房・冷房および換気能力の一次参考値を計算します（誤差±5〜10%、あくまで機器選定の見積もり用です）。

寸法や資材を変更すると自動的に再計算され、**構造** タブの **容量プレビュー** に表示されます。計算項目は次のとおりです。

| 項目 | 単位 | 説明 |
|------|------|-------------|
| 床 | m² | 建物が占める床面積 |
| 体積 | m³ | 内部の空気の体積 |
| グレージング | m² | 外皮の被覆面積（側壁＋屋根＋妻壁） |
| 換気口開放 | m² | 換気口・開口部の合計開放面積 |
| 暖房 | kW | 外皮の熱通過損失＋すきま風損失 |
| 冷房 | kW | 日射熱取得＋作物の蒸散負荷 |
| ACH | /h | 時間あたりの換気回数 — 自然換気とファンの合計 |

暖房・冷房は計算された負荷を表示します。アクチュエーターに能力を設定しておくとその合計が代わりに表示され、値にマウスを重ねると、その定格合計と計算値を比べられます。

### 自然換気の風圧シミュレーション { #natural-ventilation-wind-pressure-simulation }

`/api/geo/facility/<uuid>/wind` エンドポイントは、建物のジオメトリと風向・風速を受け取り、換気性能をシミュレートします。

クエリ値は `speed`（風速 m/s、既定 3.0）、`dir`（気象標準の風向 0〜359°、0 は北から吹く風、既定 0）、`pct`（開口部の開度 0〜100%、既定 100）です。

応答は、有効換気回数（毎時。総流入量と総流出量の小さい方）とその二つの合計、さらに開口部ごとの開口面積・風圧係数・毎時通気量・空気が入るか出るかを返します。風を受ける開口部は正圧で空気を取り込み、風を背にした開口部は吸引で外へ出し、風と平行な開口部はほとんど通気しません。天窓は風向に関係ないものとして扱い、風速の一定割合だけ換気します。

同じ風の読み値は、環境制御が開口部へ出す指令の重み付けにも使われます。

| 風 | 開口部の指令にかかる重み |
|----|--------------------------|
| 0.5 m/s 未満 | かけない — すべての開口部が指令どおりの位置へ動きます |
| 0.5〜3.0 m/s | 風圧に比例して徐々に効くため、弱く不安定な風では指令がほとんど変わりません |
| 3.0 m/s 以上 | そのまま全量かかります |

天窓は風向に関係なく熱を抜く役割なので削らず、向きが分からない開口部も指令どおりの位置に保ちます。風を受ける側窓は指令どおり開き、風を背にした側窓は減りますが 20% を下回りません。

シミュレーションが併せて返す重みは風向だけを反映した全量の値で、渡した `speed` によって緩められることはありません。

## センサー・アクチュエーターの割り当て { #sensor-actuator-binding }

AoTデバイスを、施設内でのそれぞれの役割に接続します。

### センサーの役割 { #sensor-roles }

センサーには、別に選ぶ役割名はありません。センサー行で決める値が、そのままセンサーの役割になります — 3Dや設定パネルの **構成要素** タブでセンサーを選ぶと、設定パネルにその行が表示されます。

| 欄 | 選ぶ値 | 意味 |
|----|-----------|----|
| **— チャンネルを選択 —** | Input・Function装置の測定チャンネル | 一つの装置のチャンネルを複数選べます（例: 温湿度計の温度と湿度）。別の装置のチャンネルを選ぶと、センサー全体がその装置へ移ります。 |
| 測定項目 | **— 自動 —** · **温度** · **湿度** · **CO2** · **VPD** · **日射量** · **風速** · **風向** · **突風** · **降水量** | **— 自動 —** はチャンネルから項目を推定します。違っていれば手で選びます。名前が "speed" だけの突風チャンネル(最大瞬間風速をそう出す気象台があります)は手で **突風** を選んでください — そうしないと風速として読まれます。 |
| 位置 | **屋内** · **屋外** | 屋内センサーは施設の屋内値になり（複数あれば加重平均）、屋外センサーは外の条件になります。 |
| 優先度（**屋外** のときのみ） | **メインセンサー** · **バックアップセンサー** | バックアップセンサーはメインセンサーの値が途絶えている間だけ使います。二つを平均することはありません。同じ優先度の中でも、予報モデルの入力(Open-Meteo など)は実測センサーと平均せず、実測が出さない値だけを補います。降水量は優先度にかかわらず新しい実測が予報に勝ちます。 |

一つの装置でチャンネルを一つだけ選んでも、残りが捨てられるわけではありません。その装置でその測定項目の候補チャンネルがちょうど一つだけなら、選んでいないチャンネルも合わせて読み取ります — そのため日射量のチャンネルだけを結び付けた気象ステーションでも、温度・湿度・風速・風向・降水量はそのまま得られます。逆に一つの装置が同じ項目を複数のチャンネルで出す場合（温度チャンネルを六つ送るコンソールなど）は、自動では埋めません。異なる場所の値をまとめて平均してはいけないからで、使うチャンネルを自分で選んでください。自分で選んだチャンネルが常に優先され、同じ **位置** の別のセンサーで既に選んだ項目は二度取り込みません。

### アクチュエーターの役割 { #actuator-roles }

センサー以外の行には、その構成要素を動かす装置を選ぶ **アクチュエーター** 欄（**— なし —** または Output）があります。一つのアクチュエーターで複数の構成要素を動かせます。統合環境制御がその装置を何として使うかは、構成要素の種類で決まります。

| 構成要素 | 行の設定 | 制御での役割 |
|----------|-----------|-----------------|
| **ファン** | アクチュエーター · **ファンの役割**（**循環ファン** / **排気ファン** / **吸気ファン**） | 選んだファンの役割（未設定なら循環ファン） |
| **ヒーター** | アクチュエーター | 暖房（3Dツールの名前は **冷暖房機**） |
| **加湿器** | アクチュエーター | 加湿 |
| **カーテン** | アクチュエーター | 保温カーテン（**エンベロープ** でオンにした天井・側壁保温カーテンもこの種類） |
| **遮光カーテン** | アクチュエーター | 遮光（**エンベロープ** でオンにした遮光カーテン） |
| **窓** | アクチュエーター | 開口部、天窓として扱う（**エンベロープ** でオンにした天窓もこの種類） |
| **側窓** | アクチュエーター | 開口部、側窓（外気を直接取り込む） |
| **ドア** | アクチュエーター | 開口部、側窓と同じように扱う |
| **設備** | アクチュエーター | 統合環境制御には登録されない |
| **灌水レイヤー** | アクチュエーター — そのレイヤーの **給水源**（ポンプ・主バルブ） | スプリンクラーが付いていれば加湿手段として登録、点滴だけなら環境制御には使わない |
| **灌水バルブ** | アクチュエーター — レイヤー内の一つの **ゾーン** | 灌水レイヤーと同じ |
| **メイン配管** | なし | 3Dで配管を選んで削除するための行 |

**登録方法:**

1. ステージを **3D** にします。
2. ツールバーの **追加** メニュー(**開口部**、**設備**、**センサー**、**灌水**)で位置をクリックして配置するか、設定パネルの **構成要素** タブを開き、**追加** の横で種類を選んで **追加** をクリックします。
3. 3Dまたは構成要素タブで構成要素を選びます。設定パネルで、センサーは **— チャンネルを選択 —** で測定チャンネルを選び、測定項目と **屋内**／**屋外** を指定します。それ以外の構成要素は、駆動するアクチュエーターを選びます。
4. 保存済みの施設なら少しあとで自動的に保存されます(**保存済み HH:MM**)。新規施設は **施設を保存** を押します。

### 気象予報の接続 { #weather-forecast-bindings }

施設の予報値(寒くなる前に先に温めるような先行制御に使われます)は、**連携** タブの **天気** から取得します。各行は **気温(°C)** などの測定項目1つを入力チャンネル1つに結び付けます。

**Open-Meteo Hourly Forecast** 入力を使うには **Open-Meteo予報入力から推奨接続を入力** を押します。項目ごとにチャンネルが1つずつ表に入ります。

| 測定項目 | 入力されるチャンネル |
|---|---|
| 気温 | Temperature +3h |
| 湿度 | Window Max Humidity |
| 風速 | Window Max Wind |
| 降水確率 | Window Max Rain Probability |
| 降水量 | Window Max Hourly Rain |
| 日射量 | Solar +1h |

- 同じ項目の接続が複数あると平均されるため、項目ごとにチャンネルは1つだけ入力します。
- 入力された行は、1時間(3600秒)より古い値を使わない設定になります。予報入力は30分ごとに更新されるため、2回続けて更新を逃した値は使われません。
- ボタンは表を入力するだけです。内容を確認してから **施設を保存** を押してください。
- Open-Meteo時間別予報入力が複数ある場合は、ボタンの横のリストで使う入力を選びます。有効なものがなければ、先に追加するよう案内が表示されます。
- この入力を使う同じ項目の行が既にあれば、その行を更新します(自分で付けた行名は維持)。別の入力を使う行には手を付けず、新しい値と平均されます。

## 統合ビュー { #integration-view }

`/api/geo/facility/<uuid>/integration` エンドポイントは、施設に割り当てられたすべてのセンサー・アクチュエーターの現在の状態を、ひとつにまとまったレスポンスとして返します。AoT_facilityウィジェットの環境パネルはこのAPIを使用します。ファンのアクチュエーター項目には、アクチュエーターの風量仕様、空であればファン金具に設定された風量から読み取った定格風量(`rated_m3h`)が含まれます。時間別予報入力(**Open-Meteo Hourly Forecast**)のチャンネルはセンサーとして自動解釈されず、そのような入力は施設センサーとして保存することもできません — 数時間先の値が今の値として読まれてしまうためです。予報は **接続** の **気象** タブで接続してください。

## 装置チェック { #device-check }

施設に接続されたアクチュエーターを短時間動かし、コマンドが届いてセンサーが反応するかを確認する診断ワークフローです。施設を保存したあとに利用できます。

1. **レビュー** タブの **装置チェック** でチェックする装置を選び(**すべて選択** も可)、**チェックを開始** をクリックします。
2. システムが、選択したアクチュエーターを順にオン・オフし、屋内センサーの反応を記録します。
3. 各装置の結果ステータスが表示されます。
   - **通常**: コマンドが届き、センサーが想定どおりの方向に反応しました
   - **要確認**: センサーの反応がない、または想定と逆方向です（センサーの位置と装置の配線を確認してください）
   - **応答なし**: コマンドを送信できませんでした（装置の接続を確認してください）
4. 装置ごとに **判定**（通常／センサー疑義／デバイス故障／外部擾乱／スキップ）を選び、**判定を適用** をクリックすると、結果が制御アルゴリズムの設定にすぐ反映されます。
