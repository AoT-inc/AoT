# 施設管理

`/geo/facility` ページは、温室・育苗ハウス・機械室などの建物について、3Dモデリング、工学計算、センサー・アクチュエーターの割り当て、試運転を行う場所です。

---

## 画面レイアウト

```
┌─────────────────────────────────────┐
│  施設選択ドロップダウン              │
├───────────────┬─────────────────────┤
│ A. 3Dビュー   │ B. 環境データ       │
│ (Three.js)    │ 屋内: T/RH/CO₂     │
│               │ 屋外: T/風/PAR     │
├───────────────┴─────────────────────┤
│  C. AIアドバイスパネル               │
├─────────────────────────────────────┤
│  D. 設定（外皮/センサー/アクチュエーター）│
└─────────────────────────────────────┘
```

---

## 施設登録の流れ

```
/geo/design（Facilityモード）でFacilityポリゴンを描く
         ↓
    施設名を保存する
         ↓
/geo/facility で施設を選択する
         ↓
  外皮を設定する → 3Dプレビューを確認する
         ↓
  センサー・アクチュエーターを割り当てる
         ↓
  試運転を実行する
```

## 外皮の設定

建物の物理的な構造を設定します。これらの値は、暖房・冷房負荷計算の入力として使われます。

### 構造タイプ

| タイプ | 説明 |
|------|-------------|
| `single` | 単棟温室（独立した構造） |
| `connected` | 連棟温室（複数のスパンが側壁を共有） |

### 被覆資材 { #covering-materials }

| コード | 名称 | U値 (W/m²K) | 透光率 |
|------|------|----------------|---------------------|
| `vinyl_single` | 単層ビニール | 6.0 | 85% |
| `vinyl_double` | 二重ビニール | 4.0 | 78% |
| `po_film` | POフィルム | 6.5 | 85% |
| `polycarbonate` | ポリカーボネート | 3.0 | 78% |
| `glass` | ガラス | 5.8 | 85% |
| `air_cushion` | エアクッションフィルム | 2.8 | 75% |

### 棟の設定

温室の各棟（構造単位）の寸法を入力します。

- **Bay count（棟数）**: スパンの数（連棟の場合）
- **Bay width（棟幅、m）**: 各スパンの幅
- **Length（長さ、m）**: 構造物の長さ
- **Eave height（軒高、m）**: 地面から軒までの高さ
- **Ridge height（棟高、m）**: 軒から棟までの高さ

## 3Dプレビュー

外皮の設定を保存すると、Three.jsでレンダリングされた建物モデルが **A. 3Dビュー** パネルに表示されます。

- **左クリックドラッグ**: 回転
- **右クリックドラッグ**: 平行移動
- **スクロール**: ズーム

### 3Dアセットモード

自動パラメトリック生成の代わりに、カスタムのGLTFモデルを適用することもできます。

1. `/geo/model-assets` でGLTFファイルをアップロードします。
2. 施設の **Render Mode → Asset** に切り替えます。
3. アセットライブラリからモデルを選び、位置・回転・スケールを調整します。

## 工学計算

建物の外皮に基づいて、暖房・冷房および換気能力の一次参考値を計算します（誤差±5〜10%、あくまで機器選定の見積もり用です）。

**Compute** をクリックすると、次を計算します。

| 項目 | 単位 | 説明 |
|------|------|-------------|
| Heating load（暖房負荷） | kW | 外皮の熱通過損失＋すきま風損失 |
| Cooling load（冷房負荷） | kW | 日射熱取得＋作物の蒸散負荷 |
| Forced ventilation（強制換気） | m³/h | 必要換気回数（ACH）に基づくファン容量 |
| Natural ventilation（自然換気） | m³/h | 側窓・天窓による利用可能な自然換気量 |

### 自然換気の風圧シミュレーション

`/api/geo/facility/<uuid>/wind` エンドポイントは、建物のジオメトリと風向・風速を受け取り、換気性能をシミュレートします。

## センサー・アクチュエーターの割り当て

AoTデバイスを、施設内でのそれぞれの役割に接続します。

### センサーの役割

| 役割 | 推奨される測定値 |
|------|------------------------|
| Indoor temperature（室内温度） | Temperature（°C） |
| Indoor humidity（室内湿度） | Humidity（%RH） |
| Indoor CO₂（室内CO₂） | CO2（ppm） |
| Soil temperature（地温） | Soil Temperature |
| Soil moisture（土壌水分） | Soil Moisture |

### アクチュエーターの役割

| 役割 | 出力タイプ |
|------|------------|
| Heater（暖房機） | On/Offリレー |
| Ventilation fan（換気扇） | On/OffまたはPWM |
| Shade screen（遮光スクリーン） | On/Offリレー |
| Irrigation pump（灌漑ポンプ） | On/Offリレー |
| CO₂ supply（CO₂供給） | On/Offリレー |

**登録方法:**

1. **Sensors** タブで **+ Add Sensor** をクリックします。
2. 役割を選択 → AoT Inputデバイスを選択 → 測定チャンネルを選択します。
3. **Actuators** タブでも同様に行います。
4. **Save** をクリックします。

## 統合ビュー

`/api/geo/facility/<uuid>/integration` エンドポイントは、施設に割り当てられたすべてのセンサー・アクチュエーターの現在の状態を、ひとつにまとまったレスポンスとして返します。AoT_facilityウィジェットの環境パネルはこのAPIを使用します。

---

## 試運転

施設のデバイスが正常に通信できているかを確認する診断ワークフローです。

1. **Commissioning** タブで **Start Check** をクリックします。
2. システムが、登録済みのすべてのセンサー・アクチュエーターに通信リクエストを送ります。
3. 各デバイスの応答ステータスが表示されます。
   - `OK`: 正常に通信できています
   - `TIMEOUT`: 応答なし（配線と電源を確認してください）
   - `ERROR`: エラー応答（デバイスの設定を確認してください）
4. **Verdict** ボタンを使って、個々の結果を承認または保留します。

## AIアドバイスパネル

AIが割り当てられたセンサーデータを分析し、異常アラートや運用改善を提案します。

- **緊急度の色分け**: **赤**（即対応）／**オレンジ**（注意）／**緑**（正常）
- 学習データが蓄積されるほど、アドバイスの精度が向上します。

## 関連API

| エンドポイント | 説明 |
|----------|-------------|
| `GET /api/geo/facility/list` | 施設一覧を取得 |
| `GET /api/geo/facility/<uuid>` | 施設の詳細を取得 |
| `POST /api/geo/facility` | 施設を作成／更新 |
| `POST /api/geo/facility/compute` | 容量計算のプレビュー |
| `GET /api/geo/facility/<uuid>/integration` | 統合状態を取得 |
| `GET /api/geo/facility/<uuid>/wind` | 換気シミュレーション |
| `GET /api/geo/facility/<uuid>/runtime` | リアルタイムの実行状態 |
| `POST /api/geo/facility/<uuid>/apply` | 設定を適用 |
| `POST /api/geo/facility/<uuid>/commissioning/start` | 試運転を開始 |
