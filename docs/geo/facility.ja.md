# 施設管理

`/geo/facility` ページは、温室・育苗ハウス・機械室などの建物について、3Dモデリング、工学計算、センサー・アクチュエーターの割り当て、装置チェックを行う場所です。画面上部のステップバー（**基本情報・位置・構造・エンベロープ・設備配置・連携・区画・レビュー**）でステップを選んで設定します。

---

## 画面レイアウト

```
施設設計 · <施設名> · [未保存の変更] · [施設を保存]          ← タイトル行
[基本情報] [位置・構造] [エンベロープ] [設備配置] [連携] [区画] [レビュー]   [3D | 地図]   ← ステップバー
├── ステージ: 3D または地図（一度にどちらか一方）
│     3D   — 3Dプレビューのヘッダー · 左の配置ツール · 3Dビュー
│     地図 — [地図に配置] · [クリア]
└── 設定ドロワー: 右から開き、タイトルは現在のステップ名
      そのステップの設定 · [前へ] [次へ] [キャンセル] [施設を保存]
```

- **タイトル行** — **施設設計**、開いている施設の名前、未保存の編集があるときの **未保存の変更** 表示、**施設を保存** ボタン。自動保存はありません — **施設を保存** をクリックしたときにだけ保存されます。
- **ステップバー** — ステップをクリックすると右にそのステップの設定ドロワーが開き、現在のステップは塗りつぶしのボタンで示されます。完了マークはありません。必須項目が残っているステップは、ボタンにマウスを重ねると何が足りないかを表示します（**名前を入力してください**、**地図を選択して施設を配置してください**、**まだ構成要素が配置されていません**、**まだ保存されていません**）。
- **3D | 地図** — どのステップでもステージを切り替えられます。**位置・構造**・**エンベロープ**・**設備配置** は最初に地図で、ほかのステップは3Dで開きます。手で選んだ表示はそのセッションの間、ステップごとに記憶されます。
- **ステージ — 3D** — ヘッダー（**3Dプレビュー**）に **3Dに表示**（表示フィルター）、**高品質** / **高速プレビュー**（描画品質の切り替え）、**元に戻す**、**ツール & エクスポート**（アセットライブラリ · PNG/Spec/GLBのエクスポート · Spec/GLBのインポート · 更新）があり、3Dビューの左に配置ツール（**選択**、**開口部**、**設備**、**灌水**、**+ センサー**、**カタログ**）があります。
- **ステージ — 地図** — **地図に配置** をクリックしてから、地図上で施設の中心をクリックします。置いた施設はドラッグで移動でき、寸法と回転は入力したとおりに矩形へすぐ反映されます。
- **設定ドロワー** — ステージを覆わずにページを横へ押しのけて開くので、値を変えながら3Dや地図の変化を確かめられます。スマートフォンではモデルの下にシートとして開き、**モデルを隠す** で設定欄に画面全体を使えます。

ステップごとのドロワーの内容:

| ステップ | ドロワーの内容 |
|------|-----------|
| **基本情報** | **保存済み施設**（一覧 · **+ 新規施設** · **施設を複製** · 削除）、**仕様**（名前 · この施設を操作できるグループ · プリセット · スパン · 軒高 · 棟高 · 長さ · 屋根タイプ） |
| **位置・構造** | **マップとサイト**（地図 · サイト）、**位置・構造**（構造 · ベイ数 · 間隔 · ゾーン · 回転） |
| **エンベロープ** | **被覆・換気**（被覆レイヤー · 外部側面ベント · 外部屋根ベント）、**カーテン**（天井保温カーテン · 側壁保温カーテン · 遮光カーテン） |
| **設備配置** | **構成要素の追加**、**構成要素** の表（種類ごとのタブ。行を選ぶとすぐ下に3D配置が開く）、**装置が未接続の場所**（装置を削除して構成要素だけが残ったときのみ） |
| **連携** | **天気**（予報Inputの接続）、**グループ**（同じ種類のアクチュエーターをリーダー・フォロワーでまとめる）、**ラベル色**（測定項目ごとの色の区間） |
| **区画** | ゾーンごとに何を育てているかを記録 — 施設の区画は描く必要がなく、ゾーンそのものが場所になります |
| **レビュー** | **容量プレビュー**、**IEC 統合サマリー**、**装置チェック** — 後の二つは施設を保存したあとに使えます |

## 施設登録の流れ { #facility-registration-flow }

```
/geo/facility を開く（/geo/design の施設設定で 施設設計 › 開く、またはアドレスを直接入力）
         ↓
基本情報 › + 新規施設 → 名前と仕様を入力
         ↓
位置・構造 › 地図を選択（サイトは任意）→ 地図に配置 → 地図上で施設の中心をクリック
             → 構造・ベイ数・回転
         ↓
エンベロープ › 被覆・換気・カーテン → 3Dで確認
         ↓
設備配置 › センサー・アクチュエーターを配置して装置を接続
         ↓
連携 › 天気サービス・アクチュエーターのグループ・ラベル色
         ↓
区画 › 各ゾーンに何があるかを記録
         ↓
施設を保存 → レビュー › 装置チェック
```

- 施設はこの画面の **施設を保存** で作られます。先に `/geo/design` で描く必要はありません — 保存すると、選んだ地図に施設の外形も一緒に作られます。
- 施設を指定せずに開くと、空の新規施設から始まり **基本情報** のドロワーが開きます。保存した施設は **保存済み施設** の一覧から選んで開きます。このときアドレスに `?facility_uuid=` が付くので、再読み込みやブックマークでも同じ施設が開きます。
- 保存するには地図を選び、地図に配置する必要があります — **地図に配置** をしないと保存は拒否されます。名前は空でも保存できますが、**基本情報** ステップに **名前を入力してください** が表示され続けます。
- **施設を複製** は開いている施設を複製します。接続したセンサー・出力は引き継がれません。
- **レビュー** の **IEC 統合サマリー** と **装置チェック** は、施設を保存したあとにだけ動作します。

## 外皮の設定

建物の形は前のステップで — 寸法は **基本情報 › 仕様**、構造・ベイ数・回転は **位置・構造** で — 決め、外側を覆うものは **エンベロープ** ステップで決めます。これらの値はすべて冷暖房負荷の計算と3Dモデルの入力になり、モデルは値を変えるたびに追従します。

**エンベロープ** ステップにあるもの:

- **被覆・換気**
    - **外皮（全体）** — 外側の被覆です。常にあるので、資材だけを選びます。
    - **内部カバー**（トグル） — 内側の二つ目の被覆: **被覆レイヤー**（資材）と **エアギャップ** (m)。
    - **側壁補強**（トグル） — **被覆レイヤー**、**位置**（X− ・ X+ ・ Y+ ・ Y−）、**深さ** (m、壁から外へ出る距離)。
    - **正面補強**（トグル） — **位置**（Y+ ・ Y−）、**深さ** (m)。
    - **外部側面ベント**（トグル） — 側壁に沿った側窓。**1段** または **2段** で、2段なら段ごとに高さと開始高さ (m) を決めます。
    - **外部屋根ベント**（トグル） — 天窓。**位置** は **中心** または **左右**。
- **カーテン**
    - **天井保温カーテン**（トグル） — **1層** または **2層**。
    - **側壁保温カーテン**（トグル） — 側面ベントの段構成に従います。
    - **遮光カーテン**（トグル） — **透過率**: 完全に閉じたときに通る光の割合（0.30なら10分の3が通る）。空欄なら0.50とみなします。

ここでオンにした換気窓とカーテンは、**設備配置** ステップの **構成要素** の表に **外皮生成** と付いた行として現れ、そこで動かすアクチュエーターを接続します。

### 構造タイプ { #structure-type }

**位置・構造** ステップの **構造** で選びます。

| 画面 | 値 | 説明 |
|------|----|------|
| **単棟** | `single` | 棟ごとに独立した構造物です。二つ以上なら **間隔 (m)** だけ離れて一列に並びます。 |
| **連棟** | `connected` | 複数の棟が側壁を共有して一つの建物になります。間隔の欄はありません。 |

### 被覆資材 { #covering-materials }

エンベロープ ステップの被覆ドロップダウンに出る資材と、負荷計算が使う値です。

| コード | 名称 | U値 (W/m²K) | 透光率 | 選べる場所 |
|------|------|----------------|---------------------|-------------|
| `vinyl_single` | ビニール（単層） | 6.0 | 85% | 外皮（全体）・側壁補強 / 内部カバー |
| `vinyl_double` | ビニール（二重） | 4.0 | 78% | 外皮（全体）・側壁補強 |
| `po_film` | POフィルム | 6.5 | 85% | 外皮（全体）・側壁補強 |
| `pe_film` | PEフィルム | 6.5 | 85% | 内部カバー |
| `polycarbonate` | ポリカーボネート | 3.0 | 78% | 外皮（全体）・側壁補強 / 内部カバー |
| `glass` | ガラス | 5.8 | 85% | 外皮（全体）・側壁補強 |
| `non_woven_fabric` | 不織布 | 3.5 | 50% | 内部カバー |
| `air_cushion` | エアクッション | 2.8 | 75% | 内部カバー |
| `film_white_opaque` | 不透明白色フィルム | 6.5 | 0%（不透明） | 外皮（全体）・側壁補強 / 内部カバー |
| `film_grey` | グレーフィルム | 6.5 | 0%（不透明） | 外皮（全体）・側壁補強 / 内部カバー |
| `film_black` | 黒色フィルム | 6.5 | 0%（不透明） | 外皮（全体）・側壁補強 / 内部カバー |
| `sandwich_panel` | サンドイッチパネル | 0.45 | 0%（不透明） | 外皮（全体）・側壁補強 / 内部カバー |
| `concrete` | コンクリート | 3.1 | 0%（不透明） | 外皮（全体）・側壁補強 |
| `brick` | レンガ | 2.4 | 0%（不透明） | 外皮（全体）・側壁補強 |

### 棟の設定 { #bay-configuration }

- **基本情報 › 仕様**
    - **プリセット** — **標準アーチ型**
    - **スパン (m)** — 棟一つの幅
    - **軒高 (m)** — 床から軒まで
    - **棟高 (m)** — 床から棟まで。軒高との差が屋根の高さです。
    - **長さ (m)** — 建物の長さ
    - **屋根タイプ** — **アーチ型**、**切妻屋根**、**切妻 2**（一つの棟に棟木が二つ）、**平屋根**
- **位置・構造**
    - **ベイ数** (N) — 1〜20
    - **間隔 (m)** — 棟と棟の間の距離。**単棟** のときだけあります。
    - **ゾーン** — 二つ以上のときに現れます。棟の間の境界をクリックしてゾーンを分けたりまとめたりします。地図ウィジェットとゾーン別の環境制御がこのゾーンを使います。
    - **回転** (°) — 0〜359、スライダーを動かすか値を入力

## 3Dプレビュー { #3d-preview }

ステージを **3D** にすると、Three.jsで描いた建物モデルが表示され、設定ドロワーで値を変えるたびにモデルへ反映されます。

- **右クリックドラッグ**: 回転
- **左クリックドラッグ**: 平行移動（クリックで選択）
- **スクロール**: ズーム

床の **N 矢印** がこの施設の実際の北です（位置ステップの回転値を反映）。既定の視点は南から北を見る向きなので、画面の右が東・奥が北となり、北が上の地図と左右・前後が一致します。ビューキューブの N 系の視点は北から見るため、東が左に来ます。

### 3Dアセットモード { #3d-asset-mode }

自動パラメトリック生成の代わりに、カスタムのGLTFモデルを適用することもできます。

1. `/geo/model_assets` でGLTFファイルをアップロードします。
2. **3Dプレビュー** の **ツール & エクスポート › アセットライブラリ** でモデルを選びます。
3. パラメトリックモデルに戻すには **アセットを解除** をクリックします。

## 工学計算 { #engineering-calculations }

建物の外皮に基づいて、暖房・冷房および換気能力の一次参考値を計算します（誤差±5〜10%、あくまで機器選定の見積もり用です）。

寸法や資材を変更すると自動的に再計算され、**レビュー** ステップの **容量プレビュー** に表示されます。計算項目は次のとおりです。

| 項目 | 単位 | 説明 |
|------|------|-------------|
| 床 | m² | 建物が占める床面積 |
| 体積 | m³ | 内部の空気の体積 |
| グレージング | m² | 外皮の被覆面積（側壁＋屋根＋妻壁） |
| 換気口開放 | m² | 換気口・開口部の合計開放面積 |
| 暖房 | kW | 外皮の熱通過損失＋すきま風損失 |
| 冷房 | kW | 日射熱取得＋作物の蒸散負荷 |
| ACH | /h | 時間あたりの換気回数 — 自然換気とファンの合計 |

暖房・冷房は計算された負荷を表示します。アクチュエーターに能力を設定しておくとその合計が代わりに表示され、値にマウスを重ねると、その定格合計と計算値を比べられます。

### 自然換気の風圧シミュレーション { #natural-ventilation-wind-pressure-simulation }

`/api/geo/facility/<uuid>/wind` エンドポイントは、建物のジオメトリと風向・風速を受け取り、換気性能をシミュレートします。

クエリ値は `speed`（風速 m/s、既定 3.0）、`dir`（気象標準の風向 0〜359°、0 は北から吹く風、既定 0）、`pct`（開口部の開度 0〜100%、既定 100）です。

応答は、有効換気回数（毎時。総流入量と総流出量の小さい方）とその二つの合計、さらに開口部ごとの開口面積・風圧係数・毎時通気量・空気が入るか出るかを返します。風を受ける開口部は正圧で空気を取り込み、風を背にした開口部は吸引で外へ出し、風と平行な開口部はほとんど通気しません。天窓は風向に関係ないものとして扱い、風速の一定割合だけ換気します。

同じ風の読み値は、環境制御が開口部へ出す指令の重み付けにも使われます。

| 風 | 開口部の指令にかかる重み |
|----|--------------------------|
| 0.5 m/s 未満 | かけない — すべての開口部が指令どおりの位置へ動きます |
| 0.5〜3.0 m/s | 風圧に比例して徐々に効くため、弱く不安定な風では指令がほとんど変わりません |
| 3.0 m/s 以上 | そのまま全量かかります |

天窓は風向に関係なく熱を抜く役割なので削らず、向きが分からない開口部も指令どおりの位置に保ちます。風を受ける側窓は指令どおり開き、風を背にした側窓は減りますが 20% を下回りません。

シミュレーションが併せて返す重みは風向だけを反映した全量の値で、渡した `speed` によって緩められることはありません。

## センサー・アクチュエーターの割り当て { #sensor-actuator-binding }

AoTデバイスを、施設内でのそれぞれの役割に接続します。

### センサーの役割 { #sensor-roles }

センサーには、別に選ぶ役割名はありません。**構成要素** の表のセンサー行で決める値が、そのままセンサーの役割になります。

| 欄 | 選ぶ値 | 意味 |
|----|-----------|----|
| **— チャンネルを選択 —** | Input・Function装置の測定チャンネル | 一つの装置のチャンネルを複数選べます（例: 温湿度計の温度と湿度）。別の装置のチャンネルを選ぶと、センサー全体がその装置へ移ります。 |
| 測定項目 | **— 自動 —** · **温度** · **湿度** · **CO2** · **VPD** · **日射量** · **風速** · **風向** · **降水量** | **— 自動 —** はチャンネルから項目を推定します。違っていれば手で選びます。 |
| 位置 | **屋内** · **屋外** | 屋内センサーは施設の屋内値になり（複数あれば加重平均）、屋外センサーは外の条件になります。 |
| 優先度（**屋外** のときのみ） | **メインセンサー** · **バックアップセンサー** | バックアップセンサーはメインセンサーの値が途絶えている間だけ使います。二つを平均することはありません。 |

一つの装置でチャンネルを一つだけ選んでも、残りが捨てられるわけではありません。その装置でその測定項目の候補チャンネルがちょうど一つだけなら、選んでいないチャンネルも合わせて読み取ります — そのため日射量のチャンネルだけを結び付けた気象ステーションでも、温度・湿度・風速・風向・降水量はそのまま得られます。逆に一つの装置が同じ項目を複数のチャンネルで出す場合（温度チャンネルを六つ送るコンソールなど）は、自動では埋めません。異なる場所の値をまとめて平均してはいけないからで、使うチャンネルを自分で選んでください。自分で選んだチャンネルが常に優先され、同じ **位置** の別のセンサーで既に選んだ項目は二度取り込みません。

### アクチュエーターの役割 { #actuator-roles }

センサー以外の行には、その構成要素を動かす装置を選ぶ **アクチュエーター** 欄（**— なし —** または Output）があります。一つのアクチュエーターで複数の構成要素を動かせます。統合環境制御がその装置を何として使うかは、構成要素の種類で決まります。

| 構成要素 | 行の設定 | 制御での役割 |
|----------|-----------|-----------------|
| **ファン** | アクチュエーター · **ファンの役割**（**循環ファン** / **排気ファン** / **吸気ファン**） | 選んだファンの役割（未設定なら循環ファン） |
| **ヒーター** | アクチュエーター | 暖房（3Dツールの名前は **冷暖房機**） |
| **加湿器** | アクチュエーター | 加湿 |
| **カーテン** | アクチュエーター | 保温カーテン（**エンベロープ** でオンにした天井・側壁保温カーテンもこの種類） |
| **遮光カーテン** | アクチュエーター | 遮光（**エンベロープ** でオンにした遮光カーテン） |
| **窓** | アクチュエーター | 開口部、天窓として扱う（**エンベロープ** でオンにした天窓もこの種類） |
| **側窓** | アクチュエーター | 開口部、側窓（外気を直接取り込む） |
| **ドア** | アクチュエーター | 開口部、側窓と同じように扱う |
| **設備** | アクチュエーター | 統合環境制御には登録されない |
| **灌水レイヤー** | アクチュエーター — そのレイヤーの **給水源**（ポンプ・主バルブ） | スプリンクラーが付いていれば加湿手段として登録、点滴だけなら環境制御には使わない |
| **灌水バルブ** | アクチュエーター — レイヤー内の一つの **ゾーン** | 灌水レイヤーと同じ |
| **メイン配管** | なし | 3Dで配管を選んで削除するための行 |

**登録方法:**

1. **設備配置** ステップを開きます。
2. 3Dビュー左側のツール（**+ センサー**、**開口部**、**設備**、**灌水**）で位置をクリックして配置するか、**構成要素の追加** で種類を選んで **+ 追加** をクリックします。
3. **構成要素** の表で、センサーの行は **— チャンネルを選択 —** で測定チャンネルを選び、測定項目と **屋内**／**屋外** を指定します。それ以外の行では、駆動するアクチュエーターを選びます。
4. **施設を保存** をクリックします。

`/api/geo/facility/<uuid>/integration` エンドポイントは、施設に割り当てられたすべてのセンサー・アクチュエーターの現在の状態を、ひとつにまとまったレスポンスとして返します。AoT_facilityウィジェットの環境パネルはこのAPIを使用します。

## 装置チェック { #device-check }

施設に接続されたアクチュエーターを短時間動かし、コマンドが届いてセンサーが反応するかを確認する診断ワークフローです。施設を保存したあとに利用できます。

1. **レビュー** ステップの **装置チェック** でチェックする装置を選び（**すべて選択** も可）、**チェックを開始** をクリックします。
2. システムが、選択したアクチュエーターを順にオン・オフし、屋内センサーの反応を記録します。
3. 各装置の結果ステータスが表示されます。
   - **通常**: コマンドが届き、センサーが想定どおりの方向に反応しました
   - **要確認**: センサーの反応がない、または想定と逆方向です（センサーの位置と装置の配線を確認してください）
   - **応答なし**: コマンドを送信できませんでした（装置の接続を確認してください）
4. 装置ごとに **判定**（通常／センサー疑義／デバイス故障／外部擾乱／スキップ）を選び、**判定を適用** をクリックすると、結果が制御アルゴリズムの設定にすぐ反映されます。

## AIアドバイスパネル

施設画面にはAIアドバイスパネルはありません。アプリ内のAIや接続された他のAIが出したアドバイスは、**AI → リクエスト** 画面（`/ai`）の **AIのアドバイス** に集まります。採用は同意したという記録で、何も実行しません。[AI機能の概要](../ai/overview.md)を参照してください。
