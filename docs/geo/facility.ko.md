# 시설 관리

`/geo/facility` 페이지에서 온실·재배사·설비동 등 건물의 3D 모델링, 공학 계산, 센서·액추에이터 연결, 장치 점검을 수행합니다. 화면 위쪽 단계 표시줄(**기본 정보 · 위치·구조 · 외피 · 설비 배치 · 연결 · 구획 · 검토**)에서 단계를 골라 설정합니다.

---

## 화면 구성

```
시설 설계 · <시설 이름> · [저장 안 된 변경] · [시설 저장]          ← 제목 줄
[기본 정보] [위치·구조] [외피] [설비 배치] [연결] [구획] [검토]   [3D | 지도]   ← 단계 표시줄
├── 무대: 3D 또는 지도 (한 번에 하나)
│     3D   — 3D 미리보기 머리줄 · 왼쪽 배치 도구 · 3D 뷰
│     지도 — [지도에 배치] · [지우기]
└── 설정 서랍: 오른쪽에서 열림, 제목은 지금 단계 이름
      그 단계의 설정 · [이전] [다음] [취소] [시설 저장]
```

- **제목 줄** — **시설 설계**, 지금 연 시설 이름, 저장하지 않은 변경이 있을 때 **저장 안 된 변경** 표시, **시설 저장** 버튼. 자동 저장은 없습니다 — **시설 저장**을 눌러야 저장됩니다.
- **단계 표시줄** — 단계를 누르면 오른쪽에 그 단계의 설정 서랍이 열리고, 지금 단계는 채워진 버튼으로 보입니다. 완료 표시는 없습니다. 꼭 채워야 할 것이 남은 단계는 버튼에 마우스를 올리면 무엇이 빠졌는지 알려 줍니다(**이름을 입력하세요**, **지도를 선택하고 시설을 배치하세요**, **아직 배치된 구성요소가 없습니다**, **아직 저장되지 않았습니다**).
- **3D | 지도** — 모든 단계에서 무대를 바꿉니다. **위치·구조**·**외피**·**설비 배치**는 처음에 지도로, 나머지 단계는 3D로 열리며, 직접 고른 쪽은 그 세션 동안 단계마다 기억합니다.
- **무대 — 3D** — 머리줄(**3D 미리보기**)에 **3D에 표시**(표시 필터), **고품질** / **빠른 미리보기**(렌더링 품질 전환), **실행 취소**, **도구 & 내보내기**(자산 라이브러리 · PNG/Spec/GLB 내보내기 · Spec/GLB 불러오기 · 새로고침)가 있고, 3D 뷰 왼쪽에 배치 도구(**선택**, **개구부**, **시설물**, **관수**, **+ 센서**, **카탈로그**)가 있습니다.
- **무대 — 지도** — **지도에 배치**를 누르고 지도에서 시설 중심을 클릭합니다. 놓인 시설은 끌어서 옮기고, 치수·회전은 입력하는 대로 사각형에 바로 반영됩니다.
- **설정 서랍** — 무대를 덮지 않고 페이지를 옆으로 밀며 열리므로, 값을 바꾸면서 3D·지도가 달라지는 것을 볼 수 있습니다. 휴대폰에서는 모델 아래 시트로 열리고, **모델 숨기기**로 설정 칸에 화면 전체를 줄 수 있습니다.

단계별 서랍 내용:

| 단계 | 서랍 내용 |
|------|-----------|
| **기본 정보** | **저장된 시설**(목록 · **+ 새 시설** · **시설 복제** · 삭제), **규격**(이름 · 그룹 선택 · 프리셋 · 경간 · 처마 높이 · 용마루 높이 · 길이 · 지붕 유형) |
| **위치·구조** | **지도 및 대지**(지도 · 대지), **위치·구조**(구조 · 동 수 · 간격 · 구역 · 회전) |
| **외피** | **피복 및 환기**(피복 레이어 · 외부 측면 환기 · 외부 천창 환기), **커튼**(천장 보온 커튼 · 측벽 보온 커튼 · 차광 커튼) |
| **설비 배치** | **구성요소 추가**, **구성요소** 표(종류마다 탭, 행을 선택하면 바로 아래에 3D 배치 칸이 열림), **장치 미연결**(장치를 지웠는데 구성요소가 남았을 때만) |
| **연결** | **날씨**(예보 Input 연결), **그룹**(같은 종류 액추에이터를 리더·팔로워로 묶기), **라벨 색상**(측정 항목별 색 구간) |
| **구획** | 구역마다 무엇을 기르는지 기록 — 시설 구획은 그릴 필요 없이 구역이 곧 자리입니다 |
| **검토** | **수용량 미리보기**, **IEC 통합 요약**, **장치 점검** — 뒤의 둘은 시설을 저장한 뒤에 쓸 수 있습니다 |

## 시설 등록 흐름 { #facility-registration-flow }

```
/geo/facility 열기  (/geo/design 의 시설 설정에서 시설 설계 › 열기, 또는 주소로 직접)
         ↓
기본 정보 › + 새 시설 → 이름·규격 입력
         ↓
위치·구조 › 지도 선택(대지는 선택 사항) → 지도에 배치 → 지도에서 시설 중심 클릭
            → 구조·동 수·회전
         ↓
외피 › 피복·환기·커튼 → 3D로 확인
         ↓
설비 배치 › 센서·액추에이터 배치와 장치 연결
         ↓
연결 › 날씨 서비스·액추에이터 그룹·라벨 색상
         ↓
구획 › 각 구역에 무엇이 있는지 기록
         ↓
시설 저장 → 검토 › 장치 점검
```

- 시설은 이 화면에서 **시설 저장**으로 만듭니다. `/geo/design`에서 먼저 그릴 필요가 없습니다 — 저장하면 고른 지도에 시설 외곽 도형도 함께 생깁니다.
- 시설을 지정하지 않고 열면 빈 새 시설로 시작하고 **기본 정보** 서랍이 열립니다. 저장한 시설은 **저장된 시설** 목록에서 골라 엽니다. 이때 주소에 `?facility_uuid=`가 붙어, 새로고침하거나 북마크해도 같은 시설이 열립니다.
- 저장하려면 지도를 고르고 지도에 배치해야 합니다 — **지도에 배치**를 하지 않으면 저장이 거절됩니다. 이름은 비워도 저장되지만 **기본 정보** 단계에 **이름을 입력하세요**가 계속 표시됩니다.
- **시설 복제**는 지금 연 시설을 복제합니다. 연결한 센서·출력은 복사되지 않습니다.
- **검토**의 **IEC 통합 요약**과 **장치 점검**은 시설을 저장한 뒤에만 동작합니다.

## 외피 설정

건물의 형태는 앞 단계에서 — 치수는 **기본 정보 › 규격**, 구조·동 수·회전은 **위치·구조**에서 — 정하고, 겉을 두르는 것은 **외피** 단계에서 정합니다. 이 값들은 모두 냉난방 부하 계산과 3D 모델의 입력이 되며, 모델은 값을 바꾸는 대로 따라 바뀝니다.

**외피** 단계에 있는 것:

- **피복 및 환기**
    - **외피 (전체)** — 바깥 피복입니다. 늘 있으므로 자재만 고릅니다.
    - **내부 피복** (토글) — 안쪽 두 번째 피복: **피복 레이어**(자재)와 **에어갭** (m).
    - **측벽 보강** (토글) — **피복 레이어**, **위치**(X− · X+ · Y+ · Y−), **깊이** (m, 벽 바깥으로 나온 거리).
    - **정면 보강** (토글) — **위치**(Y+ · Y−), **깊이** (m).
    - **외부 측면 환기** (토글) — 측벽을 따라 나는 측창. **1단** 또는 **2단**이며, 2단이면 단마다 높이와 시작 높이(m)를 따로 정합니다.
    - **외부 천창 환기** (토글) — 천창. **위치**는 **중심** 또는 **좌우**.
- **커튼**
    - **천장 보온 커튼** (토글) — **1중** 또는 **2중**.
    - **측벽 보온 커튼** (토글) — 측면 환기의 단 구성을 따릅니다.
    - **차광 커튼** (토글) — **투과율**: 완전히 닫았을 때 통과하는 빛의 비율(0.30이면 10분의 3이 통과). 비워 두면 0.50으로 가정합니다.

여기서 켠 환기창과 커튼은 **설비 배치** 단계의 **구성요소** 표에 **외피 생성** 표시가 붙은 행으로 나타나고, 거기서 움직일 액추에이터를 연결합니다.

### 동 설정 { #bay-configuration }

- **기본 정보 › 규격**
    - **프리셋** — **표준 아치형**
    - **경간 (m)** — 동 하나의 폭
    - **처마 높이 (m)** — 바닥에서 처마까지
    - **용마루 높이 (m)** — 바닥에서 용마루까지. 처마 높이와의 차이가 지붕 높이입니다.
    - **길이 (m)** — 건물 길이
    - **지붕 유형** — **아치형**, **박공 지붕**, **박공 2**(동 하나에 용마루 둘), **평지붕**
- **위치·구조**
    - **동 수** (N) — 1~20
    - **간격 (m)** — 동과 동 사이 거리. **단동**일 때만 있습니다.
    - **구역** — 동이 둘 이상일 때 나타납니다. 동 사이 경계를 눌러 구역을 나누거나 합칩니다. 지도 위젯과 구역별 환경 제어가 이 구역을 씁니다.
    - **회전** (°) — 0~359, 슬라이더를 끌거나 값을 입력

## 3D 미리보기 { #3d-preview }

무대를 **3D**로 두면 Three.js로 그린 건물 모델이 보이고, 설정 서랍에서 값을 바꾸는 대로 모델에 반영됩니다.

- **마우스 오른쪽 버튼 드래그**: 회전
- **마우스 왼쪽 버튼 드래그**: 이동 (클릭은 선택)
- **스크롤**: 줌

바닥의 **N 화살표**가 이 시설의 실제 북쪽입니다(위치 단계의 회전값을 반영). 기본 시점은 남쪽에서 북쪽을 바라보는 방향이라, 화면의 오른쪽이 동쪽·먼 쪽이 북쪽으로 북쪽이 위인 지도와 좌우·앞뒤가 같습니다. 뷰 큐브의 N 계열 시점은 북쪽에서 바라보므로 동쪽이 왼쪽에 옵니다.

### 3D 에셋 모드 { #3d-asset-mode }

파라메트릭 자동 생성 대신 직접 제작한 GLTF 모델을 적용할 수 있습니다.

1. `/geo/model_assets`에서 GLTF 파일 업로드
2. **3D 미리보기**의 **도구 & 내보내기 › 자산 라이브러리**에서 모델 선택
3. 파라메트릭 모델로 되돌리려면 **자산 해제** 클릭

## 공학 계산 { #engineering-calculations }

시설의 외피 치수·자재를 기반으로 냉난방 및 환기 용량의 1차 참고치를 계산합니다 (±5~10% 오차, 기계설비 견적 단계 참고용).

치수·자재를 바꾸면 자동으로 다시 계산되어 **검토** 단계의 **수용량 미리보기**에 표시됩니다. 계산 항목은 아래와 같습니다.

| 계산 항목 | 단위 | 설명 |
|----------|------|------|
| 바닥 | m² | 건물이 차지하는 바닥 면적 |
| 부피 | m³ | 내부 공기 부피 |
| 유리 피복 | m² | 외피 피복 면적 (측벽 + 지붕 + 양 끝벽) |
| 환기구 열림 | m² | 환기구·개구부의 총 열림 면적 |
| 난방 | kW | 외피 관류 손실 + 침기 손실 |
| 냉방 | kW | 일사 부하 + 작물 증산 부하 |
| ACH | /h | 시간당 환기 횟수 — 자연환기와 팬을 합한 값 |

난방·냉방은 계산된 부하를 보여 줍니다. 액추에이터에 용량을 적어 두면 그 합계가 대신 표시되고, 값 위에 마우스를 올리면 그 정격 합계와 계산값을 비교해 볼 수 있습니다.

### 자연환기 풍압 시뮬레이션 { #natural-ventilation-wind-pressure-simulation }

`/api/geo/facility/<uuid>/wind` 엔드포인트를 통해 건물 형상과 풍향·풍속을 입력받아 환기 성능을 시뮬레이션합니다.

질의 값은 `speed`(풍속 m/s, 기본 3.0), `dir`(기상 표준 풍향 0~359°, 0은 북에서 불어오는 바람, 기본 0), `pct`(개구부 개방률 0~100%, 기본 100)입니다.

응답은 유효 환기 횟수(시간당) — 총 유입량과 총 유출량 중 작은 쪽 — 와 그 두 합계, 그리고 개구부마다 열린 면적·풍압계수·시간당 통기량·공기가 들어오는지 나가는지를 알려줍니다. 바람을 맞는 개구부는 양압을 받아 공기를 들이고, 바람을 등진 개구부는 흡인을 받아 내보내며, 바람과 나란한 개구부는 거의 통기하지 않습니다. 천창은 풍향과 무관하게 보아 풍속의 일정 비율만큼 환기합니다.

같은 풍향 판독은 환경 제어가 개구부에 내리는 명령에도 가중치로 쓰입니다.

| 바람 | 개구부 명령에 걸리는 가중치 |
|------|----------------------------|
| 0.5 m/s 미만 | 걸지 않음 — 모든 개구부가 명령한 위치로 갑니다 |
| 0.5 ~ 3.0 m/s | 풍압에 비례해 서서히 들어오므로, 약하고 불안정한 바람은 명령을 거의 바꾸지 않습니다 |
| 3.0 m/s 이상 | 온전히 걸립니다 |

천창은 풍향과 무관하게 열기를 빼는 역할이므로 깎지 않고, 향한 방향을 알 수 없는 개구부도 명령한 위치 그대로 둡니다. 바람을 맞는 측창은 명령대로 열리고, 바람을 등진 측창은 줄어들지만 20% 아래로는 내려가지 않습니다.

시뮬레이션이 함께 돌려주는 가중치는 풍향만 반영한 온전한 값이며, 입력한 `speed` 로는 완화되지 않습니다.

## 센서·액추에이터 바인딩 { #sensor-actuator-binding }

시설 내 AoT 장치를 역할에 맞게 연결합니다.

### 센서 역할 { #sensor-roles }

센서는 역할 이름을 따로 고르지 않습니다. **구성요소** 표의 센서 행에서 정하는 값이 곧 그 센서의 역할입니다.

| 칸 | 고르는 값 | 뜻 |
|----|-----------|----|
| **— 채널 선택 —** | Input·Function 장치의 측정 채널 | 한 장치의 채널을 여러 개 고를 수 있습니다(예: 온습도계의 온도·습도). 다른 장치의 채널을 고르면 센서 전체가 그 장치로 옮겨 갑니다. |
| 측정 항목 | **— 자동 —** · **온도** · **습도** · **CO2** · **VPD** · **일사량** · **풍속** · **풍향** · **강수량** | **— 자동 —**은 채널에서 항목을 추정합니다. 틀리게 잡히면 직접 고릅니다. |
| 위치 | **실내** · **실외** | 실내 센서는 시설의 실내값이 되고(여럿이면 가중 평균), 실외 센서는 바깥 조건이 됩니다. |
| 우선순위 (**실외**일 때만) | **메인 센서** · **백업 센서** | 백업 센서는 메인 센서 값이 끊겼을 때만 씁니다. 둘을 평균하지 않습니다. |

한 장치의 채널 하나만 골라도 나머지가 버려지지는 않습니다. 그 장치에서 어떤 측정 항목의 후보 채널이 정확히 하나뿐이면 고르지 않은 채널도 함께 읽습니다 — 그래서 일사량 채널만 묶은 기상대도 온도·습도·풍속·풍향·강수량을 그대로 내놓습니다. 반대로 한 장치가 같은 항목을 여러 채널로 내보내면(온도 채널을 여섯 개 내보내는 콘솔) 자동으로 채우지 않습니다. 서로 다른 자리의 값을 한데 평균하면 안 되기 때문이며, 쓸 채널을 직접 고르면 됩니다. 직접 고른 채널이 언제나 우선하고, 같은 **위치**의 다른 센서에서 이미 고른 항목은 두 번 끌어오지 않습니다.

### 액추에이터 역할 { #actuator-roles }

센서가 아닌 행에는 그 구성요소를 움직일 장치를 고르는 **액추에이터** 칸(**— 없음 —** 또는 Output)이 있습니다. 액추에이터 하나가 여러 구성요소를 움직일 수 있습니다. 통합환경제어가 그 장치를 무엇으로 쓰는지는 구성요소 종류로 정해집니다.

| 구성요소 | 행의 설정 | 제어에서의 역할 |
|----------|-----------|-----------------|
| **팬** | 액추에이터 · **팬 역할**(**순환 팬** / **배기 팬** / **흡기 팬**) | 고른 팬 역할 (정하지 않으면 순환 팬) |
| **히터** | 액추에이터 | 난방 (3D 도구 이름은 **냉난방기**) |
| **가습기** | 액추에이터 | 가습 |
| **커튼** | 액추에이터 | 보온 커튼 (**외피**에서 켠 천장·측벽 보온 커튼도 이 종류) |
| **차광 커튼** | 액추에이터 | 차광 (**외피**에서 켠 차광 커튼) |
| **창호** | 액추에이터 | 개구부, 천창으로 다룸 (**외피**에서 켠 천창도 이 종류) |
| **측창** | 액추에이터 | 개구부, 측창 (외기를 직접 들임) |
| **출입문** | 액추에이터 | 개구부, 측창처럼 다룸 |
| **설비** | 액추에이터 | 통합환경제어에 등록되지 않음 |
| **관수 레이어** | 액추에이터 — 그 레이어의 **급수원**(펌프·주 밸브) | 스프링클러가 달려 있으면 가습 수단으로 등록, 점적만 있으면 환경 제어에 쓰지 않음 |
| **관수 밸브** | 액추에이터 — 레이어 안의 한 **구역** | 관수 레이어와 같음 |
| **메인 배관** | 없음 | 3D에서 배관을 골라 지우기 위한 행 |

**등록 방법:**

1. **설비 배치** 단계를 엽니다.
2. 3D 뷰 왼쪽 도구(**+ 센서**, **개구부**, **시설물**, **관수**)로 위치를 클릭해 배치하거나, **구성요소 추가**에서 유형을 고른 뒤 **+ 추가**를 클릭합니다.
3. **구성요소** 표에서 센서 행은 **— 채널 선택 —**으로 측정 채널을 고르고 측정 항목과 **실내**/**실외**를 지정합니다. 그 밖의 행은 구동할 액추에이터를 고릅니다.
4. **시설 저장** 클릭

## 장치 점검 { #device-check }

시설에 연결된 액추에이터를 짧게 작동시켜 명령이 전달되고 센서가 반응하는지 확인하는 진단 워크플로우입니다. 시설을 저장한 뒤에 사용할 수 있습니다.

1. **검토** 단계의 **장치 점검**에서 점검할 장치를 선택하고(**전체 선택** 가능) **점검 시작** 클릭
2. 시스템이 선택한 액추에이터를 차례로 켰다 끄며 실내 센서의 반응을 기록합니다.
3. 각 장치의 결과 상태가 표시됩니다.
   - **보통**: 명령이 전달되고 센서가 예상 방향으로 반응함
   - **검토 필요**: 센서 반응이 없거나 예상과 반대 방향 (센서 위치·장치 배선 확인)
   - **응답 없음**: 명령 전달 실패 (장치 연결 확인 필요)
4. 장치마다 **판정**(보통 / 센서 의심 / 장치 고장 / 외부 교란 / 건너뛰기)을 고르고 **판정 적용**을 클릭하면 결과가 제어 알고리즘 설정에 바로 반영됩니다.

## AI 조언 패널

시설 화면에는 AI 조언 패널이 없습니다. 앱 안의 AI와 연결된 다른 AI가 낸 조언은 **AI → 요청** 화면(`/ai`)의 **AI 조언**에 모입니다. 채택은 동의한다는 기록일 뿐, 아무것도 실행하지 않습니다. [AI 기능 개요](../ai/overview.md)를 참고하세요.
