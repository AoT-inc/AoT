# 노트 (Notes)

페이지: `추가 기능 -> 노트` — 그리고 같은 노트 패널이 AoT의 거의 모든 화면에서 바로 열립니다.

노트는 사진·파일·태그를 붙일 수 있는, 시각이 찍힌 짧은 글입니다. 장치, 센서, 구획이나 구역, 시설, 일지, 또는 지도 위의 한 지점 등 무엇에든 붙일 수 있습니다. 종이 업무일지나 포스트잇에 적던 내용 — 관찰한 것, 처리한 작업, 값이 이상해 보이는 이유, 뒤이어 확인할 것 — 은 여기에 적습니다. 노트는 AoT의 다른 여러 화면(일지, 지도, AI)이 읽고 쓰는 기록이므로, 여기 적어 두는 습관이 다른 곳에서도 그대로 도움이 됩니다.

---

## 노트 열기 { #opening }

AoT에는 노트 컴포넌트가 하나뿐이고(`AoTNotesBlock`), 어디서든 같은 방식으로 열립니다. 최근 항목이 보이는 카드와 **`노트 열기(Open Notes)`** 버튼입니다. 다음과 같은 곳에서 볼 수 있습니다.

- 장치·센서·컨트롤러·카메라 자체의 팝업이나 설정 화면
- 구획·구역·대지·시설 카드 — 지도 팝업 안도 포함
- [일지](geo/journal.md) 맨 아래
- 지도에 직접 찍은 핀 (아래 [지도 표시 여부](#map-visibility) 참고)

**`노트 열기`** 를 누르면 그 대상 하나로 범위가 좁혀진 패널이 슬라이드로 나타납니다 — 데스크톱에서는 (AI 채팅 패널처럼) 화면 옆에 열리고, 휴대전화에서는 전체 화면을 채웁니다. 구역·대지·시설에서는 그 안에 있는 모든 것의 노트까지 함께 보여주므로, 안에 있는 장치를 하나하나 열어보지 않아도 무슨 일이 있었는지 알 수 있습니다.

시스템 안의 *모든* 노트를 한 번에 살펴보거나 관리하려면 — 검색, 태그 필터링, 내보내기 — 전용 화면인 **노트 관리자**를 대신 씁니다: 메뉴의 `추가 기능 -> 노트`.

## 노트 작성하기 { #writing }

**`노트 열기` 패널에서** (가장 자주 쓰는 빠른 방법): 아래쪽 입력창에 적고 보냅니다. 같은 입력창(`+` 버튼)에서 사진이나 파일을 첨부하고 태그를 붙일 수 있습니다. 현재 시각이 찍혀 바로 저장되며, 임시 저장(초안) 상태는 없습니다.

**노트 관리자에서** (`추가 기능 -> 노트`): `+` 버튼으로 전체 작성 폼을 열면 추가로 다음을 할 수 있습니다.

- **주제**를 직접 입력하거나 비워 둘 수 있음
- "지금" 대신 특정 **날짜와 시각**을 지정 — 나중에 지난 일을 기록할 때 유용
- 여러 파일이나 사진을 한 번에 첨부

**스마트 제목**: 주제를 비워 두면(또는 기본값인 "Quick Note" 표시 그대로 두면) AoT가 본문 첫 줄을 제목으로 자동으로 가져옵니다 — 대부분 제목을 따로 입력할 필요가 없습니다.

**위치**: 이미 지도 위 위치를 가진 대상(장치, 구획, 구역, 대지, 시설)에서 작성한 노트는 그 위치의 좌표를 자동으로 물려받으며, 나중에 그 대상 자체가 사라져도 좌표는 남아 노트가 어디서 쓰였는지 계속 보여줍니다. 지도 위에 직접 만든 노트는 자기 자신의 핀을 갖습니다(아래 참고).

기존 노트의 본문·태그·첨부를 고치거나 노트를 완전히 삭제하는 작업은 노트 관리자 목록에서 합니다.

## 태그 { #tags }

태그는 노트를 분류해 나중에 다시 찾을 수 있게 합니다. 기존 태그를 고르거나 새 이름을 입력하면 됩니다 — 새 태그는 쓰는 순간 바로 만들어지며, 태그를 미리 관리하는 별도 단계는 없습니다.

또한 AoT는 사용자가 고른 태그와 별도로, 노트가 붙은 대상의 이름(장치 이름, 구역 이름 등)을 태그로 자동으로 붙여 둡니다. 그래서 노트 관리자의 태그 필터에서 어떤 장치나 구역의 이름으로 검색하면, 그 태그를 직접 붙이지 않은 노트까지 포함해 그동안 그것에 대해 적은 모든 노트가 나타납니다.

## 지도 표시 여부 { #map-visibility }

장치·구획·구역·대지·시설에 쓴 노트는 지도에 **별도의 마커를 만들지 않습니다** — 그 대상은 이미 지도에 그려져 있으므로, 그 도형이나 아이콘을 누르면 같은 노트 패널이 열립니다. 지도 위 빈 지점에 직접 만든 노트만 실제 핀을 가지는데, 그 노트가 어디 있는지 보여줄 방법이 핀뿐이기 때문입니다.

이런 위치 노트를 편집할 때는 **`지도 위젯 표시(Map Widget Visibility)`** 전환 스위치가 나타납니다 — 끄면 노트를 지우지 않은 채 지도의 핀만 숨깁니다. 노트 자체는 그대로 남아 노트 관리자와 검색에는 계속 나타납니다.

## 사진과 갤러리 { #photos }

노트를 쓸 때 사진을 첨부하면 업로드 전에 자동으로 크기가 줄어들어, 카메라로 찍은 큰 사진도 오래 기다리지 않고 보낼 수 있습니다. 사진이 두 장 이상인 노트는 썸네일 띠로 표시됩니다 — 썸네일이나 큰 사진을 누르면 이전/다음 이동과 손가락으로 확대(핀치 줌)가 되는 전체 화면 뷰어가 열립니다. 이미지가 아닌 파일(PDF, 스프레드시트 등)은 단순한 다운로드 링크로 표시됩니다.

## 구간을 예정으로 만들기 { #schedule-link }

`노트 열기` 패널 안에서 기존 노트의 일부 텍스트를 드래그해 선택하면 **`이 부분을 예정으로(Schedule this)`** 라고 적힌 바가 나타납니다. 날짜와 시각(그리고 필요하면 담당자)을 정해 저장하면, AoT는 선택한 텍스트를 그대로 담은 예정을 만들고, 그 구간은 노트 안에서 강조 표시된 채 남아 서로 연결돼 있음을 보여줍니다.

내용을 다시 입력할 필요가 없습니다 — 선택한 텍스트 자체가 곧 그 예정의 내용이므로, 노트와 일정이 같은 일을 서로 다르게 설명하며 어긋날 일이 없습니다.

이후 노트를 편집해 그 강조 구간이 본문에서 사라지면, 연결이 조용히 끊기거나 조용히 남지 않고 표시가 남아 사람이 직접 정하게 됩니다 — **`링크만 해제(Unlink only)`** 는 이미 잡힌 예정은 그대로 두고 연결만 잊고, **`예정 취소(Cancel the schedule)`** 는 예정 자체도 함께 없앱니다.

## 검색과 내보내기 { #search }

노트 관리자(`추가 기능 -> 노트`)는 시스템의 모든 노트를 최신순으로 나열하며, 스크롤할수록 더 불러옵니다. 여기서 할 수 있는 일:

- 노트 본문과 제목 검색
- 하나 이상의 태그로 필터링
- 날짜(그 외 기준)로 정렬, 오름차순/내림차순 선택
- 현재 필터링된 결과 내보내기, 또는
- 기간과 태그 조합으로 **PDF 보고서** 내보내기 — 단순 목록이 아니라 서식이 갖춰진 문서라, 특정 기간의 노트를 다른 사람에게 넘길 때 유용합니다

## AoT 안에서 노트가 이어지는 곳 { #elsewhere }

노트는 범용 기록이며, 매뉴얼의 다른 두 부분이 이 페이지를 되풀이하는 대신 그 위에서 다룹니다.

- **[장치 노트](Device-Notes.md)** 는 장치에 특화된 노트 사용법을 다룹니다 — 여기서 설명한 범용 노트 시스템과는 초점이 다릅니다.
- **[일지](geo/journal.md)** 는 구획·구역·대지에(그리고 그 안의 장치들에) 쓰인 모든 노트를 작성된 날짜별로 자동으로 모아 보여주고, 완성된 일지 맨 아래에 노트를 더 적을 수 있는 패널을 둡니다.

## AI와 노트 { #ai }

AI는 구역이나 장치에 붙은 노트를 읽을 수 있고 — 글자로 된 설명뿐 아니라 첨부된 사진까지 실제로 볼 수 있습니다 — 요청하면 스스로 간단한 노트를 쓰기도 합니다. 이것이 AI가 아는 것과 AI 자신이 쓴 내용을 어떻게 검토하는지는 [AI 개요](ai/overview.md)를 참고하십시오.

## 개발자를 위한 정보 { #developer }

AoT의 모든 **`노트 열기`** 버튼은 같은 하나의 공용 컴포넌트입니다. 어떤 화면에서든 다음과 같이 브라우저 이벤트를 발생시켜 특정 대상에 대해 열 수 있습니다.

```js
window.dispatchEvent(new CustomEvent('open-notes', {
  detail: { targetId: 'some-uuid', targetType: 'device', name: 'Zone A / Sensor 1' }
}))
```

노트, 태그, 노트-예정 링크는 REST API로도 제공됩니다(생성·조회·수정·삭제, 지도 표시 여부 전환). 인증 방법과 API 사용법 전반은 [API](API.md)를 참고하십시오.
