# 환경 제어 자동화

AoT 의 `env_coordinator`(화면에서는 **통합 환경 제어**)는 한 시설의 모든 액추에이터를
하나로 조율하는 3계층 제어 시스템입니다 — 개구부, 배기·흡기팬, 난방기, 냉방기,
분무기, 차광막, 보온커튼, 보광등, CO₂ 주입기.

서로 다른 두 곳에서 정해지는 두 가지가 있고, 이 둘을 섞는 것이 가장 흔한 혼란의
원인입니다.

- **무엇을 목표로 할지** — VPD·CO₂·DLI 등 — 는 그 시설에서 자라고 있는 **구획**의
  것입니다. 구획에 붙은 재배 프로그램을 통해 정해집니다.
- **어떻게 달성할지** — 어떤 설비가 있는지, 넘으면 안 되는 선은 어디인지, 목표를
  얼마나 바짝 쫓을지 — 는 **이 함수**의 것입니다.

---

## 목표는 어디서 오는가 { #targets }

| 계층 | 갖는 것 | 편집하는 곳 |
|------|--------|-------------|
| 프로그램(`GeoProgram`) | 참고 계획: 단계, 목표 항목의 어휘, 목표 곡선, 작물의 광합성 상수 | 프로그램 화면 |
| 구획(`GeoPlot`) | 실제 계획: 단계 경계 날짜와 이 구획의 단계별 목표값 | 구획 화면(단계 일정) |
| env_coordinator | 달성 방법: 설비 구성, 안전 한계, 우선순위, 튜닝, 응급 동작 | 함수 설정 |

구획은 고른 프로그램을 **내재화**합니다. 구획 화면에서 단계 목표를 고치면 그 구획의
그 항목만 덮어쓰고, 프로그램 원본과 같은 프로그램을 쓰는 다른 구획은 그대로입니다.
칸을 비우면 그 항목은 프로그램 값으로 돌아갑니다 — 되돌리기 버튼을 따로 두지 않는
이유가 이것입니다.

의도한 제약이 둘 있습니다.

- 구획은 새 목표 **항목**을 만들 수 없습니다. 어휘는 프로그램의 것(`target_defs`)이라,
  모르는 항목은 조용히 무시하지 않고 거절합니다.
- **곡선**이 걸린 항목은 숫자로 덮을 수 없습니다. 곡선이 이기고, 구획 화면에서 그
  항목은 읽기 전용으로 보입니다.

### 코디네이터가 매 사이클 읽는 것 { #targets-read }

| 값 | 쓰이는 곳 |
|----|----------|
| VPD 목표(숫자 또는 곡선) | 1차 제어 목표 |
| CO₂ 목표(숫자 또는 곡선) | CO₂ 시비. 없으면 CO₂ 제어는 쉽니다 |
| 단계 주간 온도 · 야간 온도 · 습도 | 이번 사이클의 [유도 범위](#stage-guide) |
| DLI 목표 · 일별 GDD 목표 | 누적 트래커 |
| `T_base` | GDD 적산 |
| 구획 시작일 | 경과 주차 — 단계형 곡선이 이것으로 진행합니다 |
| 광합성 상수(`A_max`, `K_L`, `K_C`, `T_opt`, `T_sigma`, `VPD_half`) | Big-Leaf 모델, 그리고 `K_L` 에서 파생하는 광포화점 |

목표 항목과 제어 축은 항목 키가 아니라 **물리량과 형태**로 잇습니다 — 사용자가 "실내
CO₂" 라고 이름 붙인 항목도 물리량이 CO₂ 면 CO₂ 제어에 닿습니다. 물리량을 고르지 않은
항목은 어느 축에도 닿지 않고 화면에 *참고* 로 표시됩니다.

### 구획이 없을 때 { #targets-no-plot }

코디네이터는 **멈추지 않습니다.** 구획이 없거나, 프로그램이 없거나, AI 초안이 아직
검토되지 않았거나, 프로그램 종류가 구획 종류와 맞지 않거나, 오늘 날짜에 해당하는
단계가 없으면 목표가 없을 뿐입니다 — 제어는 자기 유도 범위 안에서 계속 돕니다.
이것은 이미 정의된 동작입니다. 비어 있는 온실도 난방은 돌아야 합니다.

### 주·야간 온도와 습도가 유도 범위를 정합니다 { #stage-guide }

1차 목표는 계속 VPD입니다. 단계의 **주간 온도**·**야간 온도**·**습도**는 목표가 아니라,
VPD를 너무 덥고 습한 조합이나 너무 차고 건조한 조합으로 맞추는 것을 막는 가이드입니다.
코디네이터는 매 사이클 자기 유도 범위를 다음으로 바꿉니다.

| | 범위 |
|---|---|
| 온도 | 단계 주간 온도(시설 위치의 일출~일몰) 또는 야간 온도 **± 5 °C** |
| 습도 | 단계 습도 **± 10 %** |

- 폭은 고정이며 프로그램 설정이 아닙니다 — 재배 기술문서는 대부분 평균값만 주고
  주·야간 폭을 적지 않습니다.
- 단계에 그 값이 없거나, 시설 위치를 몰라 일출·일몰을 구할 수 없으면 그 항목은 함수
  자신의 유도 범위를 씁니다.
- 하드 임계(`Min/Max Temperature`, `Min/Max Humidity`)가 마지막에 적용됩니다.
- 유도 범위를 읽는 곳은 모두 따라옵니다: VPD를 나눈 온도·습도, VPD 목표가 없을 때의
  중앙값, 예보 보정, 환기 온도 상한.
- 실제로 쓴 범위는 함수 설정의 구획 아래 **가이드 범위**로 보입니다.

코디네이터에는 **자기 종료일 옵션이 없습니다.** 재배를 계속할지는 구획이 정합니다.
함수에 날짜를 따로 두면 새 작물을 심은 뒤에도 그 날짜 때문에 시설이 멈춰 있을 수
있기 때문입니다.

### 제어 기준 — VPD 직접 / 온도 우선 { #control-basis }

기본은 **VPD 직접**입니다 — 위처럼 VPD 목표를 좇고, 온도·습도는 가이드입니다. 고급 설정의
**제어 기준**을 **온도 우선**으로 바꾸면 코디네이터마다 다음처럼 돕니다.

- **온도가 1차 목표입니다.** 단계의 주간·야간 온도(시설 위치의 일출·일몰 기준)를 좇습니다.
- **습도 목표는 VPD 목표에서 만듭니다** — 그 온도에서 VPD 목표가 되는 습도입니다
  (예: 24 °C 에서 VPD 1.0 이면 약 66 %). 유도 범위 밖이면 범위 끝으로 자릅니다.
- **VPD 는 경계입니다.** 목표보다 0.4 kPa 낮거나 0.8 kPa 높아질 때만 되돌리는 쪽으로 밉니다.
- 단계에 온도가 없으면 **온도를 좇지 않고** 유도 범위 안에 두기만 합니다.

VPD 를 직접 좇으면 같은 허용오차가 8 °C 에서는 습도 ±9 %, 35 °C 에서는 ±1.8 % 가 되고,
저온에서는 닿을 수 없는 습도를 요구하기도 합니다. 온도 우선은 이 차이가 없습니다.

어느 쪽을 고르든 다른 쪽이 "그 기준이었다면 보냈을 명령" 을 매 사이클 함께 계산해 기록합니다
(제어에는 쓰지 않습니다). 두 방식을 같은 시설에서 비교하려는 것입니다.

### 범위 안에 구획이 둘 이상일 때 { #targets-reference-plot }

간작·혼작이 정상인 도메인이라 코디네이터는 추측하지 않습니다. 시설·구역 범위 안에
구획이 둘 이상이면 그 사실을 말하고 **[이걸로]** 버튼을 내놓습니다. 같은 선택이
고급 설정의 **기준 구획** 에 저장됩니다. 지정한 구획이 끝났거나 범위 밖으로 나가도
값을 지우지 않습니다 — 화면이 "지정한 구획이 여기 없다" 고 말하고, 선택 규칙을
다시 적용합니다.

> 구획에 기록된 프로그램 버전은 *버전 번호*를 고정할 뿐 *내용*을 고정하지 않습니다.
> 프로그램을 고치면 진행 중인 구획의 해석도 함께 바뀝니다.

## VPD (수증기압 포화차) { #vpd-vapor-pressure-deficit }

VPD는 식물의 증산과 수분 흡수를 결정하는 핵심 지표입니다.

```
VPD = SVP × (1 - RH/100)
SVP = 0.6108 × exp(17.27T / (T + 237.3))  [kPa]
```

| 범위 | 상태 | 권장 작물 단계 |
|------|------|---------------|
| < 0.4 kPa | 너무 낮음 — 곰팡이 위험 | — |
| 0.4–0.8 kPa | 적정 | 발아기 / 이식 초기 |
| 0.8–1.2 kPa | 적정 | 영양생장기 |
| 1.2–1.8 kPa | 적정 | 개화·결실기 |
| > 1.8 kPa | 너무 높음 — 수분 스트레스 | — |

### 공기 VPD 와 잎 VPD — 목표를 무엇과 견주나 { #leaf-vpd }

증산을 미는 것은 잎 안(**잎** 온도에서 포화)과 둘레 공기의 차이입니다. 위 식은 **공기 VPD**
— 잎이 기온과 같다고 본 값입니다. 잎 VPD 는

```
잎 VPD = SVP(엽온) − RH/100 × SVP(기온)
```

잎이 공기보다 차면 공기 VPD 보다 낮고, 따뜻하면 높습니다(25 °C·70 %: 공기 0.95 kPa, 1.5 °C 찬
잎 0.68 kPa). 작물에게 중요한 것은 잎 VPD 이고 공기 VPD 는 참고값입니다. 다만 엽온은 거의 재지
않고, 코디네이터의 효과 모델·온습도 분해·단계 가이드는 모두 공기 VPD 로 되어 있어 **제어량은
공기 VPD 그대로** 두고 목표만 옮깁니다.

[고급 설정] 의 **VPD 목표 기준** 이 정합니다:

| 설정 | 동작 |
|---|---|
| **공기 VPD** (기본) | 목표를 걸러진 온·습도로 계산한 공기 VPD 와 견줍니다 — 종전과 완전히 같습니다. |
| **잎 VPD** | 목표는 잎 VPD 입니다. 사이클마다 잰 엽온에서 그 잎 VPD 를 만드는 공기 VPD 로 옮깁니다: `공기 목표 = 잎 목표 + SVP(기온) − SVP(엽온)`. 25 °C 공기에서 잎이 1.5 °C 차면 잎 목표 0.80 kPa 가 공기 VPD 약 1.07 kPa 가 됩니다. 허용 오차(kPa)는 그대로입니다. |

적외선 엽온(군락 온도) 센서가 있고 목표가 잎 VPD 값일 때(작물 지침 대부분이 그렇게 줍니다)
**잎 VPD** 를 고르세요. 센서는 **엽온 센서** 에 묶습니다. 묶지 않으면 잎 설정은 오류를 한 번 남길
뿐 아무것도 하지 않습니다.

엽온은 신선하고(실내 센서처럼 자기 갱신 주기로 판정) · 물리 범위 안이고 · 한 값에 멈추지 않았고
(실내 온도와 같은 [멈춘 센서](#l2-situationreport-evaluation) 창) · **기온과 10 °C 이내** 일 때만
씁니다 — 그보다 크게 다르면 센서가 잎이 아니라 바닥·골조·하늘을 보고 있는 것입니다. 살짝
평활합니다(0.3 °C 흔들림이 그대로면 목표가 약 0.06 kPa 움직입니다). 쓸 수 없으면 **그 사이클은
공기 기준** 으로 돕니다 — 같은 숫자를 공기 VPD 목표로 씁니다 — 그리고 바뀔 때마다 한 번 로그를
남깁니다. **엽온을 고정 오프셋(기온 − 1.5 °C 등)으로 어림하지 않습니다**: 해 드는 낮에 기공이 닫힌
잎은 공기보다 따뜻하고 맑은 밤의 잎은 차서, 고정 오프셋은 공기 목표의 이름만 바꿀 뿐입니다. 잎이
공기보다 너무 따뜻해 포화 공기로도 목표까지 못 내리면 공기 목표는 0.1 kPa 에서 멈춥니다.

공기 기준이어도 센서를 묶어 두면 쓸모가 있습니다 — 잎 VPD 가 기록되고 AI 도구에 전해지며, 목표가 잎 기준으로 걸린 동안에는 [시설 위젯](../geo/facility-widget.md#b-environment)
에 공기 VPD 옆으로 나옵니다. 목표 단계를 건너뛰는 사이클(안전 게이트·운전
시간대 밖)은 새로 판정하지 않으며, 마지막 판정이 세 주기(최소 5분)보다 오래되면 위젯이 그것을
보이지 않습니다. 센서를 묶었거나 잎 기준이면 코디네이터가 매
사이클(디버그와 무관) 채널 94(0 공기 기준 · 1 잎 기준 · 2 잎 기준인데 쓸 엽온이 없어 공기),
95(잎 VPD, kPa), 96(정한 잎 목표)을 남깁니다. 잎 기준이면 VPD 목표 채널(3)은 옮긴 공기 목표입니다.
건강 점검이 2 로 돈 분을 말합니다 — 사람이 센서를 봐야 합니다. AI 도구(`get_control_state` 와 AI 요약)도 같은 짝을 `vpd.air_kpa`·`vpd.leaf_kpa` 라는 이름표로 알리며, 잎 값은 엽온을 잰 동안에만 있습니다.

> **이전 버전에서 저장된 VPD 값.** 입력의 자동 VPD 채널(*자동 VPD*, 엽온 = 기온 − 1.5 °C)과
> **AoT VPD** 함수는 *공기* 습도를 *잎* 포화압에 곱해 찬 잎의 VPD 를 부풀렸습니다(위 예에서 0.68
> 대신 0.87 kPa). 이제 위 식을 쓰므로 업데이트 뒤로는 저장값이 약 0.06~0.4 kPa 낮아집니다. 코디네이터는
> 이 값을 제어에 쓴 적이 없습니다.

## env_coordinator 제어 계층 { #env_coordinator-control-layers }

### L1 — EnvTarget (목표값 설정) { #l1-envtarget-setpoint }

위에서 설명한 목표를 이번 사이클의 setpoint 로 푼다. Method 를 따르는 항목은 구획의
경과 주차와 시설 현지 시간대로 계산한다.

### L2 — SituationReport (상황 평가) { #l2-situationreport-evaluation }

현재 편차, 제한 인자, 추세를 평가한다.

실내 온도·습도·VPD 는 먼저 **잡음을 거릅니다.** 센서 눈금(온도 0.1 °C, 습도 1 %)이 오르내리는 것만으로 창이 움직이지 않게 하려는
것입니다. 지수 평활을 쓰되, 원값과 온도 0.5 °C·습도 3 % 이상 벌어지면 실제 변화로 보고 곧바로 원값을 따릅니다. **제어가 쓰는 VPD 는 언제나
걸러진 온도·습도로 계산한 공기 VPD** 입니다. 센서가 자기 VPD 채널을 달고 있어도 제어에는 쓰지 않습니다 — 엽온을 어림한 값(기온 − 1.5
°C)으로 VPD 를 내는 장치가 있는데, 그 값은 목표와 온·습도 분해가 가정하는 공기 VPD 보다 낮게 나옵니다. 장치 VPD 는 온도나 습도를 잃고
그것만 남았을 때에 한해 대신 쓰이며, 둘의 차이는 기록에 남습니다. **안전 게이트와 하드 임계는 거르기 전 원값으로** 판정합니다 — 보호를 필터만큼
늦추지 않습니다.

**모든 판독에 상태를 붙입니다.** 제어가 읽는 축(실내 온도·습도·CO₂·VPD·광량, 실외 온도·습도·풍속·강우·일사)마다 센서가 준 것을
`valid`(쓸 수 있음), `stale`(신선도 한도를 넘은 낡은 값), `missing`(값이 아예 없음), `outlier`(다른 센서와 크게 어긋나
평균에서 빠짐), `out_of_range`, `frozen`(아래) 중 하나로 가르고, 축의 상태는 그 축을 먹이는 센서 중 가장 좋은 것입니다. **제어의
동작이 달라지는 것은 마지막 둘뿐입니다.** 불가능한 값(습도 102 % 초과, 온도 −40~70 °C 밖, CO₂ 150~10,000 ppm 밖 등)은
평균에도 제어에도 들어가지 않습니다 — 습도 130 % 를 보고하는 센서는 값이 없는 것으로 칩니다. 멈춘 센서도 같은 방식으로 뺍니다. 습도 100~102
% 는 눈금 오차라 100 % 로 잘라 쓰고, 일사계가 밤에 내는 −5 W/m² 이내의 값은 0 으로 읽습니다. 나머지 상태는 기록만 합니다. 축에 쓸 수
있는 센서가 하나도 남지 않으면 [측정이 없는 축, 장치가 없는 축](#actuators-missing)의 규칙을 따릅니다. 디버그 로깅이 켜져 있으면 축별
상태를 측정 `sensor_status` 의 채널 80~89(실내 온도·습도·CO₂·VPD·광량, 이어서 실외 온도·습도·풍속·강우·일사)에 0 valid ·
1 stale · 2 missing · 3 outlier · 4 out_of_range · 5 frozen 으로 남깁니다. 채널 90 은 제어 VPD 의
출처(0 없음 · 1 온도·습도로 계산 · 2 장치), 채널 91 은 장치 VPD 에서 제어 VPD 를 뺀 값(kPa)입니다.

**값이 움직이지 않는 센서는 따로 빼 둡니다.** 거울 장치나 게이트웨이가 갱신을 멈추고도
판독마다 현재 시각을 찍어 보내는 일이 있습니다. 그러면 신선도 검사를 통과하고 숫자도
그럴듯해서 — 온실이 46 °C 인데 30.7 °C 로 읽혀 창을 닫아 버립니다. 그래서 센서마다,
온도·습도·CO₂ 각각에 대해 값이 센서 눈금(0.05 °C, 0.1 %, 1 ppm) 이내에서 얼마나 오래
그대로인지 셉니다. 정상 센서라면 반드시 변했을 시간보다 오래 그대로이고 *서로 다른*
판독이 6개 이상 왔다면, 그 센서는 불가능한 값과 같이 취급해 평균에서 뺍니다.

| 상황 | 변화 없는 시간 |
|------|----------------|
| 낮(실외 일사 100 W/m² 초과) — 온도·습도 | 60분 |
| 밤이지만 30분 안에 장치가 움직임 — 온도·습도 | 2시간 |
| 조용한 밤 — 온도·습도 | 3시간 |
| CO₂ | 2시간 |

같은 축의 다른 정상 센서가 있으면 그 센서들로 계속 제어합니다. 멈춘 센서가 유일한
센서였다면 그 축은 측정할 수 없는 것으로 보고 [측정이 없는 축, 장치가 없는 축](#actuators-missing)의
규칙을 따릅니다(장치는 제자리 유지). **값이 바뀌는 순간 그 센서는 곧바로 다시 씁니다.**
정수만 내는 센서(습도 센서에 흔합니다)는 시간을 3배로 칩니다 — 고요한 밤에는 같은
정수가 몇 시간이고 이어질 수 있기 때문입니다(실측 최장 4.5시간). 습도 100 % 는 세지
않습니다. 갱신 사이에 같은 판독을 다시 내주는 느린 장치도 멈춘 것이 아닙니다 — 새
판독만 셉니다. 세기는 메모리에만 있어 재시작하면 처음부터 다시 셉니다. 전환은 한 번씩
로그에 남고, 건강 점검이 그 축을 `frozen` 으로 알려 줍니다.

⚠ 주기마다 점을 쓰면서 실제로 내내 한 값에 머무는 장치는 멈춘 센서와 구별되지 않습니다
— 대가는 그 센서 하나가 평균에서 빠지는 것뿐입니다. "변할 때만 보고" 하는 장치인지
알려 주는 장치별 설정은 없습니다.

| 평가 항목 | 설명 |
|----------|------|
| 편차 | `현재값 - 목표값` |
| 제한 인자 | 빛·CO₂·온도·수분(VPD) 중 무엇이 광합성을 막고 있는가 |
| 추세 | 값이 목표 방향으로 이동 중인가 |

VPD 목표가 있고 VPD 를 잴 수 있을 때 온·습도는 *제약*으로 강등된다 — VPD 를 풀어낼
범위이자 넘지 말아야 할 선이다. 이 함수는 온도 조절기가 아니다. 온도나 습도를 잃어 VPD 를 계산할 수 없으면 그 사이클은 온도·습도 기준으로 물러난다([측정이 없는 축, 장치가 없는 축](#actuators-missing)).

[극한 고온 보호](#heat-protect) 중에는 그 모드가 맨 앞에 섭니다 — *폭염 보호*, 단계 2 는
*비상*.

### L3 — Coordinator (액추에이터 명령) { #l3-coordinator-actuator-command }

장치마다 **위치형 PI** 로 0–100 % 명령을 냅니다. 교과서 PI 와 다른 점이 셋 있습니다.

- **적분은 누적 오차가 아니라 그 장치의 '기억된 평형 개도(%)'** 이고, 늘 0–100 안에
  묶입니다. 편차가 작으면 적분이 그대로 남아 직전 개도를 유지합니다.
- **한 장치가 여러 축에 닿으면 편차를 하나로 합칩니다.** 예를 들어 개구부는 온도·습도·
  CO₂ 에 모두 영향을 줍니다. 축마다 편차를 비례 밴드(허용오차 × 6)로 나눠 같은 척도로
  맞추고, *우선도 × 그 장치가 그 축에 주는 효과의 크기* 로 가중 평균합니다.
- **허용오차의 절반 안은 쉬는 구간(데드존)** 입니다. 그 밖에서는 데드존만큼을 뺀 값을
  쓰므로 경계에서 명령이 계단처럼 튀지 않습니다.

```
e      = Σ(우선도 × 효과 × 편차/비례밴드) / Σ(우선도 × 효과)
e_eff  = e 에서 데드존(허용오차 × 0.5)을 뺀 값
I      = clamp(I + 0.2 × e_eff, 0, 100)          # 기억된 평형 개도
명령   = clamp(1.0 × e_eff × 100 + I, 0, 100)
```

- **확정 순서는 비용 지수 순**입니다(싼 장치부터). 같은 도메인 안에서 뒤 장치는 앞
  장치가 만들 효과를 뺀 나머지 편차만 봅니다 — 이것이 부하 분담입니다.
- **움직여도 소용없는 장치는 쉽니다.** 100 % 로 돌려도 비례 밴드의 2.5 % 미만밖에 못
  움직이거나(예: 실내외 차이가 거의 없는 환기), 파킹 대상(물이 없을 때의 [분무기 전부](#water-supply) 포함)이면 사이클마다 안전 위치와의
  거리를 60 % 로 줄이며 서서히 안전 위치로 갑니다. 보온커튼은 예외로 **제자리**에 둡니다 —
  안전 위치(걷힘)로 풀면 밤에 안팎 온도차가 작아지는 순간 보온이 풀립니다. 제자리는 열 수요가
  없는 밤에만이고, 보온이 필요하면 닫습니다([밤 보온](#curtain-gap), 근거 49).
  판정에는 이력이 있습니다 — 한 번 일할 수 있다고 본 장치는 그 문턱(2.5 %)의 절반
  아래로 내려가야 '쉼'으로 바뀌므로, 문턱 근처에서 흔들리는 효과 때문에 창이 열렸다
  닫혔다를 되풀이하지 않습니다(근거 '주작용'↔'무구배').
- **의심 장치는 제자리에 둡니다.** 전송이 계속 실패하거나 몇 시간째 세게 명령했는데 반응이 없는 창은 서 있는 자리에 두고, 새 명령을 받지 않으며 부하 분담 장부에도 아무것도 올리지 않아 같은 도메인의 나머지가 그 몫을 이어받습니다([의심 액추에이터](#actuators-suspected)).
- **VPD 직접 모드에서 난방기는 온도 범위 상한 위에서 돌지 않습니다.** 이 모드에서 난방기가 받는 요구는 VPD 하나인데, 해가 진 뒤 낮 VPD 목표는 천천히 내려오고 온도 범위는 한 번에 내려갑니다(22–32 → 12–22 °C). 그래서 난방 출력은 유도 범위 상한 1 °C 앞부터 선형으로 줄어 상한 이상이면 0 이고, 사이클당 20 %p 슬루를 타지 않고 곧바로 내려갑니다(근거 17). 최저 온도 한계(Min Temperature)는 그대로 이기고, 온도가 제어 목표일 때는 이 상한을 걸지 않습니다.
- **곧 파킹될 창은 더 열지 않습니다.** [야간 닫기](#settings-ventilation)가 시작되기 전 45분 동안 환기창·팬은 닫힐 수는 있어도 VPD·습도·보통의 온도 요구로 지금 열림을 넘어 열리지 않고, 적분도 더 쌓지 않습니다(근거 48). 온도·습도 하드 임계, [극한 고온 보호](#heat-protect), 결로 탈출은 여전히 엽니다.
- **비가 오면 창은 상한을 지킵니다.** [강우 단계 제한](#safety-gates) 중에는 측창이 30 % 를 넘지 않고, 약한 예보 비로 묶인 천창은 서 있는 자리보다 더 열리지 않습니다 — VPD·습도 요구, 일사 하한, [아침 습기 빼기](#morning-purge), [극한 고온 보호](#heat-protect) 단계 1 이 무엇을 요구하든. 적분도 상한에 묶여 비가 그친 순간 창이 튀지 않습니다(근거 52).
- **해가 들면 창은 열림 하한을 지킵니다.** 실외 일사가 200 W/m² 이상이고 실내가 작물의 온도 선(온도 목표 + 허용오차 — VPD 직접 모드에서도 단계 온도 + 1 °C 를 넘지 않음)보다 높으며 바깥이 1 °C 넘게 덥지 않으면, VPD·습도 요구는 초과분에 따라 15–80 % 인 하한 아래로 창을 닫지 못하고 적분도 그 자리에 묶입니다(근거 51). [햇빛 열 빼기](#solar-vent) 참조.
- **실내 값이 없어도 맑은 날에는 창을 조금 엽니다.** 실내 온도를 잃었지만 실외 값은 실측이고, 해가 있고, 외기가 12 °C 이상이며 외기 + 일사 1 W/m² 당 0.02 °C 가 작물 선보다 높으면, 측정이 없어 제자리에 설 창을 사이클당 5 %p 씩 10–20 % 까지 열고, 해가 진 뒤에는 그만큼 열린 창을 같은 폭으로 다시 닫습니다(근거 60). [맑은 날 실내 값이 끊겼을 때](#solar-vent-blind) 참조.
- **제자리는 실제로 나간 개도를 지킵니다.** 규칙이 창을 서 있는 자리에 둘 때(실외·실내 값 없음, 환기 무익 판정 직후, 야간 닫기 직전 45분, 비·바람 값을 잃어 '더 열지 않음', 열어도 반응 없음) 명령은 직전에 실제로 나간 개도를 이번 사이클의 전달 비율(풍향 가중치)로 나눈 값입니다. 직전 개도를 그대로 내면 가중치가 사이클마다 다시 곱해져 '제자리' 인 창이 서서히 닫혔습니다 — 기록된 한 아침, 근거 21 인 채로 50분 동안 20 → 16 → 13 → 12 → 7 → 0 %.
- **아침 해에는 과습한 집을 조금 환기합니다.** 실외 일사가 100 W/m² 이상이고 실내가 과습 구간이며 이슬점이 실외보다 2 °C 이상 높으면, 집이 온도 목표의 아래 선보다 크게 낮지 않은 한 창을 *실외 너무 참* 으로 파킹하는 대신 5~15 % 최소 열림을 줍니다(근거 54). [습기 빼기](#morning-purge) 참조.
- **낮에는 보온커튼을 걷어 둡니다.** 효과 모델은 커튼의 열 교환만 알고 빛을 막는다는 것은 모르므로, 시설 위치의 일출부터 일몰까지는 걷어 두고 밤에만
  판단합니다. 한파 같은 안전 게이트는 이 규칙보다 우선합니다. 중간에 설 수 있는 커튼은 아침에 한꺼번에가 아니라 단계로 걷습니다([보온커튼 — 밤 틈과
  아침 단계 걷기](#curtain-gap)).
- **차광막은 빛을 따라 움직입니다.** 열 부하와 증산을 줄이는 데 써도 되는지는 작물이 받을 빛을 보고 한 곳에서 정하며, 왕복하지 않도록 움직임을 걸러
  냅니다([차광막으로 더위 막기](#shade-heat)).
- **커튼·차광막은 완전히 닫거나 완전히 걷습니다.** 서 있는 쪽에서 반대쪽으로 가려면 명령이 60 %(걷기) 또는 40 %(닫기)를 넘어야 합니다 —
  50 % 근처에서 끝과 끝을 오가지 않게 합니다. 기록과 화면에도 실제로 보낸 0/100 이 남습니다. 예외는 중간에 설 수 있는 보온커튼의 밤 틈과 아침
  단계 걷기뿐이고(3 · 6 · 10 · 30 · 60 %), 이때도 기록에는 실제로 보낸 값이 남습니다.
- **미는 방향이 뒤집히면 이어지는지 보고 따릅니다.** 창의 VPD 효과는 식힘과 건조한
  외기가 겨룬 합이라, 둘이 비슷하면 실외 습도 몇 %p 로 방향이 사이클마다 바뀝니다.
  새 방향이 10분 이상(그리고 2사이클 이상) 이어질 때만 따르고, 그 전에는 제자리에
  둡니다. 온도가 유도 상한에 막 닿았을 때 더해지는 온도 항도 넘은 만큼 **서서히**
  무게를 얻습니다 — 선 근처를 오르내릴 때 창이 계단으로 오르내리지 않게 합니다.
- **측창은 바람을 받는 쪽을 더 엽니다.** 바람을 등진 측창은 명령의 최소 20 % 까지
  줄입니다. 풍속 0.5 m/s 미만에서는 걸지 않고, 3 m/s 까지 풍압(풍속²)에 비례해 서서히
  강해집니다 — 약풍의 불안정한 풍향으로 측창이 사이클마다 깎였다 풀리지 않게 합니다.
- **목표를 넘어선 채 굳지 않습니다.** 데드존 안이라도 "줄여야 한다" 쪽 편차가 3사이클
  이어지면, 그 장치는 명령을 사이클마다 60 % 로 줄이며 물러납니다. 보온커튼·차광막도
  같습니다 — 효과가 개도에 비례하므로 줄이는 쪽이 곧 효과를 줄이는 쪽입니다.
- **적분 폭주 방지.** 100 % 에 막히면 넘친 만큼 적분을 되돌리고, 0 % 에 막히면 그
  사이클의 적분을 멈춥니다. 한쪽 끝에 계속 붙어 있으면 적분을 실제 개도 쪽으로
  줄입니다.
- **변화 속도 제한.** 사이클당 최대 20 %p 까지 움직이고, 액션에 전 행정 시간이 있으면
  그 장치가 실제로 움직일 수 있는 양이 더 작을 때 그 값을 씁니다. 커튼·차광막은 한
  번에 열고 닫으므로 제외입니다. 5 % 미만 명령은 0 으로 보냅니다.

**VPD 모드의 온도 상한.** VPD 를 직접 제어하면 온도는 제어 목표가 아니지만, 그대로
두면 더워져도 창을 여는 힘이 없습니다. 그래서 다음 판단 시점의 예상 온도(현재 +
상승률 × 주기)가 유도 상한 1 °C 앞에 닿으면 환기 장치에 온도 항을 더하고, 넘은
만큼 비중을 키웁니다. 한 번 켜진 항은 예상 온도가 그 선보다 0.5 °C 더 내려가야
꺼집니다 — 선 위에 걸터앉은 온도 때문에 창이 "식힌다" 와 "쉰다" 사이를 오가지 않게
하는 것입니다. **최고 온도** 하드 임계에 닿으면 냉방기에도 걸고, 식히는
방향과 맞서는 다른 축의 항을 뺍니다. 여전히 편차에 비례하는 PI 이며 무엇도 100 %
로 강제하지 않습니다 — 실외가 더 더우면 창은 오히려 닫히는 쪽으로 갑니다.

항이 꺼지는 선 아래 **1.5 °C 는 유지 구간**입니다. 이 항으로 연 창은 그 자리에 있고(더
열 수는 있고, 야간 닫기 등 파킹은 여전히 이깁니다) 예상 온도가 그 구간 아래로 내려가야
닫는 쪽으로 갑니다. 이것이 없으면 창이 한 사이클 안에 실내를 몇 도씩 바꾸는 시설에서
열기 → 항 꺼짐 → 닫기 → 다시 더워짐 → 열기 를 50분쯤마다 되풀이했습니다.

[극한 고온 보호](#heat-protect) 가 켜져 있으면 상한은 보호 중이 아니어도 문턱을 넘지
않습니다 — 평소 제어가 문턱 바로 아래부터 식히고, 그것으로 모자랄 때만 보호가 나섭니다.
보호 중에는 온도가 그 선 위에 있는 동안 상한이 하드이고, 선 아래에서는 보호 밖과 같은
방식으로 물러납니다.

유도 상한은 **목표 온도 + 허용오차를 넘지 않습니다.** 목표가 25 °C, 허용오차가 1 °C 이면 가이드
상한이 30 °C 여도 26 °C 부터 온도 항이 섭니다(항이 서는 선은 거기서 1 °C 앞, 즉 목표 + 허용오차).
예전에는 가이드 상한 근처에서만 항이 서서, 목표보다 2~5 °C 더운 채로 창이 VPD 하나만 보고
닫혀 있었습니다. 목표 온도를 알 수 없으면 가이드 상한을 그대로 씁니다.

## 액추에이터 도메인 { #domains }

부하 분담은 도메인 **안에서** 일어나고, 도메인은 장치가 비슷한가가 아니라 **에너지의
종착점이 같은가**로 가릅니다. 설정 화면도 대체로 같은 축을 따르지만, 보광등만은
예외로 차광막·보온커튼과 함께 빛과 차광에서 설정합니다.

| 도메인 | 장치 | 성질 |
|--------|------|------|
| 환기 | 개구부, 배기팬, 흡기팬 | 실내를 실외 쪽으로만 민다. 창이든 팬이든 실외 값을 넘어 움직이지 못하고, 팬의 효과는 정격 풍량과 사이클 길이를 따른다 |
| 냉난방·가습 | 난방기, 냉방기, 포그 | 외기와 무관하게 직접 넣고 뺀다 |
| 스크린 | 차광막, 보온커튼 | 들고 나는 복사를 막는다 |
| 보조 | CO₂ 주입기, 보광등, 유동팬 | 각자 자기 축을 맡고, 부하를 나눌 상대가 없다. 다만 창이 열려 있으면 넣은 CO₂ 가 곧장 빠져나가므로, 개구부 평균 개도**와 팬이 바꾸는 공기**만큼 주입 효과를 낮춰 봅니다(평균 30 % 에서 0). 팬은 같은 잣대의 개도로 환산합니다 — 시간당 20회 환기 = 창 활짝, 팬이 시간당 6회에 닿으면 0, 열린 창 때문에 팬이 힘을 못 쓰는 만큼은 덜 셉니다. 배기팬과 흡기팬은 큰 쪽만 세고, 정격 풍량이나 시설 체적을 모르는 팬은 세지 않습니다. 효과가 너무 작아지면 주입기는 쉽니다 — 창이 닫혀 있어도 팬이 돌면 마찬가지입니다 |

도메인끼리는 서로가 하는 일을 보지 않으므로, 도메인 간 조율은 암묵적인 효과 누적이
아니라 **선언된 인터록**이 맡습니다([환기](#settings-ventilation) 참조).

### 천창과 측창은 다르게 움직인다 { #vent-form }

둘 다 `opening` 액추에이터지만, 시설 도면은 천창(ridge)과 측창(side)을 구분하고 효과
모델이 그것을 씁니다.

| 형태 | 실내가 실외보다 더울 때 | 실외가 실내보다 더울 때 |
|------|------------------------|------------------------|
| 천창 | 부력이 돕는다 — 같은 면적이 열을 더 많이 뺀다 | 역전 — 더운 외기가 잘 안 내려온다 |
| 측창 | 기준 | 직접 유입, 그대로 가온이다 |

도면에 형태가 없으면 천창·측창 구분 없이 같은 모델로 동작합니다(보정 없음).

## Function 설정 { #function-configuration }

AoT UI 에서 `Function → 통합 환경 제어` 로 이동합니다. 액추에이터 자체는 따로
등록하거나([액추에이터 등록](#actuators)), 연동 시설에서 자동으로 찾습니다.

### 설정 화면 읽는 법 { #settings-screen }

아래 표를 읽기 전에 다섯 가지를 알아 두면 좋습니다.

**맨 위에 상태 머리말이 있습니다.** 시설 선택 칸 아래에서, 제어가 지금 무엇을 하고
있는지 보여 줍니다 — 따라가는 축마다 현재 값과 목표(VPD·온도·습도·CO₂·광량), 장치
종류별 개도(개구부·난방·냉방·분무·차광 …), 마지막 판단이 몇 분 전인지. 다음 줄은 이
시설이 축마다 실제로 무엇을 조절할 수 있는지 말합니다 — 양방향, 올리기만, 내리기만,
보기만, 센서 없음. 그 아래 두 줄 요약이 따르는 구획·단계와 지금 적용 중인 목표를
말합니다. 돌 수 없는 상태는 각각 다른 문장입니다 — 이 시설에 연동된 환경 제어가 없음,
제어 꺼짐(대신 이 시설을 돌리는 제어가 있으면 그 이름까지), 이 코디네이터 자신의 기준
시간을 넘겨 판단이 없음, 아직 한 사이클도 돌지 않음. 시설을 고르기 전에는 머리말이
비어 있습니다 — 고르는 칸이 바로 위에 있기 때문입니다. 구획이 2주 안에 끝나면 그 한
줄이 더 붙습니다.

**설정은 옵션 종류가 아니라 네 층으로 놓입니다.**

| 층 | 무엇 | 표시 |
|----|------|------|
| 연결 | 시설, 구역 | 항상 |
| 약속 | 온·습도 범위, 극한 고온 보호, CO₂ 허용오차 | 항상 |
| 전략 | 환기와 냉난방 조율, 야간 닫기, 분무 보호, 차광막·보온커튼 사용 | 항상(토글 또는 눈금) |
| 튜닝 | 나머지 전부 | [고급] 안, 그리고 접힌 [고급 설정] 묶음 안 |

**핵심 옵션 하나가 세부를 데리고 다닙니다.** 아무도 답할 수 없는 숫자("긴급 판정
배수를 3.0 으로 할까 4.0 으로 할까?")를 묻는 대신, 답할 수 있는 질문을 하고 값 여러
개를 함께 움직입니다 — 로봇청소기의 조용히/중간/강하게 와 같습니다. 그런 조작기가
셋 있습니다: 제어 성향, 환기와 냉난방 조율, 분무 빈도. **단계 이름 자체는 저장하지
않습니다** — 저장되는 것은 실제 값뿐이고, 지금 어느 단계인지는 그 값들에서
되짚습니다. 어느 단계와도 안 맞으면 *직접 지정* 으로 보입니다.

**범위는 손잡이 둘인 밴드로 묻습니다.** 온도와 습도는 질문이 하나입니다 — 몇 도에서
몇 도로 기를 것인가. 손잡이를 끌면 넘으면 안 되는 선이 고정 여유(±5 °C, ±5 %RH)로
따라 움직입니다. 끌지 않으면 하드 한계는 출하값(5–35 °C, 30–90 %) 그대로입니다.
밴드로는 하드 한계를 유도 범위보다 좁게 둘 수 없으므로 "12~32 °C 에서 기르되 30 °C 는
넘기지 마라" 는 표현할 수 없습니다 — 그 조합이 난방기와 냉방기를 서로 맞서게 하던
설정입니다. [고급] 에서 숫자를 직접 적어 그렇게 되면, 저장하는 그 자리에서 알려
줍니다 — 어느 축인지, 두 범위가 무엇인지, 실제로는 어느 범위 안에서만 목표를 세우는지
까지. 그 축의 네 값 중 하나라도 이번에 함께 저장했을 때 나옵니다. 그런 뒤
코디네이터는 유도 범위를 하드 한계 안으로 좁혀 쓰고 그 사실을 로그에 남깁니다.

**[고급] 스위치 하나가 모든 숫자 칸을 엽니다.** 눈금마다 숫자 칸이 함께 붙고,
고급 전용 행이 전부 드러나며, 접힌 묶음도 한 번에 펼쳐집니다. 이 스위치는 브라우저에만
있습니다 — 설정으로 저장하지 않으므로, 같은 함수를 두 사람이 다르게 보는 일이 없습니다.
상위 토글이 꺼진 설정은 비활성이 아니라 **감춰집니다.** 그래서 저장된 값이 계속
제출되고, 토글을 껐다 켜도 사라지지 않습니다.

> 어떤 설정은 특정 조건에서만 읽힙니다 — 직접 설정 구동 주기는 프로파일이
> *직접 지정* 일 때만, 야간 시각 칸은 야간 기준이 고정 시각일 때만. 입력했는데 안
> 쓰이는 값이 있으면 화면이 그것을 알려 줍니다. 그러지 않으면 조용히 아무 일도 안
> 하기 때문입니다.

### 명령 { #commands }

| 명령 | 동작 |
|------|------|
| 액추에이터 다시 불러오기 | Actions 표와 이 함수 자신의 설정을 다시 읽고 액추에이터 프로필을 재구성합니다 — 재시작이 필요 없습니다. |
| 지금 실행 | 현재 센서값으로 조율 사이클을 즉시 1회 실행합니다. 긴급 정지가 아직 제어를 붙잡고 있는 동안에는 무시하고, 남은 초를 응답으로 알려 줍니다. |
| 긴급 정지 | 모든 액추에이터를 안전 기본 위치로 보내고 60초간 제어를 정지합니다. |

앞의 두 명령 뒤에는 다음 사이클을 한 번만 긴급으로 처리합니다 — 개구부가 구동
프로필의 간격을 기다리지 않고 움직일 수 있습니다.

### 시설 설정 { #settings-facility }

| 항목 | 기본값 | 설명 |
|------|--------|------|
| 연동 시설 | (없음) | 이 코디네이터가 맡을 시설. 액추에이터와 센서가 여기서 옵니다 — 외피, 측창·천창, 커튼, 팬, 실내외 센서. 방위·면적·열관류율 같은 GIS 값이 각 액추에이터 프로필에 붙어 풍향과 시설 형상을 계산에 쓸 수 있습니다. 이것을 정하지 않으면 나머지 설정은 대상이 없습니다. |
| 동 범위 (선택사항) | (비움) | 시설의 한 동만 맡게 합니다. 그 동 안의 센서·액추에이터만 쓰고 — 어느 한 동에 속하지 않는 장치는 빠져서 시설 전체를 맡는 코디네이터 몫으로 남습니다 — 시설 부피·외피·환기 면적도 모든 동 폭을 합한 값에서 그 동이 차지하는 비율만큼 줄여 잡습니다(폭을 알 수 없으면 경고를 남기고 동 개수로 나눕니다). 비우면 시설 전체이고, 여러 동을 독립 제어하려면 동마다 코디네이터를 만듭니다. 비워 둔 코디네이터는 같은 시설의 다른 코디네이터가 이미 맡은 동을 비켜 갑니다 — 한 장치가 두 곳에서 명령을 받지 않게 하려는 것입니다. 연동 시설의 구역 목록에서 고르는 **드롭다운**입니다 — 시설에 더 이상 없는 저장값은 조용히 지우지 않고 표시를 붙여 남깁니다. 없는 동을 가리키는 동안 이 코디네이터는 시설 전체로 넓히지 않고 **아무 장치도 맡지 않습니다**. |
| 자동 제어 대상 장치 | (제외 없음) | 시설 설정 바로 아래 접힌 상자가 연동 시설의 액추에이터를 전부 토글과 함께 보여 줍니다 — 다만 여러 층 구조 모형의 위층에 있는 장치는 빠집니다. 이 코디네이터는 그런 장치를 전혀 제어하지 않으므로, 목록에 올려 두고 강제로 켜 두는 대신 처음부터 빼 둡니다([시설 — 평면 그리기](../geo/facility.md#plan-drawing) 참조). 하나를 끄면 그 장치는 자동 제어에서 통째로 빠집니다 — 명령도 나가지 않고 안전 게이트도 그 장치를 강제하지 않습니다. 수리 중이거나 손으로 잡아 둔 장치에 필요한 상태입니다. 제외 목록이라, 나중에 시설에 넣은 장치는 처음부터 제어됩니다. 끈 장치가 뒤에 시설에서 사라져도 끈 상태는 그대로 남습니다. 목록을 읽지 못하면 상자가 그 사실을 알리고, 저장된 설정은 빈 값으로 덮어쓰지 않고 그대로 둡니다. |

### 제어를 돌리는 시간대 { #time-control }

토글을 켜야 나머지가 나옵니다. 이것은 시간대별 제어가 아니라 **스위치**입니다.
창 밖 시간에는 목표 추종(L1~L3)이 **통째로** 멈춥니다 — 난방·냉방도 포함입니다.
그래도 보호는 계속됩니다.

- [사전 안전 게이트](#pre-gate-checked-before-l1l3)(강우·강풍·한파 등)는 매 사이클
  평가됩니다. 게이트가 서면 그 강제 명령을 보냅니다. 강풍 1단계 제한(근거 55 — 풍상측·
  천창 닫음, 나머지 상한)도 같고, [강우 단계 제한](#safety-gates)(근거 52)도 같습니다 — 닫은 천창은
  닫힌 채, 다른 명령이 없는 상한 대상 측창은 닫고(상한 아래 자리를 고를 PI 가 없습니다),
  예보 비로 묶인 천창은 제자리입니다.
- 온·습도 하드 임계의 **막는 쪽**도 그대로입니다. 예를 들어 실내가 최저 온도 아래로
  내려가면 창과 보온커튼을 닫고 냉방을 막습니다. 하드 임계는 원래 장치를 구동하지
  않으므로(난방기를 켜지는 않습니다) 시간대 밖에서도 "정지" 와 부딪히지 않습니다.
  광량 임계는 보광등을 켜는 구동이라 시간대 밖에서는 쓰지 않습니다.
- [극한 고온 보호](#heat-protect) 도 그대로 직접 걸립니다 — 창은 바깥이 더 시원할 때만
  열고, 해가 있으면 차광, 냉방기·유동팬은 켜고 난방·분무는 끕니다.
- 위 보호 명령을 받지 않은 장치에는 각자의 종료 동작을 보냅니다. 시각은 시설 현지 시간대로 판정하고, 시설
시간대를 모르면 농장 시간대를, 그것도 모를 때만 UTC 를 씁니다.

| 항목 | 기본값 | 설명 |
|------|--------|------|
| 시간대 제한 사용 | 꺼짐 | 켜면 시작~종료 시각 사이에만 목표 추종이 돕니다. |
| 시작 시간 (HH:MM) | 06:00 | 매일 코디네이터가 일을 시작하는 시각. 시작·종료 시각은 HH:MM 형식으로 입력해야 하며, 다른 형식은 저장할 때 거부됩니다. |
| 종료 시간 (HH:MM) | 20:00 | 멈추는 시각. 종료 시각이 시작 시각보다 이르면 자정을 넘는 시간대로 봅니다. 창 밖에서 각 장치가 무엇을 할지는 그 장치의 Action(시간창 종료 시 동작)에서 정합니다. |
| 광주기 메서드 | (없음) | 고정 시각 대신 일장 곡선으로 창을 정합니다. 주의: 일장이 짧으면 코디네이터도 그 시간만 돌아서 밤새 난방이 되지 않습니다. |
| 광주기 기준 시각 (HH:MM) | 12:00 | 태양남중에 해당하는 시각 — 창이 이 시각을 중심으로 잡힙니다. |

### 목표와 성향 { #settings-target }

| 항목 | 기본값 | 설명 |
|------|--------|------|
| 온도 범위 | 12–32 °C | 기를 범위. 한계를 넘으면 잘못된 방향으로 미는 것을 멈춥니다 — 너무 더우면 난방을 끄고 차광막을 치고, 너무 추우면 냉방을 끄고 개구부·보온커튼을 닫습니다. 무엇도 최대로 몰아붙이지 않습니다. |
| 폭염 보호 | 켜짐 | 문턱을 넘으면 목표보다 작물의 고온 스트레스를 막는 것이 먼저입니다 — 차광막을 치고, 난방을 끄고, 유동팬을 돌리며, 창은 바깥이 더 시원할 때만 열고, 분무는 아직 식힐 수 있을 때만 씁니다([극한 고온 보호](#heat-protect)). |
| 폭염 보호 문턱 (°C) | 30 | 보호를 시작하는 실내 평균 온도(20–45 °C). 작물이 견디는 온도로 정하세요. 보호를 켰을 때만 보입니다. |
| 습도 범위 | 40–85 % | 습도도 같은 규칙 — 너무 습하면 분무를 끄고, 너무 건조하면 배기팬과 흡기팬을 함께 끕니다. |
| CO₂ 허용 오차 (ppm) | 100 | 목표에서 이 값의 절반 안이면 CO₂ 주입을 그대로 둡니다. 이 값은 반응 세기의 기준도 되어, 6배 벗어나면 최대로 반응합니다([L3](#l3-coordinator-actuator-command)). 일반적으로 50–150 ppm. |
| 제어 성향 | 표준 | 목표를 얼마나 바짝 쫓을지. 한 칸을 고르면 사이클 주기·환기창 구동 프로파일·VPD 허용오차·긴급 판정 둘이 함께 움직입니다. 새로 추가한 함수의 출하값은 *표준* 단계 그대로이고, 그중 하나를 어느 단계에도 없는 값으로 직접 고치면 *직접 지정* 으로 보이며 [고급] 을 보라는 줄이 함께 나옵니다. |

[고급] 을 켜면 각 범위 밴드가 뒤에 있는 숫자 넷(`유도 T 하한/상한`,
`최저/최고 온도`, 그리고 습도의 짝)을 함께 보이고, 폭염 보호는 **해제 여유**(°C, 기본
1.5, 0.5–5 — 온도가 문턱보다 이만큼 낮은 상태로 10분 이어져야 보호를 끝냅니다)와 **최소
유지**(분, 기본 20, 5–120)를, 제어 성향은 멤버를 보입니다.

| 멤버 | 느긋하게 | 표준 | 민감하게 |
|------|---------|------|---------|
| 주기 (초) | 600 | 120 | 60 |
| 환기창 구동 프로파일 | 완만 (600초) | 표준 (180초) | 민감 (60초) |
| VPD 허용 오차 (kPa) | 0.15 | 0.1 | 0.05 |
| 긴급 판정 편차 임계값 (허용오차 배수) | 4.0 | 3.0 | 2.0 |
| 긴급 판정 변화율 임계값 (°C / 10분) | 3.0 | 2.0 | 1.5 |

같은 자리에 있지만 단계가 **정하지 않는** 멤버가 둘 더 있습니다. 같은 축의 미세
조정이기 때문입니다: **직접 설정 구동 주기 (초)** — 프로파일이 *직접 지정* 일 때만
쓰입니다 — 와 **긴급 시 최소 간격 (초)**, 기본 60. 뒤엣것은 긴급 상황에서도 두 번의
개구부 명령 사이에 두는 하한입니다.

구동 프로파일은 측창·천창이 실제로 **움직이는** 간격만 정합니다. 감지와 계산은 매
사이클 주기마다 그대로 돌고, 커튼·차광막은 한 번에 열고 닫으므로 해당이 없습니다.
안전 게이트의 강제 명령(강우·강풍 폐쇄 등)은 이 값과 무관하게 **그 장치에만** 즉시
나가고, 강제받지 않은 다른 창은 이 간격을 그대로 지킵니다. 이 간격을 통째로 건너뛰는
긴급은 실내 온도가 급변할 때와, 편차가 긴급 판정 임계값을 넘은 채 **계속 벌어지고
있을** 때(목표에서 멀리 떨어진 채 머무는 것만으로는 긴급이 아닙니다), 함수를 다시
불러오거나 지금 실행하도록 지시한 직후의 한 사이클, 그리고
[극한 고온 보호](#heat-protect) 단계가 올라간 그 한 사이클뿐입니다 — 보호가 이어지는
것만으로도 긴급이 아닙니다.

### 환기 { #settings-ventilation }

| 항목 | 기본값 | 설명 |
|------|--------|------|
| 환기와 냉난방 조율 | 고성능 | 환기와 냉난방이 서로를 방해하지 않게 합니다. 세 단계는 아래에 설명합니다. |
| 야간에 닫아 두기 | 꺼짐 | 밤새 창을 닫고 냉난방·제습이 부하를 지게 합니다. 개구부만 파킹하고 냉난방·제습은 그대로 돕니다. |
| 강풍 임계값 (m/s) | 12 | 10분 평균 풍속이 이 값(잰 돌풍은 1.5 배)에 이르면 개구부를 모두 닫습니다. 0.6 배(잰 돌풍은 0.9 배)부터는 풍상측 창과 천창을 닫고 나머지는 일부만 엽니다 — [강풍 두 단계](#safety-gates) 참고. [고급] |

**환기와 냉난방 조율**은 토글 셋을 한 번에 움직입니다.

| 단계 | 환기로 못 갈 때 창 닫기 | 환기로 닿으면 냉난방 쉬기 | 냉난방 가동 중 창 닫아 두기 |
|------|---|---|---|
| 고성능 (기본) | 켬 | 끔 | 끔 |
| 표준 | 켬 | 켬 | 끔 |
| 절전 | 켬 | 켬 | 켬 |

- **환기로 못 갈 때 창 닫기** — 환기는 실내를 실외 쪽으로만 밉니다. 목표가 실외의
  반대편에 있으면 아무리 열어도 멀어질 뿐입니다. 대표적인 경우가 야간 제습으로,
  실외가 실내보다 습할 때입니다. 켜 두면 개구부와 배기·흡기팬이 밤새 반쯤 열린 채
  있는 대신 닫힌 채 파킹합니다.
- **환기로 닿으면 냉난방 쉬기** — 실외 공기가 이미 목표 너머에 있으면 환기만으로
  닿을 수 있고, 그때 냉난방을 함께 돌리는 것은 바깥 공기가 공짜로 할 일을 돈 주고
  하는 것입니다. 조건 셋을 모두 만족해야 합니다: 실외가 목표를 허용오차보다 더 지나
  있고, 제어 대상 변수가 *전부* 그러하며, 환기에 여력이 남아 있어야 합니다(직전
  사이클의 최대 개도가 90 % 미만). 실외가 목표까지의 일부만 메울 수 있으면 냉난방은
  그 몫을 뺀 나머지 편차만큼만 돕니다. **15분이 지나도 목표에 못 닿으면** 전부
  냉난방에 넘깁니다 — 예측이 틀렸다는 뜻이기 때문입니다. 강우·풍속 값을 잃어
  개구부를 더 열 수 없거나 비 때문에 상한이 걸린 동안(근거 52)에는 이 판정 자체가 꺼집니다 — 더 열 수 없는 창의 도움을
  믿고 냉난방이 물러나면 안 되기 때문입니다. [극한 고온 보호](#heat-protect) 가 켜진
  동안에도 꺼집니다 — 그때는 냉방을 쉬게 할 때가 아니기 때문입니다.
- **냉난방 가동 중 창 닫아 두기** — 돌고 있는 기계 옆에서 환기하면 그 열이나 냉기를
  그대로 밖으로 버립니다. 다만 실외가 목표 쪽으로 도와줄 수 있는 계절에는 그 도움까지
  버리게 됩니다.

가동 감지에는 **근거**가 필요하고, 근거는 둘뿐입니다 — 이 코디네이터가 그 기계를
직접 명령하거나, 기계가 돌 때 값이 오르는 측정을 신호 칸에 지정하거나. 실내 온도로
추측하지 **않습니다.** 햇빛이 강한 낮에는 냉방기가 없어도 실내가 실외보다 서늘해질
때가 있어, "실내가 실외보다 서늘하면 냉방 중" 이라는 판정은 여유를 두어도 자주
틀립니다.

| 항목 (인터록을 켜면 나옵니다) | 기본값 | 설명 |
|------|--------|------|
| 냉·난방 가동 감지 신호 | (없음) | 이 코디네이터가 직접 켜지 **않는** 기계 전용입니다. 그 기계가 돌 때 값이 오르는 측정이면 무엇이든 됩니다 — 전력을 보고하는 스마트 플러그, 전류계, 보조 접점. 코디네이터가 직접 명령하는 기계면 비워 둡니다. |
| 가동 판정 문턱값 | 0.5 | 이 값 이상이면 가동 중으로 봅니다. on/off 접점이면 0.5 그대로 두고, 와트·암페어면 대기전력보다 높게 잡습니다. |

신호에 자기 유효시간이 없으면 그 측정의 주기(×2, 하한 300초)로 판정합니다. 만료된
신호는 *가동 중이 아님* 으로 보고, 그 사실을 로그에 남깁니다.

**야간 닫기**가 있는 이유는 밤에 습도가 오르고 이슬이 맺히기 때문입니다. 해질 무렵
쓸모 있어 보이던 개구도 아침까지 작물을 젖은 채로 둘 수 있습니다. 하위 설정은 토글을
켜야 나옵니다.

닫아 두는 것이 오히려 위험해지면 스스로 풉니다. 온도·습도 하드 임계를 넘었을 때, 그리고
**결로가 임박했는데 환기가 그것을 덜어 줄 때**입니다. 결로 임박은 실내 온도와 이슬점의
차가 2 °C 보다 작은 것이고, "덜어 준다" 는 외기를 조금 섞었을 때 그 차가 벌어지는
것입니다. 차고 습한 외기는 실내를 식혀 오히려 결로를 부를 수 있어, 실외가 건조하다는
것만으로는 열지 않습니다. 풀린 뒤에는 차가 3 °C 로 회복되거나 환기가 더는 도움이 안
될 때 다시 닫습니다. 실외 값을 모르면 풀지 않고, 값이 *만료돼* 마지막 캐시로 판단하는 동안도 풀지
않습니다 — 옛 "실외가 건조하다" 는 열 근거가 못 되고, 파킹이 서면 창이 닫힙니다(근거 19). 기록된 한
밤에는 제습으로 열린 창이 기상 값이 끊긴 뒤 세 시간 동안 13~25 % 로 남았습니다.

결로 탈출은 **수증기압 기준으로 엄격**합니다. 실외 이슬점이 실내보다 1.5 °C 이상 낮아야 하고
(이미 열려 있으면 0.75 °C), 섞었을 때 이슬점 여유가 0.3 °C 이상 벌어져야 합니다. 온도가
올라서 여유가 조금 늘어나는 것만으로는 열지 않습니다. 풀린 뒤에도 창은 [과습 구간](#humid-zone)
규칙에 따라 최대 30 % 까지만 열립니다(실외가 거의 같은 온도 이상이고 이슬점이 3 °C 넘게 낮으면 이 상한이 풀립니다). 난방 요구가 서 있거나 실외가 실내보다 8 °C 넘게 차면 열지 않고, 실내가 온도 기준선(온도가 제어 목표면 목표 + 허용오차, VPD 직접 모드면 유도 범위의 아래 끝) 이하일 때 외기가 더 차면 열지 않습니다 — 과습 구간과 같은 선입니다.
중간에서 멈출 수 있는 보온커튼이 있으면 커튼 틈이 먼저이고, 이 탈출은 틈을 다 쓴 뒤에야 섭니다([보온커튼 — 밤 틈과 아침 단계 걷기](#curtain-gap)).

|------|--------|------|
| 야간 기준 | 일몰~일출 | 밤을 일몰~일출로 잴지, 고정 시각으로 잴지. |
| 일몰 몇 분 전에 닫을지 (분) | 0 | 일몰 이 분 전부터 닫기 시작합니다. 음수는 잘라냅니다 — 일몰 뒤에 닫히는 지연이야말로 이 옵션이 없애려는 것입니다. |
| 야간 시작 / 종료 (HH:MM) | 18:00 / 06:00 | 야간 기준이 고정 시각일 때만 쓰입니다. |

세 가지가 보장됩니다. **안전 게이트가 이깁니다**(여름밤 고온이면 창은 그래도 열립니다),
온·습도 하드 임계를 넘으면 파킹이 풀리고, 태양시를 구할 좌표가 없으면 아예 파킹하지
않습니다. 이와 별개로 야간 닫기에 국한되지 않는 네 번째 규칙이 있습니다 — 실외 값
자체를 모르면(캐시가 비어 실외=실내로 가정한 합성값만 있을 때) 그 추측으로 창을 열지도
닫지도 않고 지금 위치를 그대로 유지합니다. 이번 판정에서 환기 규칙이 내린 결정도
이 유지가 덮어씁니다(다만 비·강풍 같은 비상 안전 게이트는 이 유지보다 우선해 창을 닫을 수 있습니다). 지어낸 실외=실내 값을 근거로 닫아 버리면,
기상대가 죽었을 때 한여름 낮에도 창이 닫힌 채로 남을 수 있기 때문입니다.

**모른다는 것은 열지 않을 이유일 뿐입니다.** 실외 값이 없는 동안에도 닫는 쪽 이동 셋은 그대로
일어납니다 — 셋 다 없는 값에 기대지 않기 때문입니다. 야간 닫기는 계속 닫고(근거 19), 마지막 실측
비·강풍의 제한은 그대로 걸리며(근거 52·55 — 상한 위로 열린 창은 상한까지 내려옵니다), 해가 진 뒤
(맑은 하늘 일사 50 W/m² 미만, 시설 좌표가 있어야 합니다) **10 % 이하**로 열린 창은 0 으로 닫힙니다
(근거 58, 야간 닫기 옵션이 없어도 됩니다). 비·바람 값만 잃어 창이 '더 열지 않음' 일 때도
같습니다(제어가 계속 열자고 하는 작은 창이 비 오는 밤을 그대로 서 있던 일이 있었습니다). 그보다 크게 열린 창은 서 있는 자리에 두고, 낮에 모른다는
이유만으로 닫는 창은 없습니다 — 더운 날에는 그것이 피해가 됩니다. 일몰 뒤 닫기는 온·습도 하드
임계가 환기를 원하는 동안 건너뛰는데, 기록된 한 밤에 바로 그 틈이 문제였습니다. 측창이 제습으로
25~30 % 열렸다가(RH 91~95 % > 상한 90 %) 기상 값이 끊긴 뒤 세 시간 동안 13~25 % 에 묶였고, 비가
시작돼도 볼 수 없었습니다. 그래서 실외 값(또는 비·바람 값)이 **30 분을 넘게** 없으면, 밤에 하드
습도 상한(또는 야간 닫기를 푸는 습도·결로 탈출) 때문에만 열려 있는 창을 단계로 닫습니다 —
**10분 사이클당 5 %p** 씩 0 까지(근거 58, 적분이 명령을 따라갑니다. 사이클이 짧으면 폭도 비례해
줄어듭니다). 반으로 줄이지 않고 5 %p 인 이유는, 30 % 창을 반으로 줄이면 한 번에 15 %p 가 내려가고
0 에 정확히 닿지도 않기 때문입니다 — 일정한 폭이 큰 창에서 더 부드럽고 0 에서 끝납니다. 30 분
안의 끊김은 그대로입니다(기상대 값은 평소에도 최대 30분쯤 건너뜁니다). 온도 하드 임계, 극한 고온
보호, 낮의 열림도 건드리지 않습니다. 값이 돌아오면 그 순간부터 보통의 제어이고 남는 래치는 없습니다.
30분 시계는 재시작을 넘어 이어집니다(다른 사이클 기억과 함께 저장되며, 사이클이 30분 넘게 없었던
기억은 버립니다). 시각은 시설 현지 시간대로 읽고, 시설 자체 시간대를 구할 수 없으면 농장 시간대로
물러납니다 — 서버 시각은 쓰지 않습니다. 시설 팝업에서 이 옵션으로
닫힌 장치는 *밤이라 닫아 둠 — 냉난방이 대신합니다* 로 표시되며, *지금 이 장치가 바꿀
수 있는 것이 없음* 과 구분됩니다.

**실내 값을 잃는 것은 그 반대편입니다.** 창은 서 있는 자리에 서지만(근거 21, 실제로 나간 개도 그대로),
맑은 날에는 외기와 일사만으로 정한 작은 열림을 두고 해가 지면 다시 닫습니다(근거 60 — [맑은 날 실내
값이 끊겼을 때](#solar-vent-blind)).

**닫기 직전에는 창을 더 열지 않습니다.** 파킹이 시작되기 전 45분(일몰 − *일몰 몇 분 전에 닫을지*,
또는 야간 시작 시각) 동안 환기창·팬은 코디네이터가 닫을 수는 있지만, VPD·습도·보통의
온도 요구로 **지금 열린 정도를 넘어 더 열지는** 않습니다. 해 질 무렵에는 실내 습도가
오르고 실외 공기는 더 건조해서 "환기하면 VPD 가 오른다" 가 창을 여는데, 10분 뒤 야간
닫기가 그 창을 다시 닫습니다. 기록된 어느 저녁에는 측창이 16:48~17:49 에
12 → 91 % 로 열렸다가 18:42 까지 70 → 0 % 로 닫혔습니다. 이 왕복은 모터 이동, 해지기
직전의 온도 하강, 모종에 닿는 찬 공기로 값을 치릅니다. 구간 안에서는 열림을 직전 값에
묶고 적분도 더 쌓지 않으므로 구간이 끝나는 순간 튀어나가지 않습니다. 시설 팝업에는
*현재 열림을 그대로 둡니다 — 곧 밤 파킹으로 환기창이 닫힐 예정입니다*(근거 48)로 나옵니다.
닫는 쪽으로 점점 줄이는 경사는 일부러 두지 않았습니다 — 창이 정말 필요한 집을 파킹보다
먼저 억지로 닫게 되기 때문입니다.

파킹을 푸는 사유와 더위는 이 묶음도 풉니다. 온도 하드 임계(와 온도 상한의 하드 항), 습도 하드
임계, [극한 고온 보호](#heat-protect), 위의 결로 탈출입니다. 비·강풍 게이트는 여전히 창을
닫습니다. 태양시를 구할 수 없으면 구간이 없습니다. 45분은 고정이며 옵션이 아닙니다. 규칙 기반
제어(Legacy, 물리 모델 PI)에 적용되고 MPC 는 적용하지 않습니다.

### 햇빛 열 빼기 { #solar-vent }

해가 드는 온실은 창을 닫으면 몇 분 만에 더워집니다. 햇빛이 작물·바닥을 데우고, 그 열이 나가는 길은
공기뿐입니다. 그런데 지금의 안팎 차이만 보면 바로 그때 환기가 쓸모없거나 해로워 보입니다 — 바깥이
더 건조하니 "열면 VPD 가 오른다", 안팎 온도차가 1 °C 남짓이니 "환기할 구동력이 없다"(*무구배*,
근거 15). 그 작은 차이는 대개 분무가 공기를 식혀 만든 것입니다. 그리고 증발냉각은 습해진 공기를
바꿔 줘야 이어집니다 — 분무·환기·차광은 함께 가는 수단입니다. 습도를 지키려고 창을 닫는 것은 햇빛
열부하가 없을 때(밤·흐림·서늘함)만 맞습니다.

그래서 해가 있는 동안 창에 **열림 하한**을 둡니다.

| 조건 | 값 |
|---|---|
| 해 | 실외 일사 200 W/m² 이상(150 아래로 오면 풀림). 일사를 잠깐 못 재면 맑은 하늘 일사 × 지난 30분의 구름 정도, 일사 센서가 아예 없으면 맑은 하늘 일사의 절반, 시설 위치를 모르면 판단하지 않습니다 |
| 덥다 | 실내가 *작물 선* 보다 높음 — 온도가 제어 목표이면 그 목표 + 허용오차, VPD 직접 모드에서는 유도 온도 목표 + 허용오차와 작물 선 중 낮은 쪽(아래). 그 선보다 0.5 °C 내려가면 풀림 — 단 선 뒤 30 분은 온도로 풀리지 않고 최소값으로 남습니다(창이 한 번에 집을 식혀 풀리고, 닫히면 해가 곧 다시 데워 10 분마다 켜고 끄지 않게) |
| 바깥이 더 덥지 않다 | 바깥이 안보다 1 °C 넘게 덥지 않음(넘으면 환기가 열을 들입니다) |
| 열림 하한 | 선 바로 위 15 %, 초과분에 따라 [극한 고온 보호](#heat-protect) 문턱(보호를 끄면 **최고 온도**)에서 80 %까지, 일사로 가중(200 W/m² 에서 × 0.7, 800 W/m² 이상 × 1) |

VPD·습도 요구는 그 아래로 창을 닫지 못합니다. 그 요구가 지키려던 습도는 분무(식히면서 가습)와
[차광막](#shade-heat)이 맡습니다. 하한은 적분에도 걸려서, 규칙이 풀릴 때 창이 한 번에 닫히지 않고
서 있는 자리에서 제어가 이어집니다(풀릴 때 하한을 단계로 내리는 방식은 시험했다가 되돌렸습니다 — 제어가
내려가는 하한에 맞서 창을 다시 올려, 바로 푸는 것보다 창이 더 자주 오르내렸습니다). 보호 문턱 위에서는 하한이 맨 위 값에 머물러 극한 고온 보호로
넘어갈 때 계단이 없습니다. 대상은 천창·측창이고, 창이 없을 때만 팬입니다(팬은 전기를 씁니다). 시설
팝업은 *햇빛 열을 빼려고 열어 두었습니다 — 해가 들고 온도 목표보다 높습니다*(근거 51)이고, 시작과
끝에 로그를 한 줄 남깁니다.

**덥다의 선은 작물의 온도로 긋습니다.** VPD 직접 모드의 유도 온도 목표는 VPD 를 맞추려고 옮긴
온도입니다 — 습한 아침에는 VPD 를 올리려고 실내보다 위에 서서 실내를 따라 오르므로, 그 선으로는 해가
닫힌 집을 데우는 내내 '덥지 않다' 가 됩니다(시뮬레이션: 밤새 닫혀 습했던 집에서 하한이 90 분 늦게 섰습니다).
그래서 그 목표는 *작물 선* 을 넘지 못합니다. 작물 선은 단계의 지금(주간) 온도 + 1 °C, 단계 온도가 없으면
유도 범위 아래 끝에서 폭의 2/3 지점(12~32 °C → 25.3 °C — 범위는 낮·밤을 다 담으므로 중앙은 낮 작물에게
낮고, 위 끝은 보호 문턱보다 높습니다)이며, 보호 문턱 − 0.5 °C 를 넘지 않습니다(문턱에서 하한이 80 % 로
이어지게). 건조해 유도 목표가 낮으면 종전처럼 그쪽이 선입니다. 온도 우선 모드에서 단계 온도가 없어
목표가 지금 온도를 따라갈 때와, VPD 를 잴 수 없어 물러났을 때도 작물 선을 넘지 못합니다.

이 구간에서는 분무가 식힌 공기 때문에 *무구배* 로 쉬려던 창도 하한에 머뭅니다. 효과 모델은 그대로
둡니다 — 환기의 온도 효과에 햇빛 열을 더해 세도록 바꿔 보았더니 시뮬레이션에서 창이 오히려 **덜**
열렸습니다(오차는 작은데 가중치만 커진 온도 항이 VPD 요구를 희석합니다).

하한보다 앞서는 것: 강우·강풍 게이트, 실외 모름(제자리), 강우·풍속 모름(더 열지 않음), 야간 파킹과
그 직전 45분([근거 48](#settings-ventilation)), 냉난방 연동, 극한 고온 보호의 '바깥이 더 덥다'(근거 28),
온도·습도 하드 임계, 수동 잠금, 의심 장치. 하한이 이기는 것: VPD·습도 요구, *무구배*, 환기 무익,
과습 구간의 열림 상한, '열어도 반응 없음'. 값은 정해져 있고 옵션이 아닙니다. 규칙 기반 제어(기본·물리
모델 PI)에 적용되고 MPC 는 적용하지 않습니다.

#### 맑은 날 실내 값이 끊겼을 때 { #solar-vent-blind }

위 하한은 실내 온도로 정합니다. 실내 센서가 모두 끊기면 판단할 수 없게 된 창은 서 있는 자리에
섭니다(근거 21) — 그런데 맑은 아침에 서 있는 것은 집을 닫아 두는 것입니다. 기록된 한 두절(07:29 실내
미러 센서가 모두 끊김)에서 창은 밤의 0 % 그대로 맑고 건조한 낮으로 넘어갔습니다. 한 시설의 측창은
바깥 19 °C · RH 25 % 인데 09:03~12:55 닫혀 있었고, 다른 시설은 일사 656 W/m² 에 창이 닫혀 있었습니다.
닫힌 비닐집은 해 아래서 바깥보다 15~20 °C 더워집니다.

그래서 실내 온도를 모르고 실외 값이 실측(실외 = 실내로 채운 대체값이 아님)인 동안에는 바깥만으로
정한 작은 하한을 둡니다.

| 조건 | 값 |
|---|---|
| 해 | 실외 일사 200 W/m² 이상(150 아래로 오면 풀림). 측정이 없으면 맑은 하늘 일사 × 최근 구름, 일사 센서가 아예 없으면 맑은 하늘 일사의 3/4(위의 절반보다 큽니다 — 여기서는 적게 어림하면 맑은 날 닫힌 집이 되고, 많이 어림해도 흐린 날 10 % 열림일 뿐입니다) |
| 바깥이 차지 않음 | 외기 12 °C 이상 — 따뜻한 철 모종의 저온 장해가 시작되는 언저리. 실내 온도를 모르는 채 그보다 찬 공기를 들이지 않습니다 |
| 닫힌 집이면 더울 것 | 외기 + 일사 1 W/m² 당 0.02 °C 가 작물 선(위와 같음)보다 높음. 그 선보다 0.5 °C 아래로 오면 풀림. 단동 비닐집은 정상 상태에서 바깥보다 일사 1 W/m² 당 약 0.033 °C 더워지지만, 작물 증산과 바닥의 열용량이 오전의 상승을 늦춥니다 — 폐루프 시뮬레이터에서 맑은 가을 낮 닫힌 집은 09시 0.011, 14시 0.020 °C/(W/m²) 였습니다. 오후 값이면 시뮬레이션의 집이 선을 넘는 때에 같이 넘고, 0.033 이면 아직 데워지는 집을 한 시간 일찍 '덥다' 고 합니다 |
| 열림 하한 | 선 바로 위에서 10 %, [극한 고온 보호](#heat-protect) 문턱에서 20 % 까지. 외기 자체가 그 문턱 이상이면 10 % 만 |

근거 21 로 제자리에 설 창에만 걸고, **10분 사이클당 5 %p** 씩 엽니다(사이클이 짧으면 폭도 비례해
줄어들고, 첫 걸음은 장치의 최소 개도 이상이라 0 으로 되돌려지지 않습니다). 이미 더 열린 창은 그
자리에 둡니다 — 근거가 없다는 이유로 닫는 창은 없습니다. 흐림·해 질 녘 어스름은 제자리입니다. 해가
진 뒤(맑은 하늘 일사 50 W/m² 미만, 근거 58 과 같은 선) 실내를 여전히 모르면 20 % 이하로 열린 창을 같은
폭으로 닫고, 그보다 크게 열린 창은 여전히 제자리입니다 — 단 [야간 닫기](#settings-ventilation)가 켜진 시설은 일몰부터 그 창도 야간 닫기(근거 19)가 먼저 닫습니다. 실내 값이 돌아오면 창이 서 있는 자리에서
보통의 제어가 이어집니다(적분이 개도를 따라갑니다). 시설 팝업은 *실내 값이 없어 해를 보고 조금
열었습니다 — 닫힌 집은 해 아래서 빨리 더워집니다(해가 지면 다시 닫습니다)*(근거 60)이고, 시작과 끝이
로그에 남습니다.

**바깥이 아주 덥다는 것은 닫을 이유가 아닙니다.** 실내 온도를 모르는 채 외기가 보호 문턱 이상이면
창을 닫지 않고 가장 작은 하한에 둡니다. 해 아래 닫힌 집은 언제나 바깥보다 덥습니다. 극한 고온 보호의
'바깥이 더 덥다'(근거 28)는 분무·차광이 집을 바깥보다 시원하게 해 둔 것을 **재고 나서야** 창을 닫는데,
실내 값이 없으면 그 측정이 없습니다. 그렇다고 크게 열 근거도 없습니다 — 분무가 돌고 있었다면 집이
바깥보다 시원할 수 있고, 그때 큰 환기는 뜨거운 공기를 들입니다. 작은 열림은 분무가 만든 습기를 빼
증발냉각이 이어지게 하는 몫입니다.

이 하한보다 앞서는 것: 위 햇빛 하한보다 앞서는 것 전부와 비·바람·서리 상한(근거 52·55·56). 값은
정해져 있고 옵션이 아닙니다. 규칙 기반 제어(기본·물리 모델 PI)에 적용되고 MPC 는 적용하지 않습니다.

### 냉난방·가습 { #settings-hvac }

| 항목 | 기본값 | 설명 |
|------|--------|------|
| 가습에 미니스프링클러 사용 | 켜짐 | 잎을 적시는 분무기를 습도에도 씁니다. 같은 노즐이 관수 설비를 겸하면 끕니다 — 관수용으로 고른 스프링클러는 짧게 한 번만 틀어도 잎에 물막을 남깁니다. 끄면 그 분무기는 자동 환경 제어에서 통째로 빠집니다 — 명령을 아예 보내지 않으므로, 별도 관수 제어가 그 장치를 그대로 씁니다. |
| 일소·저녁 보호 사용 | 꺼짐 | 강한 빛에서 습윤형 분무를 막고(물방울이 렌즈가 되어 볕을 모읍니다), 설정하면 일몰 전에도 막습니다. 극한 고온·건조에서는 짧은 펄스 하나가 잠금을 통과합니다 — [짧은 펄스 분무](#pulse-fog) 참고. 분무를 얼마나 자주 하는가와는 별개입니다. |
| 해 질 녘 습윤 분무 중단 | 켜짐 (고급) | 습윤형 분무는 빛이 약해지면 줄고 일몰 90분 전에 멈춥니다(일소·저녁 보호를 켜면 *일몰 전 분무 중단 시간*에) — [해 질 녘 습윤 분무](#wetting-fog-dusk) 참고. 저녁에도 분무하려면 끕니다. |
| 분무 빈도 | 자주 | 분무가 얼마나 자주 도는가 — 1회 작동 시간과 다음까지의 간격. |

분무 밸브는 거의 전부 on/off 라 물살을 줄일 방법이 없습니다. 조절할 수 있는 것은
한 번에 몇 초 켜느냐와 다음까지 얼마나 기다리느냐뿐이고, 이 눈금이 그것을 정합니다.

| 단계 | 1회 최대 분무 시간 (초) | 강제 건조 간격 (초) |
|------|------------------------|--------------------|
| 드물게 | 5 | 1200 |
| 보통 | 10 | 900 |
| 자주 | 20 | 600 |
| 아주 자주 | 30 | 450 |

일소 보호는 빈도와 **별개**의 결정입니다 — 둘을 따로 두어야 "자주 뿌리되 강한 볕에는
잠가 달라" 같은 조합을 정할 수 있습니다.

| 항목 (보호를 켜면 나옵니다) | 기본값 | 설명 |
|------|--------|------|
| 햇빛 강도에 따른 분무 조절 | 150–250 W/m² | 손잡이 둘인 밴드입니다. 아래 값보다 어두우면 분무가 자유롭게 돌고, 위 값보다 밝으면 멈추며([극한 고온·건조의 짧은 펄스](#pulse-fog)만 예외), 사이에서는 선형으로 줄어듭니다. 둘 사이를 벌려 두는 것은 구름이 지날 때 분무가 켜졌다 꺼졌다 하지 않게 하려는 것입니다. **잎을 적시는 분무에만 적용됩니다** — 안개형은 강한 볕에도 돕니다. 판정은 추정 *실내* 광량이라 차광막을 치면 잠금이 완화됩니다. 광량 측정이 아예 없으면 태양 위치로 어림한 맑은날 일사가 대신 쓰이므로, 광센서가 없는 시설에서도 보호가 걸립니다. 분무 원수가 기본값(지하수)이면 실제로는 100–150 W/m² 로 내려 씁니다. |
| 극한 고온·건조 짧은 펄스 분무 | 켜짐 (고급) | 잠금이 켜져 있어도, 극단적으로 덥거나 건조해 젖은 잎이 몇 분 안에 마르는 날에는 짧은 펄스 하나(10초 켬, 15분 이상 쉼)를 통과시킵니다 — [짧은 펄스 분무](#pulse-fog) 참고. 끄면 잠금이 그대로 유지됩니다. |
| 일몰 전 분무 허용 | 켜짐 | 끄면 밤새 잎이 마른 채로 남습니다. 엽면 습윤이 길수록 잿빛곰팡이·노균병 위험이 커집니다. **해 질 녘 습윤 분무 중단이 꺼져 있을 때만 읽습니다** — 켜 두면(기본) 이 값과 무관하게 습윤 분무가 일몰 전에 이미 멈춥니다. |
| 일몰 전 분무 중단 시간 (분) | 120 | 일몰 이 분 전에 분무를 멈춥니다. 이 모드에서는 *해 질 녘 습윤 분무 중단*도 같은 시각에 시작합니다. 차단은 다음 일출까지 이어집니다. 설치 위치 좌표를 모르면 일몰을 구할 수 없어 저녁 차단이 걸리지 않습니다. |
| 분무 원수 | 지하수 (미처리) | 처리 안 한 지하수는 대개 경도가 높고 찹니다 — 마르는 물방울이 미네랄 자국을 남기고 볕 받는 잎에 냉해를 줄 수 있습니다. 이것이 선택돼 있으면(기본값) 잠금·해제 임계가 자동으로 내려갑니다(각각 최대 150/100 W/m²). |

보호 여부와 무관하게 습윤형 분무기는 연속 변조가 아니라 펄스로 도징됩니다 — 연속
변조는 잎이 마를 틈을 주지 않기 때문입니다. 1회 시간과 간격은 분무 빈도 눈금의 값을
쓰고(출하값 *자주*: 1회 최대 20초, 건조 간격 600초), 값이 비어 있을 때만 30초/180초로
돕니다.

습윤형 분무는 **최고 습도** 하드 임계보다 앞에서도 잠깁니다. 습도가 이번 사이클의
습도 기준(VPD 목표에서 나눈 습도, 유도 범위 안) **+ 5 %** 를 넘으면 잠그고,
습도를 모를 때도 잠급니다. 이미 젖은 공기에서 잎을 더 적시지 않기 위해서입니다.
안개형(고압 미세포그)은 해당하지 않습니다. [극한 고온 보호](#heat-protect) 중에는 이 잠금이
**더 엄격해지기만** 합니다 — 기준 + 5 %, **최고 습도**, 85 % 중 가장 낮은 값. 습윤형 분무는
보호의 증발냉각기가 아닙니다. 물이 잎과 트레이에 떨어져 그것이 마르면서 식히므로, 이미
습한 공기에서 더 뿌리면 잎만 오래 젖습니다.

### 해 질 녘 습윤 분무 { #wetting-fog-dusk }

습윤형 분무기(잎을 적시는 물방울이지 안개형이 아닙니다)는 물이 공중에서 마르지 않습니다.
물은 잎과 트레이에 내려앉고, 그것이 마르면서 비로소 사라지며, 마르는 속도는 햇빛이 정합니다.
그래서 저녁까지 뿌리면 작물이 젖은 잎으로 밤을 맞습니다 — 잎이 젖어 있는 시간이 길수록
잿빛곰팡이·노균병 위험이 커집니다. 실측(토마토 온실, VPD 목표 1.0 kPa, 일소·저녁 보호 꺼짐):
습윤형 분무기가 12시부터 17시까지 100 %(근거 1, VPD)로 돌았고, 그동안 일사는 150 에서
31 W/m² 로 떨어졌으며 일몰은 17:54 였습니다. 위의 일소·저녁 보호는 육묘 모드에만 있어
이 설치를 막는 것이 없었습니다.

그래서 습윤형 분무기는 하루가 저물 때 줄입니다(일소·저녁 보호 모드에서도 — 아래 참고).

| 조건 | 습윤형 분무기 |
|---|---|
| 실외 일사 150 W/m² 이상 | 제한 없음 |
| 50 – 150 W/m² | 비례해서 줄임 — 100 W/m² 에서 명령의 절반, 75 W/m² 에서 4분의 1 |
| 50 W/m² 이하 | 끔 |
| 일몰 90분 전부터 다음 일출까지 (일소·저녁 보호 모드: *일몰 전 분무 중단 시간*부터 — 기본 120분) | 일사가 얼마든 끔 |

일사는 실외 측정값이고, 측정이 없으면 맑은 하늘 일사 × 최근 흐림 정도입니다(일사 센서가 아예
없으면 맑은 하늘 값의 절반). 일사도 시설 위치도 모르면 아무것도 제한하지 않습니다 — 모른다는
이유로 가습을 멈추지 않습니다.

이 규칙은 **줄이기만** 합니다. 하드 임계 **뒤**에 적용되므로 **최저 습도** 요구가 습윤형 분무를
저녁에 100 % 로 밀어 넣을 수 없습니다. 저녁에 모자라는 습도는 환기와 안개형 분무의 몫입니다.
안개형(고압 미세포그)은 잎을 적시지 않으므로 건드리지 않고, 드립도 그렇습니다. 안전 게이트는
여전히 이 규칙보다 뒤에서 이깁니다.

스위치는 **해 질 녘 습윤 분무 중단**(고급, 기본 켜짐)입니다. 값(150 → 50 W/m², 90분)은 옵션이
아니라 고정입니다.

**일소·저녁 보호 모드(*일소·저녁 보호 사용*)도 이 규칙을 받습니다.** 그 모드의 강한 볕 잠금과
완만한 감소는 [냉난방·가습](#settings-hvac)에 적힌 그대로이고 낮의 밝은 시간을 계속 맡습니다. 이 규칙은
약한 빛·저녁·밤을 맡습니다. 이전에는 보호가 저녁에 잠금을 풀고 일몰 뒤의 습윤 분무를 막는 것이 없어서,
모의 열대야에서 작물이 밤마다 590분쯤 젖어 있었습니다. 이 모드에서 다른 점은 저녁 중단이 시작되는 때뿐입니다.
90분이 아니라 *일몰 전 분무 중단 시간*(기본 120분)입니다.

이 모드에서 설정이 맞물리는 방식:

| *해 질 녘 습윤 분무 중단* | *일몰 전 분무 허용* | 결과 |
|---|---|---|
| 켜짐 (기본) | 켜짐 (기본) | 습윤 분무가 일몰 전에 멈추고 약한 빛에서 줄어듭니다 |
| 켜짐 | 꺼짐 | 같습니다 — 둘이 같은 시각에 멈추므로 달라지는 것이 없습니다 |
| 꺼짐 | 켜짐 | 저녁 분무를 허용합니다 (이 규칙이 생기기 전 동작) |
| 꺼짐 | 꺼짐 | 종전 저녁 차단만 — *일몰 전 분무 중단 시간*부터 일출까지 분무 없음 |

그래서 *일몰 전 분무 허용*은 이 규칙을 끈 뒤에야 읽힙니다. 일소·저녁 보호 모드에서 저녁 분무를
유지하려면 *해 질 녘 습윤 분무 중단*을 끄세요. 시설 팝업에는 *빛이 약해져 습윤 분무를
줄였습니다 — 잎이 젖은 채 밤을 넘기게 됩니다*(근거 53)로 나오고, 로그에는 제한이 시작되고
끝날 때 한 줄이 남습니다. 규칙 기반 제어에 적용되며 MPC 는 적용하지 않습니다.

### 극한 고온·건조의 짧은 펄스 분무 { #pulse-fog }

위의 일소 잠금과 [해 질 녘 규칙](#wetting-fog-dusk)은 해가 세거나 하루가 저무는 동안 습윤형 분무를
0 으로 묶습니다. 보통 날에는 옳습니다. 하지만 극단적인 날에는 습윤형 분무로 가습도 냉각도 전혀
못 하게 됩니다. 폐루프 시험의 열대야 폭염(실내 42.5 °C, 40 °C 초과 337분, VPD 가 밴드 안에 있던
몫 7 %)과 건조한 푄 바람(RH 15 %, VPD 최대 7 kPa)에서 분무가 하루 종일 꺼져 있었습니다. 이 잠금은
지하수의 무기질 잔여물이 잎에 남는 것과 물방울이 볕을 모으는 것을 막으려고 만든 것인데, 작물에서
실제로 관찰된 적은 없는 우려였습니다. 그래서 그런 날에는 **짧은 펄스 하나**를 통과시킵니다.

펄스는 일소 잠금이 켜져 있고 **그리고** 아래 줄이 모두 성립할 때만 나갑니다.

| 조건 | 뜻 |
|---|---|
| 덥거나 건조 | [극한 고온 보호](#heat-protect) 가 단계 1 또는 2 이거나, 실내 VPD 가 3 kPa 를 넘음 |
| 빨리 마름 | 건구 − 습구 8 °C 이상 — 젖은 잎이 몇 분 안에 마릅니다 |
| 습도 | 습윤형 분무 습도 잠금에 걸리지 않고, **최고 습도** 와 85 % 아래 |
| 물 | [분무용 물 공급](#water-supply) 이 물이 있다고 함(신호를 고르지 않았으면 있는 것) |
| 저녁 아님 | [해 질 녘 규칙](#wetting-fog-dusk)(근거 53)이 서기 4시간 전보다 앞이고 저녁 차단이 걸려 있지 않음 — **오후 끝자락·해 질 녘·밤에는 펄스가 없습니다.** 마지막 펄스의 물이 닫혀 가는 집 안에서 계속 증발해 밤 이슬을 앞당기기 때문입니다(폐루프 폭염: 여유 없음 +5 %, 4시간 여유 +0.4 %의 밤 젖음 분) |
| 다른 게이트 없음 | 비(실측·예보), 강풍 2단계, 한파 비상, 서리 주의·보호, 실내·실외 값 끊김이 없음. 강풍 1단계는 개구부만 묶으므로 펄스를 막지 않습니다 |

펄스 자체는 **10초 켜고 최소 15분 쉬며**, 제어가 가습을 요구할 때만(명령 5 % 이상, 요구가 없으면
꺼져 있음) 나갑니다. 모든 습윤형 분무기가 이미 타는 펄스 도징([장치 종류에 따른 자동 변환](#actuators-adapters))을
그대로 씁니다. 켜는 시간은 10초와 *1회 최대 분무 시간* 중 짧은 쪽, 쉬는 시간은 15분과
*강제 건조 간격* 중 긴 쪽입니다. 15분의 쉼은 장치 어댑터가 10분마다 다시 만들어져 잊어버리므로
코디네이터가 분무기별로 직접 잽니다. 더 짧게·더 드물게 분무하도록 정해 둔
분무기는 그 설정을 지키고, 쉬는 시간은 조건이 끝난 뒤에도 이어집니다. 시간이나 용량으로 출력을
끊을 수 없는 분무기(PWM·값 출력)는 펄스를 내지 않고 잠긴 채로 둡니다. 안개형과 드립은 관련이 없고,
일소 보호가 없으면 잠금 자체가 없어 아무것도 달라지지 않습니다.

스위치: **극한 고온·건조 짧은 펄스 분무**(고급, 일소 보호와 함께 나옴, 기본 켜짐). 끄면 예전처럼
잠금이 그대로 유지됩니다. 값 — 10초, 15분, 3 kPa, 8 °C — 은 옵션이 아니라 고정입니다. 시설 팝업에는
*극한 고온·건조 — 일소 잠금 중에도 짧은 분무 한 번을 허용합니다*(근거 57)로 나오고, 로그에는 펄스가
허용되기 시작할 때와 멈출 때 한 줄이 남습니다. 규칙 기반 제어에 적용되며 MPC 는 적용하지 않습니다.

### 분무용 물 공급 { #water-supply }

물 없이 도는 분무기는 펌프만 달구고 습도는 올리지 못하는데, 코디네이터는 탱크를 볼 수
없습니다. **분무용 물 공급 확인** 은 측정값 하나 — 탱크 수위(%), 배관 압력, 유량 스위치 — 를
묶고, 문턱의 어느 쪽이 "물이 있다" 인지 정하게 합니다.

| 항목 (확인을 켜면 나옵니다) | 기본값 | 설명 |
|------|--------|------|
| 분무용 물 공급 확인 | 꺼짐 | 아래 신호가 물이 없다고 말하는 동안 분무기를 모두 멈춥니다. 끄면 물이 있는 것으로 봅니다 — 지금까지와 똑같습니다. |
| 물 공급 신호 | — | 읽을 측정값입니다. 탱크 수위·배관 압력·유량 스위치. |
| 물 공급 문턱 | 0.5 | 신호가 쓰는 단위 그대로입니다. 켜짐/꺼짐 스위치(0 또는 1)는 0.5 로 두고, 탱크 수위는 그래도 분무하고 싶은 가장 낮은 수위로 정합니다. |
| 신호가 이럴 때 물이 있음 | 문턱 이상 | *이상*: 수위·압력·유량 — 클수록 물이 많습니다. *이하*: 말랐을 때 1 이 되는 빈 탱크 경보 스위치. |

| 신호 | 물 | 분무기 |
|---|---|---|
| 확인을 껐거나 신호를 고르지 않음 | 있는 것으로 봄 | 종전과 같음 |
| 최신 값이 문턱의 맞는 쪽 | 있음 | 종전과 같음 |
| 최신 값이 문턱의 틀린 쪽 | **없음** (부족) | 전부 멈춤 |
| 값이 없거나 오래됨 | **없음** (모름) | 전부 멈춤 |

확인을 켰는데 신호를 고르지 않았으면 로그에 한 번 알리고, 물은 여전히 있는 것으로 봅니다.

신호를 모르는 것도 일부러 "물 없음" 으로 읽습니다. 물이 있는지 모른 채 펌프를 돌리는 비용이
분무기를 몇 분 쉬게 하는 비용보다 크고, 쉬는 것은 신호가 돌아오는 사이클에 끝나기
때문입니다. 신선도는 이 신호 자신의 주기로 판정합니다(냉난방 가동 신호와 같은 규칙).
한 번 "없음" 이 되면 문턱에서 문턱의 5 % 만큼 더 돌아와야 다시 있는 것으로 봅니다 —
펌프가 돌 때 생기는 수압 출렁임에 매 사이클 뒤집히지 않게 하려는 것입니다.

물이 없는 동안은 폭염 여부와 무관하게 **분무기 전부**를 파킹하고(*분무용 물이 없습니다*,
근거 41) 그 사이클부터 0 으로 내보냅니다. 어느 엔진(그레이박스 MPC 포함)이 명령을 냈든,
수동 잠금이 잡고 있든 최종 오버라이드가 0 으로 자릅니다. 극한 고온 보호도 분무를 막고 있으면
*지금은 분무로 공기를 식힐 수 없습니다* 대신 근거 41 이 이깁니다 — 사람이 할 일(물 채우기)이
보여야 하기 때문입니다. 보호는 같은 플래그를 읽습니다.

바뀔 때마다 로그를 한 번 남깁니다(*물이 없어 분무기를 모두 멈춥니다* / *분무용 물 공급이
돌아왔습니다*). 확인을 켜면 채널 92 에 1(있음)·2(부족)·3(신호 없음·만료)을 디버그 여부와
무관하게 매 사이클 남기고, 건강 점검은 물이 없어 분무기가 멈춘 시간을 분 단위로 말합니다 —
0 이 아니면 사람이 탱크·압력·신호를 봐야 합니다.

### 빛과 차광 { #settings-light }

| 항목 | 기본값 | 설명 |
|------|--------|------|
| 차광·보광 기준 | 0–800 W/m² | 안에 머무르라는 범위가 아니라 기준선 둘입니다. 밴드보다 어두우면 보광등이 켜지고 차광막이 열립니다. 밝으면 차광막이 닫힙니다. 밴드 안에서는 아무 일도 일어나지 않습니다. 기준은 **작물이 실제로 받는 광량**입니다 — 실외 일사에 피복재와 차광막의 투과율을 반영한 값입니다. |
| 차광막으로 더위 막기 | 켬 | 작물이 그날 필요한 빛을 받을 수 있을 때만 차광막을 쳐서 열·수분 스트레스를 덜어 줍니다. 끄면 예전처럼 VPD·온도 편차만 보고 움직입니다. [차광막으로 더위 막기](#shade-heat) 참조. |
| 밤 결로에 보온커튼 조금 열기 | 켬 | 밤에 공기가 이슬점에 가까워지면 창보다 먼저 닫힌 보온커튼을 3 → 6 → 10 % 엽니다 — 빠져나가는 열이 허락하는 만큼만. 중간에서 멈출 수 있는 커튼 모터에만 쓰입니다. [보온커튼 — 밤 틈과 아침 단계 걷기](#curtain-gap) 참조. |

양 끝을 각각 끌 수 있고, "끔" 의 뜻은 두 끝에서 반대입니다. 아래 손잡이가 0 이면
*보광 안 함*, 위 손잡이를 끄면 *차광 안 함* 입니다. 시설에 차광막이나 보광등이 등록돼
있지 않으면, 아무 일도 못 하는 손잡이를 내놓는 대신 화면이 그렇게 말합니다.

차광 쪽 기준선은 닫힌 막 아래의 광량이 아니라 **막을 걷었을 때** 얼마나 밝은가로
판정합니다 — 그러지 않으면 닫는 순간 어두워져 판정이 풀리고, 다음 사이클에 다시
걷습니다. 실외 광량을 모르면(실내 센서만 있는 설치) 지금 값으로 판정합니다. 차광이
걸려 있는 동안에는 보광과 개방을 동시에 강제하지 않습니다. 두 기준선을 함께 만족시킬
수 없으면 — 막을 닫으면 보광 기준선보다 어두워지는 설정 — 차광을 우선하고, 그 모순을
로그에 한 번만 남겨 사람이 고칠 수 있게 합니다.

실제 값은 **최소 광량 임계값 (보광)**(기본 0)와 **최대 광량 임계값**(기본 800)이고, 둘 다
[고급] 에서 보입니다.

관련된 값 셋은 이 화면에 **없습니다.**

- **차광막 투과율**은 시설의 것이고, 시설 편집기의 차광 커튼 아래에 있습니다. 실내
  광센서가 없을 때만 쓰입니다 — 그때는 실외 일사와 차광 개도로 실내 광량을
  어림합니다. 값이 없거나 범위 밖이면 0.50 으로 돌아가고, 차광막이 **없다고 선언한**
  시설에서는 1.0 입니다. 천이 다른 차광막 하나는 자기 Action 에서 따로 지정할 수
  있습니다.
- **피복재 투과율**은 외피 자재에서 자동으로 나옵니다(유리 0.85 · 2중 비닐 0.78 ·
  부직포 0.50 등). 차광막이 없어도 지붕은 늘 빛을 깎으므로 실내
  광량 추정에 함께 곱합니다. 그래서 광량 상·하한은 **실내 기준**입니다. 같은 250 이라도 유리온실과
  부직포 하우스에서 작물이 받는 빛은 두 배 가까이 다릅니다.
- **광포화점**은 차광 임계가 아니라 프로그램의 작물 `K_L` 에서 파생합니다. 둘을 한
  값으로 두면 차광을 일찍 하려고 임계를 낮추는 순간 광합성 모델이 "빛은 이미
  충분하다" 고 판정해, 강한 햇빛 아래에서도 광 제한을 보지 못하게 됩니다. `K_L` 이 없으면 시스템 기본 600 W/m² 를
  씁니다.

### 차광막으로 더위 막기 { #shade-heat }

차광막을 치면 두 겹으로 식습니다 — 공기를 데우는 일사가 줄고, 작물의 증산이 줄어 공기가
덜 마릅니다. 그런데 빛도 빼앗고, 빛은 효과 모델이 따지는 양이 아닙니다. 맡겨 두면
제어기는 차광을 공짜 냉방으로 여깁니다. 그래서 차광막을 열·습도 조절에 써도 되는지는 한
곳(`screen_policy`)에서 정하고, 제어기는 그 답만 읽습니다. 해가 있을 때만 판단합니다(실외 일사
150 W/m² 부터, 100 아래로 내려가야 풀림 — 극한 고온 보호와 같은 선. 일사를 모르면 일출~일몰). 할 일이
없는 막은 해가 있을 때만 걷힘으로 돌아갑니다 — 밤에는 제자리입니다. 쳐 둔 막이 작물이 하늘로 식는 것을
막기 때문입니다.

**빛의 세 상태.** 막을 **다 쳤을 때** 작물이 받을 광량과 오늘의 광(DLI)을 봅니다. 오늘의 광은
지금까지 받은 것에 "해 질 때까지 막을 친 채 둔다면" 남은 하루가 줄 광을 더한 값입니다 — 시설
위치의 맑은 하늘 일사에 지난 30분의 흐린 정도, 피복재, 차광막 천을 곱합니다.

| 상태 | 언제 | 차광막은 |
|---|---|---|
| 빛 지킴 | 다 치면 **최소 광량 임계값** 아래로 가거나, 그날 광이 프로그램의 DLI 목표에 못 미친다 | 걷어 둡니다(*차광막을 걷어 둡니다*, 근거 44) |
| 빛 넉넉 | 다 쳐도 작물의 광포화점 이상이거나, 습윤형 분무의 일소 잠금이 걸릴 만큼 밝다 | 열·VPD 조절에 마음대로 씁니다(*열을 막으려 차광막을 쳤습니다*, 근거 43) |
| 그 사이 | 치면 광합성은 줄지만 그날 광은 충분하다 — DLI 목표나 광량을 모를 때도 여기 | 더 싼 수단을 다 쓴 뒤에만 씁니다. 창·팬이 모두 80 % 이상(또는 바깥이 실내 − 1 °C 보다 따뜻함) **그리고** 분무를 다 썼다(분무기 없음, 물·일소 잠금·고온 보호로 막힘, 또는 80 % 이상 가동). 그 전까지는 걷어 둡니다(근거 44) |

써도 될 때는 [온도 상한](#l3-coordinator-actuator-command) 항도 차광막을 몰아, 선을 넘은 뒤가
아니라 넘기 전에 칩니다. 덥고 마른 날의 순서는 이렇게 됩니다: 창 → (빛 넉넉 차광) → 분무 →
(그 사이 차광) → 팬 → 냉방. 이 순서는 위의 "다 썼는가" 판정이 만듭니다 — 비용으로는 만들 수
없습니다. 부하 분담은 도메인마다 따로라, 차광막에 비용을 붙여도 분무를 기다리게 할 수 없습니다.

**왕복 줄이기.** 차광막은 한 번 움직이는 데 몇 분이 걸립니다. 제어기가 시키는 이동은 거릅니다.
움직인 뒤에는 적어도 15분(또는 전 주행 시간의 세 배 중 긴 쪽) 제자리, 움직이라는 요구가 5분
이어져야 움직이고, 해가 없으면 치지 않으며, 시설 현지 날짜로 하루 8번까지만 움직입니다 — 그 뒤
남은 하루 동안 제어기의 요구는 제자리에 둡니다(*차광막을 제자리에 둡니다*, 근거 45, 로그 한 번).
해가 진 뒤 걷는 것은 횟수에 걸리지 않습니다. 최대·최소 광량 임계값, 온도 하드 한계, 극한 고온
보호, 안전 게이트, 수동 잠금, 빛 지킴이 시킨 이동은 언제나 통과합니다.

**누가 쥐는가.** 극한 고온 보호가 켜져 차광막을 쳤으면(또는 보류했으면) 보호가 주인입니다 —
이 절의 규칙을 걸지 않습니다. 보호도 빛 판단을 여기에 묻습니다 — 단계 1 에서는 빛 상태가 *빛 지킴*
(최소 광량 또는 그날 DLI)이면 치지 않고, 단계 2 거나 문턱보다 3 °C 이상 높으면 상관없이 칩니다. 최대·최소
광량 임계값과 온도 하드 한계는 이 절의 모든 것을 이깁니다.

차광막의 효과 모델은 천의 투과율 τ 를 씁니다. 막은 빛의 (1 − τ) 만 막고, 막을 열면 VPD 는
데워지는 만큼에서 **늘어난 햇빛으로 작물이 증산한 물만큼을 뺀** 만큼 오릅니다 — 온도만 오른다고
볼 때의 약 60~80 % 입니다. 계수를 손으로 맞춘 차광막(`k_override`)은 그 값을 새 단위로 읽습니다
— τ = 0.5 에서 절반으로 셉니다.

빛 상태는 바뀔 때만 로그에 남깁니다. 건강 점검은 근거 43~45 를 *차광·열부하*, *차광·빛 지킴*,
*차광·왕복 방지* 로 부릅니다.

### 보온커튼 — 밤 틈과 아침 단계 걷기 { #curtain-gap }

모터가 중간에서 멈출 수 있는 보온커튼 — 위치로 움직이고(짝 모터나 위치 출력) 전 주행 시간을
아는 커튼 — 은 열림·닫힘만이 아니라 중간도 씁니다. 나머지(릴레이 커튼, 주행 시간 없음)는 0/100
그대로입니다. 평소 제어의 명령은 어느 쪽이든 0/100 이고, 아래 두 동작만 중간에서 멈춥니다(정지점
0 · 3 · 6 · 10 · 30 · 60 · 100 %). 기록되는 값이 곧 보내는 값입니다.

**밤 보온 — 모든 보온커튼.** 밤에 집이 열을 지켜야 하면 커튼을 닫습니다: 실내가 목표 온도의 아래 선
(온도가 제어 목표면 목표 − 허용 오차, VPD 직접 모드면 유도 범위 — VPD 에서 유도한 온도 목표는 선으로 쓰지 않습니다) + 2 °C 보다 낮거나, 바깥이 그 아래 선보다 찰 때, 또는 실내 공기가 이슬점 3 °C 안으로 다가왔을 때입니다(이슬 수요: 걷힌 커튼
아래 작물은 밤하늘로 식어 공기보다 먼저 젖습니다. 시뮬레이션에서 같은 여름 저녁이 커튼이 닫히면 밤 젖음
173분, *무구배*로 걷힌 채 남으면 433분이었습니다. 이슬 수요에서는 실내가 목표 위 선을 넘어야만 식힐 일로
보고, 여유가 4 °C 위로 돌아오면 풉니다. 비가 오거나 그친 뒤 한 시간 안, 또는 바깥 RH 가 95 % 이상인 동안은 구름이 하늘 복사를 막으므로 이슬 수요를 보지 않습니다). **난방이 돌고 있으면 그것도 열 수요입니다**: 직전 사이클에 난방기가 0 보다 큰 명령을 받았고(멎은 뒤 30분까지) 바깥이 실내보다 차면 실내가 범위 한가운데여도 커튼을 닫습니다 — 그러지 않으면 난방기가 데우는 동안 걷힌 커튼이 열을 버립니다. 난방이 도는 동안에는 실내가 들어간 선보다 한참 위여도 풀지 않습니다. 판단은 목표와
실외 온도로 하고, 지금의 안팎 공기 온도차로 하지 않습니다 — 걷힌 커튼 아래 실내는 바깥을 따라가므로 그
차이가 작은 것은 커튼이 걷혀 있기 *때문*이고, 닫힌 커튼은 공기 온도차에 드러나지 않는 맑은 밤하늘로의
복사 손실도 막습니다. 실내가 목표 위 선의 1 °C 안이거나 그 위(식힐 일이 있다), 또는 바깥 공기가 실내보다
따뜻하면 평소 제어에 맡깁니다. 닫은 뒤에는 실내가 들어간 선보다 1 °C 오르고 바깥도 아래 선보다 1 °C
오르거나, 실내가 목표 위 선을 넘거나, 바깥이 실내보다 1 °C 넘게 따뜻해지면 풉니다(*밤 동안 열을 지키려고
보온커튼을 닫았습니다*, 근거 49). 릴레이 커튼도 닫습니다. 아래의 밤 틈은 닫힌 커튼을 여전히 조금 열고,
**최저 온도**·안전 게이트·해 뜰 때 걷기는 그대로입니다.

**밤 틈 — 결로는 커튼이 먼저.** 밤에 커튼이 닫혀(5 % 이하) 있고 실내 공기가 이슬점 2 °C 안으로
다가오면 커튼을 조금 엽니다: 3 %, 그다음 6 %, 그다음 10 %. 단계마다 15분 두고, 그동안 여유가
회복되기 시작하지 않았을 때만 다음 단계로 갑니다(*밤 습기를 빼려고 보온커튼을 조금 열었습니다*, 근거
46). 여유가 3 °C 위로 돌아오면 다시 닫습니다([과습 구간](#humid-zone)과 같은 선). 열이 먼저입니다:
난방이 강제되는 동안(**최저 온도**)이나, 난방기가 없는데 실내가 목표 온도 아래 선 이하면 틈을 내지
않고, 바깥이 실내보다 8 °C 넘게 차거나 난방기가 80 % 이상 돌면 첫 단계까지만 엽니다. 한파 게이트와
**최저 온도**는 이 모든 것 위에서 커튼을 닫습니다.

창의 야간 결로 탈출([환기](#settings-ventilation) 참조)은 틈을 기다립니다 — 틈을 낼 수 있는 데까지
내고 15분을 두었는데도 공기가 여전히 이슬점에 가까울 때만 허락됩니다. 중간에서 멈추는 커튼이 없거나
이 옵션을 끄면 창은 예전과 같습니다.

**아침 단계 걷기.** 해가 뜨면 밤새 닫혀 있던 커튼을 한 번에 걷지 않고 10, 30, 60, 100 % 로 걷습니다
— 커튼 위의 찬 공기가 작물 위로 내려앉지 않게 합니다. 단계마다 10분이고, 그 단계 동안 실내가 1 °C
이하로만 떨어졌고 여전히 온도 범위의 아래 끝 이상일 때만 다음 단계로 갑니다 — 뒤 조건은 처음 두 시간만 겁니다. 난방이 범위까지 못 데우는 날 커튼을 하루 내내 닫아 두지 않기 위해서입니다(*아침 찬 공기가 … 단계로 걷는
중입니다*, 근거 47). 실내가 바깥보다 5 °C 덜 따뜻하면 걱정할 찬 공기층이 없으므로 곧장 걷습니다. 그 밖의
낮 걷기는 예전과 같습니다(근거 22).

#### 효과 캘리브레이션 { #settings-calibration }

| 항목 | 기본값 | 설명 |
|------|--------|------|
| 효과 엔진 | Legacy | `Legacy`: 내장 K_* 상수(기본, 안전). `Shadow`: 그레이박스 모델을 나란히 돌려 기록만 하고 제어는 그대로. MPC 가 제어했다면 보냈을 명령과 그 예측도 함께 기록합니다. `Grey-box`: 물리 모델이 제어. 매 사이클 MPC(몇 단계 앞을 내다보는 최적화)를 먼저 시도하고, 안 되면 물리 모델 PI, 그다음 Legacy 로 물러납니다. MPC 는 앞으로의 실외를 이렇게 봅니다. 일사는 태양 위치로 계산한 맑은 날 일사에 지금의 맑음 정도를 곱해 봅니다(시설 좌표가 있으면 어느 나라든). 외기 온도·습도는 **예보가 말하는 변화량**만큼 지금 실측에서 움직입니다. 예보는 시설(기상 탭)에 연결된 Open-Meteo 시간별 예보 입력의 파일을 받은 지 2시간 이내면 그것을 씁니다 — 시설 좌표의 예보라 시간대를 따지지 않습니다. 아니면 기상청 단기예보가 발표 6시간 이내이고 시설 시간대가 같을 때 그것을 쓰고, 둘 다 없으면 지금 값 그대로 둡니다. 예보 값 자체가 아니라 변화량을 쓰는 것은 예보(넓은 격자 평균)와 이 시설 기상대의 차이를 지우기 위해서입니다. MPC 도 PI 와 **같은 판정**을 지킵니다 — 야간 닫기, 실외로는 목표에 못 가는 환기, 냉난방 가동 중 개구부 잠금, 환기 우선, 온도가 원하는 방향의 반대편 냉·난방, [과습 구간](#humid-zone)(실외가 더 습하면 닫고 열어도 되면 최대 30 %). 이 판정이 선 장치는 MPC 가 열거나 켜지 않습니다. MPC 는 창과 팬을 **풍량**으로 봅니다(창 면적, 팬 정격 풍량). 같은 환기량이면 실내가 더울 때는 천창부터, 실외가 더 더울 때는 측창부터 엽니다. 팬 풍량이 창보다 크면 팬으로 내고 창은 닫아 둡니다(창이 열리면 벽면 팬은 공기를 빼지 못합니다). 차광막과 보온커튼은 MPC 가 움직이지 않고 지금 위치를 예측에 반영합니다 — 보온커튼을 치면 외피 열손실이 줄어드는 것까지 계산합니다. 권장 순서는 Shadow 다음 Grey-box. 쌓인 데이터와 성적은 앱·데몬을 다시 시작해도 이어집니다(주기를 바꾸거나 일주일 넘게 멈춰 있었으면 처음부터 다시 쌓습니다). 물리 모델은 **Shadow 로 쌓인 데이터로 학습하고, 10사이클 앞을 예측해 "지금 값 그대로" 라는 단순 예측보다 나을 때만** Grey-box 제어가 켜집니다. 이 비교는 기상 구간(더운 낮·온화한 낮·일출·일몰·밤 등)마다 따로 하며, 표본이 충분히 모인 모든 구간에서 나아야 하고 그런 구간이 2개 이상이어야 합니다 — 그 전에는 Legacy 로 돕니다. 모델의 물리식이 바뀌는 업데이트 뒤에는 이 학습과 검증을 새 식으로 다시 합니다. Shadow 나 Grey-box 를 고른 동안에는 이 나란한 계산이 계속 돌아야 그 학습이 진행됩니다 — 3사이클 연속 실패하면 로그에 적고, 그 뒤에는 60사이클마다 한 번 더 적습니다. 멈춘 것을 모르고 지나치지 않게 하기 위해서입니다. [극한 고온 보호](#heat-protect) 중인 사이클은 Legacy 로 돕니다(MPC 는 그 규칙을 모릅니다). 부하 분담에서 뺀 [의심 액추에이터](#actuators-suspected)가 있는 사이클도 마찬가지이고, 실내 온도나 습도(CO₂ 목표가 있으면 CO₂ 도)를 잴 수 없는 사이클도 그렇습니다 — MPC 가 지어낸 값으로 최적화하게 되기 때문이며, 사유가 바뀔 때와 이어지는 동안 한 시간마다 로그에 남깁니다. 시험 중이 아니면 바꿀 이유가 없습니다. |
| RLS 캘리브레이션 사용 | 꺼짐 | 장치마다, 내장 모델이 예측한 것보다 실제로 각 값(온도·습도·CO₂)을 얼마나 세게 움직이는지를 **배율**로 배웁니다(1.0 = 모델 그대로). 모델의 조건 계산(실내외 차·풍속·면적)은 그대로 두고 크기만 고칩니다. 그 장치만 명령이 바뀐 사이클에서만 배웁니다 — 다른 장치가 같이 움직이면 누구 몫인지 가를 수 없기 때문입니다. 며칠 치 데이터가 필요하고, 그때까지는 모델을 그대로 씁니다. |
| 능동 프로빙 사용 | 꺼짐 | 캘리브레이션 식별성을 높이려고 주기적으로 한 액추에이터를 ±10 % 흔듭니다. 부하가 낮고 안전 게이트가 없을 때만 발동하며, 순환팬은 대상으로 고르지 않습니다. RLS 캘리브레이션이 필요합니다. |

|------|--------|------|
| 예보 피드포워드 사용 | 꺼짐 | 단기 기상 예보로 온·습도 setpoint 를 악천후가 닿기 전에 미리 옮깁니다. 예보가 지금 실내 온도보다 3 °C 이상 높으면 온도 목표를 1.5 °C 내리고, 3 °C 이상 낮으면 1.0 °C 올리고, 예보 습도가 85 %RH 를 넘으면 습도 목표를 5 %RH 내립니다. 옮긴 목표도 정해 둔 범위 안에 머뭅니다. 예보의 비·강풍은 판단 요약에 함께 표시되지만 그것만으로 개구부를 닫지는 않습니다 — 닫는 것은 실측 풍속·강우입니다. |
| 예보 선행 시간 (시간) | 3 | 몇 시간 앞까지 볼지. 단계: 짧게(1) / 표준(3) / 길게(6). 길수록 일찍 알지만 과보정할 수 있습니다. 시간은 **지금부터** 셉니다 — 예보 파일이 늦게 갱신돼도 이미 지난 시간대의 예보는 보지 않고, 앞으로 올 시간이 파일에 없으면 보정하지 않습니다. 시설에 연결된 예보 입력이 Open-Meteo 시간별 예보 하나뿐이고 그 파일을 받은 지 2시간 이내면, 이 시간만큼을 그 파일에서 읽습니다(기온 최고·최저, 습도·풍속 최대). 이때 강수확률 50 % 이상은 같은 시간 안 시간당 강수가 0.5 mm/h 에 이를 때만 비로 봅니다 — 강수량이 없으면 확률만으로는 보지 않습니다. 그 밖에 시설에 예보 공급원이 연결돼 있으면 그 값을 그대로 쓰고 이 값은 쓰지 않습니다. 둘 중 하나만 쓰고 함께 쓰지 않습니다. |

> **디버그 로깅은 더 이상 별도 옵션이 아닙니다.** 프레임워크의 디버그 스위치와
> 같은 스위치가 둘이던 상태였고, 이 옵션이 감싸던 것은 거의 전부 DEBUG 레벨이라
> 혼자서는 아무것도 출력하지 않았습니다. 이제 함수 고급 설정의 스위치 하나가 둘 다
> 합니다. 중요 사건 — 안전 게이트, 디스패치 실패, 런타임 상태 오류 — 은 이 값과
> 무관하게 항상 기록됩니다.

## 액추에이터 등록 { #actuators }

연동 시설 도면에 그려진 액추에이터는 자동으로 찾습니다. 그 밖의 장치는 이 함수에
**환경 제어(Environment Control)** 액션으로 등록하고, 장치마다 액션을 하나씩
추가합니다. 수동 액션은 시설에서 찾은 목록과 병합됩니다.

페어드 액추에이터 모듈도 자동으로 찾지만 **연동 시설에 속한 것만** 찾습니다. 시설의
슬롯에 묶여 있거나 시설 지도에 올라 있어야 합니다. 어느 시설도 쓰지 않고 지도에도
없는 모듈(시험용, 연결이 모두 끝난 장치)과 다른 시설에 속한 모듈은 무시합니다.
여러 층 구조 모형의 위층에 있는 장치도 같은 식으로 빠지고 '자동 제어 대상 장치'
목록에도 나오지 않습니다 — 이 코디네이터는 층을 모르므로 그 장치의 센서도
액추에이터도 제어에 들지 않고, 화면과 수동 조작에는 계속 나옵니다
([시설 — 평면 그리기](../geo/facility.md#plan-drawing) 참조). '자동 제어 대상
장치'에서 끈 장치는 어떤 경로로 찾아져도 꺼진 채로 둡니다. 팬의 정격 풍량은
액추에이터의 *풍량* 사양 또는 팬 피팅의 풍량에서 읽고, 둘 다 없으면 기본값(배기·흡기팬
3000 m³/h, 유동팬 1500 m³/h)을 씁니다.

| 액션 옵션 | 기본값 | 설명 |
|-----------|--------|------|
| Output 채널 | — | 제어할 Output 채널. |
| 액추에이터 종류 | — | 개구부 · 냉방기 · 난방기 · 분무기/가습기 · CO₂ 주입기 · 차광막 · 보온커튼 · 보광등 · 유동팬 · 배기팬 · 흡기팬. |
| 비용 지수 | 5.0 | 낮을수록 우선(1 = 공짜인 자연 환기, 10 = 비싼 장치). 여기에 장치의 에너지 비용(kW × 개도)이 더해집니다. kW 는 출력 채널의 **전기소모량(A) × 시스템 사용 전압**을 먼저 쓰고, 없으면 시설 도면의 정격, 그것도 없으면 종류별 기본값을 씁니다. 사용 전압은 시스템 설정에 있고 기본이 120 V 라, 220 V 설치는 맞춰 두어야 합니다. |
| 시간창 종료 시 동작 | 아무것도 안 함 | 제어 시간창이 끝날 때 이 액추에이터가 할 일: 아무것도 안 함 / 끄기 / 켜기 / 개도 % 지정(개구부 전용). |
| 종료 개도 % | 0 | 그 순간의 목표 개도(개구부 전용). |
| 차광포 투과율 개별 지정 (0–1, 차광막 전용) | 0 | 이 차광막의 천이 다른 것과 다를 때만. 0 으로 두면 연동 시설 값을 씁니다. 실내 광 센서가 없을 때 쓰는 값입니다 — 그때는 실외 일사와 차광막 위치로 실내 광량을 추정합니다. |
| 효과 계수 개별 지정 (K_*) | 0 | 0 = 기본값 사용. 실측 데이터로 보정할 때만 입력합니다. |

### 디바이스 타입별 자동 변환 { #actuators-adapters }

명령은 언제나 0–100 % 로 산출됩니다. 어댑터는 Output 모듈의 메타데이터에서 정해지고
별도 설정이 없습니다.

| Output 타입 | 어댑터 | 변환 |
|-------------|--------|------|
| 페어(정/역) 액추에이터 모듈 | Paired | 정/역 페어 변환, 모듈 내부에서 처리 |
| 스스로 위치를 잡는 `value` 출력(Matter 커튼·블라인드·전동 환기창) | Paired | 0–100 % 를 목표 위치로 전달, 0 % 는 정지가 아니라 완전히 닫기 |
| `vol` / `volume` (용량형 펌프) | Volumetric | `vol_ml = flow_lpm × on_sec / 60 × 1000` |
| `pwm` | PWM | duty = pct |
| `on_off` 릴레이 | 시간 비례 | `on_sec = cycle_sec × pct/100`, 5 % 미만은 OFF |
| 그 밖 | Value | 0–100 % 직접 전달(DAC, 스텝모터) |

| 명령 (%) | on/off 릴레이 (60초 사이클) | PWM | 용량형 펌프 (1.5 L/min) |
|---:|---|---|---|
| 0 | OFF | duty 0 | OFF |
| 30 | ON 18초 | duty 30 | 450 mL/사이클 |
| 100 | ON 60초 (상시) | duty 100 | 1,500 mL/사이클 |

**스크린.** 차광막과 보온커튼은 어떤 어댑터로 구동하든 완전히 열거나 완전히 닫습니다([L3](#l3-coordinator-actuator-command)).
예외는 위치로 구동하는 스크린 — 페어 모터나 위치 출력이면서 전 행정 시간을 아는 것입니다. 보온커튼의 밤 틈과 아침 단계 걷기는 그런 스크린을 중간에 세우며(3
· 6 · 10 · 30 · 60 %, [보온커튼 — 밤 틈과 아침 단계 걷기](#curtain-gap) 참조) 기록에는 실제로 보낸 값이 그대로 남습니다. 릴레이나
PWM 스크린은 늘 0/100 입니다.

습윤형 분무기는 여기에 펄스 도징이 한 겹 더 씌워집니다 — 1회 분무를 최대 작동 시간에서
끊고, 건조 간격이 지나기 전까지는 아무 명령이 와도 뿌리지 않습니다. [극한 고온·건조의 짧은 펄스](#pulse-fog)
(근거 57) 하나는 이 도징을 더 조인 상한 — 최대 10초 켬, 최소 15분 쉼(쉼은 코디네이터가 잼) — 으로 씁니다.
건조 간격은 코디네이터가 설정과 장치를 다시 읽을 때(10분마다, 또는 다시 불러오기) 이어집니다 —
방금 뿌린 분무기가 다시 읽은 직후에 또 뿌리지 않습니다. 건조 간격을 줄이면 새 값이 마지막 분무부터
바로 적용되고, 늘리면 지금의 쉼도 늘어납니다. 코디네이터를 재시작하면 간격은 처음부터 셉니다.
건조 간격은 두 분무의 *시작* 사이 간격으로 봅니다(사이클 흔들림 몇 초 허용, 최대 간격의 10분의 1) —
그래서 주기 600초에 간격 600초면 한 사이클 건너가 아니라 매 사이클 뿌립니다. 근거 57 펄스 뒤의 15분 쉼에는 이 허용이 없습니다.

관수 유량은 시설 도면에서 집계합니다 — 한 레이어에 딸린 모든 emitter 유량을 합해 그
액추에이터의 `flow_lpm` 으로 두고, 용량형 어댑터가 그 값을 그대로 씁니다. 없을 때의
우선순위는 액추에이터별 유량 → 시설 전체 합계 → 1.0 L/min 입니다.

포그 효과 모델은 **다른** 유량을 씁니다 — 그 액추에이터의 드립이 아닌 분사 노즐 유량만
보고, 폴백하지 않습니다. 투여량에는 뿌리로 가는 드립이 들어가야 하지만, 공기 중으로
증발하는 양에는 들어가지 않기 때문입니다. 그래서 도면에 노즐 정보가 없는 분무기는
시설 합계를 물려받는 대신 냉각·가습 효과가 아예 없는 것으로 계산됩니다.

### 과습 구간과 반응 없는 창 { #humid-zone }

공기가 포화에 가까우면 VPD 로 환기를 판단하는 방식이 틀립니다. VPD 는 온도에 끌려다니는
양이라, 실외가 더 따뜻하면 수분이 훨씬 많아도 실외 VPD 가 더 높게 나옵니다. 그러면
"열면 건조해진다" 로 읽고 습한 공기를 들이게 됩니다. 그래서 **실내 VPD 가 0.3 kPa 보다
낮거나 이슬점 여유(온도 − 이슬점)가 2 °C 보다 작으면** 환기를 수증기압(이슬점)으로
판단합니다. 나오는 문턱은 VPD 0.4 kPa, 여유 3 °C 로 더 높습니다.

| 실외 이슬점 | 창이 하는 일 | 화면 문구 |
|---|---|---|
| 실내보다 **8 °C 넘게 차다**, 또는 **실내가 온도 기준선 이하**이거나 난방 요구 중(최저 온도 한계 포함)인데 실외가 1 °C 넘게 더 차다 | 이슬점과 상관없이 열지 않고 **닫는 쪽**으로 갑니다. 온도가 이슬점 판단을 이깁니다 — 열어서 잃는 열(겨울 난방 중)이 습기 제거보다 큽니다. 예외: 아래 [습기 빼기](#morning-purge) | 과습 — 실외 너무 참 |
| 실내보다 1.5 °C 이상 낮다 (이미 열려 있으면 0.75 °C) | 열되 **최대 30 %** 까지만. 습기를 빼는 것이 목적입니다. 예외: 아래 *열림 상한 풀기* | 과습 — 열림 제한 |
| 그보다 덜 낮거나 더 높다 | 열지 않고 **닫는 쪽**으로 갑니다. 창으로는 해소할 수 없습니다 | 과습 — 환기로 해소 불가 |

- **온도 기준선**은 온도가 제어 목표면 목표 + 허용오차이고, **VPD 직접 모드면 유도 범위의 아래 끝**입니다.
  VPD 직접 모드의 유도 온도 목표는 지금 실내보다 늘 앞서 있어서(습할수록 더 멀리) 그것을 기준으로 삼으면
  실외가 1 °C 만 차가워도 *실외 너무 참* 으로 닫혔습니다 — 김제 10월 13일 12:48~15:59 에 실내 RH 82~91 %,
  실외는 기온이 거의 같고 이슬점이 3~4 °C 낮은데도 측창이 6~30 % 에 머물고 두 번 닫혔습니다. 이제 이 모드에서는
  실내가 유도 범위의 아래 끝보다 낮을 때만 난방 요구로 읽습니다([습기 빼기](#morning-purge) 의 온도 하한과 같은 선).
  유도 목표에서 나온 '난방 요구' 는 이 판정에 쓰지 않습니다. 최저 온도 한계의 강제 난방은 그대로 닫습니다.
- 온도 비상(폭염)이나 온도 상한 항이 서 있으면 이 구간을 적용하지 않습니다 — 덥고 습한 날의
  환기는 습도가 아니라 온도가 요구합니다.
- 하드 습도 상한을 넘었으면 열림 상한을 풉니다. 다만 실외가 더 습하면 여전히 열지 않습니다.
- **열림 상한 풀기.** 30 % 상한의 뜻은 "열어서 온도·VPD 를 맞추지 않는다" 이지 "습기를 덜 뺀다" 가 아닙니다. 실외가
  **거의 같은 온도 이상**(실내 − 2 °C 이상)이고 **이슬점이 3 °C 이상 낮으면**(플레인 문턱 1.5 °C 의 두 배) 더 열수록 습기가
  더 빠지고 열 손실은 늘지 않으므로 상한 없이 열립니다. 이미 풀려 있었다면 온도 3 °C · 이슬점 2 °C 로 완화돼 경계에서
  오르내리지 않습니다. 실외가 그보다 차갑거나 덜 건조하면 종전처럼 30 % 입니다.
- 실외 값을 모르면 이 구간이 판단하지 않습니다(실외 값 없음 규칙이 맡습니다).
- 난방·제습 장치가 없는 시설에서는 창으로 해소할 수 없는 과습을 풀 수단이 없습니다.
  화면이 그 사실을 그대로 보여 줍니다.

**열어도 편차가 줄지 않는 창은 더 열지 않습니다.** 효과가 작은 창(유효도 0.06 미만)이 10 % 이상
열려 있는데 45분 동안 편차가 10 % 도 좁혀지지 않으면 더 열지 않고 제자리에 둡니다. 열어도
실내가 안 변하는 동안 제어가 "더 열어라" 를 쌓아 창이 천천히 100 % 로 올라가는 것(드리프트)을
막습니다. 편차가 다시 좁혀지면 이어 갑니다. 효과가 큰 창은 해당하지 않습니다 — 해가 강해져
편차가 커지는 경우에는 더 열어야 합니다. (효과가 큰 창이 몇 시간째 활짝 열려 있는데도 전혀 반응이 없는 것은 다른 경우입니다 — [의심 액추에이터](#actuators-suspected) 참조.)

**작은 VPD 차이로는 창을 움직이지 않습니다.** 환기 무익 판정이 "실외가 실내와 다르다" 의
문턱을 허용오차(기본 0.1 kPa)가 아니라 **0.25 kPa** 로 잡습니다. RH 1~2 %p 의 센서 잡음
안에 드는 차이로는 열지 않습니다.

**무익 판정은 문턱에서 뒤집히지 않고, 열린 창은 바로 깎이지 않습니다.** 새로 무익이 되려면 차이가 문턱의
60 %(0.15 kPa) 아래로 내려가야 하고, 무익에서 나오려면 문턱(0.25 kPa) 이상으로 회복돼야 합니다.
열려 있는 창은 무익 판정이 **20분** 이어질 때까지 제자리에 두고, 그 뒤부터 닫는 쪽으로 감쇠합니다.
닫혀 있던 창은 바로 파킹합니다.

**실외 온습도는 10분 이동평균으로 판단합니다.** 정수 단위 값이 몇 시간마다 바뀌며 판정을
뒤집지 않게 합니다. 강우·풍속 같은 안전 게이트는 평균하지 않은 원본을 봅니다.

### 과습한 아침의 습기 빼기 { #morning-purge }

해가 나는 아침에는 위 표의 *실외 너무 참* 줄이 집을 RH 90 % 이상으로 몇 시간씩 닫아 둘 수 있습니다 — 해가 공짜 열로
집을 데우고 바깥 공기가 더 건조한데도 그렇습니다(잿빛곰팡이 위험). 영양, 10월 10일: 07:00~09:30 에 해가 집을 9.5 →
22.9 °C 로 데우는 동안 RH 91 % 인 채 창은 0 % 였습니다. 그래서 해가 집을 데우는 동안에는 창을 파킹하는 대신
**5~15 % 의 작은 최소 열림**(근거 54)을 줍니다.

| 조건 | 값 |
|---|---|
| 해 | 실외 일사 100 W/m² 이상(70 미만에서 풀림) — [햇빛 열 빼기](#solar-vent) 와 같은 값 |
| 과습 | 실내가 위의 과습 구간 안(들어가고 나오는 문턱도 같음) |
| 바깥이 더 건조 | 실내 이슬점이 실외보다 2 °C 이상 높음(이미 빼는 중이면 1 °C) — 수증기압으로 판단하므로, 따뜻해서 VPD 는 높아도 수분이 더 많은 바깥 공기는 해당하지 않음 |
| 열 손실이 작음 | 실내가 온도 목표의 아래 선(목표 − 허용오차) 아래로 1 °C 이내. 3 °C 아래까지는 집이 데워지는 중(사이클 사이로 잰 0.5 °C/h 초과)일 때만. 그보다 아래, 최저 온도 한계로 강제 난방 중, 바깥이 실내보다 15 °C 넘게 찰 때, 아래 선 아래에서 1 °C/h 보다 빨리 식을 때는 하지 않음 |
| 열림 | 5 % 에 최대 10 % 를 더함 — RH 가 85 % 를 넘은 만큼과 일사(문턱 위 400 W/m² 이면 최대)에 따라 커짐. 아래 선보다 1 °C 넘게 낮으면 5 % 만 |

습기 빼기는 창을 그 열림까지 **올려 둘 뿐**, VPD 나 온도를 좇아 더 열지 않습니다(그건 제어기와 햇빛 열 규칙의 몫).
적분도 그 자리에 묶이므로 풀릴 때 창이 한 번에 닫히지 않습니다. 실내가 과습 구간을 나가거나, 해가 약해지거나, 바깥이
더 건조하지 않게 되거나, 집이 식으면 풀립니다. 앞서는 판정: 강우·풍속 게이트, [강우 단계 제한](#safety-gates)(근거 52 — 습기 빼기는 창을 비 상한 위로 올리지 않습니다: 닫은 천창은 닫힌 채, 상한이 걸린 측창은 30 % 이하로), 실외 값 없음, 강우·풍속을 잃음, 야간
파킹과 그 직전 45분, 냉난방 연동, 극한 고온 보호의 '바깥이 더 덥다'. *실외 너무 참*·*구동력 없음*·환기 무익을 이기며,
햇빛 열 최소 열림(근거 51)이 더 크면 그쪽 문구가 남습니다. 팝업은 *밤새 쌓인 습기를 빼려고 조금 열어 둠 — 해가 집을
데우고 바깥 공기가 더 건조함* 이고, 시작과 끝은 로그에 한 줄씩 남습니다. 값은 고정이며 옵션이 아닙니다. 규칙 기반 제어
(Legacy 와 물리 모델 PI)에 적용되고 MPC 는 적용하지 않습니다.

### 이슬 맺히는 밤의 순환팬 { #night-dew-fan }

열대야에는 실외 이슬점이 실내보다 높게 남아, 창을 열면 습기가 빠지는 게 아니라 들어옵니다. 집은 닫힌 채
공기가 포화에 가깝고 작물은 아침까지 젖어 있습니다 — 폐루프 `heatwave_tropical_night`(3일, 밤 RH 90 % 이상)에서
밤 1148분이 젖어 있었습니다. 잎은 바람 없는 공기에서 가장 오래 젖습니다: 두꺼운 경계층이 증발을 늦추고 잎이
공기보다 식어 이슬이 맺힙니다. 공기를 움직이면 경계층이 얇아져 잎이 더 빨리 마르고 이슬이 덜 맺힙니다.
집 안의 습기를 빼는 것이 아니라 **잎이 젖어 있는 시간을 줄이는** 수단입니다.

**순환팬**이 등록돼 있고 **고급 옵션 *밤 이슬 순환팬(실험)* 을 켰으면**(**기본 꺼짐**) 아래 둘이 함께 설 때 팬을 **100 %**(근거 59)로 돌립니다:

| 조건 | 값 |
|---|---|
| 밤 | 시설 위치의 일몰~일출. 위치를 모르면 아무것도 하지 않습니다 |
| 이슬점 여유가 작다 | 실내 온도 − 이슬점이 **2 °C** 미만. **3 °C** 에서 풀리고, 켠 뒤 30분은 끄지 않습니다. [과습 구간](#humid-zone)·밤 [커튼 틈](#curtain-gap) 과 같은 문턱입니다 |

15분 켜고 15분 끄는 듀티가 아니라 연속입니다: 효과가 공기가 움직이는 시간에 비례하고(팬이 서면 경계층은 몇 분
안에 다시 두꺼워집니다), 듀티는 5~10분 주기를 넘는 별도 기억이 필요하며, 순환팬은 가장 싼 장치이고 이 규칙은
여유가 작을 때만 서기 때문입니다. 순환팬이 없는 시설은 달라지지 않습니다. [극한 고온 보호](#heat-protect)와
공간 센서가 찾은 핫스팟은 각자의 근거(1)로 팬을 100 % 로 돌리고, 서리 보호([서리](#frost), 근거 56)도 100 % 로
둡니다 — 그쪽이 항상 이깁니다. 팝업에는 *순환팬 가동 — 밤 공기가 이슬점에 가까워 공기를 움직이면 잎이 젖어
있는 시간이 줄어듭니다* 로 보이고(번역), 팬이 서고 멈출 때 로그가 한 줄 남습니다. 문턱 값은 고정이며 옵션이 아닙니다(켜고 끄는 스위치만 옵션입니다).

**기본이 꺼짐인 이유.** 가상 순환팬을 단 폐루프 `heatwave_tropical_night` 에서 이 규칙은 밤 젖음 분을 그대로 두고(918) 팬 전력만 17 %, 피복 결로를 80분 늘렸습니다 — 열대야의 닫힌 집은 공기를 움직이는 것만으로 잎을 이슬점 위로 올리지 못합니다. 시험용으로 남겨 두며, 아래 건강 점검의 밤 이슬·서리 시간은 이 옵션과 무관하게 셉니다.

건강 점검(`check_env_coordinator_health`)은 실내 온·습도 센서로 기간의 **밤 이슬 분**(밤이면서 실내 RH ≥ 95 % 이거나
이슬점 여유 1 °C 미만)과 **실내 0 °C 이하 분**도 서리 주의·보호 분 옆에 냅니다. 밤 이슬이 밤의 4분의 1 이상(그리고
60분 이상)이거나, 실내 서리가 15분 이상, 서리 보호가 60분 이상이면 시설 권고 한 줄 — *제습기·보온커튼·난방 검토*
(순환팬·난방기가 없으면 그 사실도) — 을 더합니다. 시설 몫이라 종료 코드의 결함으로 세지 않습니다.

### 측정이 없는 축, 장치가 없는 축 { #actuators-missing }

시설마다 갖춘 장치가 다릅니다. 잴 수는 있는데 움직일 수단이 없는 축, 반대로 움직일
수는 있는데 잴 수단이 없는 축이 모두 정상 구성입니다. 코디네이터는 그 조합을 보고
스스로 다르게 움직입니다.

| 상황 | 코디네이터가 하는 일 |
|------|----------------------|
| 잴 수는 있는데 그 축을 움직일 장치가 없다 | 그 값은 **참고값**입니다. 제어 대상에서 빠지고(실외값이 있으면 그 축의 목표를 실외값으로 바꿔 둡니다), 광합성 판정이나 다른 축의 계산에는 그대로 쓰입니다. 목표를 벗어난 채 머물면 시설 팝업이 *움직일 장치가 없습니다* 라고 말합니다. |
| 한 방향만 있다 (난방만 있고 냉방은 없다) | 정상입니다. 그 방향의 요구가 오면 일하고, 반대 방향이면 0 % 로 쉽니다. |
| 장치는 있는데 그 축을 잴 수 없다 | 그 장치가 미는 다른 축을 잴 수 있으면 그 축으로 계속 제어합니다(예: 습도는 못 재도 온도는 재는 개구부). 미는 축을 **하나도** 잴 수 없을 때만 **제자리**에 섭니다 — 실제로 나간 개도 그대로라 풍향 가중치가 조금씩 닫지 않습니다. 편차를 모르는데 움직이면 근거 없이 장비를 쓰는 것이고, 닫거나 여는 것도 결정이기 때문입니다. 하나의 예외는 맑은 날의 환기입니다 — 닫힌 창을 그대로 두는 것 자체가 집을 덥히기 때문입니다: [맑은 날 실내 값이 끊겼을 때](#solar-vent-blind)(근거 60). |
| 실내 온도·습도를 잴 수 없다 | 그 축이 통째로 제어에서 빠집니다. 없는 값을 0 으로 지어내지 않습니다 — 그러면 "실내 0 °C" 로 읽혀 난방이 최대로 돕니다. 잎을 적시는 분무는 습도를 모르는 동안 잠깁니다. VPD 목표가 있는데 습도를 잃으면 온도·습도로는 VPD 도 계산할 수 없습니다. 센서가 자기 VPD 를 내주면 그것이 대신하고, 그렇지 않으면 그 사이클은 온도·습도 기준으로 물러납니다 — 창·난방·냉방은 온도로 계속 움직이고, 로그의 빠진 항목에 *vpd* 가 그 설명과 함께 남습니다. |

함수 설정 맨 위의 **조절 가능** 줄이 이 조합을 축마다 한 단어로 보여 줍니다
(온도·습도·VPD·CO₂·광량). 장치 구성과 이번 사이클에 잰 값으로 코디네이터가 계산한
것이고, 단어에 마우스를 올리면 그 축을 움직이는 장치 이름이 보입니다.

| 표시 | 뜻 |
|------|----|
| 양방향 | 잴 수 있고, 올리는 장치와 내리는 장치가 모두 있습니다. |
| 올리기만 / 내리기만 | 잴 수 있고, 한 방향 장치만 있습니다. |
| 보기만 | 잴 수는 있는데 움직일 장치가 없습니다(참고값). |
| 센서 없음 | 그 축을 직접 움직이는 장치는 있는데 잴 수 없습니다. |

장치도 센서도 없는 축은 표시하지 않습니다. 창이 CO₂ 를 조금 내리는 것처럼 **부수
효과로만** 움직이는 축은, 센서가 없으면 역시 표시하지 않습니다. VPD 는 온도와 습도
양쪽 장치를 함께 봅니다 — 가습 분무는 VPD 를 내리고, 환기는 실외가 건조하면 VPD 를
올립니다. 이 줄은 지금은 **표시 전용**이고, 제어는 위 표의 규칙대로 돕니다.

**안전 게이트도 같은 규칙입니다.** 실내 값을 잃으면 게이트가 그 사실에 이름을
붙여 화면과 로그에 남기지만, **강제 명령은 만들지 않습니다.** 모든 장치를
안전 기본 위치로 모는 것(개구부는 닫히고 스크린은 걷힘)은 근거가 없다는 이유로
장비를 움직이는 것이기 때문입니다. 실외 값을 잃었을 때와 같은
판단이고, 제어를 통째로 멈추지도 않습니다: CO₂ 나 광량처럼 아직 잴 수 있는
축은 계속 제어합니다.

⚠ 비바람처럼 **실외만으로 판단할 수 있는 위험은 그대로 막습니다.** 반대로
폭염·한파는 실내 온도를 모르면 판정하지 않습니다 — 그 게이트는 전 장비를
한쪽으로 몰기 때문에 근거가 확실할 때만 서야 합니다.

어긋난 조합은 건강 점검이 함께 알려 줍니다:

```bash
python3 -m aot.scripts.check_env_coordinator_health
```

목표는 있는데 측정이 없는 경우, 목표는 있는데 장치가 없는 경우, 장치는 있는데 그
장치가 미는 축을 하나도 못 재는 경우를 **설정 점검**에 보고합니다. 측정만 있고
목표도 장치도 없는 축은 보고하지 않습니다 — 그것이 곧 참고값입니다.

### 의심 액추에이터 { #actuators-suspected }

계속 실패하거나 아무 일도 안 하는 것 같은 장치에 명령을 계속 쌓으면 안 됩니다 —
적분이 와인드업하고, 코디네이터가 그 장치가 하고 있다고 *믿는* 몫이 부하 분담 장부에
남아 나머지 장치가 덜 일합니다. 그래서 **의심** 액추에이터는 부하 분담에서 빼고 선 자리에
그대로 둡니다.

의심이 되는 길은 둘입니다.

| 길 | 조건 |
|---|---|
| 전송이 계속 실패 | 5사이클 연속 실패 **그리고** 첫 실패에서 4분 이상. 한 번이라도 성공하면 처음부터 셉니다. 몇 주에 걸쳐 흩어진 실패는 해당하지 않습니다(학습 가중치용 누적 횟수는 다른 숫자이고 여기서는 읽지 않습니다). |
| 세게 명령했는데 반응 없음 (환기 장치만) | 위 *열어도 편차가 줄지 않는 창* 과 같은 판정을 반대 대역에 적용합니다. 모델이 **효과가 뚜렷하다**고 하는(유효도 0.06 이상) 환기 장치가 직전 명령 **80 % 이상**이고 실외 값을 아는데, **2시간 동안 편차가 10 % 도 좁혀지지 않았고** — **그리고** 지금 명령된 환기 효과의 80 % 이상을 이 장치 혼자 내고 있으며(여러 창이 함께 활짝 열렸는데 안 나아지면 원인은 창 하나가 아니라 공통입니다 — 열린 루프 센서·센서 고장·용량 부족) — **그리고** 다른 환기 장치가 남을 때. 이 길로는 도메인당 한 번에 한 장치만 빼고, 다음은 6시간 뒤에야 뺍니다. |

의심인 동안 그 장치는 *이 장치는 고장으로 의심됩니다*(근거 42)로 표시되고, 명령은 마지막
위치 그대로이며 **전송하지 않고**, 적분은 그대로 두며, 장부에는 아무것도 올리지 않습니다 —
같은 도메인의 나머지가 그 몫을 이어받습니다. 안전 게이트·하드 임계·극한 고온 보호는 이 근거가
아니므로 여전히 그 장치에 닿습니다. Grey-box 를 골랐어도 의심 장치가 있는 사이클은 Legacy 로
돕니다(MPC 는 이 규칙을 모릅니다).

**30분** 뒤에 자동으로 풀려 다시 시도합니다. 풀린 직후에는 전송이 연속 두 번(다섯 번이 아니라)
실패해도 곧바로 다시 빠지고, 한 번 성공하면 시험이 끝납니다. 저장하지 않으므로 재시작하면
모든 의심이 풀립니다.

장치가 의심이 될 때와 풀릴 때 한 번씩 로그에 남습니다(바뀔 때만, 사유와 함께). 채널 93 에는
보류 중인 수를 남기고(하나라도 있는 동안, 끝날 때 0 한 번), 건강 점검은 보류 분·장치·사이클을
말합니다 — 거기 나오면 사람이 그 장치를 봐야 합니다. 채널 73(*신뢰도 낮은 액추에이터*, 디버그
전용)은 다른 숫자입니다 — 학습 가중치를 따르며 장치를 제어에서 빼는 근거가 아닙니다.

### 안전 기본 위치 { #actuators-safe-default }

각 액추에이터에는 안전 게이트 발동, 긴급 정지, 외부 `force_safe_state()` 호출 시
이동할 안전 위치가 있습니다. 이 위치는 장치 종류를 따릅니다 — 보온커튼과 차광막은
100 % 로 파킹하고, 나머지는 0(끔)입니다. 시설 도면에서 찾은 액추에이터든 액션으로
등록한 액추에이터든 같습니다.

## Method (제어 곡선) { #methods-setpoint-curves }

Method 는 setpoint 가 시간에 따라 어떻게 변하는지 정의합니다. Method 는 이 함수가
아니라 **프로그램의 목표 항목**에 붙습니다 — 곡선이 걸린 항목은 구획 화면에
*곡선을 따름* 으로 표시되고 숫자로 덮을 수 없습니다.

- **Daily** — 시각(HH:MM)별 setpoint
- **Duration** — 시작 후 경과 시간(h)별
- **Daily Bezier** — 부드러운 일주 곡선
- **Repeating** — 반복 패턴

생육 주차로 진행하는 곡선은 구획 시작일을 기준으로 계산합니다. 날짜만 있는 값은 시설
현지 시간대의 자정으로 읽고, 주차는 구획 화면·구획 일지와 같은 계산을 씁니다.

**작물 단계 스케줄 예시(토마토):**

| 일차 | VPD 목표 | CO₂ 목표 |
|------|---------|---------|
| 파종~7일 | 0.6 kPa | 800 ppm |
| 8~21일 | 0.8 kPa | 900 ppm |
| 22~42일 | 1.0 kPa | 1000 ppm |
| 43일~ | 1.3 kPa | 1000 ppm |

`SEED:` 로 시작하는 Method 는 시드 프리셋이라 읽기 전용입니다. 편집하려면 복제한 뒤
수정하세요.

## 극한 고온 보호 { #heat-protect }

작물이 오래 견디지 못하는 온도를 넘으면 목표가 바뀝니다 — 설정값을 쫓는 것보다
작물의 고온·수분 스트레스를 막는 것이 먼저입니다. **극한 고온 보호** 가 그 일을
합니다. 기본으로 켜져 있고, 작물마다 다르므로 문턱은 [목표와 성향](#settings-target)
의 설정입니다(기본 30 °C).

**언제 서고 언제 풀리나.** 걸러진 실내 **평균** 온도로 판정합니다 — 가장 더운 센서로
재면 30 °C 에서 너무 자주 섭니다.

| 단계 | 시작 | 해제 |
|---|---|---|
| 1 — 보호 | 실내가 문턱 이상으로 3분 이어지거나, 다음 판단 시점의 예상 온도(현재 + 상승률 × 주기)가 문턱보다 1 °C 이상 높을 때 | 실내가 문턱보다 해제 여유(기본 1.5 °C) 이상 낮은 상태로 10분 이어지고 **그리고** 최소 유지(기본 20분)가 지났을 때 |
| 2 — 심각 | **최고 온도** 하드 임계를 넘었을 때(난방을 끄고 차광막을 치는 그 래치) | 하드 임계가 풀리면 — 그 뒤로는 단계 1 규칙 |

실내 값이 끊기면 보호를 새로 시작하지 않습니다. 이미 켜져 있었으면 최대 30분 유지하고
(차광은 그대로, 난방은 끈 채, 분무는 멈추고, 창은 제자리) 그 뒤 풉니다. [서리](#frost)와는 함께 서지
않습니다 — 서리 단계가 서 있는 동안 고온 보호는 풀리고 시작하지 않습니다.

**무엇을 하나** — 위 줄이 아래 줄을 이깁니다.

1. 강우·강풍 폐쇄가 여전히 이깁니다. 안전 게이트가 닫은 창은 닫힌 채입니다.
2. 실외 값을 모르면 창과 팬은 제자리입니다.
3. 창과 팬은 **바깥이 실내보다 1 °C 이상 시원할 때만** 열고, 바깥이 실내보다 더워질
   때까지 그 허락을 유지합니다. 열어도 되는 동안에는 야간에 닫아 두기·냉난방 연동·
   "환기해도 소용없음"·"열어도 반응 없음" 이 그 창을 닫지 않습니다. 바깥이 더 더우면
   닫는 쪽으로 갑니다(*폭염 — 바깥이 더 더워서 창을 닫아 둡니다*). 직전 사이클에 안개형
   분무가 돌았으면 15 % 는 열어 둡니다 — 팬이 있으면 팬, 없으면 창 — 습기가 빠져야 분무가
   계속 식힐 수 있습니다. 열어도 되는 창은 풍향 가중치로 깎지 않습니다.
4. 온도가 먼저입니다. [온도 상한](#l3-coordinator-actuator-command) 선(문턱 − 1 °C) 위에서는
   항이 하드라 창을 닫으려는 VPD·습도 항을 뺍니다. 선 아래에서는 평소 제어처럼 제자리에
   있거나 물러납니다. 온·습도를 직접 제어할 때도 — 온도 우선 기준이거나, 습도(따라서 VPD)
   값을 잃어 온·습도로 물러난 경우 — 온도 목표 위에 이 선을 겁니다. 그 목표는 문턱보다 높을
   수 있기 때문입니다(단계 온도가 없으면 가이드 상한). 온도의 우선순위도 2.0 이상으로 올립니다.
5. 분무는 물이 있고([분무용 물 공급](#water-supply) — 신호를 고르지 않았으면 있는 것으로 봅니다), 공기가 아직 물을 받을 수 있고(건구 − 습구 4 °C 이상, 2.5 °C 아래로
   떨어지면 멈춤), 습도가 85 % 아래일 때만(80 % 아래로 와야 다시 허용) 씁니다. 습도를
   모르면 멈춥니다(*폭염 — 지금은 분무로 공기를 식힐 수 없습니다*). 냉각기로 쓰는 것은
   안개형(고압) 분무뿐입니다 — 하드 온도 항이 그것을 돌립니다. 습윤형(아래 향 살수)은 평소
   제어와 습도 잠금을 그대로 따르고, 보호는 그 잠금을 좁히기만 합니다. 물이 공중에서 날지
   않고 잎과 트레이에 떨어지므로, 식히려고 돌리면 대부분 흘러내리고 잎이 밤까지 젖습니다.
   위 세 조건은 모든 분무기를 멈춥니다. 일소·저녁 분무 잠금은 여전히 이기지만, [짧은 펄스 분무](#pulse-fog)
   하나만은 예외입니다.
6. 해가 있으면(실외 일사 150 W/m² 부터, 100 아래로 내려가야 풀림) 차광막을 칩니다.
   단계 1 에서는 친 막 아래 광량이 **최소 광량 임계값** 이상이고 그날 광이 허락할 때만([차광막으로
   더위 막기](#shade-heat)의 *빛 지킴* 이 아닐 때), 단계 2 거나 문턱보다 3 °C 이상 높으면 그와 상관없이 칩니다. 한 번 친 막은 해가 있는
   동안 그대로 두고, 그동안 차광막은 보호가 쥡니다.
7. 난방은 끄고, 유동팬을 돌리고, 냉방기는 단계 1 에서 하드 온도 항을 따르고 단계 2 에서
   100 % 로 돕니다. 단계 2 에서는 열어도 되는(바깥이 더 시원한) 창과 흡배기팬도 100 % 입니다 —
   모델의 추정이 아니라 능력 전부를 쓰고, **최저 습도** 의 팬 끄기보다 이깁니다. *환기로
   목표에 닿으면 냉난방 쉬기* 는 멈춥니다.

보호 중에는 Grey-box 를 골라 두었어도 그 사이클은 Legacy 로 돕니다 — MPC 는 이 규칙을
모릅니다. 단계가 올라가는 것은 **한 번만** 긴급입니다 — 창 구동 주기를 그 한 사이클만
건너뜁니다. L1~L3 를 건너뛰는 사이클(비·바람 게이트, 운전 시간대 밖)에서도 보호는
그대로 걸립니다: 창 100 %·15 %·0 %, 분무 끔, 냉방기·유동팬 100 %, 난방 끔, 차광 —
게이트가 명령한 장치는 건드리지 않습니다.

매 사이클 단계(채널 75: 0/1/2)와 판단(채널 76, 비트마스크: 창 열어도 됨 · 바깥이 더
더움 · 분무 허용 · 증발 여력 부족 · 습도 높음 · 물 없음 · 차광 · 광량 하한 때문에 차광
보류 · 실내 값 끊김)을 남깁니다 — 디버그 로깅과 상관없습니다. 건강 점검
(`check_env_coordinator_health`)이 활성 분과 단계 전환을 셉니다. 시간당 한 번 넘게
바뀌면 온도가 문턱에 걸쳐 있다는 뜻입니다. 단계 2 에 들어가면 폭염 경보 메일을 보냅니다
(하루 최대 한 번). 문턱이 최고 온도 이상이면 로그에 한 번 알립니다.

예전의 *폭염 비상* 게이트(실외 ≥ 45 °C 그리고 실내 ≥ 35 °C → 창 전개)를 대신합니다. 그
조건에서는 거의 언제나 바깥이 더 더워 창을 활짝 열면 온실이 더 뜨거워졌고, 작물이 실제로
고생하는 30–35 °C 구간에서는 한 번도 서지 않았습니다.

## 안전 게이트 { #safety-gates }

안전은 L1~L3 조율 알고리즘 **밖에서** 돕니다 — 매 사이클 L1~L3 앞에서 평가하는
Pre-Gate 와, L3 결과를 내보내기 직전에 검증하는 Post-Gate 입니다. 한 번 발동한
Pre-Gate 는 마지막 발동 후 최소 300초 동안 유지됩니다(빠른 on/off 반복 방지).
게이트가 풀리면, 게이트가 움직인 장치는 **게이트가 둔 위치에서** 평형을 다시
찾습니다. 게이트 전의 평형 개도로 곧장 돌아가지 않습니다 — 그사이 조건이 바뀌었을
수 있기 때문입니다. 게이트의 강제 명령은 구동 주기를 기다리지 않고 즉시 나가며,
게이트가 서 있는 동안 매 사이클 다시 보냅니다. 게이트가 강제하지 않은 장치는 평소
구동 주기를 그대로 지킵니다 — 한 장치에 게이트가 서 있다고 시설 나머지가 빨라지지
않습니다.

### Pre-Gate (L1~L3 진입 전 평가) { #pre-gate-checked-before-l1l3 }

| 게이트 | 발동 조건 | 동작 |
|--------|----------|------|
| 강우(실측) | 강우계·기상대가 ≥ 0.5 mm/hr (고정, 사용자 설정 불가) 를 알리고, 바람 없는 약한 비가 **아닐 때**(아래) | 측창·천창을 닫고 L1~L3 를 건너뜁니다. 커튼·차광막은 실내 설비라 건드리지 않습니다. |
| 강우(단계 제한) | **예보 모델**(Open-Meteo·기상청 단기예보·NASA POWER)의 강수, 또는 바람 없는 약한 실측 비 | 전부 닫지 않습니다 — 아래 [강우: 실측과 예보](#safety-gates) 참고. 제어는 계속 돕니다(근거 52). |
| 강풍(2단계) | 10분 평균 풍속 ≥ **강풍 임계** 옵션(기본 12 m/s), 또는 잰 돌풍 ≥ 그 1.5 배(18 m/s) | 풍향과 무관하게 개구부를 모두 닫고 L1~L3 를 건너뜁니다. |
| 강풍(1단계) | 10분 평균 ≥ 임계의 0.6 배(7.2 m/s), 또는 잰 돌풍 ≥ 0.9 배(10.8 m/s) | 전부 닫지 않습니다 — 아래 [강풍 두 단계](#safety-gates) 참고. 제어는 계속 돕니다(근거 55). |
| 한파 비상 | 실외 ≤ −5 °C **그리고** 실내 ≤ 5 °C (둘 다 고정). 해제는 둘 중 하나가 2 °C 이상 올라갔을 때 | 개구부 폐쇄, 보온커튼 폐쇄, 난방기 100 % 강제. |
| 서리 주의 / 보호 | 유효 실내 ≤ 4 °C / ≤ 2 °C — [서리](#frost) 참고 | 주의: 커튼 닫음, 개구부 더 열지 않음. 보호: 개구부·커튼 닫음, 난방기·유동팬 100 %, 분무·CO₂·냉방 끔, L1~L3 건너뜀. 근거 56. |
| 한파 판정 불가 | 실내 온도를 모름 | 비상 게이트가 **서지 않습니다** — 전 장비를 한쪽으로 모는 조치라 근거가 확실할 때만 발동합니다. |
| 실내 값 끊김 | 실내 온·습도가 오지 않음(센서마다 자기 신선도 규칙으로 판정 — 별도의 120초 시계는 없습니다) | **아무것도 강제하지 않습니다.** 편차를 잴 수 없으므로 그 축이 제어에서 빠지고, 근거를 잃은 장치는 제자리에 섭니다. 잴 수 있는 축(CO₂·광량)은 계속 제어하고, 값이 돌아오면 바로 재개합니다(300초 유지 없음). |
| 실외 비·바람 끊김 | 받던 강우·풍속 값이 더 오지 않음(센서마다 자기 신선도 규칙으로 판정 — 별도의 300초 시계는 없습니다). 원래 없던 센서는 해당하지 않습니다. 마지막 값은 재시작을 넘으므로(최근 30 분 안의 기억) 이미 끊긴 센서가 재시작 뒤 '원래 없던 센서' 로 읽히지 않습니다. | 마지막 값이 비·강풍이었으면 강우·강풍 게이트가 새 값이 올 때까지 개구부를 **닫은 채** 둡니다. 아니면 개구부는 제자리에 있거나 닫힐 수는 있어도 **더 열리지 않습니다** — 오래된 "비 안 옴" 은 여는 근거가 못 됩니다. 예외: **최고 온도** 하드 임계 위에서는 열 수 있습니다. 차광막과 나머지 장치는 정상 제어를 이어 갑니다. |
| 분무 잠금 | 강한 빛, 또는 저녁 차단 시각 (일소·저녁 보호가 켜져 있을 때) | 습윤형 분무기만 잠급니다. 국소 잠금이라 나머지 제어를 얼리지 않고 300초 유지도 하지 않습니다. 극한 고온·건조에서는 짧은 펄스 하나가 통과합니다(근거 57, [짧은 펄스 분무](#pulse-fog)). |

**강우: 실측과 예보.** 예보 모델의 시간 강수는 "그 격자에 그 시간 비가 올 *수도*
있다" 이지 "지금 창으로 비가 들이친다" 가 아닙니다. 그래서 게이트는 먼저 강우 값의 출처를
봅니다. 드라이버가 스스로 모델이라고 밝힌 입력(`data_origin: model` — Open-Meteo·기상청
단기예보·NASA POWER)은 예보이고, 그 밖의 것과 **판정하지 못한 것은 실측**(더 엄격한 쪽)으로
봅니다.

**강우 입력이 여럿이어도 평균하지 않습니다.** 신선한 값을 낸 실측 입력이 하나라도 있으면
메인·백업 순위와 상관없이 실측만 쓰고, 그중 **가장 큰 값**을 씁니다(0/1 감우기의 1 과
강우계의 0 은 "0.5" 가 아니라 비입니다). 예보 강수는 신선한 실측이 하나도 없을 때만 쓰고,
그때는 예보로 봅니다. 예전에는 강우계 0 과 순위 표시 없는 Open-Meteo 1.2 가 0.6 으로
평균되어 실측 비로 읽혀, 한낮에 개구부가 전부 닫혔습니다. 비를 알리던 강우계가 끊기면
예보가 넘겨받지 않습니다 — 게이트는 강우계의 마지막 값으로 닫힌 채 강우계가 돌아오기를
기다립니다(마지막 값이 0 이던 강우계는 곧바로 예보에 넘깁니다).

**강우 값은 모두 시간당 mm(mm/h)입니다.** 채널마다 게이트 앞에서 바꿉니다: 15 분 누적
(기상청 `rn_15m`, `rain_15m`·`15-min`·`강수15분` 같은 이름)은 4 배, 10 분 누적은 6 배,
Open-Meteo·기상청 단기예보의 시간 강수는 그대로, NASA POWER 의 하루 합계는 24 로 나누고,
인치 단위는 mm 로 바꿉니다. 0/1 감우기는 0/1 그대로입니다. 구간을 모르는 채널은 그대로
쓰고, 한 시간보다 긴 실측 누적은 줄이지 않습니다 — 둘 다 닫는 쪽으로만 틀립니다.

| 강우 값 | 천창(형태를 모르는 개구부 포함) | 측창 |
|---|---|---|
| 예보 0.1 이상 1.0 mm/h 미만 | **30 %** 까지(더 열려 있으면 30 % 로 닫음) | 정상 제어 |
| 예보 1.0 mm/h 이상(문턱이 더 높으면 그 값) | 닫음 | **30 %** 까지. 풍속 2 m/s 이상이고 풍향을 알면 풍상측 측창은 닫음 |
| 실측 0.5 이상 1.0 mm/h 미만, 이번에 잰 풍속 2 m/s 미만 | 닫음 | **30 %** 까지 |
| 실측 그 밖(1.0 이상 — 0/1 감우기의 1 포함 —, 풍속 2 m/s 이상, 풍속 센서 없음, 값 끊김) | 닫음 | 닫음 — 위의 강우 게이트 그대로 |

한 번 걸린 제한은 30분이 지나야 한 단계 내려갑니다 — 시간 예보가 0.9/1.0 mm 를 오가거나
소나기가 끊겼다 이어져도 천창이 오가지 않습니다. 제한은 코디네이터 안에서 걸어 기억(적분)이
상한에 감기지 않게 하고, 마지막에 한 번 더 자릅니다. [극한 고온 보호](#heat-protect)는 측창을
상한까지만 쓰고, 비로 닫힌 천창은 열지 못합니다. 30 % 상한은 고온 보호 단계 2 에서도
유지됩니다. 값이 끊겨도 규칙은 이어집니다 — 끊긴 실측 강우는
전부 닫고, 끊긴 예보는 제한을 유지한 채 "더 열지 않음" 을 더합니다. 운전 시간대 밖에는 상한
아래 어디에 둘지 정할 PI 가 없으므로, 다른 명령이 없는 상한 대상 창은 닫습니다.

**강풍 두 단계.** 예전에는 문턱 하나로 한 사이클에 개구부를 전부 닫고 다음 사이클에 다시
열었습니다. 10~12 m/s 로 꾸준히 부는 푄에서는 하루에도 여러 번 전부 닫혔다 열렸고, 맑은 오후에는
한 사이클에 실내가 10 °C 뛰었습니다. 이제 **강풍 임계**가 두 단계의 기준이고, 나머지 숫자는 모두
그 배수입니다.

| 단계 | 들어가는 값 | 풍상측 개구부(풍향 ±60° 이내) | 그 밖의 천창(형태를 모르는 개구부 포함) | 그 밖의 측창 |
|---|---|---|---|---|
| 1 | 평균 ≥ 0.6 배(7.2 m/s) 또는 돌풍 ≥ 0.9 배(10.8 m/s) | 닫음 | **30 %** 까지. 개구부 방위나 풍향을 모르면 닫음 | **50 %** 까지 |
| 2 | 평균 ≥ 1 배(12 m/s) 또는 돌풍 ≥ 1.5 배(18 m/s) | 닫음 | 닫음 | 닫음 |

단계에는 바로 들어갑니다. 나올 때는 그 단계가 선 뒤 **최근 20분 값의 평균**(10분 평균 풍속과 잰
돌풍 각각)이 그 단계 들어가는 값의 **0.85 배** 아래면 한 단계씩 내려갑니다 — 잦아드는 폭풍은
2 → 1 → 없음으로 갑니다. 보통의 10분 주기면 값 세 개라, 가장 이른 내림은 단계가 선 뒤 30분입니다.
내려가는 값 위로 한 번 튄 값은 평균에 섞일 뿐 시계를 다시 세우지 않습니다(예전 "20분 연속" 은 10.2 m/s
언저리를 오가는 푄에서 시계가 거듭 다시 서, 맑은 날 개구부가 80분 전부 닫혀 있었습니다). 그 단계
**들어가는** 값을 다시 넘으면 20분을 처음부터 셉니다. 풍속 값이 끊긴 동안은 세지 않고 평균 창도
비웁니다(오래된 "잔잔함" 은 여는 근거가 못 됩니다).

**더우면 2단계가 짧아집니다.** 실내가 [극한 고온 보호](#heat-protect) 문턱 이상이거나 보호가 이미
서 있으면, 2단계 근거가 사라진 첫 사이클 — 10분 평균이 임계 아래이고 잰 돌풍(돌풍 센서가 있으면)이
1.5 배 아래 — 에 바로 1단계로 내립니다. 풍상측 창과 천창은 닫힌 채, 나머지는 1단계 상한까지만 엽니다.
2단계 바람이 돌아오면 그 즉시 전부 닫습니다. 풍속·돌풍 값이 끊겼을 때와 극한 고온 보호를 끈 설치에서는
하지 않습니다. 1단계 → 없음은 이 지름길이 없습니다. 돌풍은 센서가 잴 때만 씁니다: 실외 센서에 측정 항목 **돌풍** 채널을 묶으세요([센서
역할](../geo/facility.ko.md#sensor-roles)). 여럿이면 가장 센 값입니다. 없으면 돌풍을 **추정하지
않습니다** — 1단계의 평균 0.6 배가 이미 흔한 돌풍 계수 1.5 를 가정한 돌풍 0.9 배와 같은 자리이고,
추정 돌풍으로 한낮에 개구부를 전부 닫아서는 안 됩니다. 2단계의 돌풍 값(1.5 배)도 같은 계수를 따릅니다
— 기상대의 돌풍은 10분 동안의 최댓값이라, 1.25 배(15 m/s)로 두었더니 평균 10 m/s 의 푄에서 나오는 값
아래로 영영 내려가지 못해 시뮬레이션에서 맑은 하루 내내 개구부가 닫혀 있었습니다. 개구부 방위는 그 장치를 묶은 지도 도형에서
나옵니다. 방위가 없는 개구부는 한 번 기록되고("측창 방위각 미설정 — 풍향별 닫기를 못 함"), 풍향
센서가 묶여 있으면 건강 점검이 목록을 냅니다. 1단계 상한은 강우 상한과 같게 동작합니다 —
코디네이터 안에서 걸어 기억(적분)을 상한에 묶고, 마지막에 한 번 더 잘라 [극한 고온 보호](#heat-protect)
도 상한까지만 열며, 운전 시간대 밖에 다른 명령이 없으면 닫습니다. 비와 바람이 한 창에 함께 상한을
걸면 낮은 쪽이 이깁니다. 2단계는 전면 게이트라 고온 보호가 다시 열지 못합니다(고온은 위처럼 2단계를
짧게 할 뿐입니다).

**값을 잃은 것은 비상이 아니라 제약입니다.** 실내 값 끊김과 실외 비·바람 끊김은
둘 다 강제 명령을 만들지 않고, 300초 유지도 걸지 않으며, 이 둘만 서 있으면
L1~L3 가 정상 실행됩니다. 근거가 없다는 이유로 장비를 움직이지 않는다는 규칙이고,
움직일지 말지는 코디네이터가 축별로 판단합니다.

**폭염 게이트는 없습니다.** 고온은 사용자가 정한 문턱에서 [극한 고온 보호](#heat-protect)
가 맡습니다. 강우·한파 임계는 코드에 고정돼 있고, 함수 옵션으로 노출된 것은 **강풍**
임계 하나뿐입니다. 여러 게이트가 동시에 활성일 수 있으며(예: 강우 + 강풍), 그때 개구부는
풍향과 무관하게 무조건 닫힙니다. 한 개구부를 두고 게이트와 고온 보호가 엇갈리면 게이트가
이깁니다 — 강우·강풍은 고온 보호가 열려고 해도 그 개구부를 닫은 채 두고, 차광막·냉방기·
팬은 그대로 고온 보호의 명령을 받습니다.

**게이트가 걸린 사이클도 사이클입니다.** 게이트가 사이클을 일찍 끝내면 축소 요약을
남기고 사이클 도장을 찍습니다. 그래서 시설 위젯이 무슨 일이 있었는지 계속 보여 주고,
코디네이터가 무응답인 것처럼 보고하지 않습니다. 축소 요약에도 이번 사이클에 실제로
잰 환경 값은 그대로 실립니다 — 게이트가 걸려 있어도 센서는 계속 재고 있기 때문입니다.
빠지는 것은 L1~L3 가 만들었을 값(목표·편차 등)뿐입니다. 장치도 게이트가 강제한 것만이
아니라 전부 목록에 남습니다 — 건드리지 않은 장치는 0 % 가 아니라 명령 자체가 없습니다.
장치별 최종 명령 기록(채널 100+)도 게이트 사이클에 남습니다 — 게이트의 명령, 고온 보호의
명령, 나머지 장치는 직전 명령을 근거 12 로. 그래서 어느 시각에 창이 닫혀 있었든 로그로
설명할 수 있습니다. 게이트 사이클에도 규칙의 기억은 나아갑니다 — 오늘의 광 적산, 구름비, 맑은 하늘
일사, 일사 부하 환기의 '해 있음' 래치. 그래서 긴 게이트가 풀린 첫 사이클이 게이트가 선 시각에 굳은
값으로 판단하지 않습니다. 장치를 어떻게 둘지는 여전히 게이트가 정합니다.

### 서리 { #frost }

위의 한파 비상 게이트는 시설이 얼어붙는 날(실외 −5 °C **그리고** 실내 5 °C)을 위한 것입니다. 작물은 그보다
훨씬 일찍 상합니다. 맑고 바람 없는 밤에는 잎과 피복이 공기보다 2~4 K 낮아(복사냉각) 공기 2~4 °C 에서
잎은 이미 0 °C 입니다. 폐루프 시험 *늦서리*(맑은 낮 18 °C, 이어서 바람 없는 맑은 밤 −4 °C)에서 비상 게이트는
한 번도 서지 않았고 작물은 경보도 조치도 없이 약 390 분을 영하에서 보냈습니다. **서리**는 훨씬 일찍 서는
두 단계 보호이며, 주로 **실내** 온도(가장 찬 센서)로 판단합니다.

| 단계 | 시작 | 하는 일 |
|---|---|---|
| 서리 주의 | 유효 실내 ≤ **4 °C** | 보온커튼을 닫고, 개구부는 **더 열지 않습니다**(닫히는 것은 허용). 제어(L1~L3)는 그대로 돕니다. 근거 56 으로 표시됩니다. |
| 서리 보호 | 유효 실내 ≤ **2 °C** | 개구부·흡배기팬·보온커튼을 닫고, 난방기 100 %, **유동팬 100 %**(잎 위에 가라앉은 찬 공기를 섞음), 분무·CO₂·냉방을 끕니다. 한파 비상처럼 L1~L3 를 건너뜁니다. 경보 메일은 하루 한 통. 차광막과 보광등은 건드리지 않습니다. |

*유효 실내*는 복사냉각이 예상될 때 실내 값에서 2 °C 를 뺀 값입니다. 복사냉각 조건은 실외 ≤ 2 °C, 풍속
2 m/s 미만, 실측 비 없음, 해가 없음(측정, 광량 센서가 없으면 태양 위치로 어림)입니다. 제어기는 구름 값을
받지 않으므로 흐린 밤도 맑은 것으로 봅니다 — 서리를 놓치는 쪽이 비싸고, 잘못 올린 주의의 비용은 닫힌 커튼
정도입니다. 그래서 맑고 바람 없는 밤에는 실내 4 °C 에서 서리 보호가 섭니다.

**작물.** 서리는 물리의 선(얼음은 0 °C 근처에서 맺힘)이라 고정이지만, 사용자가 정한 한계를 **넘지는
않습니다.** 보호선은 2 °C 와 **최저 온도 − 1 °C** 중 낮은 쪽이고, 주의선은 보호선 + 2 °C 입니다.
최저 온도가 9 °C(토마토 육묘장)이면 4 / 2 °C 그대로입니다 — 9 °C 아래는 서리가 아니라 저온이며 최저 온도
한계(근거 33)가 맡습니다. 어는점을 견디는 작물이라 최저 온도를 1 °C 로 둔 곳은 2 / 0 °C 가 됩니다.
따로 설정하는 값은 없습니다.

**들락거리지 않게.** 단계는 즉시 시작하고, 실내가 그 선보다 1 °C 높아지고 **그리고** 그 단계가 마지막으로
필요했던 때부터 30 분이 지나야 끝납니다. 보호는 주의를 거치지 않고 곧장 풀릴 수 있습니다. 실내 값을
잃으면 서 있던 단계를 최대 30 분 유지한 뒤 끝내고, 값이 없이 새로 서지는 않습니다. 단계는 재시작을
넘습니다(최근 30 분 안의 기억).

**다른 규칙과.** 서리와 [극한 고온 보호](#heat-protect)는 함께 서지 않습니다 — 서리가 서 있는 동안
고온 보호는 풀리고 시작하지 않습니다. 서리는 보온커튼의 밤 결로 틈(근거 46), 아침 램프(47), 일사 부하·
아침 습기 빼기의 환기 하한(51, 54)보다 앞섭니다. 커튼은 닫힌 채이고 창은 더 열리지 않습니다. 비와 서리가
한 창을 함께 제한하면 비의 상한이 남습니다. 한파 비상과 겹치면 그쪽 값이 서고, 서리는 유동팬과 분무·CO₂·
냉방 끄기를 더합니다. 없는 장치에는 명령이 없습니다(난방기가 없는 시설도 닫기는 하며, 경보 메일이 데울 수
없다고 알립니다). 시설 점검은 서리 주의·보호에 있던 시간(분)을 보고합니다.

### Post-Gate (L3 이후, 디스패치 직전 검증) { #post-gate-checked-after-l3-before-dispatch }

| 검증 | 동작 |
|------|------|
| 비유한 명령(NaN/Inf) | 해당 액추에이터를 안전 기본 위치로 되돌립니다. |
| 범위 초과 명령 | [0, 100] 으로 클램프합니다. |
| Manual Lock 활성 | 잠긴 값으로 덮어씁니다. |
| 분무용 물 없음([분무용 물 공급](#water-supply)) | 분무기를 모두 0 으로 강제합니다 — 수동 잠금이 잡고 있어도 마찬가지입니다. 펌프가 말라 돌면 안 되기 때문입니다. |
| 의심 액추에이터 보류(근거 42) | 아예 보내지 않습니다 — 서 있는 자리에 둡니다([의심 액추에이터](#actuators-suspected)). 안전 게이트·하드 임계·극한 고온 보호가 그 자리에 둔 명령은 그대로 나갑니다. |
| 냉방기와 난방기 동시 ON (둘 다 5 % 초과) | 허용하지 않습니다. 하드 임계 대응까지 모두 끝난 **마지막**에 검사하고, 명령의 출처가 센 쪽을 남깁니다 — 안전 게이트 > 극한 고온 보호 > 수동 잠금 > 일반 제어. 출처가 같으면 비용 지수가 낮은 쪽을 남기고, 다른 쪽을 0 으로 강제합니다. L3 도 온도 요구의 반대편(더울 때 난방기, 추울 때 냉방기)을 미리 쉬게 하므로 이 검사까지 오는 일은 드뭅니다. |

### 긴급 정지와 안전 상태 { #emergency-stop }

| 진입점 | 설명 |
|--------|------|
| Function Command → 긴급 정지 | 화면 버튼. |
| Conditional / Trigger → `force_safe_state` | 외부 자동화에서 즉시 진입. |
| RPC `output_off` | 우회 경로 — 개별 Output 하나만 정지합니다. |

긴급 정지 후 60초 동안 다음 사이클이 지연됩니다. 그 직후 액추에이터가 움직이지 않는
것은 고장이 아니라 이 지연입니다.

## 트러블슈팅 { #troubleshooting }

| 증상 | 점검 항목 |
|------|----------|
| 화면에 목표가 없다 | 이 시설·구역에서 자라는 구획이 있는지, 그 구획에 프로그램이 있는지, 그 프로그램이 검토됐는지. 하나라도 없으면 코디네이터는 유도 범위로만 돕니다 — 고장이 아니라 정상입니다. |
| 목표는 있는데 한 축이 무시된다 | 그 목표 항목에 물리량이 지정되지 않았을 수 있습니다(그러면 *참고* 일 뿐입니다). 곡선이 걸린 항목은 구획에 적은 숫자를 무시합니다. |
| 액추에이터가 작동하지 않는다 | 액션이 등록됐는지, Output 이 활성인지. 액션이나 시설을 바꿨으면 **액추에이터 다시 불러오기** 를 실행합니다. |
| on/off 릴레이가 너무 짧게 켜진다 | 명령값이 5 % 미만일 가능성이 큽니다 — 시간 비례 어댑터가 그 아래에서는 끕니다. |
| 펌프가 항상 1.0 L/min 으로 계산된다 | 시설의 emitter 유량이 0 이 아닌지, 관수 레이어가 그 펌프 Output 을 가리키는지 확인합니다. |
| 강풍에 환기창이 닫히지 않는다 | 강풍 임계와 시설의 실외 풍속 센서 바인딩을 확인합니다. |
| 아주 더운 오후에 창이 닫혀 있다 | [극한 고온 보호](#heat-protect) 중에는 바깥이 실내보다 더 더우면 창을 닫습니다 — 열면 더 뜨거운 공기를 들입니다. 시설 팝업이 *폭염 — 바깥이 더 더워서 창을 닫아 둡니다* 라고 말합니다. 식히는 일은 차광·냉방과 (공기가 아직 물을 받을 수 있으면) 분무가 맡습니다. |
| 밤에 창이 계속 닫혀 있다 | **야간에 닫아 두기** 를 켰다면 정상입니다 — 시설 팝업이 *밤이라 닫아 둠* 이라고 말합니다. 온·습도 하드 임계와 안전 게이트는 그래도 파킹을 풉니다. |
| 실외값이 없다고 나온다 | 최대 센서 유효 시간이 공급원의 주기보다 짧을 수 있습니다. 0 으로 두어 센서마다 자기 주기로 판정하게 하세요. |
| 난방기와 냉방기가 함께 돌았다 | 디스패치 직전 인터록이 금지합니다([Post-Gate](#post-gate-checked-after-l3-before-dispatch)). 유도 범위가 하드 임계보다 넓은 설정이면 저장하는 자리에서 막지 않고 경고하며, 코디네이터는 유도 범위를 하드 임계 안으로 좁혀 씁니다. |
| 설정한 값이 무시되는 것 같다 | 조건부 옵션일 수 있습니다 — 직접 설정 구동 주기는 프로파일이 *직접 지정* 일 때만, 야간 시각 칸은 야간 기준이 고정 시각일 때만 쓰입니다. 입력했는데 안 쓰이는 값은 화면이 알려 줍니다. |
| 모든 장치가 제자리에 서 있다 | 실내 측정이 사라졌을 수 있습니다. 온도·습도를 잴 수 없으면 그 축은 제어에서 빠지고, 잴 수 있는 축이 하나도 남지 않은 장치는 **아무것도 하지 않습니다** — 닫지도 열지도 않습니다. 시설 팝업이 *지금 잴 수 없어 제자리* 라고 말하고, 로그에도 한 번 남습니다. 센서 연결과 최대 센서 유효 시간을 확인하세요. |
| 도면에 그린 장치가 제어에 안 나타난다 | 제어가 다루는 종류가 아닐 수 있습니다(개구부·차광막·보온커튼·냉난방·분무·CO₂·보광·팬). 그런 설비는 등록에서 빠지고 그 사실이 로그에 한 번 남습니다 — 시설 편집기에서 종류를 바꾸면 들어옵니다. |
| 시설 변경이 반영되지 않는다 | **액추에이터 다시 불러오기** 를 실행하거나, 함수를 비활성화했다 활성화합니다. |
| 워치독이 장시간 정지를 보고한다 | 의도된 정지 — 시간창 밖이거나 등록된 액추에이터가 없는 경우 — 는 고장이 아니라 정지로 보고합니다. 진짜 정지는 그대로 경고합니다. |

## AI와의 연동 { #ai-integration }

AoT 의 AI 채팅과 MCP 로 연결한 AI 는 다음 도구로 이 코디네이터를 봅니다. 쓰기 도구는
모두 사람의 승인을 거칩니다.

| 도구 | 하는 일 |
|------|--------|
| `get_control_state` | 읽기. 코디네이터별 목표·허용오차·우선도·안전 범위·운전 시간대와, 마지막 사이클이 실제로 쓴 목표·제한 인자·안전 게이트 상태·장치별 명령과 그 사유. 제어에 대해 조언하기 전에 먼저 읽는 값입니다. 코디네이터별 최근 사이클에는 현재 VPD 도 이름표를 달고 실립니다 — `vpd.air_kpa` 는 온도·습도로 계산한 공기 VPD, `vpd.leaf_kpa`(와 `leaf_temp_c`)는 엽온을 실제로 잰 때만 나타납니다. 목표의 기준(`air` 또는 `leaf`)은 `vpd_basis` 로 알려 주므로, 편차를 엉뚱한 VPD 와 견주는 일이 없습니다. |
| `get_cumulative_status` | 읽기. DLI·GDD 일별 누적과 부족분(DLI / GDD 트래커를 켠 경우). |
| `get_function_detail` | 읽기. 함수 설정 전체. |
| `modify_function_options` | 쓰기. 이 함수의 옵션을 바꾸고 다시 읽힙니다. |
| `activate_function` / `deactivate_function` | 쓰기. 함수를 켜거나 끕니다. |

목표는 이 함수가 아니라 구획의 단계 계획에 있습니다. 한 구획의 목표만 바꾸려면 구획
화면에서 고칩니다. AI 가 프로그램을 고치는 도구(`modify_program`)로 단계 목표를
바꿀 수도 있지만, 그 프로그램을 쓰는 모든 구획에 적용됩니다.
