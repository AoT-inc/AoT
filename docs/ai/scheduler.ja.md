# スケジューラー

スケジューラーは、AoTの農場イベントを共同で管理する台帳です — AIが起案した提案と、人が入力した作業タスク(除草、点検、清掃、デバイス操作など)を、同じひとつのタイムライン上でまとめてレビュー・承認・追跡します。メインメニューの `追加機能 -> スケジュール` から利用でき、`edit_controllers` 権限が必要です。

---

## ジョブの状態 { #job-states }

スケジューラーの各エントリー(ジョブ)は、次のいずれかの状態を経て進みます。

| 状態 | 意味 |
|-------|---------|
| 下書き | AIが提案したジョブで、人による承認または却下を待っている状態 |
| 保留中 | 承認済み、または手動で作成されたジョブで、予定時刻を待っている状態 |
| 実行中 | 現在実行中(デバイス制御ジョブのみ) |
| 完了 | 正常に終了した |
| 失敗しました | 実行に失敗した |
| アーカイブ済み | キャンセル/削除されたジョブで、履歴として保持されている |

---

## AI提案 { #ai-proposals }

AIエージェントがスケジューリング操作を提案すると(`add_schedule` や `schedule_device_control` などを通じて)、`下書き` ジョブとして保存され、**AI → リクエスト**画面の「スケジュールの提案」にカードとして現れます。各カードには、内容・場所・提案された時刻・エージェントの判断理由が表示されます。スケジューラー画面の上部には待っている提案の数とリクエスト画面へのボタンが1行で表示され、カレンダーで提案を押してもリクエスト画面に移ります。

- **承認** — ジョブを `保留中` に移行します。デバイス制御ジョブの場合、この時点でトリガーが登録されます。
- **却下** — ジョブを `アーカイブ済み` に移行します。
- **詳細**を開くと、承認する前に時刻・担当・内容・場所を調整できます。

提案を決定するには、コントローラーを編集する権限が必要です。グループを使っている場合、対象が自分のグループ内にあるジョブだけを作成・承認・編集・取り消しできます。AIの提案を承認すると承認した人がそのジョブの責任者になり、ジョブが実行されるたびにその人の権限とグループで改めて確認し、条件を満たさなくなっていれば実行せず失敗として記録します。

**人が行う作業**(除草、点検など)も、どこで作っても同じ決まりに従います — ここ、ノートの一部分、AIアシスタントやMCP、Googleカレンダーの取り込みのいずれでも、作業の作成・編集・取り消しには編集者の役割(コントローラーを編集する権限)が必要です。編集者より下の役割は、設定の編集権限があっても作業を閲覧することしかできません。

**責任者のいないジョブ。** 関数やシステムが作ったジョブ、この確認ができる前に作られたジョブ、責任者のアカウントが削除または無効化されたジョブには責任者がいません。これらのジョブはこれまでどおり実行され、ユーザーを削除または無効化してもその人が担当していたジョブは止まりません。アカウントを再び有効にしても責任者は自動では戻らないため、改めて指定してください。アクティブなジョブの一覧では、責任者の列に **責任者なし** と表示されます。ユーザーを管理する権限のある人は、ジョブの詳細で **責任者** を選び **責任者を指定** を押せます。無効化されたアカウントは選べません。その種類のジョブを作成できる役割の人だけが候補に表示され、ジョブの対象がその人の権限やグループの外であれば指定されず、指定した内容は監査記録に残ります。それ以降は、実行のたびにその人で確認します。

## 手動タスク { #manual-tasks }

**新規タスク**をクリックすると、AIを介さずに直接ジョブを作成できます。

1. タスク種別(**出力制御**、**PID調整**、**トリガー関数**、**抽象プラン (状態)**)を選び、それに応じた対象を選びます — デバイス(チャンネルとオン/オフの状態まで)、PIDコントローラー(変更する項目:設定値、Kp、Ki、Kd)、機能、ゾーン/サイトのいずれかです。出力制御とPID調整では量も入力します — デバイスは秒またはPWM、PIDは新しい値です。
2. 日時を選びます。入力した時刻は、ブラウザやシステムの時刻としてではなく、**対象自身のローカル時刻**(デバイスローカル)として解釈されます — これを明示するため、フィールドの下に同じ瞬間を対象のタイムゾーン、あなたの時刻、UTCで並べて表示します。対象に位置が設定されていない場合はその行にそう書かれ、時刻はシステムのタイムゾーンで解釈されます。
3. 繰り返しを選びます — **1回のみ**、**日次**(毎日同じ時刻)、または**間隔 (分)** で何分ごとに繰り返すかを指定します。
4. 任意で、継続時間(分)とタスクノートを設定します。

手動タスクは承認ステップを経ずに、直接 `保留中` になります。

## AIに質問 { #ask-ai }

新規タスクのモーダルは**手動**タブで開きます。2つ目の**スマートAI**タブでは、タスクを自然言語で記述し(例:「3구역 관수 밸브 내일 아침 6시에 5분만 열어줘」)、どのAIエージェントに解釈させるかを選べます — 選択をシステムに任せる**自動ディスパッチ（AIマルチエージェント）**か、動作中のエージェントを名前と役割で直接指定します(内蔵AIが動作している必要があります)。**AIに質問**を押すと、同じタブに答えが表示されます — エージェントの**インサイト**と、提案された**アクション**の一覧です。デバイスを操作するもの、予定を登録するもの、設定を変えるものは `下書き` の提案になり、**AI → リクエスト**画面で決定します — 明示的に**承認**しない限り、その種のものは何も実行されません。答えるために必要だった参照だけの操作は、答えが表示された時点ですでに終わっています。

## タイムラインとデバイスタイムライン { #timeline-device-timeline }

- **タイムライン** — 直近200件の予定ジョブを週/月/週の一覧で表示し、状態ごとに色分けして示すカレンダーです。上の一覧と同じ範囲を載せます — 下書き・保留中・実行中・完了のジョブで、自動実行の記録は表示に切り替えない限り含まれません。失敗・アーカイブのジョブは履歴にのみ現れます。カレンダーの軸は見る人の時計で、項目にカーソルを合わせると対象自身のタイムゾーンでの時刻が出て、クリックするとジョブの詳細が開きます(提案は**AI → リクエスト**画面へ移動します)。
- **デバイスタイムライン**(ベータ) — デバイスごとに1行で、まだ待機中の**予定作業**の予約と、直近24時間の実際の稼働を長さを記したバーで表示します。バーをクリックすると名称と区間が表示されます。スマートフォンではデバイスごとに1行へ折りたたまれ、予約の件数と稼働の件数だけを表示します。

---

## 履歴 { #history }

完了・失敗・アーカイブされたジョブは**履歴**に保存されます。直近20件が内容・場所・最終状態・登録時刻とともに並び、**詳細**を開くと全記録(タスク種別、状態、場所、内容、予定時刻、継続時間、提案した主体、その根拠)が表示され、実際に何が実行されたかを監査できます。

システムが自ら残した記録(自動実行)は、人やエージェントが作成したジョブを埋もれさせないよう既定で非表示になります。見出しの横の**自動実行の記録を表示 (n件)**リンクが、何件隠れているかを示して再表示し、同じリンクで再び隠せます。タイムラインもこの設定に従います。

---

## 時刻の表示 { #time-display }

農場のデバイスはそれぞれ独自のタイムゾーンを持つことができるため、スケジューラーに表示されるすべてのタイムスタンプには、それが属するタイムゾーンが明記されます(デバイスローカルを基準とします)。対象に位置が設定されていない場合は「デバイス現地」とは書かず、システムのタイムゾーンで推定したと表記されます。全体のモデルについては[時刻とタイムゾーン](../time-handling.md)を参照してください。
