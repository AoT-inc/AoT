# 스케줄러

스케줄러는 AoT의 협업형 농장 이벤트 원장(元帳)입니다. AI가 제안한 작업과 사람이 직접 등록한 작업(제초, 점검, 청소, 장치 조작 등)이 하나의 타임라인에서 함께 검토·승인·추적됩니다. 메인 메뉴의 `추가 기능 -> 스케줄`에서 접근하며, `edit_controllers` 권한이 필요합니다.

---

## 작업 상태

스케줄러의 각 작업(job)은 다음 상태 중 하나를 가집니다.

| 상태 | 의미 |
|------|------|
| Draft | AI가 제안했으나 아직 승인/반려되지 않은 작업 |
| Pending | 승인되었거나 수동 등록되어 예약 시각을 기다리는 작업 |
| Running | 실행 중 (장치 제어 작업만 해당) |
| Completed | 정상 완료 |
| Failed | 실행 실패 |
| Archived | 취소/삭제된 작업 (이력으로 보관) |

---

## AI 제안

AI 에이전트가 작업을 제안하면(`add_schedule` 또는 `schedule_device_control` 도구를 통해) `Draft` 상태로 등록되고, **AI → 요청** 화면의 "일정 제안"에 카드로 나타납니다. 각 카드에는 내용, 장소, 예정 시각, 에이전트의 판단 근거(reasoning)가 표시됩니다. 스케줄러 화면 맨 위에는 기다리는 제안 수와 요청 화면으로 가는 단추가 한 줄로 보이고, 달력에서 제안을 눌러도 요청 화면으로 갑니다.

- **승인** — 작업을 `Pending`으로 전환합니다. 장치 제어 작업이라면 이 시점에 실제 트리거가 등록됩니다.
- **거절** — 작업을 `Archived`로 전환합니다.
- **자세히**를 열면 승인 전에 시각·담당자·내용·장소를 조정할 수 있습니다.

제안을 결정하려면 제어기를 편집할 권한이 있어야 합니다. 그룹을 쓰는 경우 대상이 내 그룹 안에 있는 작업만 만들고 승인하고 고치고 취소할 수 있습니다. AI 제안을 승인하면 승인한 사람이 그 작업의 책임자가 되며, 작업이 실행될 때마다 그 사람의 권한과 그룹으로 다시 확인해 더 이상 맞지 않으면 실행하지 않고 실패로 기록합니다.

**사람이 하는 작업**(제초, 점검 등)도 어디서 만들든 같은 규칙을 따릅니다 — 여기, 노트 구간, AI 어시스턴트나 MCP, Google 캘린더 가져오기 모두 작업을 만들고 고치고 취소하려면 편집자 역할(제어기 편집 권한)이 필요합니다. 편집자보다 낮은 역할은 설정 편집 권한이 있더라도 작업을 볼 수만 있습니다.

**책임자 없는 작업.** 함수나 시스템이 만든 작업, 이 확인이 생기기 전에 만든 작업, 책임자 계정이 지워졌거나 사용 중지된 작업에는 책임자가 없습니다. 이런 작업은 지금처럼 계속 실행되며, 사용자를 지우거나 계정을 사용 중지해도 그 사람이 맡던 작업은 멈추지 않습니다. 계정을 다시 사용하게 해도 책임자는 자동으로 돌아오지 않으니 다시 지정하세요. 활성 작업 목록의 책임자 열에 **책임자 없음**으로 표시됩니다. 사용자를 관리할 권한이 있는 사람은 작업 자세히에서 **책임자**를 고르고 **책임자 지정**을 누를 수 있습니다. 사용 중지된 계정은 고를 수 없습니다. 그 종류의 작업을 만들 수 있는 역할인 사람만 후보로 나오고, 작업 대상이 그 사람의 권한이나 그룹 밖이면 지정되지 않으며, 지정한 내용은 감사 기록에 남습니다. 그 뒤로는 실행될 때마다 그 사람으로 확인합니다.

## 수동 작업 등록

**New Task**를 클릭하면 AI를 거치지 않고 직접 작업을 등록할 수 있습니다.

1. 대상(출력/채널, PID, Function, 구역 중 하나)을 선택합니다.
2. 날짜/시각을 입력합니다. 입력한 시각은 브라우저나 시스템 시각이 아니라 **대상 장치 자신의 현지 시각**으로 해석됩니다 — 이를 명확히 하기 위해 입력란 옆에 대상의 타임존이 함께 표시됩니다.
3. 필요하면 소요 시간과 메모를 추가로 지정합니다.

수동 작업은 승인 단계 없이 바로 `Pending` 상태로 등록됩니다.

---

## AI에게 물어보기

New Task 모달은 **직접 입력** 탭으로 열립니다. 두 번째 **AI** 탭에서는 자연어로 작업을 설명하고(예: "3구역 관수 밸브 내일 아침 6시에 5분만 열어줘") 이를 해석할 AI 에이전트를 선택할 수 있습니다(내장 AI 가 켜져 있어야 합니다). 에이전트의 응답은 `Draft` 제안으로 등록되어 **AI → 요청** 화면에서 결정하며, **명시적으로 승인하기 전까지는 아무것도 실행되지 않습니다.**

---

## 타임라인 / 장치별 타임라인

- **Timeline** — 전체 예약 작업을 상태별 색상으로 구분해 보여주는 캘린더(주/월) 뷰입니다.
- **Device Timeline** — 특정 장치 하나로 필터링한 캘린더로, 해당 장치의 과거 이력과 예정 작업을 한눈에 확인할 때 유용합니다.

---

## 이력(History)

완료·실패·보관된 작업은 **History**에 실제 실행 결과와 시각 정보와 함께 남아, 실제로 무엇이 실행되었는지 감사(audit)할 수 있습니다.

---

## 시각 표시

농장의 각 장치는 서로 다른 타임존을 가질 수 있으므로, 스케줄러에 표시되는 모든 시각에는 해당 시각이 속한 타임존(장치 현지 기준)이 함께 표기됩니다. 전체 모델은 [시간·타임존](../time-handling.md) 문서를 참고하세요.
