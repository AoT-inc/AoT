# 連携

ページ: `設定 -> 連携`

連携ページは、AoTを外部サービスに接続します。現在対応しているのは1つの連携だけです — [スケジューラー](ai/scheduler.md)と個人のGoogleカレンダーとの双方向同期です。各ユーザーは自分自身のGoogleアカウントを接続します。管理者はまず、Google Cloud ConsoleでAoTをOAuthアプリケーションとして登録し、発行されたクライアント資格情報をこのページに入力しておく必要があります。

---

## 管理者による設定: Google OAuthクライアント { #google-oauth-setup }

ユーザーがアカウントを接続できるようになる前に、管理者はこのページの**Google OAuth設定**(管理者)で、インスタンス全体用のGoogle OAuthクライアントを設定しておく必要があります。これが済んでいない間、他のユーザーには次のメッセージだけが表示されます: 「Googleカレンダーはまだ設定されていません。管理者に設定を依頼してください。」

1. [Google Cloud Console](https://console.cloud.google.com/)で、プロジェクトを作成(または選択)し、**Google Calendar API**を有効にします。
2. 種類が**OAuth 2.0 クライアントID**、アプリケーションの種類が**Web application**の認証情報を作成します。
3. このページで、まず**公開 Base URL**(例: `https://your-aot-domain`)を入力します — AoTはこれを使って、コールバック用の固定アドレスを算出し、フィールドのすぐ下に`<公開 Base URL>/oauth/google/callback`として表示します。
4. その正確なURLを、Google Cloud Console側のOAuthクライアントの**Authorized redirect URIs**にコピーします。
5. Google Cloud Consoleから**OAuth Client ID**と**OAuth Client Secret**をコピーし、このページの該当するフィールドに貼り付けたのち、**保存**します。

これら3つの値は、環境変数(`GOOGLE_OAUTH_CLIENT_ID`、`GOOGLE_OAUTH_CLIENT_SECRET`、`OAUTH_PUBLIC_BASE_URL`)を通じてインスタンス全体に対して指定することもでき、その場合は上記フィールドの値より優先されます — 同じクライアントを複数のサーバーで共有する場合、デプロイ設定を通じて渡せるため便利です。値が環境変数から来ている場合、ページ上でその旨が示されます。

アカウントを接続すると、次のスコープが要求されます: **Calendar**へのフルアクセス(イベントの読み書き用)、**email**(接続したアカウントにラベルを付けるため)、**openid**、そしてユーザーが明示的に選んだファイルに限定されたDriveアクセス(`drive.file`。AIライブラリのGoogle Driveソースのみで使われ、カレンダー同期では使われません)。

## アカウントを接続する { #connecting }

上記の設定を管理者が完了させたら、このページの**Google カレンダー**にある**Google カレンダーを接続**をクリックします。Googleの同意画面に移動し、アクセスを許可すると、このページに**接続済み**として戻り、接続したアカウントのメールアドレスが表示されます。

AoTが無人で同期を続けるためには、Googleがリフレッシュトークンを返す必要があります。もし返されない場合(以前にアクセスを許可していて、それを完全に取り消していないアカウントで起こり得ます)、AoTはエラーを表示し、Googleアカウントの外部アプリ連携からAoTを削除したうえで、あらためて接続するよう求めます。

---

## 何が、どのように同期されるか { #sync-direction }

AoTはあなたのアカウントに、[スケジューラー](ai/scheduler.md)のジョブカテゴリーごとに1つずつ、合計3つの別々のGoogleカレンダーを作成します。これにより、個人の予定とAoTの予定が混ざることはありません。

<thead>
<tr class="header">
<th>Googleカレンダー</th>
<th>AoTのカテゴリー</th>
<th>Google側で作った新しいイベントはAoTのジョブになるか?</th>
</tr>
</thead>
<tbody>
<tr>
<td>AoT · AI</td>
<td>AIが起案したジョブ</td>
<td>ならない — ジョブはAI自身が作成するもので、編集・キャンセルのみが同期で戻ってきます。</td>
</tr>
<tr>
<td>AoT · User</td>
<td>人が行うタスク</td>
<td>なる — 通常の人間用タスク(保留中)になります。</td>
</tr>
<tr>
<td>AoT · Device</td>
<td>デバイス制御ジョブ</td>
<td>なる — 下書きとして作成されたデバイス制御ジョブになり、実行には通常のスケジューラーの承認が必要です。Googleのイベントがデバイスを直接動かすことは決してありません。</td>
</tr>
</tbody>
</table>

各イベントには、その予定の内容 — 場所、デバイス、状態、ノート — が、イベントの説明欄に、構造化された人間にも編集可能な`ラベル: 値`形式のテキストブロックとして書き込まれ、あなたのインターフェース言語で読み書きされます。そのテキスト(またはイベントの時刻)をGoogle側で編集して同期すると、その変更は対応するAoTのジョブに反映されます。

- **AoT → Google(送信)**: 送信可能なすべてのジョブ(保留中・実行中・完了・失敗しました)が、それぞれのカテゴリーのカレンダーに書き込み、または更新されます。
- **Google → AoT(受信)**: 過去に同期したイベントに対する編集・時刻変更・キャンセルは、対応するAoTのジョブを更新またはアーカイブします。AoT · User / AoT · Deviceカレンダー上の新しいイベントは、上記のとおり新しいジョブを作成します。
- **同期方向の切り替え**: 同期方向は**AoT → Google** / **Google → AoT**として表示され、どちらもデフォルトでオンになっており、真の双方向同期になっています。
- **競合**: 同じジョブ/イベントが両側で変更されていた場合は、より新しく更新された側が優先されます。

同期はおよそ15分ごとにバックグラウンドで自動的に実行されるほか、**今すぐ同期**を押すとその場ですぐに実行されます。**最終同期**には直近の実行時刻(UTC)が表示され、実行に失敗した場合(たとえばGoogle側でアクセスを取り消した場合など)は**エラー**バッジが表示されます。

## 連携を解除する { #disconnecting }

Google カレンダーの**連携解除**は、バックグラウンド同期を停止し、Google側でのAoTのアクセスをベストエフォートで取り消し、AoT側に残っている接続の記録とイベントとの対応情報を削除します。Googleカレンダー側にすでに作成済みのイベントは削除**されません** — それらが不要な場合は、Googleカレンダー側で直接削除してください。

---

## セキュリティ { #security }

GoogleのリフレッシュトークンとアクセストークンはユーザーごとにDB上で暗号化して保存され、平文の資格情報がデータベースに現れることは一切ありません。管理者が設定するOAuthクライアントの資格情報はインスタンス全体で共有されるもので、アカウントを接続するすべてのユーザーが利用します。一方、各ユーザー自身の接続とトークンは、そのユーザー本人だけのものとして保たれます。
