# スタートガイド

AoT は、自分の空間を地図に収め、そこの記録と機器をつなぎます。そして、その空間を AI が人と一緒に見て、
判断し、作業できるようにします。オープンソースであり、機器を動かす操作はユーザーが承認してはじめて実行されます。

このガイドは、AoT を初めてインストールして使い始めるときに、順番にたどっていく案内書です。インストールから、地図・センサー・出力の
設定、条件に応じた自動運転、問題が起きたときのメール受信、一つの画面での現場の確認、AI の接続までを扱います。
マニュアルのほかのページは機能を一つずつ詳しく説明し、このガイドはそれらの機能をどの順番で組み合わせるかを説明します。
オプションの意味を知りたい場合は、各章の最後にある**さらに詳しく**のリンクをたどってください。

## この章を終えると { #goal }

- インストールから AI の接続まで、各章がどのようにつながっているかがわかります
- このガイドで例として使う二つの現場（現場 A・現場 B）の構成がわかります

## 手順 { #steps }

### 1. 全体の流れ { #step-1 }

| 章 | 行うこと | 終わると |
|---|---|---|
| [インストール](g01-install.md) | Docker で AoT を起動し、管理者アカウントを作成します | ブラウザーからログインできます |
| [主な設定](g02-settings.md) | タイムゾーン・言語・単位・ユーザーを設定します | 各自が適切な権限でログインできます |
| [ネットワーク接続](g03-network.md) | ポートを開けずに外部から接続し、ファイアウォールの許可リストを作成します | 事務所やスマートフォンから現場の AoT が開けます |
| [地図の構成](g04-map.md) | 背景地図を登録し、サイト・ゾーン・施設・区画を描きます | 現場が地図上に表されます |
| [センサーの接続](g05-sensors.md) | センサーの値を取り込み、地図や施設に結び付けます | リアルタイムの値が入ってきます |
| [出力の接続](g06-outputs.md) | バルブ・ポンプ・窓・カーテンを出力として登録します | 画面から手動でオン・オフできます |
| [機能](g07-functions.md) | センサーとデバイスをつなぐルールを作成します | 設定した条件でデバイスが自動で動きます |
| [メールアラート](g08-email.md) | 問題が起きたときにメールが届くようにします | 条件を満たしたときにメールが1通届きます |
| [モニタリング](g09-monitoring.md) | 毎日何を確認するかを決めます | 途切れたセンサーや停止した機能をすぐに見つけられます |
| [ダッシュボードの構成](g10-dashboard.md) | 見る人に合わせて画面を構成します | 一つの画面で現場を見渡せます |
| [AI・MCP 接続](g12-ai-mcp.md) | 使い慣れた AI アシスタントを MCP で AoT に接続します | AI に現場の状態を尋ね、作業を任せられます |
| [ヘルプと問題の報告](g13-help.md) | マニュアル・API・エラー報告を探す場所を知ります | 困ったときに自分で調べて報告できます |
| [注意事項](g11-cautions.md) | 事故につながりやすい点を確認します | バックアップ・アップデート・停電に備えられます |

地図が必要ない現場であれば、地図の構成は飛ばしてかまいません。リモートアクセスが必要なければ、ネットワーク接続は
後で行ってもかまいません。AI・MCP 接続とヘルプはいつ読んでもかまいません。それ以外は、前の章を終えないと次の章に進めません。

### 2. まず機器なしで試す { #step-2 }

実際のセンサーやデバイスがなくても、このガイドを最後まで進められます。センサーの代わりに、値を直接入力する
**テスト入力**を（[センサーの接続](g05-sensors.md#step-6)）、デバイスの代わりに、オン・オフの動作だけをまねる
**仮想出力**を（[出力の接続](g06-outputs.md#step-1)）使います。仮想の機器で設定を確認したあと、
実際の機器に切り替えられます。

## 確認 { #check }

次の二点を整理しておいてください。次の章から、どの節をたどるかを選ぶときに使います。

- 自分の現場は、現場 A と現場 B のどちらに近いですか？
- 自分のセンサーとデバイスは、それぞれどの方式（LoRaWAN、MQTT、PLC、気象 API、直接接続）でつながっていますか？

## 現場 A { #site-a }

**露地と施設の両方がある現場**です。約30,000 m² の敷地に、露地のゾーンが2か所と単棟の温室が1棟あります。

- センサー：露地の温湿度・土壌水分（LoRaWAN 無線）、外の気象（気象 API）、温室内の温湿度（MQTT）
- デバイス：露地のバルブ8個とポンプ（LoRaWAN バルブコントローラー）、温室の左右の側窓、ミスト装置
- 自動制御：露地は曜日・時間帯ごとの**順次灌水**、温室は**環境制御**

一つの現場に複数の接続方式が混在しているため、センサーの接続と出力の接続の章で例として使います。

## 現場 B { #site-b }

**施設が中心の現場**です。もともとあった6連棟温室の制御設備に AoT を追加しました。

- センサー：温室内5か所の温湿度と外の気象ステーション（既存の設備から MQTT で受信）
- デバイス：側窓・天窓・保温カーテン（既存の制御盤の開・閉リレーをそのまま使用）、ミスト装置
- 自動制御：温室全体を一つの**環境制御**が担当

既存の設備を変えずに接続する方法の例として使います。

## うまくいかないとき { #trouble }

このガイドの画面名やボタンが実際の画面と異なる場合は、インストールした AoT のバージョンを確認してください。
バージョンは 管理 → システム情報 で確認できます。このガイドは AoT 26.09.07 を基準にしています。
