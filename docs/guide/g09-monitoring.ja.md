# モニタリング

自動制御が動き始めたら、あとはそれが問題なく動き続けているかを確認することが仕事になります。この章では、毎日どこを見るか、
そして問題が起きたときにどの順番で原因を探すかを決めます。

## この章を終えると { #goal }

- 毎日何を見れば、すべてが正常かどうかを判断できるかが分かる
- 値が途切れたセンサー、応答しないデバイス、止まった機能を見つけられる

## 始める前に { #prepare }

- センサーが接続された AoT（[センサーの接続](g05-sensors.md#check)）。機能やデバイスも接続されていると、なおよいです

## 手順 { #steps }

### 1. 毎日1分の点検 { #step-1 }

| 順番 | 見る場所 | 正常な状態 |
|---|---|---|
| 1 | 画面左上の **ロゴの背景色** | 色が変わっていない（赤 = 制御の中核が停止、灰色 = ウェブの接続が切れている） |
| 2 | 追加機能 → **リアルタイム測定** | すべてのセンサーに値と最近の時刻がある。「直近 N 秒間のデータがありません」の表示がない |
| 3 | ダッシュボードの **関数ステータス** ウィジェット | 有効にした機能が「無効化しました」になっておらず、エラーも表示されていない |
| 4 | 受信トレイ | [メールアラート](g08-email.md) が届いていない |

この4つが正常なら、その日はそれ以上確認することはありません。[ダッシュボードの構成](g10-dashboard.md) で説明しているように
2 と 3 を1つの画面にまとめておけば、点検は1分で終わります。

### 2. 値が途切れたセンサーを探す { #step-2 }

- **リアルタイム測定**：値が途切れた入力には「直近 N 秒間のデータがありません」と表示され、値の位置に `--` が表示されます。
  MQTT や LoRaWAN のように自分から値を送る入力は、**測定の有効期限** を過ぎてから途切れたものとして表示されます。
- 設定 → **入力**：値のない入力のカードには `--` が表示されます。

途切れたセンサーを見つけたら、次の順番で確認します。

1. センサーの電源とバッテリー（LoRaWAN センサーは、バッテリーが切れると前触れなく途切れます）
2. 途中の機器（ゲートウェイ、MQTT ブローカー、PLC）の電源が入っているか
3. 管理 → **システムログ** で、ログを **デーモン**、最小レベルを WARNING にして、その入力の名前で検索します。
   Docker でインストールした場合、一覧の一部のログ（ウェブのエラー、Nginx など）は「ファイルが見つかりません」と表示されます。**デーモン** と **ウェブアプリ** を見れば十分です。

### 3. 応答しないデバイスを探す { #step-3 }

設定 → **出力一覧** で、カードに **応答なし** または **接続なし** と表示されている出力を探します。これは、コマンドは送られたものの、
機器がそれを確認しなかったことを意味します。LoRaWAN の機器は電波とバッテリーを、有線の機器は通信ケーブルと電源を確認します。

### 4. 止まった機能を探す { #step-4 }

- 設定 → **機能** で、有効にしておくべき機能が無効になっていないか確認します。
- 環境制御の機能は、設定画面の上部にある状態ヘッダーで、現在の判断と **調整可能** なデバイスを確認します。
  センサーが途切れると、制御は「その位置で保持」に切り替わり、止まっているように見えることがあります。その場合は、手順 2 に戻ってセンサーを確認します。
- システムログで、ログを **デーモン**、最小レベルを ERROR にして、最近のエラーを確認します。

### 5. 毎週確認すること { #step-5 }

| 見る場所 | 確認すること |
|---|---|
| 管理 → **システム情報** | ディスク使用量が 80% を超えていないか、デーモンが「実行中」か |
| 管理 → **監査ログ** | 心当たりのないログインや設定の変更がないか |
| 管理 → **アップグレード** | 新しいバージョンがあるか（すぐにはアップグレードせず、先に [注意事項](g11-cautions.md#step-2) を読みます） |
| 管理 → **バックアップ復元** | 最近のバックアップがあるか |

## 確認 { #check }

どれか1つのセンサーの電源を少しの間抜きます（またはテスト入力を無効にします）。数分後、リアルタイム測定でそのセンサーが
途切れたものとして表示されれば完了です。[メールアラート](g08-email.md) を設定している場合は、メールも届くはずです。

## 現場 A { #site-a }

現場 A は無線センサーが多いため、もっとも頻繁に確認するのは **途切れ** です。

- 毎日：リアルタイム測定で、3-1 と 3-2 にある6台の LoRaWAN センサーの時刻
- 灌水の日：シーケンスコントローラーのウィジェットで、バルブが順番に動いたか、応答なしになったバルブがないか
- 毎週：土壌センサーのバッテリーの値（測定値と一緒に届きます）

## 現場 B { #site-b }

現場 B では、1つの環境制御の機能が温室全体を動かしているため、まず **制御器の状態** を確認します。

- 毎日：関数ステータスのウィジェットで、環境制御の目標値、現在の値、調整可能なデバイス
- 気象ステーションの値が途切れると窓がそれ以上開かないため、リアルタイム測定で風速と降雨の時刻もあわせて確認します。

## うまくいかないとき { #trouble }

| 症状 | 確認すること |
|---|---|
| ロゴが赤い | 管理 → システム情報 → **デーモンを再起動**。繰り返し起きる場合は、システムログ → デーモンを確認します |
| すべてのセンサーが同時に途切れた | 問題はセンサーではなく、共通の経路（ゲートウェイ、ブローカー、現場のインターネット）にあります |
| リアルタイム測定は正常なのに、グラフが空になっている | グラフのウィジェットの期間とデータソースを確認してください |
| システムログに何も表示されない | 最小レベルを下げ、機能のデバッグログを有効にします |
