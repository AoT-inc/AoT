# 機能

センサーが値を送り、デバイスが指令を受けられるようになったら、その二つをつなぐルールを作ります。AoT では、このルールを
**機能**と呼びます。「毎朝 6 時にバルブを順番に開く」「温室が暑くなったら窓を開く」
「センサーの値が途絶えたら通知する」は、どれも機能です。

## この章を終えると { #goal }

- 目的に合った機能の種類を選ぶ
- 露地の順次灌水と施設の環境制御を機能として作り、機器を動かさずに先に試す

## 始める前に { #prepare }

- センサーとデバイスを接続した AoT（[センサーの接続](g05-sensors.md#check)、[出力の接続](g06-outputs.md#check)）
- 施設の環境制御を行う場合：施設、その中の区画、施設のセンサー枠（屋内・屋外）が埋まっている必要があります
- 最初の試験に使う仮想出力（[出力の接続 手順 1](g06-outputs.md#step-1)）

## 手順 { #steps }

### 1. 機能の種類を選ぶ { #step-1 }

設定 → **機能** で種類を選び、**追加** をクリックします。
新しい機能は**オフの状態で作成される**ため、設定を終えた後に **有効化** をクリックしないと動作しません。

| やりたいこと | 選ぶ種類 | 使わない場合 |
|---|---|---|
| 複数のバルブを決まった順番で、曜日と時間帯ごとに動かす | **シーケンス** | 温度や湿度などの目標を保ちたいとき |
| 温室 1 棟の窓、カーテン、噴霧をまとめて動かし、環境を保つ | **統合環境制御** | 同じノズルを灌水にも使うとき |
| 一つの値を目標値に保つ（ヒーター 1 台、ファン 1 台） | **PIDコントローラー** | 複数のデバイスを一緒に動かす必要があるとき |
| 条件が満たされたら何かを実行する（通知、他の機能のオン・オフ） | **条件付きコントローラ** | 単に時刻に合わせて行う作業 |
| 決まった時刻、間隔、日の出・日の入りに実行する | **トリガー** グループの時刻トリガー | 条件によって変わるとき |
| 特定の日付に一度だけ行う | 追加機能 → **スケジュール** | 毎日繰り返す制御 |

**一つのデバイスを二つの機能が同時に動かさない**ようにしてください。たとえば、環境制御と時刻トリガーが
同じ窓を動かすと、互いの指令を上書きし合います。

### 2. 順次灌水を作る（シーケンス） { #step-2 }

1. **シーケンス** を追加し、歯車アイコンで設定ウィンドウを開いて **名前** を付けます（例：「3-1・3-2 順次灌水」）。
2. **アクション → アクションを追加** で **Output: On/Off/Duration** を選び、**追加** をクリックします。
   ポンプに一つ、バルブごとに一つずつ追加します。
3. 各行を設定します。**出力** を選び、**状態** が **オン** になっていることを確認します。
   状態を空欄のままにしてもエラーなく保存されますが、その段階はデバイスをオフにするだけで、オンにはしません。
   - ポンプ：**動作モード = 合計**。バルブが開いた後にポンプが動き、バルブが閉じる前にポンプが止まるように、
     **開始遅延** と **早期停止** をそれぞれ数秒に設定します。
   - バルブ：**シングル**、**デフォルト期間（秒）**。一緒に開くバルブには同じ **グループ** 名を付けます。
   - 各行の右側にある **保存** をクリックして、その行を保存します。
4. **時刻設定** で開始時刻、終了時刻、**周期 秒** を設定し、ウィンドウ下部の **保存** をクリックします。周期とは「1 巡を再び始める間隔」のことです。
   新しいシーケンスの既定の周期は 60 秒なので、**有効化する前に必ず変更してください。**
5. 曜日ごとに変えたい場合は、ダッシュボードに **シーケンスコントローラー** ウィジェットを置き、ウィジェットで **曜日別** を選んで、
   曜日ごとに時間帯を設定します（機能の設定ウィンドウには曜日の欄がありません）。

!!! warning "1 巡の時間と周期を合わせてください"
    1 巡（すべてのバルブの動作時間の合計）が周期より長いと、1 巡を終える前に最初からやり直します。
    周期が短すぎると、1 日に何十回も動きます。例：06:00〜16:00 で周期が 300 秒なら、1 日に 120 回動きます。
    **バルブの動作時間の合計 < 周期 < 時間帯の長さ** になるように設定してください。

土が湿っているときに灌水を省くには、二つの方法があります。

- Conditional Controller で土壌水分を監視し、このシーケンスを **無効化/有効化** します（無効化すると、進行中の 1 巡はすぐに止まります）。
- バルブの行の **動的期間参照** に測定値を割り当てると、その値が動作時間（秒）として使われます。

### 3. 施設の環境制御を作る（統合環境制御） { #step-3 }

始める前に、屋内・屋外のセンサー枠（[センサーの接続 手順 7](g05-sensors.md#step-7)）と、窓やカーテンなどのデバイス
（[出力の接続 手順 7](g06-outputs.md#step-7)）を施設に結び付けておいてください。環境制御は、この結び付けだけを見て動きます。

1. **統合環境制御** を追加します（追加一覧の「カスタム機能」グループにあります）。
   歯車アイコンで設定を開き、施設がわかる名前に変更します（例：「環境制御：現場 B 温室」）。
2. **連携施設** で温室を選びます。屋内・屋外のセンサーはその施設のセンサー枠から、窓、カーテン、噴霧器は
   施設に結び付けられたデバイスから、自動的に見つけられます。温室の一部の棟だけを任せる場合は、**ベイ範囲(任意)** を選びます。
3. **温度範囲** と **湿度範囲** に、決して超えてはならない限界を入力します（既定は 12–32 ℃、40–85 %）。
4. 制御の基準は、既定では **VPD**（飽差。湿度と温度を合わせて見る）です。温度を優先したい場合は、**詳細** をオンにして、
   **制御の基準** を **温度優先** に変更します。
5. 目標は、施設内の**区画の現在のステージ**から取得します。区画がない場合は、項目 3 の範囲内でだけ動きます。
6. **保存** をクリックし、一覧で **有効化** をクリックします。

有効化した後に設定をもう一度開くと、**現在** の行に現在の値と目標（例：「湿度 78→62.5 · 温度 31→22 · 開口部 86%」）が、
**調整可能** の行にこの温室で動かせる方向（例：「温度 下げるのみ · 湿度 下げるのみ」）が表示されます。
**自動制御の対象デバイス** には、制御機能が見つけたデバイスが、オンのトグルとともに一覧表示されます。あるデバイスを自動制御から外すには、
そのトグルをオフにします。ダッシュボードの **関数ステータス** ウィジェットでも確認できます。

!!! warning "有効な間に変更した設定は適用されません"
    環境制御が有効になっている間は、設定を変更しても適用されません。**無効化 → 設定変更 → 保存 → 有効化** の順に行ってください。

!!! note "センサーの値が途絶えたときの動作"
    センサーの周期の 2 倍（最低 5 分）の間、新しい値が届かなければ、そのセンサーは途切れたものとみなされます。屋内の温湿度が途絶えると、
    その値に頼っていた判断を止め、デバイスを**その位置のまま**にします。屋外の雨や風の値が
    途絶えた場合、最後の値が雨や強風であれば窓を閉じたままにし、そうでなければそれ以上は開きません。
    そのため、センサーが途切れると、制御が止まったように見えることがあります。途切れたセンサーは [モニタリング](g09-monitoring.md) で探してください。

### 4. 機器を動かさずに試す { #step-4 }

1. 最初は、機能が**仮想出力**を動かすようにします。シーケンスの場合は各バルブの行の出力を仮想出力にし、
   環境制御の場合は仮想出力で作った窓をテスト用の施設に結び付けます。
2. [テスト入力](g05-sensors.md#step-6) で温度や湿度の値を入力して、条件を作ります。
3. 仮想出力のカードと機能の状態を見て、期待どおりにオン・オフすることを確認します。
4. 確認できたら、出力を実際のデバイスに切り替え、**機器のそばに人がいるときに**有効化します。

!!! warning "シーケンスで「すべてのアクションを実行」をクリックしないでください"
    このボタンは、アクションを順番にではなく**一度にすべて**実行します。シーケンスでは、すべてのバルブとポンプが
    同時にオンになることがあります。

### 5. 記録を見る { #step-5 }

管理 → **システムログ** をクリックすると **ログ表示** ページが開きます。機能の記録はここで確認します。機能の設定で **デバッグロギングを有効化** をオフにすると、重要な記録だけが
残るため、試験中はオンにしておき、終わったらオフにします。

## 確認 { #check }

機能を有効化した後、**決めた時刻や条件でデバイスが期待どおりの順番で動き、機能の状態にその判断が表示されれば**完了です。

- シーケンス：最初の時間帯に、バルブが順番に開閉すること、ポンプがバルブより後にオンになり、バルブより先にオフになることを確認します
- 環境制御：**自動制御の対象デバイス** に窓、カーテン、噴霧器がすべて表示され、**現在** の行に現在の値と目標の両方が表示されることを確認します
- 同じデバイスを動かす有効な機能が、二つ以上ないことを確認します

## 現場 A { #site-a }

現場 A には、2 種類の機能があります。

- **露地の順次灌水**（トリガー：シーケンス）：06:00〜16:00 に、3-1 と 3-2 の 8 個のバルブを曜日ごとに順番に開きます。
  バルブとバルブの間でポンプが止まらないように、**動作モード = 合計** にしています。これとは別のシーケンスで、夕方 16:00〜20:00 に
  3-2 だけにそれぞれ 1 時間ずつ追加で与えています。
- **温室の環境制御**（統合環境制御）：単棟温室の左右の側窓と噴霧器を、VPD を基準に動かします。
  目標は、温室内のレタスの区画のステージから取得します。レタスを収穫して区画が終わったら、制御が古い目標に従わないように、
  **区画も終了する必要があります**（[地図の構成 手順 9](g04-map.md#step-9)）。

## 現場 B { #site-b }

現場 B では、一つの統合環境制御が温室全体を担当しています。

- 連携施設：6 連棟温室
- 動かすデバイス：側窓、天窓、保温カーテン（すべて開く・閉じるをまとめた出力）、噴霧器
- 目標：トマトの区画の開花期ステージ（VPD 1.0 kPa）、安全範囲 9〜36 ℃
- 屋外の値：気象観測所の風と雨。強風や雨のときに窓を閉める根拠になります。

設定を試すために同じ制御機能を複製した場合は、使わないほうを **削除** してください。同じ名前の制御機能が二つあると、
どちらが動いているのかわかりにくく、AI に名前で依頼したときに違うほうを指してしまうことがあります。

## うまくいかないとき { #trouble }

| 症状 | 確認すること |
|---|---|
| 機能が何もしない | **有効化** したかどうか。新しい機能はオフの状態で作成されます |
| シーケンスが 1 巡を終えずに最初からやり直す | バルブの動作時間の合計が周期より長くなっています（[手順 2](#step-2) の警告を参照） |
| シーケンスが 1 日に何度も動きすぎる | 周期が短すぎます。既定の 60 秒のままにしていないか確認してください |
| シーケンスは動くがバルブがオンにならない | アクションの行の **状態** が空欄かオフになっています。**オン** に変更して、その行を保存してください |
| 環境制御の「調整可能」の一覧が空になっている | デバイスを施設に結び付けていないか、連携施設を選んでいません。**アクチュエーターを再読み込み** を実行してください |
| 環境制御が屋内の値を把握していない | 屋内のセンサーが施設のセンサー枠に入っていません（[センサーの接続 手順 7](g05-sensors.md#step-7)） |
| 窓が二つの機能の間で行ったり来たりする | 二つの機能が同じデバイスを動かしています |
| ログに何も記録されていない | ログのレベルがデバッグになっていません（[手順 5](#step-5)） |
