# インストール

Docker で AoT をインストールし、最初の管理者アカウントを作成して、正しく動作しているかを確認します。Docker は
一般的な PC・サーバー・64ビットの Raspberry Pi で同じ方法でインストールできるため、このガイドの標準の手順として使います。
Raspberry Pi に直接インストールする方法は [手順5](#step-5) で別に説明します。

このガイドでは、AoT をインストールする PC・サーバー・Raspberry Pi をすべて**コンピューター**と呼びます。

!!! note "Docker とは"
    Docker は、プログラムを実行に必要なものと一緒にまとめ（コンテナ）、どのコンピューターでも同じ方法で動かせるようにする
    無料のツールです。AoT もこのまとまり（イメージ）として配布されています。インストールは [docs.docker.com/get-docker](https://docs.docker.com/get-docker/) から行います。

    - macOS・Windows：**Docker Desktop** をダウンロードしてインストールし、起動しておきます。
    - Linux・Raspberry Pi：**Docker Engine** をインストールします。最も簡単な方法は `curl -fsSL https://get.docker.com | sh` です。

    インストール後、ターミナルで `docker compose version` がバージョンを表示すれば準備は完了です。

## この章を終えると { #goal }

- Docker で AoT を起動し、最初の管理者アカウントを作成できます
- インストールが正しくできたかを自分で確認できます

## 始める前に { #prepare }

- 64ビットの Linux・macOS・Windows のコンピューター1台（一般的な PC・サーバー、または64ビット OS を入れた Raspberry Pi 4・5）
  - 32ビット OS では Docker でのインストールは使えません。[手順5](#step-5) の直接インストールを使ってください。
- [Docker](https://docs.docker.com/get-docker/) と Compose v2
- インターネット接続（インストール用のイメージをダウンロードします）
- そのコンピューターでコマンドを入力するターミナル

## 手順 { #steps }

### 1. ダウンロードして設定ファイルを作成する { #step-1 }

```bash
git clone https://github.com/AoT-inc/AoT.git /opt/AoT
cd /opt/AoT
cp docker/.env.prod.example docker/.env
```

`docker/.env` を開き、次の4行だけを確認します。それ以外は、最初はそのままにしておきます。

| 項目 | 入力する値 | 意味 |
|---|---|---|
| `AOT_IMAGE_TAG` | [リリース](https://github.com/AoT-inc/AoT/releases) にある正確なバージョン（例：`26.09.07`） | インストールするバージョン。`latest` ではなくバージョンを書いておくと、いつ何が変わったかがわかります |
| `AOT_PORT` | `8084` | ブラウザーで開くポート。すでに使われているポートであれば変更します |
| `TZ` | 現場のタイムゾーン（例：`Asia/Seoul`） | 最初のインストール時の **システムのタイムゾーン** の初期値。その後は画面上のシステムのタイムゾーンの設定が使われます |
| `HARDWARE_PROFILE` | Raspberry Pi や小型のコンピューターは `LOW`、一般的な PC・サーバーは `HIGH` | AI 機能がコンピューターにかける負荷を決めます。制御機能は同じです |

### 2. 起動する { #step-2 }

```bash
docker compose -f docker/docker-compose.prod.yml up -d
```

初回はイメージのダウンロードに数分かかります。インストールが完了すると、四つのコンテナが実行中になっているはずです。

```bash
docker compose -f docker/docker-compose.prod.yml ps
```

| コンテナ | 役割 |
|---|---|
| `aot-app` | Web 画面 |
| `aot_daemon` | センサーの読み取りとデバイスの制御（AoT の中核） |
| `aot_mcp` | AI との接続窓口 |
| `influxdb` | 測定値の保存先 |

!!! danger "`docker compose down -v` を実行しないでください"
    `-v` を付けると、設定と測定値が入った保存領域（ボリューム）まで削除されます。停止するときは `down` だけを、再び起動するときは `up -d` だけを使います。

### 3. 最初の管理者アカウントを作成する { #step-3 }

1. ブラウザーで `http://<コンピューターの IP>:8084` を開きます。同じコンピューター上であれば `http://localhost:8084` です。
2. 最初の画面で **ログイン** をクリックします。まだ管理者がいないため、先に案内画面が表示されます。内容を読んで **承認します** をクリックします。
3. **管理者を作成** 画面で、ユーザー名・メールアドレス・パスワードを入力し、**管理者アカウントを作成** をクリックします。
   - ユーザー名：英字・数字で3〜64文字
   - パスワード：8文字以上。よく使われるパスワードは受け付けられません
4. ログイン画面で、作成したアカウントでログインします。最初に表示される画面は **リアルタイム測定** です。まだセンサーがないため、何も表示されません。

### 4. 正しく動作しているか確認する { #step-4 }

- **画面左上のロゴ**：背景色が変わらなければ正常です。赤の場合は制御の中核（デーモン）が停止しています。
  灰色の場合は Web 画面との接続が切れています。
- **管理 → システム情報**：デーモンの状態が「実行中」であること、データベースのバージョンに警告がないことを確認します。ディスクの使用量もここで確認できます。
- 問題がある場合はログを確認します。
  ```bash
  docker compose -f docker/docker-compose.prod.yml logs -f aot-app aot_daemon
  ```
  画面上では、管理 → **システムログ** で同じ記録を確認できます。

### 5. Raspberry Pi に直接インストールする（別の方法） { #step-5 }

Raspberry Pi の GPIO・I2C にセンサーやリレーを直接つないで使いたい場合は、直接インストールを使います。
Docker でのインストールでは、コンピューターの GPIO・I2C・1-Wire がコンテナの中に渡されないためです。直接インストールは
32ビット・64ビットのどちらの OS でも使えますが、測定値の保存先（InfluxDB）を使うには64ビット OS をお勧めします。

```bash
curl -L https://aot-inc.github.io/AoT/install | bash
```

- Debian 系の OS で、root 以外のユーザーとして実行します。`/opt/AoT` がすでにある場合は停止します。
- インストールが終わったら `https://<Pi の IP>` を開きます。直接インストールした AoT は自分で作成した（自己署名の）証明書を使うため、
  ブラウザーに「この接続ではプライバシーが保護されません」のような警告が表示されます。アドレスが自分の Pi であれば、先に進みます。
  - Chrome・Edge：**詳細設定** → **<Pi の IP> にアクセスする（安全ではありません）**
  - Safari：**詳細を表示** → **このWebサイトを閲覧**
  - 一部のブラウザーやアプリ内のブラウザー画面では、この警告を先に進めることができず、ページが開きません。その場合は上記のブラウザーを使ってください。
- 管理者アカウントの作成以降は、[手順3](#step-3) と同じです。

!!! warning "直接インストールでは MQTT ブローカーも一緒にインストールされます"
    直接インストールでは、コンピューターに MQTT ブローカー（ポート1883）も一緒にインストールされます。初期状態では**同じコンピューターからの
    接続だけ**を受け付けます。外部ゲートウェイのようにほかの機器がこのブローカーに接続する必要がある場合は、インストール
    コマンドを実行する前に、同じ端末で `export AOT_MQTT_LISTEN_ALL=1` を実行します。このときブローカーはネットワーク全体に
    **ログインなしで**開かれるため、信頼できるネットワークでのみ使うか、ブローカーにログインを設定してください。以前の
    バージョンでインストールしたコンピューターは、すでにネットワーク全体に開かれている場合があります。アップグレードではこの設定は
    変わらず、警告が表示されるだけです（[MQTT ブローカー](../index.md#mqtt-broker-security)）。

## 確認 { #check }

ブラウザーからログインでき、ロゴの背景が赤や灰色ではなく、システム情報でデーモンが「実行中」と表示されていれば完了です。

## 現場 A { #site-a }

現場 A は複数のゾーンと施設を1台のコンピューターで管理し、AI との接続も使うため、現場事務所の小型 PC に Docker で AoT を
インストールし、`HARDWARE_PROFILE=HIGH` にしています。LoRaWAN のセンサーは ChirpStack を経由してネットワークから
入ってくるため、GPIO は必要ありません。

## 現場 B { #site-b }

現場 B は既存の設備の値を MQTT で受け取るため、同じく GPIO は必要ありません。温室の横の制御室に64ビットの
Raspberry Pi を置いて Docker で AoT をインストールし、`HARDWARE_PROFILE=LOW` にしています。

## うまくいかないとき { #trouble }

| 症状 | 確認すること |
|---|---|
| `up -d` で、ポートがすでに使われているというエラーが出る | `docker/.env` の `AOT_PORT` を別の番号に変更します |
| イメージをダウンロードできない | コンピューターが amd64 または arm64 であるか、インターネット（`ghcr.io`）に接続できるか |
| ブラウザーでページが開かない | `aot-app` が動いているか（`docker compose ... ps` で確認）、コンピューターの IP とポートが正しいか |
| ロゴが赤い | `aot_daemon` のログを確認します。初回の起動中であれば1〜2分待ちます |
| `https://<Pi の IP>` が警告画面で止まる、または開かない | 自己署名証明書の警告です。[手順5](#step-5) のとおりに先に進んでください |
| macOS・Windows でデータベースのエラーが出る | compose ファイルの保存領域の設定を変更しないでください。フォルダーを直接マウントすると、データベースが壊れます |
