# 出力の接続

バルブ、ポンプ、ファン、噴霧器のように、AoT がオン・オフするものを**出力**と呼びます。この章では、
出力を登録し、手動でオン・オフしてみて、窓やカーテンのように「開く」と「閉じる」の 2 系統で動く設備を
一つにまとめます。また、電源が切れて復旧したときに、各出力がどの状態に戻るかを決めておきます。

## この章を終えると { #goal }

- バルブ、ポンプ、噴霧器などのデバイスを出力として登録し、手動でオン・オフする
- 開く・閉じるの 2 系統で動く窓やカーテンを、一つの出力にまとめる
- 停電や再起動の後にデバイスがどの状態になるかを決め、確認する

## 始める前に { #prepare }

- センサーまで接続した AoT（[センサーの接続](g05-sensors.md#check)）
- 接続するデバイスの情報：何でオン・オフするか（リレー、LoRaWAN バルブコントローラー、PLC、MQTT で指令を受ける機器）、
  窓やカーテンの場合は端から端まで動くのにかかる時間（秒）
- 実際の機器なしで先に試したい場合：何も必要ありません。仮想出力を使います（[手順 1](#step-1)）

!!! warning "最初の接続は、機器のそばに人がいるときに行ってください"
    出力を保存したり AoT を再起動したりすると、設定した起動時の状態が機器に送られることがあります。
    ポンプ、バルブ、窓が実際に動いても安全なときに、機器を目で確認できる人がいる状態で接続してください。

## 手順 { #steps }

### 1. 出力を追加する { #step-1 }

設定 → **出力** で、上部の一覧から種類を選んで **追加** をクリックします。選ぶ種類は、デバイスを
何でオン・オフするかによって異なります。

| 何でオン・オフするか | 選ぶ種類（一覧での名前の末尾） | 必ず入力する値 |
|---|---|---|
| Raspberry Pi のピンに接続したリレー | `Raspberry Pi GPIO`（[手順 2](#step-2)） | ピン番号、オン状態（HIGH/LOW） |
| LoRaWAN バルブコントローラー | `ChirpStack gRPC` | API Key、DevEUI |
| PLC（Modbus TCP） | `Modbus TCP Coil (PLC)` | ホスト、ポート、ユニット ID、コイルアドレス |
| MQTT で指令を受ける機器 | `MQTT Publish` | ホスト名、ポート、トピック、オンとオフのペイロード |
| **機器なしで練習** | `Virtual Single-Channel` | なし |

LoRaWAN バルブコントローラーや PLC のように、値も送り指令も受ける機器では、制御する側をここで**出力**として追加します。
同じ機器の測定値は、[センサーの接続](g05-sensors.md) で入力として別に追加します。

各出力には、**現場で呼んでいる名前そのまま**を付けます（例：「3-1 バルブ 1」「側窓 左」）。この名前は、一覧、地図、通知メールに表示されます。
「Name」や「Output 1」のような既定の名前のままにしないでください。

### 2. Raspberry Pi の GPIO・I2C で接続する { #step-2 }

リレーボードを Raspberry Pi に配線して、バルブ、ファン、ポンプをオン・オフする方法です。

!!! warning "Docker でのインストールでは使えません"
    Docker でインストールした AoT は、Pi の GPIO や I2C を使えません。[直接インストール](g01-install.md#step-5) を使ってください。
    I2C を使う場合は、[センサーの接続 手順 5](g05-sensors.md#step-5) のとおり、先に raspi-config で I2C をオンにします。

**GPIO ピンにリレーを直接接続する場合**

| Pi | 一覧での名前 | 入力する欄 |
|---|---|---|
| Raspberry Pi 4 以前 | `Raspberry Pi GPIO (Pi <= 4) [GPIO]` | **Pin: GPIO**（BCM 番号）、**オン状態** |
| Raspberry Pi 5 | `Raspberry Pi GPIO (Pi 5) [GPIO]` | 同じ |

- **ピン番号は BCM 番号です。** ボード上の物理ピン番号（1〜40）ではありません。例：物理ピン 11 = GPIO17。
- **オン状態**：リレーボードが LOW 信号でオンになる種類（市販のリレーモジュールに多い）なら、**LOW（低）** に変更します。逆の設定のままだと、
  「オフ」をクリックしたときにリレーがオンになります。最初に接続したら、まず **オフ** をクリックしてリレーがオフになることを確認してください。
- 明るさや速度を調整する PWM 出力には、`PWM: Raspberry Pi GPIO (Pi <= 4) [GPIO]` を使います。pigpio ライブラリを使うほうを
  おすすめします（一覧の灰色の説明で区別できます）。Raspberry Pi 5 用の PWM 出力はまだありません。

**I2C のリレーボードや拡張ボードを使う場合**

ピンが足りない場合は、I2C でチャネルを増やします。**I2Cアドレス** と **I2Cバス** を入力し、チャネルごとに名前、オン状態、起動時・終了時の状態を設定します。

| ボード | 一覧での名前に含まれる語 | 既定のアドレス |
|---|---|---|
| 8 チャネルの拡張チップ | `PCF8574 8-Channel` | 0x20〜0x27 |
| 16 チャネルの拡張チップ | `MCP23017 16-Channel`、`PCF8575 16-Channel` | 0x20〜0x27 |
| リレー HAT・ボード | `Grove Multichannel Relay`、`Sequent Microsystems 8-Relay HAT`、`Sparkfun Relay Board` | ボードの説明書を参照 |
| 16 チャネル PWM | `PCA9685 16-Channel` | 0x40 以降 |

アドレスは、管理 → **システム情報** の I2C アドレス表で確認します。

**避けるべきピン**

| ピン（BCM） | すでに使っているもの |
|---|---|
| GPIO2、GPIO3 | I2C |
| GPIO14、GPIO15 | UART |
| GPIO4 | 1-Wire（オンにしている場合） |
| GPIO7〜11 | SPI（オンにしている場合） |

!!! note "電源を入れた瞬間のカチッという音"
    Pi の起動中は AoT がまだピンを制御していないため、ピンが浮いた状態になったり一瞬 HIGH になったりして、リレーがカチッと鳴ることがあります。
    その瞬間にオンになってはいけない機器（ポンプなど）には、プルダウン抵抗を付けるか、起動中に LOW のままのピンを選んでください。
    [起動状態](#step-5) は、AoT が動き始めた後にしか適用されません。

### 3. 手動でオン・オフする { #step-3 }

出力カードのチャネル行にある **オン** と **オフ** のボタンをクリックします。現在の状態のボタンが濃い色で塗られます。
数秒間だけオンにするには、カードの歯車アイコンで出力設定を開き、**期間** に秒数を入力して **送信** をクリックします。

指令の確認を返す機器（LoRaWAN バルブなど）では、チャネル行に状態の文字も表示されます。

| 表示 | 意味 |
|---|---|
| 確認中… | 指令は送られ、機器からの確認を待っています |
| 応答なし | 決められた時間内に確認が届きませんでした。カードは以前の状態に戻ります |
| 接続なし | AoT が機器と通信できません |

LoRaWAN 機器では、「確認中…」が数秒から長いときは数分続くことがあります。指令は一つの待ち行列に並んで
一つずつ送られ（最低 1.5 秒間隔）、機器の種類によっては、次に機器のほうから AoT に通信してくるまで待つためです。
複数のバルブを一度に動かすと、そのぶん遅れます。詳しい動作は
[ダウンリンク：デバイスの制御](../LoRaWAN-ChirpStack.md#downlink) で説明しています。

### 4. 開閉する設備を一つにまとめる { #step-4 }

側窓、天窓、保温カーテン、遮光カーテンは、ふつう一つのモーターに「開く」リレーと「閉じる」リレーが別々にあります。
AoT では、まずこの二つをそれぞれ出力として登録し（[手順 1](#step-1)）、次に二つをまとめる出力をもう一つ作ります。

1. 設定 → **出力** で `Actuator Paired` を追加します。
   複数の窓が 1 系統のモーター電源を共用している場合は、`Actuator Paired (Shared Bus)` を選びます。
2. **アクチュエーター種類** を選びます：側面換気口、屋根換気口、保温カーテン、遮光カーテン、ボールバルブ。
3. **出力: 開く** と **出力: 閉じる** で、手順 1 で作った二つの出力を選びます。
4. **開放移動時間 (秒)** と **閉鎖移動時間 (秒)** に、端から端まで動くのにかかる時間を入力します。
   AoT はこの時間を使って、現在何 % 開いているかを計算します。わからない場合は空欄のままにし、手順 6 で測ります。
5. 保存した後、カードの **閉じる** をクリックして、完全に閉じた状態（0%）から始めます。

まとめた出力のカードには、**閉じる / 停止 / 開く** のボタンと現在の開度 % が表示されます。方向を変えるときは、
まず反対方向のリレーをオフにし、少し待ってから（**逆方向一時停止 (秒)**、既定は 5 秒）動かします。

!!! warning "まとめた後は、まとめた出力だけで動かしてください"
    まとめるのに使った「開く」や「閉じる」の出力を直接オンにしても、AoT が先に反対側のリレーをオフにするため、二つのリレーが同時にオンになることはありません。ただし、直接動かすと、
    AoT が記憶している**開度 %** が実際と食い違います。窓やカーテンは必ずまとめた出力だけで動かし、モーター側に
    電気的なインターロックがあるかどうかも設備の担当者に確認してください。

### 5. 停電・再起動後の状態を決める { #step-5 }

各出力のチャネル設定には、**起動状態** と **シャットダウン状態** があります。この値で、AoT が起動するときと
停止するときに、その出力をどうするかが決まります。

| デバイス | おすすめの起動状態 | 理由 |
|---|---|---|
| バルブ、ポンプ、噴霧器 | オフ | 電源が戻ったときに、水がひとりでに流れないようにするため |
| PLC のコイル | 何もしない、またはオフ | PLC が自身のロジックで保持している状態を AoT が覆さないようにするため |
| 開く・閉じるでまとめた窓やカーテン | （設定なし） | まとめた出力には起動状態がなく、**最後の位置**だけを記憶します |

!!! note "動作中に電源が切れた場合"
    窓が動いている途中で AoT が停止すると、再び起動したときに、記憶している位置が実際と異なることがあります。
    再起動した後は、**閉じる** を一度クリックして 0% に合わせ直してください。

!!! level-2 "関係者"
    AoT が再起動する短い間や、コントローラーの電源が入る瞬間に、リレーが一瞬カチッと鳴る機器があります。
    この動作は AoT の設定ではなく、リレーボードやコントローラーの特性です。設置する前に、
    電源を切って入れ直して確認し、問題になる場合はハードウェアで防いでください。

### 6. 移動時間を測る（窓・カーテン） { #step-6 }

移動時間がわからない場合は、束ねた出力の設定の下にある **コマンド** で、**▶ キャリブレーション開始** の **実行** をクリックし、
窓が端まで動いたら **■ 停止して保存** の **実行** をクリックします。かかった時間が移動時間として保存されます。開くときと閉じるときで
かかる時間が違う場合は、**キャリブレーション方向** を変えてもう一度測ります。

すでに値がわかっている場合は、**開放移動時間 (秒)** と **閉鎖移動時間 (秒)** に直接入力して **保存** をクリックします。
片方だけ入力すると、もう片方にも同じ値が使われます。

### 7. デバイスを地図と施設に結び付ける { #step-7 }

出力を地図上に置くと、そのデバイスがどのゾーンや施設に属するかを AoT が把握します。環境制御の機能は、この結び付けを見て、
どの窓やカーテンを動かすかを選びます。

- 露地のバルブ：地図デザイン画面のデバイスモードで出力を選んで表示し、ドラッグして所定の位置に置きます
  （[地図デザインツール](../geo/design-tool.md)）。
- 施設内の窓、カーテン、噴霧器：設定 → **施設** → 施設を選択 → **設備配置** の構成要素で、側窓、
  窓、カーテンなどのまとまりをクリックし、各枠のデバイス一覧から出力を選んで **施設を保存** をクリックします。「2個連動」と表示された枠では、
  片方を選ぶだけで、対になる枠にも同じ出力が結び付けられます（[施設管理](../geo/facility.md)）。

### 8. 参考：設定 → デバイス メニュー { #step-8 }

設定メニューには **デバイス** という項目が別にあります。コントローラーや PLC のように、自ら動作しながら入力と出力の両方を扱う機械を
一つの単位にまとめるための機能で、**まだ改良中です。** このガイドでは使いません。
機器の測定値は入力として、制御は出力として追加してください。機能が整いしだい、この節を補います。

## 確認 { #check }

各出力を手動でオン・オフしたときに、**機器が実際に動き、カードが「アクティブ/非アクティブ」に変われば**完了です。

- バルブ・ポンプ：オン → 水が出ることを自分の目で確認 → オフ
- まとめた窓：閉じる（0%）→ 50% 開く → 半分ほど開いたことを確認 → 閉じる
- AoT を再起動した後、すべての出力が設定した起動状態に戻ることを確認

## 現場 A { #site-a }

現場 A には、露地のバルブと施設の窓の両方があります。

- **露地のバルブ 8 個**（ゾーン 3-1 に 4 個、ゾーン 3-2 に 4 個）とポンプ 2 台。バルブは LoRaWAN バルブコントローラーでオン・オフします。
  一度に複数を開くと指令が順番に送られるため、最後のバルブは数秒遅れて開きます。
  名前はゾーンと順番がわかるように付けています（例：「v311」ではなく「3-1 バルブ 1」）。
- **施設（単棟温室）の左右の側窓**。それぞれ開く・閉じるの出力を `Actuator Paired (Shared Bus)` でまとめています。
  二つの窓が 1 系統のモーター電源を共用しているためです。
- **噴霧器 1 台**：オン・オフの出力。

## 現場 B { #site-b }

現場 B は、既存の施設制御設備に AoT を追加した場所です。既存の制御盤の「開く」と「閉じる」のリレーを
そのまま使い、AoT では次のようにまとめただけです。

| 設備 | 既存のリレー | AoT での設定 |
|---|---|---|
| 側窓 | 開く 1 系統、閉じる 1 系統 | `Actuator Paired`、種類 = 側面換気口 |
| 天窓 | 開く 1 系統、閉じる 1 系統 | `Actuator Paired`、種類 = 屋根換気口 |
| 保温カーテン | 開く 1 系統、閉じる 1 系統 | `Actuator Paired`、種類 = 保温カーテン |
| 噴霧器 | オン 1 系統 | オン・オフの出力 |

既存の設備を使うときは、**必ず移動時間を測り直してください。** 古いモーターは銘板の値より遅いことが多く、
開くときと閉じるときで時間が異なることもよくあります。

## うまくいかないとき { #trouble }

| 症状 | 確認すること |
|---|---|
| カードが「応答なし」に戻る | 機器の電源と通信。LoRaWAN の場合は、ゲートウェイと機器の間の電波、および機器が最近 ChirpStack に通信してきたか |
| まとめた窓が動かない | **出力: 開く/閉じる** を選び直して保存してください。出力を複製して作った場合、これらの欄は空になっています |
| 窓が端まで届かない、または動く時間が長すぎる | 移動時間が実際と異なります。[手順 6](#step-6) で測り直してください |
| 表示される % と実際の開度が異なる | 閉じるで 0% に合わせてから、もう一度試してください |
| 再起動したらバルブが開いた | その出力の起動状態がオンに設定されています |
