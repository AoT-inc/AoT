# 主な設定

インストールの直後に決めておかないと、後で混乱のもとになる設定がいくつかあります。この章では、**初日に行うこと**と
**後回しにしてよいこと**を分けて説明します。設定の多くは 管理 → **システム管理** にまとまっています。

## この章を終えると { #goal }

- 初日に必ず行う設定を、順番どおりに終えられます
- 一緒に AoT を使う人のために、適切な権限でアカウントを作成できます

## 始める前に { #prepare }

- インストールして管理者としてログインした AoT（[インストール](g01-install.md#check)）
- 現場のタイムゾーン（例：`Asia/Seoul`）
- AoT を使う人の一覧と、それぞれが行うこと（設定の変更まで行う人、見るだけの人）

## 手順 { #steps }

### 1. タイムゾーンと言語 { #step-1 }

管理 → システム管理 → **一般設定** で、次のように設定します。

- **言語**：**ブラウザーのデフォルト** にすると、各自のブラウザーの言語で表示されます。人ごとに変えたい場合は、各自が 管理 → **ユーザー設定** で設定します。
- **ランディングページ**：ログイン後に最初に表示される画面です（最初はリアルタイム測定）。ダッシュボードを作成したら、ダッシュボードに切り替えると便利です。
- **インデックスページ**：画面左上のロゴをクリックしたときに表示される画面です（最初は **ランディングページと同じ**）。
- **システムのタイムゾーン**：現場のタイムゾーンを入力します（`Asia/Seoul` のような「地域/都市」の形式）。
  デバイスやゾーンに個別のタイムゾーンがないときに使われる、最後の基準です。

システムのタイムゾーンには、インストール時に設定した `TZ` の値がすでに入っています。現場のタイムゾーンと同じであればそのままにします。変更した場合は、上部の **保存** をクリックします。

!!! note "時刻が複数の場所で決まる理由"
    AoT は、機器が複数のタイムゾーンに分散していても動作するように、デバイス → ゾーン・サイト → システムのタイムゾーン の
    順に時刻を決めます。現場が一つだけであれば、システムのタイムゾーンだけが正しければ十分です。日の出・日の入りの時刻は
    地図に描いた現場の位置から計算するため、[地図の構成](g04-map.md) も済ませておいてください。

### 2. ユーザーを作成する { #step-2 }

管理 → システム管理 → **ユーザー一覧** をクリックすると、**ユーザー設定** ページが開きます（タブ：**ユーザー一覧**・**役割一覧**・**グループ**・**一般**）。
**ユーザー一覧** タブで **ユーザーを追加** をクリックし、ログインアカウント・名前・メールアドレス・パスワード・ロールを入力します。
ログインアカウントは後から変更できません。

| ロール | できること | 対象 |
|---|---|---|
| 管理者 | すべて。ユーザー管理とすべてのグループへのアクセスを含む | システムの担当者1〜2名 |
| 編集者 | ユーザー管理を除くすべて（デバイスの操作や設定の変更を含む） | 現場の管理者 |
| モニター | 閲覧と AI への質問 | 点検者、状況を見るだけの人 |
| ゲスト | 何もできない | 使用しない |
| キオスク | カメラと統計の閲覧 | 壁掛けの画面など |

一覧に最初からある **AoT System (internal AI)** は、AI 機能が使う内部アカウントです。このアカウントでは
ログインできません。そのままにしておいてください。

管理者アカウントを複数の人で共有しないでください。一人ひとりが自分のアカウントを持っている場合にだけ、
**管理 → 監査ログ** に、誰が何を行ったかが記録されます。

### 3. グループで操作できる範囲を分ける（必要な場合） { #step-3 }

現場が複数あり、人によって担当する現場が異なる場合は、**グループ** を使います。グループは、人が**操作**できる範囲を
絞るもので、閲覧は制限しません。ダッシュボード・地図・施設の設定でグループを割り当てると、その時点から、そのグループの
人だけが操作できるようになります。現場が一つだけであれば、この手順は飛ばしてください。

### 4. ログインの保護 { #step-4 }

- パスワードを5回間違えると、アカウントが10分間ロックされます。このために行う操作はありません。
- 外部からのアクセスを許可する予定がある場合は（[ネットワーク接続](g03-network.md)）、すべてのアカウントに長いパスワードを使ってください。
- 二要素認証（TOTP）は、現在は画面から有効にできません。管理者がデータベースで設定する必要があります（[二要素認証](../Security.md#totp)）。

### 5. 後回しにしてよいこと { #step-5 }

| 設定 | 時期 |
|---|---|
| アラート設定（メールサーバー） | [メールアラート](g08-email.md) を行うとき |
| ユーザーの API キー | AI ツールを接続するとき。管理 → システム管理 → ユーザー一覧 → ユーザーの歯車アイコンをクリックして **ユーザー編集** を開く → **APIキー** の欄の **新しいキーを発行** の行に名前を入力して **生成** |
| 外部サービスのキー（気象・地図・LoRaWAN） | その機能を使うとき。管理 → システム管理 → **APIキー管理** |
| サイト名の表示 | カスタムUI → ブランドテキスト |
| 測定単位の追加と変換 | 標準の単位では足りないとき。管理 → システム管理 → 測定 |
| アップデートの確認と統計の収集 | 初期値（アップデートの確認はオン）で十分です。外部への接続を遮断している現場では、一般設定でオフにします |

**ユーザーの API キー** と **APIキー管理** は別のものです。前者は、AI ツールが AoT に入るときに使うキーです。
後者は、AoT が外部のサービス（気象・地図・ChirpStack）に入るときに使うキーです。

## 確認 { #check }

- リアルタイム測定やシステムログに表示される時刻が現場の時刻と一致していれば、タイムゾーンは正しく設定されています。
- 新しく作成したアカウントでログインし、ロールに応じてメニューが表示されたり制限されたりすることを確認します（例：モニターのロールでは出力をオンにできないはずです）。

## 現場 A { #site-a }

現場 A は、管理する機関の担当者と現場の作業者が一緒に使います。

- 管理者1名（システムの担当）、編集者2名（現場の管理者）、モニター数名（点検者と訪問者）
- 現場が一つだけなので、グループは使いません。

## 現場 B { #site-b }

現場 B は、1〜2名の運用者が使います。管理者1名と編集者1名で十分です。温室の横の壁掛けの画面には、
操作の権限がないモニターのアカウントでダッシュボードを表示しています。

## うまくいかないとき { #trouble }

| 症状 | 確認すること |
|---|---|
| 時刻が数時間ずれる | システムのタイムゾーン、および 管理 → ユーザー設定 → タイムゾーン（個人の表示用） |
| 新しいユーザーを作成するときにパスワードが受け付けられない | 8文字以上であるか、よく使われるパスワードではないか |
| アカウントがロックされた | 10分後にもう一度試すか、管理者がユーザー一覧の画面でロックを解除します |
| ある人が特定のダッシュボードだけを操作できない | そのダッシュボードにグループが割り当てられています（[手順3](#step-3)） |
