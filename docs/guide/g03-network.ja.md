# ネットワーク接続

現場に置いた AoT に事務所や自宅から接続するには、インターネットを経由して現場の AoT コンピューターまで届く**接続経路**が
必要です。ところが、現場のインターネットは通常、通信事業者の LTE ルーターや建物のルーターを経由しており、こうしたネットワークは
**外部から入ってくる接続を遮断します。** ルーターのポートを開けて（ポートフォワーディング）解決することもできますが、
グローバル IP がなかったり変わったりすることが多く、開けたポートはインターネット全体にさらされます。

この章では逆の方向を使います。**AoT コンピューターが先に外部への接続を開いておき**、利用者はその接続を通って
入ってきます。ルーターには手を加えません。これを実現するサービスとして、次の二つを扱います。

- **Tailscale**：自分の機器（AoT コンピューター・ノートパソコン・スマートフォン）をインターネット越しにまとめ、一つの
  プライベートネットワークのように使えるようにするサービスです。同じアカウントでログインした機器どうしだけが互いに見えます。
- **Cloudflare Tunnel**：AoT コンピューターから Cloudflare への接続を開いておき、自分のドメインのアドレス（例：`aot.example.com`）に
  来た訪問者をその接続に渡すサービスです。接続する人はブラウザーだけあれば使えます。

どちらのサービスも無料プランで始められます。最後に、AoT が外部に開く接続をすべて一覧にし、
現場のファイアウォールの管理者に渡せる許可リストを作成します。

## この章を終えると { #goal }

- 現場のルーターのポートを開けずに、外部から AoT に接続できます
- AoT が外部に開く接続を把握し、ファイアウォールの許可リストとして渡せます

## 始める前に { #prepare }

- Docker でインストールし、現場のネットワークで `http://<コンピューターの IP>:8084` から開ける AoT（[インストール](g01-install.md#check)）
- AoT コンピューターに接続してコマンドを入力できるターミナル
- 接続に使う機器（ノートパソコンやスマートフォン）
- 選んだ方法に応じて：Tailscale のアカウント、または Cloudflare のアカウントと Cloudflare に接続したドメイン1つ

## 手順 { #steps }

### 1. 方法を選ぶ { #step-1 }

| | 方法 A：Tailscale | 方法 B：Cloudflare Tunnel |
|---|---|---|
| 接続する人 | 少数の管理者 | 初めて訪れる人を含む多くの人 |
| 接続する機器側 | Tailscale アプリをインストール | ブラウザーだけ |
| アドレス | プライベートなアドレス（`http://<コンピューター名>:8084`） | 自分のドメイン（`https://aot.example.com`） |
| ドメイン | 不要 | 必要 |
| Web の暗号化 | Tailscale のトンネルで暗号化 | Cloudflare が提供する HTTPS |
| AoT の設定変更 | なし | `AOT_BEHIND_TLS=1` が必要 |

初めての場合は **方法 A** をお勧めします。設定が少なく、AoT の画面がインターネットに公開されません。
両方を併用することもできます（管理者は方法 A、訪問する点検者は方法 B）。

### 2. 方法 A：Tailscale で接続する { #step-2 }

1. AoT コンピューター（コンテナではなく **コンピューター自体**）に Tailscale をインストールし、ログインします。
   ```bash
   curl -fsSL https://tailscale.com/install.sh | sh
   sudo tailscale up
   ```
   画面に表示されたアドレスをブラウザーで開いてログインします。これでコンピューターが自分の Tailscale ネットワークに参加します。
2. 接続に使うノートパソコンやスマートフォンに Tailscale アプリをインストールし、**同じアカウント** でログインします。
3. Tailscale の管理コンソール（Machines）で、AoT コンピューターの名前を確認します。
4. 接続する機器で `http://<コンピューター名>:8084` を開きます。

AoT 側で変更するものはありません。`AOT_BEHIND_TLS` は **設定しないでください**。

### 3. 方法 B：Cloudflare Tunnel で接続する { #step-3 }

1. Cloudflare のダッシュボードで Zero Trust → Networks → Tunnels を開いて新しいトンネルを作成し、
   コネクターのインストール方法として **Docker** を選びます。表示されたトークンをコピーします。
2. AoT コンピューターでコネクターを起動します。`--network host` を付けて起動すると、コネクターはコンピューターのポート8084 に直接届きます。
   ```bash
   docker run -d --name cloudflared --restart unless-stopped --network host \
     cloudflare/cloudflared:latest tunnel --no-autoupdate run --token <token>
   ```
3. トンネルの Public Hostname にアドレス（例：`aot.example.com`）を追加し、サービスを
   `HTTP` · `localhost:8084` に設定します。
4. `docker/.env` に1行を追加し、AoT を再び起動します。
   ```bash
   AOT_BEHIND_TLS=1
   ```
   ```bash
   docker compose -f docker/docker-compose.prod.yml up -d
   ```
5. **Cloudflare Access で入口をもう一つ設けます。** Zero Trust → Access → Applications で
   同じアドレスを登録し、許可したいメールアドレスだけをポリシーに追加します。これで、AoT のログイン画面が
   表示される前に、Cloudflare がメールによる認証を求めるようになります。

!!! warning "`AOT_BEHIND_TLS=1` を有効にすると、現場でも HTTPS のアドレスを使う必要があります"
    この値を有効にすると、ログイン用の Cookie は HTTPS の接続でのみ送られます。現場のネットワークで `http://<コンピューターの IP>:8084`
    を開くと、ログインできません。現場でも `https://aot.example.com` を使うか、現場用に
    方法 A を併用してください。詳しい理由は
    [リバースプロキシの背後での Cookie](../Security.md#behind-tls) にあります。

### 4. 外部への接続の許可リストを作成する { #step-4 }

現場のファイアウォールが外部への接続まで遮断している場合（官公庁・学校・工場のネットワークなど）は、次の表から
**使う機能の行だけ** を選んで管理者に渡します。AoT への接続を外部から受け入れるよう依頼する必要は
ありません。

**AoT コンピューターのオペレーティングシステム**

| 用途 | 接続先 | ポート | 遮断された場合 |
|---|---|---|---|
| 時刻の同期（NTP） | オペレーティングシステムが使う NTP サーバー | UDP 123 | コンピューターの時計がずれ、スケジュールや記録の時刻が正しくなくなります |
| インストールとアップデートのイメージ | `ghcr.io` | TCP 443 | インストールとアップデートができません（動作中のシステムはそのまま動き続けます） |
| Tailscale（方法 A） | Tailscale の調整サーバーと中継サーバー | UDP 41641、TCP 443 | リモートアクセスができません |
| Cloudflare Tunnel（方法 B） | Cloudflare のトンネルサーバー | TCP・UDP 7844 | リモートアクセスができません |

**AoT が自分で開く接続 — 設定しなくても動くもの**

| 用途 | 接続先 | ポート | 遮断された場合 |
|---|---|---|---|
| 新しいバージョンの確認（48時間ごと） | `ghcr.io` | TCP 443 | 「新しいバージョン」のお知らせが表示されないだけです。設定でオフにできます |
| インターネット接続の確認（直接インストールした AoT で 管理 → アップグレード 画面を開いたとき。Docker でのインストールでは行いません） | `8.8.8.8`（一般設定の **アップグレード設定** → **インターネットテストIPアドレス**・**インターネットテストポート** で変更可能） | TCP 53 | その画面にインターネット接続がないと表示されます |

**AoT が開く接続 — その機能を設定した場合のみ**

| 機能 | 接続先（例） | ポート | 遮断された場合 |
|---|---|---|---|
| メール通知 | 設定した SMTP サーバー（例：`smtp.gmail.com`） | TCP 465 または 587 | 通知メールが送信されません |
| 気象の入力 | 追加した各入力のサーバー（`api.open-meteo.com`、`apihub.kma.go.kr`、`apis.data.go.kr`、`api.openweathermap.org` など） | TCP 443 | その入力の値だけが止まります |
| MQTT デバイス | 設定したブローカー | TCP 1883 または 8883 | そのデバイスの値と制御が止まります |
| LoRaWAN（ChirpStack） | 設定した ChirpStack サーバー | TCP 8080（API）、1883（MQTT） | デバイスの一覧取得とダウンリンクによる制御ができません |
| PLC（Modbus TCP） | 設定した PLC | TCP 502 | そのデバイスとの接続が切れます |
| 地図のオーバーレイレイヤーと住所・地番の検索 | 追加したレイヤーのサーバー（`api.vworld.kr`、`nominatim.openstreetmap.org` など） | TCP 443 | オーバーレイレイヤーが空になり、検索が動作しません |
| AI との接続 | 選んだ AI サービス（`api.anthropic.com`、`api.openai.com`、`generativelanguage.googleapis.com` など） | TCP 443 | AI とのチャットや要約が動作しません |
| Google カレンダーとの連携 | `accounts.google.com`、`oauth2.googleapis.com`、`www.googleapis.com` | TCP 443 | カレンダーの同期が動作しません |
| ほかの AoT サーバーとの接続 | 登録した AoT のアドレス | TCP 443 | リモートのデバイスの値が届きません |
| Webhook のアクションとカメラ | 入力したアドレス | そのアドレスのポート | その機能だけが失敗します |
| モジュールの依存関係のインストール | `pypi.org`、`files.pythonhosted.org` | TCP 443 | 依存関係が必要な入力や出力を追加できません |

**画面を見る人のブラウザー** — 次の項目は、AoT コンピューターではなく **接続した機器** が直接取得します。
見る人のネットワーク（事務所のファイアウォールなど）で遮断されている場合は、その人の画面でだけ表示されません。

| 用途 | 接続先 | 遮断された場合 |
|---|---|---|
| 背景地図のタイル | 選んだ背景地図のサーバー（OpenStreetMap、VWorld、Esri など） | 地図の背景が空白になります |
| フォントと一部の画面効果 | `fonts.googleapis.com`、`cdnjs.cloudflare.com` | 文字が標準のフォントで表示され、一部のアイコンや効果が表示されません |

!!! level-3 "エンジニア"
    AoT のコンテナが外部に公開するポートは、Web 画面（`AOT_PORT`、初期値 8084）だけです。
    MCP（5700）と InfluxDB（8087）は、初期設定では `127.0.0.1` でのみ開かれます。リモートの AI クライアントが
    Tailscale 経由で MCP に接続する必要がある場合は、`docker/.env` の `AOT_MCP_BIND` にコンピューターの Tailscale のアドレスを設定してください。
    `0.0.0.0` で開かないでください。

## 確認 { #check }

外部からログイン画面が開き、ログインした後にほかのメニューへ移動してもログインが保たれていれば完了です。

1. スマートフォンの Wi-Fi をオフにし（LTE を使うため）、方法 A または方法 B のアドレスを開きます。
2. ログインした後、ダッシュボード → 設定 → ダッシュボード の順に移動します。途中でログイン画面に
   戻されないことを確認します。
3. 管理 → アップグレード 画面を開き、**インストール済みバージョン** と一緒に **最新バージョン** が表示されることを確認します。AoT がインターネットに
   つながらない場合は、最新バージョンの代わりに、イメージの一覧を読み込めなかったというお知らせが表示されます。

## 現場 A { #site-a }

現場 A には露地と施設の両方があり、センサーの値は三つの異なる方式で入ってきます。そのため、許可リストには
3行が入ります。

- LoRaWAN のセンサー → ChirpStack サーバーの API（8080）と MQTT（1883）
- 気象の入力 → `api.open-meteo.com` と韓国気象庁（KMA）の API サーバー
- 施設内の MQTT のセンサー → 使用しているブローカー（1883）

管理者は方法 A で接続し、訪問する点検者には方法 B のアドレスを伝えます。

## 現場 B { #site-b }

現場 B では、既存の施設の制御設備に AoT を追加しました。センサーの値は、既存の設備側にある MQTT ブローカーから
受け取ります。そのため、ブローカーが同じ建物のネットワーク上にあれば、ファイアウォールに追加する行はほとんどありません
（NTP、イメージレジストリ、リモートアクセスの1〜2行）。リモートアクセスは方法 A だけで十分です。

## うまくいかないとき { #trouble }

| 症状 | 確認すること |
|---|---|
| ログインした直後に、またログイン画面が表示される | `AOT_BEHIND_TLS` がオフのまま HTTPS のアドレスから入ったか、オンのまま `http://` から入っています。接続方法と設定を一致させてください |
| Tailscale のアドレスが開かない | 接続する機器と AoT コンピューターが同じ Tailscale のアカウントを使っているか、両方で Tailscale が「Connected」と表示されているかを確認します |
| Cloudflare のアドレスで 502 エラーが出る | Public Hostname のサービスが `localhost:8084` になっているか、コネクターを `--network host` で起動したかを確認します |
| 地図の背景だけが空白になる | AoT ではなく **見る人のネットワーク** がタイルサーバーを遮断している可能性が高いです。別のネットワーク（スマートフォンの LTE）から開いて比べてください |
| 通知メールだけが送信されない | 通信事業者や建物のネットワークでは、メールのポート（25、465、587）が遮断されていることがよくあります。587 に変更してみてください。それでも送信できない場合は、SMTP サーバーのアドレスとポートを許可リストに追加するよう管理者に依頼してください |
