# 지도 모달 정보 구조(IA) 통일 계획

site → zone → facility → 장치(Input/Output/Function) 네 계층의 모달·팝업이
각각 따로 개발되어 문법이 갈라진 것을 하나의 정보 구조로 통일하는 계획.
**상태: 계획(미구현, 2026-08-09).** 구현 커밋이 단계별로 이 문서를 갱신한다.

관련 정본: [map-site-summary.md](map-site-summary.md) (site 요약·계층 화살표·
현재 환경 블록 — 이 계획의 선행 구현), [color-system.md](color-system.md).

## 1. 문제 — 같은 질문에 계층마다 다른 답의 자리

2026-08-09 실측 기준, 사용자가 어느 계층을 눌러도 묻는 것은 같다:
"지금 괜찮은가 → 왜 그런가/조작하려면 → 이것의 정체는 무엇인가".
그런데 답이 놓인 자리가 계층마다 다르다.

| | site | zone | facility | Input | Output/Function |
|---|---|---|---|---|---|
| 셸 | 중앙 모달 | 중앙 모달 | 중앙 모달 | 중앙 모달(공용 센서) | **지도 앵커 소형 팝업** |
| 탭 | 없음(단일) | **상태**/환경·제어/**기능** | **현황**/환경·제어/**개요** | 없음 | 없음 |
| 현재값 숫자 | 행별 대표값 | 현재 블록(신규) | 현재 블록(신규) | 차트 레전드 | 라벨의 대표값 1채널 |
| 사진 | 없음 | **[상태] 탭** | **[개요] 탭** | — | — |
| 노트 | 맨 아래 | [상태] 탭 | [현황] 탭 | 모달 하단 | 팝업 하단(1건) |
| 이력 차트 | 없음 | [환경·제어] | [환경·제어] | 본문 | **없음(의도적)** |
| 배터리·통신 배지 | 무응답 수만 | 무응답 수만 | 신규(응답 수) | 제목줄 배지 | 없음 |
| 상위 이동 | (최상위) | ← 있음(신규) | ← 있음(신규) | **없음** | **없음** |
| 빈 상태 문구 | "장치 없음: …" | "기능 없음" | "No automatic control…" | — | "No records" |

같은 정보가 계층마다 다른 탭 이름(상태 vs 현황), 다른 탭 위치(사진), 다른
표현(빈 상태 문구)에 있으니, 한 계층에서 배운 조작이 다음 계층에서 통하지
않는다. 특히 Output/Function 은 소형 팝업이 전부라 이력·노트 목록·배지로
"파고들" 곳이 없다.

## 2. 원칙

1. **단계별 공개(progressive disclosure).** 정보는 4단에서 산다:
   지도 라벨(한 줄) → 요약(모달 첫 화면/소형 팝업) → 심화(탭: 차트·제어) →
   설정 페이지. 상위 단은 하위 단의 요약이어야 하고, 하위 단으로 가는 길이
   항상 한 번의 클릭이어야 한다.
2. **같은 질문은 같은 자리.** "지금 괜찮은가"는 어느 계층이든 [현황] 첫
   블록, "정체가 무엇인가"는 [개요], 조작·차트는 [환경·제어]다.
3. **계층은 양방향.** 내려가는 길(행 클릭)과 올라가는 길(제목줄 ←)이 전
   계층에 있다. 모달 위에 모달을 쌓지 않는다.
4. **소형 팝업은 없애지 않는다.** 장치 마커의 앵커 팝업은 "지도 위에서 빠른
   제어"라는 고유 가치가 있다(이력 차트를 안 넣은 것도 anchor 높이 계산
   때문의 의도적 결정). 소형 팝업 = 요약 단, 모달 = 심화 단으로 **역할을
   나눠서** 공존시킨다.
5. **문구·단위·시각은 공용 함수로.** keyDisplay/defaultDecimals/AoTTz/
   공용 빈 상태 문구. msgid 는 뜻이 다르면 나눈다("Sensors"="센서류" 교훈).

## 3. 목표 구조 — 공통 템플릿

### 제목줄 (전 계층 동일)

```
[← 상위]  이름  [상태 점]                    [배지: 배터리·통신*]  [✕]
```
- ←: 상위 계층 모달로. site 는 없음. 장치는 소속 zone/facility →
  없으면 site. (`parent_site_for_shape` 확장: `parent_area_for_shape`)
- 상태 점: site 요약과 같은 판정(comm_fault→fault, battery/응답→warning).
  **밴드색(표시 설정)은 판정에 쓰지 않는다.**
- 배지*: 장치 모달에만 (기존 link_status 배지 그대로).

### 탭 (site 제외 전 계층 동일 키·순서·이름)

| 탭 키 | 이름 | 내용 (위→아래 순서 고정) |
|---|---|---|
| `overview` | **현황** | ① 현재 환경(buildEnvNowHtml) ② 상태 요약(운전 모드·편차·추세 / 장치는 가동 상태·작동 시간) ③ 조언·경고 ④ 노트(최근 2 + 작성/전체) |
| `envctl` | **환경·제어** | ① 이력 차트 ② 제어(액추에이터/출력 토글·슬라이더·예약) ③ 기능 목록(zone — 기능 탭을 여기로 흡수) |
| `about` | **개요** | ① 사진 ② 정체(면적·치수·소속·개수 인벤토리) ③ 설명 |

- **zone**: `상태→현황` 이름 변경, 사진·면적·개수를 [개요]로 이동,
  [기능] 탭을 [환경·제어] 하단 섹션으로 흡수(탭 3개 고정).
- **facility**: 이미 이 구조. [현황]의 노트 위치만 규칙에 맞춤.
- **site**: 탭 없이 단일 화면 유지하되 블록 순서를 같은 문법으로
  (현황성 블록 → 오늘 → 노트 → 개요성 블록). 필지는 "고를 곳"이지
  "머무를 곳"이 아니므로 탭이 오히려 방해다.
- **장치**: 아래 4절.

### 장치 2단 구조 (Phase B 핵심)

```
마커 클릭 → 소형 팝업(현행 유지: 토글·개도·작동시간·노트 1건)
              └ [자세히] → 중앙 모달(공통 템플릿)
```
- Input: 이미 중앙 모달(공용 센서 모달)이므로 제목줄 문법(← 화살표·상태 점)만 합류.
- Output/Function/3-way: 소형 팝업에 [자세히] 추가 → 중앙 모달:
  - [현황] 가동 상태·Current/Last Work Time·노트
  - [환경·제어] 가동 이력 차트(`renderOutputHistory` — **이미 있는 공용 렌더러**,
    zone 모달이 오버레이로 쓰는 `/api/geo/output/<id>/history` 재사용) + 토글·예약
  - [개요] 소속(zone/facility)·종류·채널 목록
- 소형 팝업은 그대로 둔다 — 기존 사용자의 빠른 제어 동선을 깨지 않는다.

### Phase A — 문법 통일 ✅ 구현 완료 (2026-08-09, UI 검증 일부 미완)

**popup_default_tab 하위 호환은 필요 없었다.** 이 옵션은 원래부터 facility 키

매핑 코드가 오히려 **사라졌다**(계획 §6 의 우려는 오해였다).

#### A-6 출력 행 2행 골격 (`buildOutputRow`)

on/off·PWM·개폐형이 각각 1행·2행·3행이라 목록에서 줄 높이가 들쭉날쭉했고,
"언제부터 켜져 있나"는 마커 팝업에만 있어 구역·시설 목록에서는 알 수 없었다.

```
1행 .aot-act-line : [드래그] 이름 ................ 주 제어(토글/3버튼/현재값)
2행 .aot-act-meta : 작동·예약 시간 ................ 설정(예약 버튼 / 슬라이더)
```

왼쪽은 언제나 정체·상태, 오른쪽은 언제나 조작이다. 구역 장치 목록과 시설
액추에이터 목록이 같은 빌더를 쓴다.

2행 좌측은 **작동 시간 한 칸**(`timeSlotHtml`)이다. 처음에는 정적 문구
`outputMetaHtml(rt)`(작동 중 → 예약 → 마지막 작동 우선순위)였는데, 그리는
순간의 스냅샷이라 **모달을 열어 둔 채 장치를 켜도 숫자가 그대로였다.**
자세한 것은 아래 §A-6-1.

시간 표기는 공용 `AoTTime.formatDuration`(HH:MM:SS)을 쓴다 — 마커 팝업의 작동
시간 스톱워치와 같은 표기여야 하고, 시/분/초를 단어로 쓰면 언어마다 msgid 가
셋 더 생긴다.

데이터는 신규 `POST /api/geo/output_runtimes`(배치). **`/api/geo/output_states`
에 얹지 않은 것이 요점이다** — 그쪽은 구역 모달이 5초마다 치는 폴링 경로인데,
작동 시작 시각·마지막 작동은 채널마다 influx 를 읽는다. 모달을 열 때 한 번만
받는다. 예약 시각은 서버가 장치 현지 시각대로 문자열을 만들어 보낸다
(클라이언트가 다시 추측하면 tz 해석이 두 벌이 된다).

#### A-6-1 작동 시간 한 칸 — 골격만 공용이면 부족했다 (2026-08-10)

골격(`buildOutputRow`)과 [설정] 버튼은 공용이었는데 **그 안의 시간은 아니어서**
계층마다 세 벌로 갈렸다: 시설=그릴 때 찍은 정적 스냅샷, 구역=열 때 배치로 한 번
채우고 끝, 장치 모달=스톱워치. 같은 장치가 세 화면에서 세 가지로 보였고,
구역 목록은 눈앞에서 켜고 꺼도 시간이 멈춰 있었다.

시간 칸 자체를 `aot-map-popup.js` 로 올렸다. 생성처도 갱신처도 한 곳이다.

| API | 하는 일 |
|---|---|
| `timeSlotHtml({outputId, channel, runtime, on, deferLast})` | 첫 렌더. 켜져 있으면 경과, 아니면 마지막 작동 |
| `applyTimeSlot(el, {countsRuntime, startEpoch})` | 상태 폴링이 부르는 갱신구. **바뀐 때만** 갈아 끼운다 |
| `seedTimeSlot(el, rt)` | 배치 응답으로 마지막 작동 심기(구역 목록) |
| `nextRunHtml(rt)` | 예약 시각 — 시간 칸 옆에 덧붙는다 |
| `wireTimeSlots(root)` | innerHTML 직후 배선. 보통은 안 불러도 된다(아래) |

- **한 칸이 두 상태를 번갈아 쓴다.** 꺼짐=마지막 작동, 켜짐=흐르는 타이머.
  예전의 "현재 작업 시간 / 마지막 작업 시간" 두 줄은 둘 중 하나가 늘
  `00:00:00` 이라 절반이 빈 줄이었고, 지난 기록은 이력 그래프가 이미 보여 준다.
- **문구를 두지 않고 숫자를 키웠다**(`--aot-font-size-sm`, 2행에서 가장 큰 글자).
  어느 쪽인지는 같은 행의 토글과 색(`.aot-act-time-on`)이 말하고, 좁은 줄에서
  "마지막 작동" 다섯 글자는 정작 읽어야 할 숫자를 밀어낸다. 무엇인지는 `title`.
- **배선을 호출처에 맡기지 않는다.** 호출처가 이미 여섯 곳이고 더 는다 — 한
  곳만 빠뜨리면 그 화면의 시간만 조용히 멈춘다(구역 목록이 정확히 그랬다).
  그래서 `timeSlotHtml` 이 문서 훑기를 예약하고, 아직 배선 안 된 칸
  (`_aotSwOn` 미정)만 붙잡는다. `wireTimeSlots` 는 **HTML 을 만든 tick 과
  꽂는 tick 이 다를 때**만 필요한 탈출구다(현재 호출처는 전부 같은 tick).

함정 둘, 둘 다 실제로 밟았다.

- `AoTStopwatchManager` 는 등록된 요소의 `textContent` 를 통째로 덮어쓴다.
  꺼질 때 `unregister` 를 빼먹으면 매 tick 이 마지막 작동 시간을 지운다.
- 시작 시각을 모른 채 `register` 하면 스톱워치가 **직전 가동의** `startMs` 를
  물고 있어 첫 sync 까지 엉뚱한 경과가 뜬다. 모르면 먼저 물어보고 등록한다.

개폐형(3-way)에는 시간 칸을 붙이지 않았다 — 거기서는 "얼마나 돌았나"보다
"지금 몇 %인가"가 상태다. PWM 은 듀티>0 을 가동으로 보고 붙인다.

#### 검증 상태

- **서버 ✅** — zone contents(`status`=warning, `site_name`="3포장", `env` 4종,
  센서 2/3), facility overview(`area_status`, `site`), output_runtimes 응답 형태.
  `site_name` 은 이 작업 전까지 **늘 비어 있었다**(parent_id NULL).
- **렌더 빌더 ✅** — 브라우저에서 직접 호출해 확인: 제목줄(화살표 hidden 초기값,
  상태 점 주의/오류 표시·정상 시 제거), zone [현황]=현재환경+노트 /
  [개요]=사진+인벤토리 분리, 빈 줄, 출력 행 2행(실행 중 00:12:34 / 예약 14:00 /
  마지막 작동 00:25:00 / —), CSS 적용(flex).
- **지도 위 전체 흐름 ✅** — 김제(구역 3-2)·영양(시설 육묘장)에서 확인:
  제목줄 `← 3-2 ●`(주의 점), 탭 3개(현황/환경·제어/개요), [현황]=현재 환경
  +센서 응답 2/3+노트, [개요]=사진+필지 3포장+면적+개수, 시설 [환경·제어]의
  개폐형 액추에이터가 2행(1행 이름+닫기/정지/열기, 2행 "시스템 0% · 현재 0%"
  +슬라이더), 시설 → 상위 필지 화살표 이동.
- **구역 장치 목록의 작동·예약 시간 ✅ (2026-08-10)** — 처음에는 로컬 DB의 구역
  18개 중 Output 을 품은 구역이 하나도 없어 미검증으로 남았다. 구역 3-2 에
  밸브3·밸브51 이 들어오면서 실측: 모달을 열어 둔 채 밖에서 켜면
  `00:00:29`(흐림) → `00:00:03`(진함, 흐름) → `00:00:30`(흐림)으로 따라온다.

> **검증 함정**: 브라우저 페인 탭이 `document.hidden` 이면 rAF 가 스로틀되어
> MapLibre 가 로드를 끝내지 못한다 — `map.on('load')` 가 영영 발화하지 않아
> 라벨·칩이 하나도 안 생긴다. 타일 서버는 정상인데(직접 fetch 200) 지도만
> 회색인 상태가 이것이다. **스크린샷을 연달아 찍으면 페인이 깨어나 진행된다.**

### Phase B — 장치 2단 구조 ✅ 핵심 구현 완료 (2026-08-09)

| 작업 | 결과 |
|---|---|
| B-1 [자세히] 버튼 | Output/Function·3-way 팝업 모두에 한 줄 추가. 팝업 높이 제약(anchor)을 지키려 버튼 하나만 얹었다. 누르면 팝업을 닫고 모달을 연다 — 지도 팝업과 중앙 모달이 같이 떠 있으면 어느 쪽을 보는지 알 수 없다 |
| B-2 장치 중앙 모달 | `_openDeviceModal` — 구역·시설과 같은 셸·제목줄·탭 3개. 센서 모달(`AoTSensorLabel.openPopup`)은 **건드리지 않았다**(facility fitting 과 공유되는 검증된 경로) |
| B-3 가동 이력 | [환경·제어] 탭 최초 진입 시에만 렌더(차트는 비싸다). `renderOutputHistory` + 기존 `/api/geo/output/<id>/history` |
| B-4 장치→상위 화살표 | 신규 `GET /api/geo/device/<uuid>/detail` 의 `parent`. `_wireUpBtn` 이 `kind`(zone/site/facility)에 따라 여는 모달을 고른다 |
| B-5 Input 모달 제목줄 합류 | **미착수** — 공용 센서 모달을 고쳐야 하는데 그 경로는 시설 fitting 라벨과 공유된다. 별도로 다룬다 |

#### 상위 판정 우선순위 — 좁은 것부터 (구역 > 시설 > 필지)

`parent_area_for_device()`. 마커가 필지 안에 있다는 사실은 시설 설비에 매여
있다는 사실보다 **덜 구체적이다.** 처음엔 마커를 먼저 집었더니 온실 안의
창문 모터가 "이 장치는 (같은 이름의) 필지 소속"이라고 답했다. 마커가 구역을
가리킬 때만 마커를 우선하고, 아니면 시설 바인딩을 먼저 본다.

바인딩의 `spatial_id` 는 `<시설uuid>:<슬롯>` 계약이라 앞부분으로 시설을 찾는다.

#### 검증

- 영양 `Env Coordinator`(function 마커): 팝업에 [상세 정보] → 모달(← Env
  Coordinator / 현황·환경·제어·개요), [현황]=현재+노트, [개요]=유형 사용자
  지정·위치 육묘장, [환경·제어]=이력 없음 안내, ← 누르면 상위 모달로 이동.
- `천창1`(시설 설비 바인딩 출력): `parent.kind='facility'` 로 시설을 정확히
  가리킨다. `Env Coordinator` 는 바인딩이 없어 `site` 로 떨어지는데 그것이
  이 장치가 가진 유일한 소속이다(정상).
- **미검증**: 3-way 팝업의 [자세히](로컬에 3-way 마커 없음), 권한 없는 계정.

### Phase C — 세밀 UX 개선 (일부 완료, 2026-08-09)

#### ✅ 구역 라벨의 대표값·문제 점

지도만 보고 "어디가 문제인가"를 답하게 하는 마지막 조각. 시설 bay 칩이 이미
하던 문법(2행 = 이름 + 대표값, 밴드색 배경)을 구역 라벨로 올렸다.

- 신규 `GET /api/geo/zones/status?map_uuid=` → `zone_status_for_map()` (60초 캐시).
  **구역마다 따로 물으면 안 된다** — `read_link_status_batch` 가 호출마다 데몬
  왕복을 하므로 구역 수만큼 데몬을 두들긴다. 지도 전체 장치를 모아 한 번 읽는다.
- 값이 없는 구역은 2행을 그리지 않는다("—" 만 있는 줄은 라벨만 키운다).
- 문제 점은 주의·이상일 때만, 라벨 모서리에. 이유는 `title` 로("2/3", "무응답 1").
- 실측(김제): 3-2 = 32.86°C·주황 밴드·주의 점(title "2/3"), 1-4 = 34.3°C·붉은
  밴드, 1-5/2-1 = 센서 없음이라 이름만.

**입력 라벨과 맞물린다 (2026-08-10).** 입력 라벨("1-1 28.7°C")이 떠 있는데 구역
라벨이 다시 대표값을 말하면 같은 값이 두 번 뜨고 밴드색이 두 겹으로 칠해져 어느
쪽이 기준인지 알 수 없다. 그래서 **입력 라벨이 켜져 있으면 구역 라벨은 이름만**
내고, 꺼져 있을 때만 그 몫을 대신 진다. 배선은 인스턴스 훅
(`_repaintZoneLabels`) — 라벨 토글(`addLayerPanel`)과 구역 상태 페인터는 형제
스코프라 서로 직접 닿지 않는다. 다시 칠할 때 서버를 또 부르지 않고 캐시된
`_zoneStatus` 를 쓴다.

> **함정**: 되돌릴 때 배경을 **비우면 안 된다.** 라벨의 기본 배경은 CSS 가 아니라
> 생성 시 인라인(`el.style.cssText`)으로 박히므로, 지우면 배경 없는 글자만 남는다.
> 원래 색은 `dataset.labelColor` 에 있다. 값이 사라진 구역(센서 두절)도 같은
> 이유로 마지막 밴드색을 계속 달고 있었다.

> **함정(실제로 겪음)**: `.geo-label-marker { position: relative }` 를 주면
> maplibre 의 `.maplibregl-marker { position: absolute }` 를 덮어써서 **라벨이
> 전부 전체 폭 막대로 흘러내린다**(클래스 하나끼리라 나중에 로드되는 쪽이 이긴다).
> 절대배치 기준 상자가 필요하면 라벨 요소가 아니라 **안쪽 이름 줄**에 준다.

#### ✅ 외기(`runtime.outdoor`) 노출

시설 [현황]의 현재 블록 아래 muted 한 줄("실외 32.1°C · 56.0% · 5.0m/s").
안이 더운 것인지 그냥 더운 날인지는 둘을 나란히 놔야 갈린다. 값을 크게 넣으면
실내값과 구분이 안 되므로 한 줄로 붙인다.

#### ✅ 폴리곤 클릭

예전에는 작은 라벨 알약만 눌러야 모달이 열렸다. 이제 폴리곤 전체가 눌린다 —
터치 타깃이 수십 배 커진다(특히 폰).

- `_installShapeClick()` 하나가 `queryRenderedFeatures` 로 판정한다.
  겹친 도형은 **좁은 것부터**: `facilities-fill` > `zones-fill` > `sites-fill`.
  넓은 것을 먼저 집으면 안쪽 도형을 영영 못 연다.
- 거리 측정·노트 찍기 도구가 켜져 있으면 비켜선다. 도구가 활성 상태를 커서
  (`crosshair`)로만 알려서 그것으로 판단한다 — 공용 플래그가 생기면 교체할 것.
- 라벨·칩·마커는 DOM 요소라 이 핸들러까지 오지 않는다(캔버스 클릭만 온다).
- **서버 변경 필요했다**: `_shapes_to_geojson` 이 `properties.shape_uuid` 를
  **항상** 싣도록 고쳤다. `properties.id` 는 `setdefault` 라 저장된 feature 에
  draw id 가 있으면 그게 남고, MapLibre 는 `queryRenderedFeatures` 에서 문자열
  `feature.id` 를 버린다 — uuid 를 되찾을 다른 길이 없었다.
  (시설은 `geo_overlays` 가 이미 `shape_uuid` 를 싣고 있었다.)
- 실측: 구역 안 클릭 → 구역 모달, 구역 밖·필지 안 → 필지 모달, 시설 도형 →
  시설 모달.

#### ✅ 단위 `'none'` 억제를 공용 함수로

`AoTSensorLabel.displayUnit()` 신설. `formatChannel` 과 차트 레전드
(`valueSuffix`)가 모두 거치게 해서 **한 곳에서만 판단**한다. 예전에는 값 라벨·
레전드·장치 팝업이 각각 `unit` 을 그대로 붙여 무차원 채널이 "522.0none",
"토양 정전용량: 522.0 none" 으로 나왔다.

#### ✅ 노트 날짜를 장치 현지 시각으로

`fillOverviewNotes` 가 브라우저 시각대로 `M/D` 를 찍고 있었다. 다른 지역 농장을
원격으로 보면 자정 언저리 노트의 날짜가 하루 어긋난다. `/notes/target` 이 주는
`date_tz` 로 `AoTTz.formatDevice` 를 쓴다.

> 주의: `AoTTz.formatDevice(iso, tz, opts)` 의 Intl 옵션 자리는 `opts.fmt` 다.
> 옵션을 바로 넘기면 조용히 무시되고 기본 `datetimeShort` 가 나온다.

#### ✅ 모바일 점검

폰(375×812)에서 확인: 모달 전체화면, 제목줄(← · 이름 · 상태 점) 유지, 탭 3개
가로 배치, [현황]의 현재값 4개가 한 줄에 접히고 "센서 응답 2/3" 우측 정렬,
차트가 폭에 맞게 축소. 스크롤바는 숨김 유지.

#### ⏳ 남은 항목

- 장치 모달 [환경·제어] 탭에 `aot-ov-skel` 스켈레톤(현재는 차트 자체 로딩 표시).
- 모달 내 벽시계 표기는 노트 날짜 외에 없다(작동 시간은 duration 이라 tz 무관).
  새로 추가할 때는 AoTTz 를 거칠 것.

## 5. 하지 않을 것

- **전면 리라이트 금지.** 셸(.aot-center-modal)·차트(renderHistory/
  renderOutputHistory)·노트(fillOverviewNotes)·현재 환경(buildEnvNowHtml)은
  이미 공용이다. 이 계획은 "남은 비공용 부분을 공용으로 옮기는 것"이지
  새 컴포넌트 체계를 만드는 것이 아니다.
- 소형 앵커 팝업 폐지 금지(4절). 지도 위 빠른 제어는 별도 가치다.
- 센서 모달(공용) 내부 개조 금지 — facility fitting 라벨과 공유되는
  검증된 경로. 제목줄 합류(B-5)만 한다.
- 색을 도형·응답에 되써 넣기 금지, 밴드 경계 서버 재구현 금지
  (map-site-summary.md §달라진 것 1 과 동일한 이유).

## 6. 공통 주의 (이 레포 특유)

- JS 는 `dist/aot-map-widget.bundle.js` 재빌드 + dist 커밋. CSS 는
  `AoT_map.py` 의 `?v=` 수동 증가 + 위젯 템플릿 재생성. 둘은 캐시 경로가
  다르다(map-site-summary.md §구현 시 주의).
- i18n: `.po` 서지컬 추가 + 해당 언어만 컴파일. `/api/v1/locale/js` 10분
  캐시 주의. 전체 재추출 금지.
- **정적 파일 캐시가 `max-age=31536000`(1년)이다.** `?v=` 를 올려도 브라우저가
  이전에 같은 URL 을 받은 적이 있으면 옛 내용을 쓴다. Phase A 검증 중 실제로
  겪었다 — 규칙은 서버에 있는데(curl 로 확인) 화면에는 안 먹었다.
  `fetch(url, {cache:'reload'})` 로 캐시 항목을 갱신한 뒤 새로고침하면 된다.
- **지도 위 검증은 외부 타일 소스에 의존한다.** `map.on('load')` 안에서 레이어·
  라벨·칩을 전부 만들기 때문에, 벡터 타일 소스에 못 닿으면 지도만 회색으로
  뜨고 모달을 열 수단 자체가 없다. 이때 `map.loaded()` 는 계속 false,
  `isSourceLoaded('openmaptiles')` 도 false다. 코드 문제로 오진하지 말 것.
