# 손가락으로 쓰는 화면은 기준 글자 크기가 15% 크다

> **2026-09-11 이후 손가락 화면(폰·태블릿)은 예외다** — 글자만 키우지 않고 페이지 전체를
> 키운다(문서 끝 "화면 배율" 절). 이 절의 규칙은 스크립트가 돌지 못한 경우의 안전망으로만 남는다.

데스크탑에서 읽기 좋은 크기가 폰에서는 작다. 화면이 작아서가 아니라 **보는
거리와 조준 수단이 다르기 때문**이다 — 팔 길이만큼 떨어진 화면을 손가락으로
짚는다. 모달만의 문제가 아니라 앱 전반이 같다.

```css
/* aot-base.css */
@media (pointer: coarse) and (hover: none) {
  html { font-size: 115%; }
}
```

실측(로컬, 375px): 루트 16px → **18.4px**, 본문 13.92px → **16.008px**.
데스크탑은 그대로다(16px / 13.92px).

## 왜 루트 하나인가

이 저장소의 글자 크기는 대부분 rem/em 이다. 실측:

| 단위 | 곳 |
|---|---|
| rem · em | 1,222 |
| 토큰 `var(--aot-font-size-*)` | 129 |
| px | 88 |

루트를 키우면 그 **94%가 함께 따라온다.** 토큰(`--aot-font-size-xs/sm/base/lg`)도
rem 이라 자동으로 커진다. 파일마다 미디어쿼리를 흩으면 새로 만드는 화면이 매번
그것을 기억해야 하고, 한 곳만 빠뜨리면 그 화면만 작게 남는다.

## `%` 로 쓴다 — px 로 못 박지 않는다

`115%` 는 **브라우저 기본 크기의 115%** 다. 시력 때문에 브라우저 글자 크기를
키워 둔 사람의 설정이 그대로 살아 있다. `18.4px` 로 적으면 그 설정을 덮어쓴다.

## 판정에 뷰포트 폭을 쓰지 않는다

폰을 가로로 눕히면 폭이 844px 라 `max-width: 768px` 류의 기준은 그 순간
데스크탑이라고 답한다 — **글자가 가장 작아 보이는 그때 커지기를 멈춘다.**
`pointer: coarse` 와 `hover: none` 은 회전으로 뒤집히지 않는다. 같은 이유로
`aot-map-widget-vector.js` 의 `_isDesktopClass()` 도 이 신호를 쓴다(그쪽 배경은
`.local/` 기록과 CLAUDE.md 의 타일 캐시 항목에 있다).

**태블릿도 함께 커진다.** 태블릿 역시 손가락으로 쓰는 화면이라 같은 이유가
그대로 적용된다. 폰만 고르려면 화면 크기를 봐야 하는데, 그것이 위의 회전 문제를
도로 불러온다.

## 지도 위 라벨 — 기준이 MapLibre 에 묶여 있었다

MapLibre 자체 CSS 가 `.maplibregl-map { font: 12px/20px ... }` 를 건다. 지도 위
라벨은 대부분 `em` 이라(위젯 옵션 `size_em` · `.aot-bay-chip` 0.92em …) 그 12px 가
**모든 라벨의 기준**이 된다 — 앱의 루트와 완전히 끊겨 있었다. 그래서 폰에서 앱
전체가 커져도 지도 라벨만 그대로였다.

```css
/* map/map.css — maplibre 벤더 CSS 보다 뒤에 로드된다 */
.maplibregl-map { font-size: 0.75rem; line-height: 1.667; }
```

`0.75rem × 16px = 12px`(데스크탑 **그대로**), `0.75rem × 18.4px = 13.8px`(터치
+15%). 라벨마다 미디어쿼리를 다는 대신 **기준 하나만** 바꾼다 — em 으로 쓰인
라벨이 전부 따라오고 새로 만드는 라벨도 자동으로 맞는다. 줄높이도 비율로
되돌린다(20/12 = 1.667): 고정 20px 로 두면 글자만 커져서 두 줄짜리 칩(이름+값)이
눌린다.

실측(폰): 지도 기준 12 → **13.8px**, 칩·장치 이름 14.4 → **16.56px**.
데스크탑은 12px / 14.4px 그대로.

**대가**: 라벨이 커지면 지도 위에서 서로 더 겹친다. 밀도와 가독성은 맞바꾸는
관계이고, 여기서는 가독성을 택했다.

### 범례·측정 안내도 같은 기준을 따른다

px 로 못 박혀 있던 12곳을 **12px 기준의 em** 으로 환산했다. 데스크탑 실효 크기는
그대로고(`0.833em × 12 = 10px`) 터치 화면에서만 함께 커진다.

| 요소 | 데스크탑 | 폰 |
|---|---|---|
| 범례 칩 · 제목 · 측정 안내 | 12px | **13.8px** |
| 범례 눈금 · 단위 · 길이 라벨 | 10px | **11.5px** |
| 범례 값 | 18px | **20.7px** |

`!important` 는 그대로 둔다 — 좁은 지도(`.aot-map-w-sm`)에서 범례를 줄이는
규칙이라, 없애면 작은 위젯에서 범례가 지도를 덮는다.

**새 지도 크롬에 px 를 쓰지 말 것.** px 로 적는 순간 그것만 폰에서 작게 남고,
그 사실은 옆에 커진 라벨이 있어야 비로소 눈에 띈다.

## 따라오지 않는 것

- **MapLibre 벤더 크롬**(축척 `maplibregl-ctrl-scale`, 저작권 표시) — 벤더 CSS 다.
  저작권 표시는 라이선스 준수 대상이라 함부로 건드리지 않는다
  (`project_map_attribution_compliance`).
- **지도 밖 공용 컴포넌트가 지도 위에 들어온 경우**(`.btn-sm` 등) — 부트스트랩
  크기라 지도만 따로 키울 수 없다. 앱 전역 규칙(루트 115%)을 따른다.
- **px 고정 높이**(`--aot-btn-height: 36px` 등) — 글자만 커지고 상자는 그대로다.
  15% 는 그 안에서 넘치지 않지만, 더 키우려면 geometry 토큰도 함께 봐야 한다.

## 확인한 것

`html`/`body` 어디에도 `font-size` 를 못 박은 규칙이 없다(브라우저 기본값 16px 을
그대로 쓰고 있었다) — 그래서 루트 한 줄로 충분했다. 가로 넘침은 대시보드·출력
페이지에서 `scrollWidth == clientWidth` 로 확인했다(넘침 0).

## 더 키우고 싶어지면

이 값 하나만 올린다. 다만 **가로 넘침을 페이지마다 다시 확인할 것** — 15% 는
넘침이 없었지만 그 여유가 얼마나 남았는지는 재 보지 않았다.

# 사다리를 지키는 검사 (2026-09-06)

크기를 한 번 맞춰 놓아도 다음 화면이 또 벗어나면 몇 달 뒤에 같은 문서를 다시
쓴다. 검사가 둘 있고, **규칙 함수는 하나를 같이 쓴다**
(`_abs_font_size_offenders`). 규칙이 두 벌이 되면 한쪽만 고쳐지는데, 그것이
애초에 사다리가 두 벌이 됐던 경위다.

| 검사 | 범위 |
|---|---|
| `aot/tests/test_widget_ui_conventions.py` | 위젯 파이썬 + `static/css/widget/*.css` |
| `aot/tests/test_css_conventions.py` | 그 나머지 — 페이지 CSS · AoT 테마(`bootstrap-4-themes/aot.css`) · **템플릿 인라인 `style=`** |

서드파티 부트스트랩 테마 20종, vendor, `*.min.css` 는 우리가 쓴 것이 아니라
받아 온 것이라 사다리를 강요하지 않는다.

**템플릿 인라인도 본다** (2026-09-07). CSS 파일 밖이라 사다리 검사가 닿지 않던
사각지대였다 — 감사 시점에 193곳. 통과시키는 것은 둘이다: 서버가 채우는
Jinja 값(`{{ }}`)과 **토큰**(`var(--aot-…)`). 인라인이어도 사다리 위에 있으면
되고, 이미 107곳이 그렇게 쓴다. 상한을 비우는 것은 별건(계획 11번)이다.

반투명 `rgba()` 35곳은 **일부러 안 본다** — 거의 전부 그림자와 스크림이고,
그것들이 가야 할 그림자·높이 사다리가 아직 없다. 갈 곳이 없는 것을 막으면
검사가 통과할 수 없는 요구를 하게 된다. 그 사다리를 세울 때 함께 켠다.

모서리 사다리(`--aot-radius-*`)도 같은 파일이 같은 방식으로 지킨다.

**`!important` 도 같은 파일이 센다** (2026-09-07). 다만 이것만 목표가 0 이
아니다. 앞의 셋은 사다리에서 고르면 되는 일이지만, `!important` 는 부트스트랩을
이겨야 하는 자리가 실제로 있고 그 자리의 것은 일을 하고 있다. 브라우저에서
직접 떼어 보고 잰 결과 — 22개 화면·모달 열린 상태·어두운 테마까지 — 펼친 선언
3,887개 중 **627개(16%)만 실제로 무언가를 이긴다.** 그래서 상한은 0 이 아니라
현재 수치이고, 내려가기만 한다.

새로 붙이려 할 때 먼저 물을 것은 **"무엇을 이기려고 붙이는가"** 다. 이기려는
상대가 우리 CSS 라면 선택자를 고치는 쪽이 답이다. 1·2차로 걷어낸 412회가 거의
전부 그런 자리였다 — 우리가 우리 걸 덮고 있었다.

재는 방법에는 함정이 둘 있고, 둘 다 실제로 밟았다.

**`@media` 안은 그 조건에서 재야 한다.** 조건부 블록은 그 조건이 성립하는
화면에서만 적용되므로, 데스크톱 폭 하나에서 재면 좁은 화면·인쇄에서만 하는
일이 "아무 일도 안 함" 으로 보인다. 1차에서 39곳을 그렇게 지웠다가 되돌렸고,
5차에서 **폭 320·500·700·800·1400px 다섯 자리**를 돌며 `matchMedia` 로 그때
성립하는 블록만 골라 다시 쟀다. `@media print` 는 흉내 낼 수단이 없어 남겼다.

**한꺼번에 떼서 잰 결과는 일부만 뗄 때 그대로 성립하지 않는다.** 남긴
`!important` 가 다른 자리를 이기기 시작한다. 지울 목록을 정한 뒤 **그 상태로
다시** 편집본·원본을 나란히 켜서 대조해야 한다.

**JS 가 인라인으로 쓰는 속성도 재지 않은 것이다.** `display` 가 대표다 —
jQuery `.show()`/`.hide()` 는 인라인 스타일을 쓰고, 인라인은 `!important` 아닌
규칙을 전부 이긴다. 정지 화면에서 "아무 일도 안 한다" 여도 JS 가 인라인을 심는
순간부터 일을 한다.

**`:hover` 같은 상태도 재지 않은 것이다.** 평상시 화면만 재면 상태에서만 하는
일이 안 보인다 — `.btn-primary` 의 배경색은 평상시엔 순서만으로도 이기지만
부트스트랩의 `.btn-primary:hover` 는 명시도가 더 높다. 같은 속성을 건드리는 상태
규칙이 같은 요소에 걸리면 후보에서 뺀다(3차에서 361개 중 84개가 그랬다).

## 죽은 규칙은 저장소 전체로 잰다

`aot/scripts/check_dead_css.py` — CSS 가 쓰는 클래스·id 이름을 모아, 마크업을
만들 수 있는 모든 파일(템플릿·파이썬·JS 소스·번들·벤더)에 그 이름이 한 번이라도
나오는지 본다. **브라우저로는 죽음을 증명할 수 없다** — 화면을 아무리 돌아도
"이 화면에는 없다" 까지다.

    python3 aot/scripts/check_dead_css.py            # 보고
    python3 aot/scripts/check_dead_css.py --apply    # 삭제

2026-09-07 에 이 방법으로 규칙 181개(1,342줄)를 걷어냈다. 검사기 자신이 틀리는
자리(쉼표 목록·잘라내는 범위·주석)는 `aot/tests/test_dead_css_audit.py` 가 못을
박아 두었다.

**`--apply` 뒤에는 반드시 전체 테스트를 돌린다.** 안 쓰이지만 **계약으로 있어야
하는** 규칙이 있다 — `.aot-notice-box-info` 는 성공·위험·경고·정보 네 톤 한 벌의
일원이라 마크업에 없어도 지우면 계약이 깨진다. 안 쓰인다는 것과 있어선 안 된다는
것은 다르고, 그 경계를 정하는 것은 계약이다.

## `!important` 를 뗄 때 — **짝**을 봐야 한다 (2026-09-07, 회귀 1건)

`!important` 제거 감사가 대시보드에 회귀를 남겼다. 사용자가 "탭바와 위젯 사이
여백이 과거보다 많이 늘었다" 고 알려 와서 찾았다.

    .aot-sticky-tabs { margin-bottom: 50px !important; }   공용(다섯 화면)
    #dash-sticky     { margin: 0 !important; }             대시보드만

`!important` 끼리 붙으면 승자는 **특이도**가 가른다. ID 인 `#dash-sticky`
(1,0,0)가 클래스인 `.aot-sticky-tabs`(0,1,0)를 이겨, 대시보드 여백은 0 이었다
(위젯 격자가 `padding: 1em` 을 이미 갖고 있다).

감사가 `#dash-sticky` 쪽 `!important` 를 "아무 일도 안 한다" 로 판정해 뗐다.
**그 판정 자체는 맞다** — 그 선언은 다른 평범한 선언과 다투고 있지 않았다.
문제는 상대가 `!important` 였다는 것이다. 한쪽만 떼자 승자가 뒤집혔다.

| | 탭바 아래 → 첫 위젯 |
|---|---|
| 예전 | **14px** |
| 회귀 후 | **64px** |
| 지금 | **14px** |

### 왜 A/B 가 못 잡았나

측정은 **화면에 있는 요소**만 잰다. 대시보드는 프로브 페이지 집합에 없었고,
`#dash-sticky` 는 대시보드에만 있다. **그 요소가 화면에 없으면 그 규칙은
"아무 일도 안 한다" 로 보인다** — 이 함정은 감사 문서에 이미 적혀 있었고
(약 400곳이 그랬다), 이번 것이 그 400곳 중 하나였다.

### 고친 방법 — 되붙이지 않았다

`#dash-sticky` 에 `!important` 를 되붙이는 대신 **공용 쪽에서 뗐다.**

    .aot-sticky-tabs { margin-bottom: 50px; }   ← !important 없음

둘 다 평범한 선언이 되어 특이도만으로 갈린다. 대시보드는 ID 가 이겨 0,
나머지 네 화면(입력·출력·함수·프로그램)은 경쟁 규칙이 없어 50px 그대로다.
**`!important` 총계는 오히려 하나 줄었다.**

`test_shared_sticky_tabbar_margin_has_no_important` ·
`test_dashboard_sticky_keeps_zero_margin` 이 짝을 지킨다. 둘 다 일부러
어겨서 잡히는 것을 확인했다.

### 남는 규칙

**`!important` 를 뗄 때는 같은 속성을 다투는 다른 `!important` 가 있는지 먼저
본다.** 있으면 그 자리는 "아무 일도 안 하는" 자리가 아니라 **특이도로 갈리는
짝**이고, 한쪽만 떼면 승자가 뒤집힌다.

## 같은 선택자가 두 벌일 때 — 승자가 로드 순서면 결함이다 (2026-09-07)

토글 스위치의 정의가 **세 벌**이었다.

| 파일 | 선택자 | 켜짐색 | 실렸나 |
|---|---|---|---|
| `components/aot-toggle.css` | `.btn-toggle*` | `--aot-band-3` | 실린다(정본) |
| `bootstrap-4-themes/aot.css` | 같은 `.btn-toggle*` | `--primary`(= 흰색) | 실리지만 늘 진다 |
| `components/btn-toggle.css` | `.switch` `.slider` | `#5fdd54` 하드코딩 | **아무 데서도 안 실린다** |

셋째는 죽은 파일이라 지우면 된다(`.switch`/`.slider` 마크업도 0곳). 문제는
둘째다 — **같은 선택자에 다른 값**이고, 어느 쪽이 이기는지가 순전히
`layout.html` 의 `<link>` 순서였다. 지금은 정본이 뒤에 실려 늘 이기지만,
링크 한 줄을 옮기면 켜진 스위치가 흰색이 된다.

### 지우기 전에 물어야 할 것: **전부** 덮이는가

덮인다고 다 죽은 것은 아니다. 지는 블록에도 **정본에 없는 선언**이 있으면
그 줄만은 살아 있다. 여기서 두 개가 그랬다.

- `margin: 0` — `.btn-toggle` 은 `<label>` 로도 붙는다(76곳). 부트스트랩
  reboot 의 `label { margin-bottom: .5rem }` 을 이 한 줄이 막고 있었다.
- `align-self: center` — `align-items: stretch` 인 행에서 세로로 늘어나지
  않게 한다.

블록을 통째로 지웠다면 토글 아래에 8px 이 생기고 행에서 늘어났을 것이다.
**선택자 단위가 아니라 선언 단위로 대조한다.**

셋째 파일을 지우면서 같은 어휘의 마지막 잔재도 나왔다 — `.switch-label` 은
`aot-toggle.css` 에 남아 있었지만 마크업에 0곳이고, 죽은 CSS 감사기의
**벤더 예외 목록**에 들어가 있어 안 잡혔다. 우리 클래스인데 "라이브러리가
런타임에 붙이는 이름" 칸에 있었던 것이다. 규칙과 예외를 함께 지웠다.
**예외 목록은 검사를 무디게 한다 — 넣을 때 근거를 적고, 근거가 사라지면 뺀다.**

### 확인 방법 — 원본 사본을 옆에 두고 잰다

`git show HEAD:<경로>` 로 수정 전 파일을 사본으로 꺼내, 그것만 다르게 부르는
프로브 두 벌을 만들고 계산값을 통째로 비교했다(토글 4종 × 컨테이너·슬라이더·
손잡이 × 11속성 × 라이트/다크 = 272개). **차이 0.**

⚠ 두 번 헛디뎠다.

- **캐시.** 프로브 HTML 만 `?v=` 를 바꾸면 CSS 는 옛것이 그대로 온다.
  링크마다 캐시버스터를 붙여야 한다.
- **`link.disabled` 로 테마를 갈면 전이가 얼어붙는다.** 창이 보이지 않는
  상태에서는 `transition` 이 진행되지 않아, 색이 **시작값에 멈춘 채로**
  계산값에 나온다(다크로 바꿨는데 슬라이더가 계속 `#dddddd` 였다). 테마는
  URL 로 정해 **새로 로드**해서 잰다.

## 사다리

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--aot-font-size-2xs` | 0.7rem (11.2px) | 조밀한 상세 라벨 |
| `--aot-font-size-xs` | 0.75rem (12px) | 캡션·타임스탬프·배지 |
| `--aot-font-size-sm` | 0.875rem (14px) | **기준** — 본문·행 라벨·값·단위 |
| `--aot-font-size-base` | 1rem (16px) | 컨테이너 제목 |
| `--aot-font-size-lg` | 1.125rem (18px) | 단락 제목 · 값 한 단 아래 |
| `--aot-font-size-xl` | 1.5rem (24px) | 페이지 제목 · 측정값·게이지 중앙 |

역할 이름(`--aot-fs-title` · `--aot-fs-body` · `--aot-fs-value` …)은 위 단들을
가리키기만 한다. 읽기 쉬운 쪽을 쓴다.

**어느 역할이 어느 단을 쓰는지는 `ui-guide.md` §2-3 역할표가 정본이다**
(2026-09-11 확정: 페이지 제목 24 · 단락 제목 18 · 컨테이너 제목 16, 제목 굵기 500).
이 표의 "쓰임" 은 그 요약이다.

## 고치기 전에 켰다 — 상한은 내려가기만 한다

앱 쪽 검사를 켤 때 위반이 **152곳** 남아 있었다. 다 고친 뒤에 켜는 것이 깔끔해
보이지만 그러면 고치는 동안 새것이 계속 들어온다. 위젯 작업에서 확인된 순서가
있다 — 검사를 먼저 세우자 **그 검사가 곧바로 18곳을 더 잡았다.**

그래서 그 시점 수치를 `_FONT_SIZE_BUDGET` 에 파일별로 박았다.
**2026-09-07 에 그 표를 0 으로 비웠다** — 지금은 상한이 없으므로 절대 크기가
하나라도 들어오면 즉시 걸린다. 검사 셋이 함께 움직인다:

- 늘면 막는다.
- **줄었는데 표를 안 내리면 그것도 막는다.** 상한이 실제보다 높게 남으면 그
  차이만큼 새 위반이 조용히 들어올 자리가 된다.
- 표가 없는 파일을 가리키면 막는다(삭제·이름 변경).

**그래서 이 표가 곧 남은 작업 목록이었다.** 152 → 0 으로 비우는 데 커밋 여섯이
들었고, 표가 매번 다음 파일을 지목했다.

## 벗어나야 할 때 — 이유를 적는다

```css
/* 사다리 예외: 고정 크기 원형 배지 안에 그리는 SVG 숫자다. 사다리 최소단
   (2xs = 11.2px)이면 원 밖으로 넘친다 — 원을 키우면 지도 위 마커가 커진다.
   본문 글자가 아니라 도형에 갇힌 글자라 도형이 크기를 정한다. */
font-size: 9px;
```

`사다리 예외:` 뒤에 **열 글자 이상**을 적어야 통과한다. 빈 표시나 "짧음" 같은
말은 검사가 그대로 막는다(그렇게 동작하는지 역검증해 두었다).

**상한부터 올리지 않는다.** 올려야 한다고 판단했다면 왜 그 자리가 사다리
밖이어야 하는지가 먼저 있어야 하고, 그 이유는 예외 주석으로 적을 수 있다.

## `em` 은 왜 안 보는가

`em` 은 "사다리에서 고르는 크기" 가 아니라 **담는 상자를 따라가는 장치**다.
그래서 검사는 **체인의 뿌리**(px·rem)만 본다 — 뿌리가 사다리에 있으면 가지는
저절로 사다리 위에 선다. 자세한 근거는 `_abs_font_size_offenders` 의 독스트링과
`aot-sensor-label.css` 주석에 있다(전역 rem 으로 끌어왔다가 "화면마다 비율이
어긋난다" 로 되돌린 기록).

앱 쪽 위반 152곳을 셀 때도 `em` 101곳은 대상에서 뺐다. 원래 계획서가 "266곳"
으로 적었던 것이 실제로는 152곳인 이유다.

# 화면 배율 — 스마트폰·컴퓨터 (2026-09-11)

글자만 15% 키우는 위의 방식은 px 로 박힌 폭·높이·버튼·아이콘이 따라오지 않아
"같이 커지지 않는 요소가 너무 많다"(사용자). 고령 농업인(경영주 평균 67.7세,
2025 농림어업총조사)에게는 글자 크기표를 한 단씩 올리는 시안도 여전히 작았다.
그래서 **스마트폰은 페이지 전체를 키운다.**

| 항목 | 값 |
|---|---|
| 대상 | 모바일 — 손가락 화면(`pointer: coarse` + `hover: none`) 전부, **폰과 태블릿**(2026-09-11 사용자 결정으로 태블릿 포함). 컴퓨터는 아래 "컴퓨터도 고른다" |
| 기본값 | **115%** — 로그인 전 화면(로그인·비밀번호 찾기 등)도 같다 |
| 사용자 설정 | 계정 모달 "모바일 화면 크기", 90~150%·5 단위(`users.ui_zoom_phone` — 이름은 폰 전용이던 때 그대로, 비우면 기본값) |
| 적용 | `templates/_screen_zoom.html` — `<meta name="viewport">` 바로 뒤, 화면을 그리기 전에 돈다 |
| 글자 115% 규칙 | 모바일에서는 끈다(`html.aot-mobile`). 둘 다 걸리면 글자가 1.32배가 된다 |

## 컴퓨터도 고른다

"데스크탑에서 문자 크기가 작아서 매번 확대해서 읽어야 한다"(사용자) — 계정 모달
"컴퓨터 화면 크기"(`users.ui_zoom_desktop`, 90~150%·5 단위). **기본값은 100%** 라
고르기 전에는 아무것도 바뀌지 않는다. 대상은 마우스 화면(`hover: hover` +
`pointer: fine`)이고, 데스크톱 브라우저는 뷰포트 메타를 쓰지 않으므로 CSS zoom 만
쓴다.

## 확대 방식이 둘이다

- **뷰포트 확대**(안드로이드 등): 뷰포트 폭을 기기 폭 ÷ 배율로 알린다. 두 손가락
  확대와 같은 원리라 모든 것이 같이 커지고 지도 좌표도 그대로다.
- **CSS zoom**(iPhone·iPad — 사파리·크롬 모두 WebKit, 그리고 컴퓨터): 좁은 뷰포트 폭을 받지
  않는다(2026-09-11 사용자 폰 실측). `html` 에 `zoom` 을 걸고 `--aot-zoom` 을 함께 심는다.
  iPadOS 사파리는 Mac 으로 자기를 소개하므로 "터치 되는 Mac" 을 iPad 로 본다.

## CSS zoom 의 함정 — 뷰포트 단위

CSS zoom 아래에서는 `vw`·`vh`·`dvh` 에도 배율이 **한 번 더** 곱해진다. 125% 에서
`100vw × 100dvh` 가 1280×900 화면에 1600×1125 로 그려졌다(지도 위젯 전체화면).
그래서 뷰포트 단위는 배율로 나눈 토큰으로만 쓴다:

```css
height: calc(100 * var(--aot-dvh));
max-height: min(80 * var(--aot-vh), 760px);
```

`--aot-vw` / `--aot-vh` / `--aot-dvh` 는 `aot-theme-variables.css` 에 있고,
`--aot-zoom` 이 없으면 1 이라 원래 단위와 같다. 원시 단위는
`test_viewport_units_go_through_zoom_tokens` 가 막는다(자체 CSS·위젯 CSS).
템플릿 `<style>`·위젯 파이썬·JS 문자열 속 뷰포트 단위도 같은 토큰으로 바꿨다.

**전체화면은 크기 대신 네 변으로 잡는다.** `position: fixed` 에 `inset: 0` 이면
배율과 무관하게 화면에 맞는다(`.aot-map-pseudo-fullscreen`).

**아직 남은 것:** JS 가 `window.innerWidth/innerHeight` 로 잰 값을 px 로 박는 자리는
CSS zoom 아래에서 배율만큼 커진다. 넘치는 창이 보이면 그 자리다.
