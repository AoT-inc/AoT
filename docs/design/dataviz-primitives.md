# 데이터 시각화 프리미티브 — 밴드 바 · 불릿 · 기간 바

지도 위젯 모달(site · zone · facility · plot)과 앱 화면이 공유하는 표준
그래픽 3종. 구현은 두 파일뿐이다.

| | 파일 |
|---|---|
| 모양·색 | `aot/aot_flask/static/css/components/aot-dataviz.css` |
| 값 → 위치(%) 계산 | `aot/aot_flask/static/js/common/aot-dataviz.js` (`window.AoTViz`) |

## 왜 만들었나

모달의 [현황]·[개요]는 전부 라벨-값 텍스트 행(`_pRow`)이다. 그래서 "지금
정상인가" · "목표 대비 얼마나 왔나" · "다음 단계까지 며칠인가" 를 사람이
숫자를 읽고 매번 계산해야 한다. 값을 **위치**로 바꾸면 그 계산이 사라진다.

세 가지를 각자 만들지 않은 이유는 톤 때문만이 아니다. 값을 %로 바꾸는 계산이
버그가 사는 자리이고(범위가 뒤집힌 경우 · 폭이 0 인 경우 · 범위를 벗어난 경우 ·
값이 아예 없는 경우), 화면마다 각자 나누기를 하면 그 네 가지를 각자 틀린다.

## 하나의 골격

셋은 같은 마크업이다. 켜는 부품만 다르다.

```
.aot-viz-head     라벨 + 값
.aot-viz-track    전체 범위 — 중립 회색
  .aot-viz-ok       적정 구간 / 현재 단계 구간
  .aot-viz-fill     실측 막대            (불릿)
  .aot-viz-tick     구간 경계            (기간 바)
  .aot-viz-now      현재 위치            (밴드 · 기간 바)
  .aot-viz-target   목표 눈금            (불릿)
.aot-viz-scale    양 끝 눈금
```

## 색은 셋뿐이고, 세 컴포넌트에서 뜻이 같다

| 역할 | 뜻 | 토큰 | custom_ui 필드 |
|---|---|---|---|
| 트랙 | "전체 범위" | `--aot-color-text-primary` 10% 혼합 | `text_color_primary` |
| 구간 | "여기다" | `--aot-color-success` 45% 혼합 | `color_success` |
| 마커 | "이 지점" | `--aot-color-text-primary` | `text_color_primary` |

**셋 다 settings/custom_ui 가 제어하는 필드다**(`forms_settings.THEME_COLOR_FIELDS`).
custom_ui 가 제어하지 않는 색을 여기에 새로 넣지 말 것 — 운영자가 테마를 바꿔도
이 컴포넌트만 옛 색으로 남는다.

역할이 같으면 **색도 모양도 같아야 한다.** 불릿의 채운 막대는 밴드 바의 적정
구간과 같은 초록이고(둘 다 "여기다" 를 말하는 면이다), 불릿의 목표 눈금은
밴드 바의 현재 마커와 같은 마커다(둘 다 "이 지점" 이다). 트랙 높이와 라운드도
셋이 같다. 여기서 하나라도 갈라지면 세 블록이 나란히 놓였을 때 서로 다른
그림처럼 읽힌다 — 실제로 한 번 그렇게 만들었다가 되돌렸다(불릿만 진한 회색
막대 + 달성 시 밝은 초록, 트랙 높이 10/14/12px).

**줄마다 색을 바꾸는 손잡이를 두지 않는다.** 한 화면에 여러 줄이 서로 다른
색으로 서면 그것이 곧 "제각각" 이다. 지표를 구분하는 것은 색이 아니라 왼쪽의
이름이고, 계열별 색이 필요한 자리는 그래프 위젯이다. 같은 지표를 단계별로
여러 색으로 칠하지도 않는다 — 단계는 위치가 말한다.

**목표 달성도 색으로 말하지 않는다.** 막대가 목표 눈금을 넘었는지로 읽는다.
달성색을 하나 더 두면 같은 화면의 밴드 바·기간 바와 톤이 갈린다.

**트랙을 회색 토큰(`--aot-bg-off` 등)으로 칠하지 말 것.** 그 토큰들은 다크
재정의가 `custom-dark.css` 에 없어 값이 갈리지 않는다 — 어두운 카드 위에서
밝은 회색 덩어리가 된다. 글자색을 섞으면 두 테마 모두에서 "배경보다 한 단계
진한 면" 이 된다.

## 눈금 줄도 규칙이 하나다

양 끝은 축의 끝을 적고, **가운데는 그 줄의 기준**을 적는다. 기준은 가운데
고정이 아니라 **가리키는 것의 실제 위치**에 붙는다.

| | 가운데 라벨 | 붙는 위치 |
|---|---|---|
| 밴드 바 | 적정 범위 | 적정 구간의 중앙 |
| 불릿 | 목표 | 목표 눈금 |
| 기간 바 | 오늘 | 오늘 마커 |

가운데 고정으로 두면 기준이 왼쪽 끝에 있는데 라벨은 가운데 있어, 둘이 서로
다른 것을 가리키는 것처럼 읽힌다. 양 끝 12% 안쪽이면 끝에 붙여 세우고 같은
쪽 축 라벨을 가린다 — 축의 끝은 트랙이 이미 보여 주지만 기준은 이 라벨 말고
적을 자리가 없다.

## 어느 것을 쓰나

| 질문 | 쓰는 것 |
|---|---|
| 지금 값이 적정 범위 안인가 | `AoTViz.band` |
| 쌓아서 도달하는 목표에 얼마나 왔나 | `AoTViz.bullet` |
| 전체 일정에서 지금 어디인가 | `AoTViz.timeline` |

**불릿을 상·하한 목표에 쓰지 말 것.** "주간 최고온도 28°C 이하" 를 불릿으로
그리면 막대가 채워질수록 잘하고 있는 것처럼 읽히는데 실제로는 정반대다.
그런 목표는 밴드 바가 맞다. 그래서 `bullet` 에는 적정 구간 인자가 아예 없다 —
구간이 필요하다는 것 자체가 밴드 바여야 한다는 뜻이다.

## 쓰는 법

```js
AoTViz.band({
  label: _t('Air temperature'), value: 26.4, valueText: '26.4', valueSub: '°C',
  min: 10, max: 40, okMin: 22, okMax: 28,
  scale: ['10', { text: okRangeText, anchor: true }, '40']
});

AoTViz.bullet({
  label: _t('Daily irrigation'), value: 1.8, target: 2.4,
  valueText: '1.8', valueSub: '/ 2.4 L',
  scale: ['0', { text: targetText, anchor: true }, '3.0']
});

AoTViz.timeline({
  label: stageName, valueText: 'D22', valueSub: '/ 98',
  segments: [{span: 14}, {span: 7}, {span: 20, current: true}, {span: 22}, {span: 35}],
  positionPct: 22.4,
  scale: [startText, { text: todayText, anchor: true }, endText]
});

AoTViz.group([ rowA, rowB, rowC ]);   // 줄 사이 여백만 담당
```

반환은 **HTML 문자열**이다 — 지도 팝업 빌더(`aot-map-popup.js`)가 문자열을
이어 붙이는 방식이라 거기에 그대로 섞인다.

### 상태 플래그

| 인자 | 뜻 | 화면 |
|---|---|---|
| `stale: true` | 값이 오래됐다 | 값과 마커를 흐리게. **숨기지 않는다** |
| (자동) 범위 밖 | `okMin`/`okMax` 를 벗어남 | 값 글자만 위험색. 막대 색은 늘리지 않는다 |
| (자동) 값 없음 | `value` 가 없거나 범위가 성립 안 함 | 마커를 그리지 않는다. 0 으로 그리면 "없음" 이 "가장 낮은 값" 으로 읽힌다 |

## 문구는 만들지 않는다

라벨·값·눈금은 **이미 번역·서식된 문자열**을 받는다. 서식(소수점 자릿수·단위·
날짜)은 부르는 쪽이 이미 알고 있고, 번역 문구를 빌더에서 만들면 msgid 가 그
파일에 갇힌다. 특히 리터럴 `%` 는 babel 이 python-format 으로 읽어
`pybabel compile` 이 **그 언어 전체를 거부한다**(CLAUDE.md 의 리터럴 % 금지).

## 여백

값 두 개가 리듬을 만든다. 둘 다 `.aot-viz` 와 `.aot-viz-group` 양쪽에 정의돼
있다 — 묶음이 아래 여백을 계산할 때 `tail` 을 읽어야 하는데 부모는 자식의
커스텀 속성을 못 읽기 때문이다.

| 변수 | 기본값 | 뜻 |
|---|---|---|
| `--aot-viz-tail` | 16px | 한 줄이 **자기 아래에 갖는 몫** |
| `--aot-viz-gap` | 34px | 줄과 줄 사이의 **전체** 거리 |

**`gap` 은 줄 안의 여백(제목 6 + 눈금 6 = 12px)의 배 이상이어야 한다.** 좁으면
앞 줄의 눈금이 다음 줄의 제목에 붙어 한 덩어리로 읽히고, 어느 눈금이 어느 막대의
것인지 매번 되짚게 된다 — 그 되짚음이 곧 "복잡해 보인다" 이다. 묶음의 경계는
선이 아니라 여백이 만든다. 20px 로 만들었다가 좁다는 지적을 두 번 받고 34px 로
왔다.

**`tail` 은 담는 카드의 모서리 라운드 이상이어야 한다.** `.aot-ov-block` 은
`border-radius: 16px` 인데 세로 padding 이 10px 뿐이라, 그냥 넣으면 마지막 줄의
눈금이 둥근 모서리 안쪽으로 들어가 테두리에 닿는다. 라운드가 더 큰 곳에 넣으면
`--aot-viz-edge` 를 그 값으로 지정할 것 — `.aot-viz-group` 이 모자란 만큼을
더 확보한다.

**한 줄에 굵은 글자를 셋 두지 않는다.** 제목·값이 이미 굵으므로 눈금의 기준
라벨은 한 단계 가볍다(600). 셋이 같은 무게면 어디를 먼저 볼지 정해지지 않는다.

## 좁은 화면

**줄 간격을 좁히지 말 것.** 줄이 좁아지는 것이 아니라 화면이 좁아지는 것이라,
폰에서는 오히려 위아래 이웃과 붙어 보이기 쉽다. 묶음의 경계는 선이 아니라
여백이 만든다 — 줄 안(제목·트랙·눈금)보다 줄 사이를 넉넉히 벌린다.
트랙 높이와 글자 크기도 줄이지 않는다(마커를 못 읽는다).

## 붙이는 법

```html
<link rel="stylesheet" href="/static/css/components/aot-dataviz.css?v=1">
<script src="/static/js/common/aot-dataviz.js?v=1"></script>
```

- 버전 쿼리 없이 붙이지 말 것 — 정적 자산은 `max-age` 1년으로 나간다
  (`check_static_cache_busting.py`).
- 위젯 `.py` 의 head 문자열을 고쳤으면 `generate_widget_html()` 을 다시 돌려야
  페이지에 반영된다(CLAUDE.md 의 위젯 템플릿 재생성 규칙).
- 번들에 넣는 경우 `tools/bundles.json` 에 올리고 재빌드까지 한 커밋에
  담을 것(`check_js_bundles.py`).

## 담는 곳

마커 둘레의 링은 색이 아니라 **담는 카드의 바탕**이다(`--aot-viz-surface`,
기본 `--aot-surface-card`). `.aot-ov-block` 안에서는 그대로 맞는다. 배경이
다른 곳에 넣으면 그 요소에 `--aot-viz-surface` 를 지정할 것 — 안 하면 마커
둘레에 카드색 테두리가 뜬다.
