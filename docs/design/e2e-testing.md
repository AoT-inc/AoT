# E2E(종단) 검사

브라우저로 실제 화면을 여는 유일한 검사 층이다. 나머지 CI 워크플로는 전부
정적 가드이고, 단위 스위트도 브라우저를 켜지 않는다. 그래서 아래 같은 사고는
여기서만 걸린다.

- CSS 가 통째로 안 실려 화면이 무너지는 것(`@layer` 순서, 주석 오타, 링크 누락)
- 인라인 JS 가 깨져 그리드스택 같은 것이 통째로 죽는 것
- 저장은 됐다는데 새로고침하면 사라지는 것
- 카드가 그려지긴 하는데 누를 것이 없는 것

## 돌리는 법

```bash
aot/scripts/run_e2e.sh          # 기동 → 시드 → L0 → L1
aot/scripts/run_e2e.sh l0       # 라우트 스모크만 (~15초)
aot/scripts/run_e2e.sh l1       # 페이지 부팅 검사만 (~2분 30초)
aot/scripts/run_e2e.sh l1 /geo/design        # 한 화면만
AOT_E2E_HEADED=1 aot/scripts/run_e2e.sh l1 /dashboard   # 브라우저를 보면서
```

준비물은 `pip install playwright && playwright install chromium` 뿐이다.

`pytest aot/tests` 는 **지금까지와 똑같다**. `AOT_E2E_BASE_URL` 이 없으면
`aot/tests/e2e` 는 수집조차 되지 않으므로, 브라우저도 서버도 필요 없고 수집
시간도 그대로다. 환경변수를 주는 것이 곧 "E2E 를 돌리겠다" 는 의사 표시다.

## 환경 — 개발 스택과 완전히 분리한다

`docker/docker-compose.e2e.yml` 이 프로젝트명 `aot-e2e` 로 8085 에 뜬다.
개발 스택(`aot_local`, 8084)과 볼륨·포트가 전부 갈린다. 라이브 compose 가
bind mount 로 쓰는 것(`../influxdb_data`, `../logs`)은 여기서 전부 named
volume 이다 — **bind mount 는 프로젝트명으로 갈라지지 않기 때문이다.**
공유하는 것은 코드(`../:/app`)뿐이고, 그것이 목적이다(지금 브랜치를 시험한다).

데몬은 `--profile control` 뒤에 있다. L0~L2 는 데몬 없이 판정되고 L3 만
데몬을 쓴다 — 다만 **CI 는 항상 데몬까지 띄운다.** 건너뛴 검사는 없는 검사와
같기 때문이다(데몬이 없으면 L3 는 skip 된다).

## 픽스처

`aot/tests/e2e/seed.py` 가 컨테이너 안에서 돈다. `AOT_E2E=1` 이 아니면
아무것도 하지 않고 종료한다 — 개발/운영 DB 에 픽스처를 쓰는 사고를 막는
안전핀이다. 멱등이라 테스트 사이에 다시 불러도 된다.

이름과 값은 `aot/tests/e2e/fixtures.py` 한 곳에만 적는다. 시드(컨테이너 안)와
테스트(호스트)가 같은 파일을 읽어야 둘이 조용히 어긋나지 않는다.

## 층

| 층 | 파일 | 보는 것 | 시간 |
|---|---|---|---|
| L0 | `test_route_smoke.py` | GET 라우트 전수 — 5xx·렌더 실패 없음, 익명은 전부 차단 | ~15초 |
| L1 | `test_page_boot.py` | 페이지마다 **부팅됐는가** | ~2분 30초 |
| L2 | `test_journey_*.py` | 사람이 하는 일 — 저장하고 되읽기까지 | 시나리오마다 |
| L3 | `test_control_loop.py` | 누른 것이 **데몬까지 갔는가**, 실패가 정직하게 돌아오는가 | ~1분 |

### L0 — 대상이 자동으로 자란다

돌고 있는 앱의 `app.url_map` 을 덤프해서 쓴다(`dump_routes.py`). 소스를 grep
하지 않으므로 조건부로 등록되는 것까지 포함하고, **새 페이지를 만들면 다음
실행부터 자동으로 검사 대상이 된다.** 아무도 테스트를 쓰지 않아도 렌더가
터지는 화면은 여기서 걸린다.

익명 검사는 `check_route_auth.py` 와 짝이다 — 그쪽은 데코레이터를 정적으로
보고, 이쪽은 **실제 응답**을 본다. 데코레이터가 붙어 있는데도 응답이 새는
경우가 실제로 있었다.

### L1 — 부팅 판정 항목

페이지마다 아래를 전부 본다.

1. JS 콘솔 오류 0건
2. 4xx/5xx 응답 0건
3. **규칙이 있는데 하나도 적용되지 않은 스타일시트 0개**
4. 앵커 요소가 그려져 있고 높이가 0 이 아님
5. 본문 높이 > 0, 가로로 넘치지 않음

3번이 `@layer` 순서 사고와 주석 오타 사고를 정확히 잡는 조건이다. 단,
**비어 있는 것이 정상인 파일**이 있으므로(예: `custom-light.css` 는 "라이트
기본값과 다른 것만" 담는 규칙이라 지금은 주석뿐이다) 파일을 실제로 받아
규칙 블록이 있는지 확인한 뒤에만 사고로 센다.

판정이 "페이지가 부팅됐는가" 이므로 기능이 바뀌어도 잘 깨지지 않는다. 대신
대상이 넓다 — **손대지 않은 화면이 죽는 것**을 잡는 것이 목적이다.

대상 선정은 `pages.py` 의 `NOT_A_PAGE` 로 거른다. 새 라우트가 페이지가
아니면 여기에 추가한다. 귀찮아 보이지만, 새 표면이 생겼다는 사실을 한 번은
보게 만드는 것이 목적이다.

무시할 콘솔 오류·실패 응답은 **사유와 함께** 목록에 등록한다
(`check_route_auth.py` 의 `PUBLIC_ROUTES` 와 같은 방식).

| 파일 | 무엇을 고정하나 |

| `test_journey_dashboard.py` | 위젯을 끌어다 놓으면 저장되고 새로고침해도 그 자리에 있다 |

### L2 — 저장은 되읽어야 끝난다

모든 쓰기 시나리오는 `저장 → 새로고침 → 되읽기`까지 간다. 중간만 보면
"저장된 것처럼" 보이는 상태와 진짜 저장된 상태를 구분할 수 없다.

버튼 문구를 셀렉터로 박지 않는다. 문구를 박으면 UI 를 손볼 때마다 거짓
경보가 나고, 정작 겨냥한 사고("조작 수단이 통째로 사라짐")는 "누를 것이
하나라도 있는가" 로 충분히 걸린다. 버튼을 가려야 할 때는 `processRequest(this,
'output_mod')` 처럼 **동작**으로 가린다 — 언어를 바꿔도 그대로다.

#### 셀렉트는 드롭다운을 열어서 고른다

`journeys.choose_option()` 을 쓴다. 이 앱의 셀렉트는 bootstrap-select 로
감싸져 있고, 화면 코드는 대개 `changed.bs.select` 만 듣는다(`journal-page.js`
의 `_onSelect`). `<select>` 값을 바꿔 네이티브 `change` 를 쏘는 방식으로는
**아무 일도 일어나지 않는다** — 값은 바뀌었는데 화면은 고른 줄 모른다.
그리고 열린 목록은 래퍼가 아니라 **body 바로 아래**에 붙는다
(`data-container="body"`).

#### 비동기로 만들어지는 것은 완성을 기다린다

일지가 그렇다. 생성 요청이 200 을 준 직후의 화면은 "생성하고 있습니다" 다.
그 상태를 통과로 세면 **영영 완성되지 않는 문서**를 못 잡고, 실패로 세면
거짓 경보가 난다. 완성 조건을 적어 기다린 뒤에 본다.

#### 자기가 바꾼 것은 되돌린다

여정이 픽스처를 고쳤으면 끝에서 되돌린다. 다음 여정이 같은 상태를 전제하기
때문이다. 되돌리기도 **단언한다** — 조용히 실패하면 그 뒤 검사들이 엉뚱한
전제 위에서 돈다. 시퀀스 순서처럼 "맨 위를 맨 아래로" 가 회전인 경우, 한 번
더 한다고 제자리가 되지 않는다(단계 수만큼 돌려야 원위치다).

#### 시드 뒤에는 데몬을 다시 읽혀야 한다

데몬은 **기동 시점의 DB** 를 들고 있다. 시드가 장치를 지우고 새로 만들면
uuid 가 바뀌는데, 먼저 떠 있던 데몬은 그것을 모른다 — 제어 폐루프가 "그 출력의
상태가 아예 없음" 으로 깨진다. `run_e2e.sh` 와 CI 는 시드 다음에 데몬을
재시작한다. 손으로 돌릴 때도 순서는 **시드 → 데몬 재시작 → 검사** 다.

### L3 — 데몬이 살아 있는지는 **응답으로만** 판단한다

컨테이너가 `running` 인 것, 로그가 "AoT daemon started" 라고 말하는 것, 그리고
앱이 실제로 데몬과 말이 되는 것은 셋 다 다른 사건이다. 처음엔 로그로 판단했다가
**컨테이너를 멈췄다 켜면 로그가 누적된다**는 것을 놓쳐, 이전 실행의 그 줄을 보고
아직 포트도 안 연 데몬에 제어를 보냈다(2026-09-18 실측). 지금은 "출력 상태가
돌아오는가" 로만 본다.

실패는 **데몬을 잠시 내려** 만든다. 가짜 오류를 주입하는 것보다 현실적이다 —
데몬이 죽어 있는 동안 사람이 버튼을 누르는 일은 실제로 일어난다. 끝나면 되살린다.

## 아직 없는 것

- **도형을 지우는 흐름.** 삭제 모드는 버튼으로 켜지지만 캔버스 클릭만으로는
  반응하지 않았다 — `_deleteAtPoint` 가 `queryRenderedFeatures` 로 최상단
  레이어를 찾는 구조라, 자동화가 찍어야 할 지점 조건이 더 있다. "겹친 도형을
  지우면 전량이 지워지던" 2026-08 사고의 재발 감시는 그 조건을 짚은 뒤에 붙인다.

## 실패했을 때

`.local/e2e-artifacts/<경로>.png` 에 그 순간의 전체 화면이, `.txt` 에 콘솔
오류와 실패 응답이 남는다. CI 는 이것을 아티팩트로 올린다.

## 규칙

- **실패한 E2E 는 머지를 막는다.** 막지 않으면 곧 빨간 불이 상시가 되고
  아무도 안 본다.
- **불안정한 검사는 고치거나 지운다.** 재시도로 덮지 않는다 — 덮는 순간
  검사 자체가 "조용한 실패" 를 저지른다.
- 현장 사고가 나면 **재현 시나리오를 L2 에 한 줄 더하는 것**을 수정의
  일부로 삼는다.
