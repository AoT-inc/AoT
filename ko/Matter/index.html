    Matter~

    실험 기능

    Matter 지원은 실험 기능입니다. 가상 장치로는 검증했지만 다양한 실제 장치와 스마트홈 생태계에서는 아직 충분히 검증하지 못했습니다. 연결이 끊기면 피해가 생기는 용도에는, 직접 가진 장치로 충분히 시험하기 전까지 쓰지 마세요.

    AoT는 어떤 제조사나 앱 생태계에도 매이지 않는 Matter 컨트롤러가 될 수 있습니다. Apple Home, Google Home, SmartThings, Alexa 등 다른 Matter 앱에 이미 설정된 장치를 Matter Multi-Admin으로 AoT와 공유할 수 있습니다. 다른 앱이 짧은 시간 동안 공유 창을 열고, 그 코드를 AoT에 입력하면, AoT가 장치를 자신의 Matter 네트워크(fabric)에 연결합니다. 그러면 장치는 두 생태계에 동시에 속하며 원래 앱에서도 계속 동작합니다.

    AoT는 이 장치를 입력과 출력을 가진 평범한 AoT 장치로 바꾸므로, 그래프·트리거·PID 제어·시퀀스·환경 코디네이터·AI 어시스턴트 등 AoT의 나머지 기능을 그대로 쓸 수 있습니다.

    읽기와 제어는 AoT와 장치 사이에서 내 로컬 네트워크로 직접 오갑니다. 다른 생태계의 클라우드를 거치지 않으므로 그쪽의 API 요금이나 요청 한도가 적용되지 않습니다.

    모든 관리는 한 화면에서 합니다: 관리 → 시스템 관리 → Matter.

    AoT가 하지 않는 일~

    • AoT는 장치가 어느 앱에서 왔는지 모르고, 신경 쓰지도 않습니다. 오직 "AoT의 fabric에 추가할 수 있는 장치인가"만 봅니다.
    • 같은 장치를 두 번 들여오지 않습니다. 이미 다른 경로(예: 클라우드 연동)로 AoT에 들어온 장치를 Matter로도 추가하면 측정값이 두 번 저장되므로 하나만 쓰세요.
    • AoT의 AI 어시스턴트는 Matter 장치를 추가하거나 제거하지 못합니다. 페어링 코드는 사람만 다룹니다. 장치가 만들어진 뒤에는 출력이 다른 출력과 똑같이, 어시스턴트와 그 승인 단계를 포함해 제어됩니다.
    • AoT는 IP로 닿는 장치를 다룹니다. Wi-Fi, Ethernet, 또는 이미 네트워크에 있는 경계 라우터를 거치는 Thread 장치입니다. AoT 자신이 Thread 경계 라우터는 아닙니다.

    요구 사항과 켜는 방법~

    Matter는 다른 AoT 기능보다 네트워크에 요구하는 것이 많습니다. 실패의 대부분은 AoT가 아니라 호스트 네트워크에서 생깁니다. 무엇보다 먼저 아래를 확인하세요.

    • Linux 호스트. Docker 배포, 또는 네이티브 설치에 Matter 서버만 Docker로 띄웁니다(네이티브 설치). macOS나 Windows의 Docker Desktop은 Matter에 필요한 멀티캐스트 네트워킹을 제공하지 못합니다. 라즈베리 파이 한 대로 충분합니다: 라즈베리 파이에 설치.
    • 호스트가 Matter 장치와 같은 네트워크(같은 VLAN)에 있어야 합니다.
    • Matter 서버는 기계의 호스트 네트워크에서 돌며, IPv6가 켜져 있고 IPv6 라우터 광고를 받아들이며 mDNS가 동작해야 합니다. 멀티캐스트를 "최적화"하는 일부 메시 Wi-Fi나 공유기는 이를 깨뜨립니다.
    • Bluetooth로 새 장치를 추가하려면 호스트에 Bluetooth 어댑터와 BlueZ도 필요합니다. 선택 사항입니다(아래 참고).

    1. 호스트 점검~

    점검 스크립트는 컨테이너가 아니라 호스트에서 실행하세요. 설정을 읽기만 하고 아무것도 바꾸지 않으며, 찾은 문제마다 고치는 명령을 출력합니다.

    aot/scripts/check_matter_host.sh
    옵션 의미
    --iface <이름> 이 네트워크 인터페이스를 점검합니다. 생략하면 기본 경로의 인터페이스를 씁니다
    --ble 새 장치 추가용 Bluetooth도 점검합니다: BlueZ, 어댑터 유무, rfkill 차단, 전원, D-Bus 소켓
    --json 결과를 JSON으로 출력합니다

    각 줄은 OK, WARN, FAIL 중 하나로 시작합니다. FAIL이 없으면 종료 코드는 0입니다. 먼저 FAIL을 모두 고치고, 이어서 해당되는 경고를 고치세요.

    2. Matter 서버 시작~

    Matter 서버는 Docker 배포에 들어 있지만 기본값은 꺼짐입니다. docker/.env 에 다음을 추가합니다.

    COMPOSE_PROFILES=matter

    그다음 평소처럼 스택을 시작합니다.

    docker compose -f docker/docker-compose.prod.yml up -d

    컨테이너가 두 개 더 뜹니다. matter_server(Matter 스택)와 matter_socket(AoT가 이 서버와 말할 로컬 소켓을 만들어 주는 작은 중계)입니다. 데이터 볼륨 matter_data 에 fabric이 저장됩니다.

    docker/.env 의 다른 설정:

    설정 의미
    MATTER_SERVER_TAG Matter 서버 이미지 버전. 자동 업데이터는 이 서비스를 업데이트하지 않습니다. 새 버전을 쓰려면 태그를 직접 올리세요
    MATTER_TEST_DCL 기본값 false. 개발·시험용 장치(벤더 ID 0xFFF1)를 추가할 때만 true 로 하세요. 운영에서는 끄세요
    MATTER_LOG_LEVEL info 를 유지하세요. debug 에서는 서버가 Wi-Fi 비밀번호를 포함한 원문 요청을 로그에 남깁니다
    MATTER_BLUETOOTH_ADAPTER 아래 Bluetooth 파일을 쓸 때의 Bluetooth 어댑터 번호(0 = hci0)

    AoT 에서 관리 → 시스템 관리 → 일반 설정 의 Matter 사용 (실험) 을 켜고 저장합니다. 그러면 설정 메뉴에 Matter 가 나타납니다(꺼져 있으면 보이지 않습니다).

    관리 → 시스템 관리 → Matter 를 엽니다. Matter 서버 카드에 상태(연결됨 / 연결되지 않음), 서버 버전, Fabric ID, 장치 수와 그중 응답 중인 수가 표시됩니다. 연결되지 않았으면 마지막 오류와 같은 시작 안내가 표시됩니다.

    3. 선택: 새 장치용 Bluetooth~

    막 개봉한 장치를 추가하려면 호스트에 Bluetooth가 필요합니다. aot/scripts/check_matter_host.sh --ble 를 실행해 보고된 문제를 고친 뒤, 추가 compose 파일과 함께 서버를 시작하세요.

    docker compose -f docker/docker-compose.prod.yml -f docker/docker-compose.matter-ble.yml up -d

    이후 compose 명령에는 항상 두 파일을 함께 쓰세요. 첫 파일만으로 up -d 를 하면 Bluetooth 설정이 빠진 채 서버가 다시 만들어집니다. 컨테이너는 비특권 상태를 유지하며 호스트의 D-Bus를 읽기 전용으로만 받습니다.

    Bluetooth가 켜져 있지 않으면 새 장치 추가 아래에 그렇다고 표시됩니다. 공유된 장치 추가와, 이미 네트워크에 있는 장치 추가는 그래도 동작합니다.

    4. 네이티브 설치에서 시작~

    AoT를 Docker가 아니라 네이티브(/opt/AoT 의 aot·aotflask·aotmcp 서비스)로 설치했다면, Matter 서버만 Docker로 띄우고 AoT 서비스에 그 주소를 알려 줍니다. 아래 명령은 모두 호스트의 /opt/AoT 에서 실행하며 관리자 권한이 필요합니다.

    1. 호스트를 점검합니다(위 1단계). 블루투스를 쓸 거면 --ble 을 붙입니다.
    2. Docker Engine을 설치합니다(이미 있으면 건너뜁니다). 
      curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
    3. Matter 서버를 시작합니다. 블루투스로 새 장치를 추가하려면 이후에도 항상 -f docker/docker-compose.matter-ble.yml 을 함께 씁니다. 
      sudo docker compose -f docker/docker-compose.matter-native.yml up -d
    4. AoT 서비스 세 개에 서버 주소를 알려 주고 다시 시작합니다. 
      for s in aot aotflask aotmcp; do
  sudo install -D -m 644 install/aot-matter.conf /etc/systemd/system/$s.service.d/matter.conf
done
sudo systemctl daemon-reload
sudo systemctl restart aot aotflask aotmcp
    5. 관리 → 시스템 관리 → 일반 설정 의 Matter 사용 (실험) 을 켭니다. 필요한 패키지가 없으면 패키지 관리 화면으로 안내되니 설치합니다. 그다음 Matter 페이지에서 서버가 연결됨으로 나오는지 확인합니다.

    Docker 설치와 다른 점:

    • 소켓 중계(matter_socket)가 없습니다. AoT가 호스트에서 돌아 서버의 루프백 포트(127.0.0.1:5580)에 바로 닿습니다. 이 포트에는 인증이 없으므로, 이 호스트에 로그인할 수 있는 사람은 Matter 장치를 조작할 수 있습니다.
    • Matter 데이터(Docker 볼륨 aot_matter_matter_data)는 AoT 백업에 들어가지 않습니다. Fabric 루트 CA 키가 들어 있으니 따로 백업하고 비밀로 다루세요. 
      sudo docker run --rm -v aot_matter_matter_data:/data -v "$PWD":/backup alpine tar czf /backup/matter_data.tgz -C /data .
    • AoT를 업그레이드해도 Matter 서버는 바뀌지 않습니다. 버전은 MATTER_SERVER_TAG 로 직접 올립니다.

    다른 앱에서 공유한 장치 추가~

    이미 다른 Matter 앱에 설정된 장치에 쓰는 방법입니다.

    1. 해당 앱에서 장치를 열고 공유, 페어링 모드, 연결된 Matter 앱 옵션을 고릅니다. 앱마다 표현이 다르며 흔히 "페어링 모드 켜기"나 "다른 허브·앱에 연결"에 있습니다.
    2. 앱이 11자리 페어링 코드(와 QR 코드)를 보여 줍니다. 약 15분 동안 쓸 수 있습니다.
    3. AoT에서 공유된 장치 추가 에 있는 페어링 코드 에 코드를 입력하고 추가 를 누릅니다.

    추가는 보통 1분이 안 걸립니다. 코드가 틀렸거나 만료됐다면 AoT가 포기하기까지 몇 분 걸릴 수 있으니 화면을 열어 두세요.

    그러면 AoT가 Matter 장치마다 AoT 장치 하나를 만들고 활성화합니다. 그 아래에는 다음이 생깁니다.

    • 장치가 제공하는 측정값마다 채널이 하나씩 있는 센서 입력
    • 제어 가능한 엔드포인트를 위한 출력: 스위치 출력과 디머 출력은 각각 하나이고 엔드포인트마다 채널이 하나씩, 커튼은 하나마다 출력 하나

    추가된 센서와 스위치 수가 알림으로 표시됩니다. 장치는 Matter 장치 목록과 장치 화면에 나타납니다. AoT는 장치에 자신을 "AoT"라는 이름으로 등록하므로, 다른 앱의 연결된 앱 목록에도 "AoT"로 보입니다.

    AoT는 페어링 코드를 저장하거나 기록하지 않습니다. 코드는 Matter 서버로 곧바로 전달되고 잠깐만 유효하지만, 만료되기 전까지는 장치의 열쇠나 다름없으니 다른 곳에 붙여 넣지 마세요.

    장치를 제거했다가 나중에 다시 공유하면 AoT는 제조사가 정한 고유 ID로 장치를 알아보고, 새 장치를 만드는 대신 기존 AoT 장치에 다시 연결하므로 측정 이력이 이어집니다.

    Bluetooth로 새 장치 추가~

    막 개봉했거나 공장 초기화한 장치는 새 장치 추가 를 쓰세요. AoT가 Bluetooth로 장치를 찾고, 내 네트워크에 연결하고, 자신의 fabric에 추가하므로 다른 앱이 필요 없습니다.

    필요한 것:

    • 장치 또는 포장 상자에 인쇄된 페어링 코드
    • Matter 서버의 Bluetooth 켜짐(위 참고), 그리고 AoT 서버 가까이에 둔 장치
    • 네트워크 로 다음 중 하나:
      • Wi-Fi: Wi-Fi 네트워크 이름 과 Wi-Fi 비밀번호 를 입력합니다. 장치가 2.4 GHz만 지원하면 2.4 GHz 네트워크를 고르세요.
      • Thread: 내 Thread 네트워크의 Thread 데이터셋(16진수) 을 붙여 넣습니다. Thread 경계 라우터가 이미 네트워크에서 동작 중이어야 합니다.
      • 이미 네트워크에 연결됨(Ethernet): 장치가 이미 네트워크에 닿아 있으므로 자격 증명이 필요 없습니다.

    추가 를 누릅니다. 작업은 백그라운드에서 돌고, 화면이 몇 초마다 진행을 확인합니다. 장치 찾기, 네트워크 연결, 네트워크에서 다시 찾기까지 몇 분 걸릴 수 있으며, AoT는 약 12분 뒤 포기합니다. 장치가 나타나면 AoT 장치가 자동으로 만들어집니다. 화면을 닫아도 됩니다. 화면이 닫혀 있는 동안 연결된 장치는 목록에 AoT 장치 없음 으로 나타나며 AoT 장치 만들기 로 만들 수 있습니다(없어진 장치와 고아 장치 참고).

    Wi-Fi 비밀번호와 Thread 데이터셋에 대하여

    AoT는 Wi-Fi 비밀번호나 Thread 데이터셋을 보관하지 않습니다. 장치를 연결하기 위해 Matter 서버에 한 번만 전달하고, 작업이 성공하든 실패하든 서버의 자격 증명 목록에서 지웁니다. AoT의 작업 파일이나 로그에도 쓰지 않습니다.

    다만 Matter 서버는 데이터를 추가 전용 기록으로 저장하므로, 자격 증명을 지운 뒤와 재시작 뒤에도 비밀번호나 데이터셋이 그 기록에 평문으로 남아 있을 수 있습니다. 현재 서버로는 AoT가 이를 지울 수 없습니다. 이 데이터는 AoT 백업(matter_data)에 들어갑니다. 그러므로

    • matter_data 가 든 백업은 모두 비밀로 다루고(업그레이드·백업·복원),
    • 네트워크 보안이 중요하면 장치를 추가한 뒤 Wi-Fi 비밀번호를 바꾸세요.

    만들어지는 것~

    센서~

    입력은 장치가 스스로 보내는 보고를 읽습니다. 값은 장치가 변화를 보고할 때와, 일정 주기의 표본(기본 60초, 입력의 샘플링 간격 (초) 로 설정)으로 기록되므로, 안정된 값이 낡은 값처럼 보이지 않습니다. 응답하지 않는 장치는 값이 더 이상 들어오지 않고, 장치에 통신 장애가 표시됩니다. 장치가 "값 없음"이라고 알린 값은 건너뛰며 0으로 저장하지 않습니다.

    측정 저장 단위
    온도 °C
    상대 습도 %
    조도 lux
    접점(열림/닫힘) 켜짐/꺼짐
    배터리 %
    압력 kPa
    유량 L/min
    재실 켜짐/꺼짐
    CO₂ ppm
    PM2.5 µg/m³
    토양 수분 %
    전력·전압·전류 W, V, A
    누적 에너지 kWh
    버튼 누른 횟수(길게 누름은 −1로 기록)

    CO₂와 PM2.5는 장치가 AoT가 저장하는 단위로 알릴 때만 추가되므로, 다른 단위의 값을 잘못 환산해 저장하지 않습니다. AoT가 알지 못하는 값은 같은 이유로 무시합니다.

    접점·재실·버튼은 값이 바뀔 때 입력에 붙은 edge 트리거도 실행합니다(켜짐 = rising, 꺼짐 = falling). GPIO 입력과 같은 방식입니다. 버튼은 눌렸을 때만 기록하며 반복 표본으로 다시 쓰지 않습니다.

    잠자는 배터리 장치는 폴링 때문에 배터리가 닳지 않도록, 직접 읽는 대신 장치의 보고를 받아 씁니다.

    출력~

    장치 AoT 출력 동작
    스위치·플러그·릴레이 On/Off 출력 켜고 끕니다
    조광 조명 PWM 출력, 0–100 % 듀티 1–100 %가 밝기, 0 % 또는 끔은 끄기, 값 없는 "켜기"는 이전 밝기로 켜기입니다. 스스로 디머라고 알리는 장치만 디머로 다룹니다. 일반 릴레이 플러그를 "30 % 레벨"로 구동하는 일은 없습니다
    커튼·차광·환기창 값 출력, 0–100 % 위치, 100 = 열림 아래 참고

    스위치와 디머는 각각 출력 하나에 엔드포인트마다 채널이 하나씩 생깁니다(2구 플러그는 채널 두 개인 출력 하나). 커튼은 하나마다 출력이 따로 생겨, 통합 환경 제어가 하나씩 쓸 수 있습니다. 조광 가능한 엔드포인트는 스위치 채널 대신 디머 채널이 됩니다.

    커튼과 창 덮개. AoT는 100 = 완전히 열림, 0 = 완전히 닫힘으로 쓰며, 장치의 방식(Matter 자체는 0 = 열림)과의 변환은 AoT가 합니다. 위치를 보고하는 장치는 정확한 퍼센트까지 움직입니다. 위치를 보고하지 못하는 장치는 50 % 이상이면 "열기", 50 % 미만이면 "닫기"로 해석합니다. AoT는 마지막 위치를 기억하므로(이동 중에는 약 10초마다) 환경 코디네이터가 커튼을 차광이나 환기 액추에이터로 쓸 수 있습니다.

    커튼에서 끄기는 정지이지 닫기가 아닙니다

    커튼에 끄기 명령을 보내면 움직임이 멈춥니다. 닫히지 않습니다. 비상 정지, 종료 동작처럼 "끄기"를 "닫힘"의 뜻으로 쓰는 기능에도 같이 적용됩니다. 커튼은 그 자리에서 멈출 뿐입니다. 커튼을 닫으려면 값 0 을 보내세요. (지도의 닫기 버튼과 AI 어시스턴트의 닫기 명령은 이미 0을 보내고, 끄기·정지는 멈춥니다.)

    모듈 이름은 MATTER_NODE(입력), MATTER_ON_OFF·MATTER_LEVEL·MATTER_COVERING(출력)입니다. 옵션 목록은 지원 입력과 지원 출력에 있습니다.

    Matter 장치 카드에는 AoT의 fabric에 있는 모든 장치가 나옵니다.

    열 의미
    장치 이름·제조사·모델(펌웨어 버전 또는 업데이트 진행 상황)
    센서와 스위치 AoT가 만든 센서와 스위치 항목 수
    응답 중 응답 중, 또는 서버가 장치를 놓치면 응답 없음. 서버는 장치가 응답을 멈춘 지 약 5분 뒤에 응답 없음으로 표시합니다
    AoT 장치 이 장치를 감싸는 AoT 장치, 또는 AoT 장치 없음

    행마다 있는 버튼: 다시 읽기, 이 장치 공유, 펌웨어, 제거, 그리고 AoT 장치가 없는 장치에만 AoT 장치 만들기.

    다시 읽기 는 장치를 다시 읽어, 장치를 추가했을 때는 AoT가 몰랐지만 지금은 지원하는 센서나 제어(예: AoT 업데이트 뒤)를 덧붙입니다. 추가만 합니다. 기존 채널은 건드리지 않으며, 스위치로 등록된 조광 엔드포인트는 자동으로 바뀌지 않습니다. 그 스위치 출력을 지우고 다시 읽으면 디머가 됩니다.

    AoT의 장치를 다른 앱과 공유~

    반대 방향도 됩니다. AoT가 이미 제어하는 장치를 Apple Home, Google Home 같은 다른 앱도 쓸 수 있게 공유할 수 있습니다.

    1. Matter 장치 목록에서 장치의 이 장치 공유 를 누릅니다(응답 중이어야 합니다).
    2. 대화상자에 11자리 코드가 표시되고 복사 할 수 있으며, 요구하는 앱을 위한 QR 코드 텍스트도 나옵니다. 코드는 15분 동안 유효합니다(공유 창은 180~900초 사이로 열 수 있으며, 화면은 900초로 엽니다).
    3. 다른 앱에서 장치 추가, Matter를 차례로 선택하고 코드를 입력합니다. 대부분의 앱은 스캔 대신 11자리 코드를 받아들입니다.
    4. 다른 앱이 장치를 추가할 때까지 대화상자를 열어 두세요. 대화상자를 닫거나 공유 닫기 를 누르면 공유 창이 닫히고 코드가 무효가 됩니다.

    공유 창을 다시 열면 이전 코드는 무효가 됩니다. AoT는 코드를 저장하지 않습니다. 장치에 다른 생태계를 위한 빈 자리가 없으면 AoT가 시작 전에 거절하고, 그 장치의 다른 연결 하나를 먼저 제거하라고 안내합니다.

    연결된 생태계~

    같은 대화상자의 연결된 생태계 에 장치가 현재 연결된 모든 앱과 허브(이름·제조사, 그리고 장치가 지원하는 수 중 사용 중인 연결)가 나옵니다. AoT 자신의 행에는 AoT입니다 라고 표시됩니다.

    연동 해제 는 다른 생태계를 장치에서 제거합니다. 그러면 그 앱은 장치를 제어할 수 없게 되고, 다시 쓰려면 장치를 다시 추가해야 합니다. AoT는 이후 장치를 다시 확인해 연결이 실제로 사라졌는지 검증합니다. AoT 자신은 여기서 해제할 수 없습니다. 장치에서 AoT를 지우려면 장치를 제거하세요.

    다른 앱이 장치에서 AoT를 지운("쫓아낸") 경우, 장치가 몇 분 동안 응답 중으로 보일 수 있습니다. AoT는 센서를 장치에서 바로 읽으므로 실패한 표본은 기록되지 않고, 장치에 통신 장애가 표시되며, 명령은 오류로 끝납니다.

    펌웨어 업데이트~

    펌웨어 는 현재 버전이 있는 대화상자를 엽니다. 업데이트 확인 은 새 버전이 있는지 묻습니다. AoT는 펌웨어를 스스로 설치하지 않으며, 업데이트는 항상 사람이 시작합니다.

    AoT는 다음 조건일 때만 업데이트를 설치합니다.

    • 인증된 출처(CSA의 운영용 분산 적합성 원장)의 것일 때. 시험용·로컬 이미지는 인증되지 않았으므로 거절합니다.
    • 장치가 응답 중일 때
    • 장치가 유휴 상태이며 이미 업데이트 중이 아닐 때

    업데이트 를 누르고 확인하세요. 장치가 다시 시작되며 몇 분 동안 쓸 수 없을 수 있습니다. 그 순간 중요한 것(펌프·히터·환기창)을 제어 중인 장치는 업데이트하지 마세요. 진행 상황(다운로드·설치 등)은 장치 행에 표시됩니다.

    없어진 장치와 고아 장치~

    • Matter 서버에 없음 — 다시 공유해 연결하거나 제거하세요 는 AoT에는 장치가 있지만 Matter 서버가 더 이상 그 장치를 모른다는 뜻입니다(예: 서버 데이터가 초기화됨). 다른 앱에서 장치를 다시 공유하면 AoT가 같은 AoT 장치에 다시 연결하며, 아니면 제거 를 누르세요.
    • AoT 장치 없음 은 장치가 AoT의 fabric에는 있지만 AoT 장치가 없다는 뜻입니다. 예를 들어 추가하는 도중에 화면을 닫은 경우입니다. AoT 장치 만들기 를 누르세요.

    장치 제거~

    행의 제거 를 누르거나 장치 화면에서 AoT 장치를 삭제하고, 확인하세요. 그러면 AoT는

    1. 장치에서 AoT를 제거해 연결 자리를 비웁니다(꼭 필요한 단계입니다. 자리가 새면 결국 다른 앱이 장치를 추가하지 못하게 됩니다).
    2. AoT 장치와 그 입력·출력을 삭제하고,
    3. 기록된 측정 이력은 데이터베이스에 남겨 둡니다.

    장치가 꺼져 있거나 닿지 않아도 제거는 진행되지만, AoT가 장치에서 자신을 지우지 못하므로 경고가 표시됩니다. 이때는 다른 앱의 연결된 앱 목록에서 AoT를 지우세요.

    시퀀스·PID·위젯·트리거 등이 그 입력이나 출력을 아직 쓰고 있으면 제거는 거절되고 아무것도 바뀌지 않습니다. 그쪽에서 먼저 빼세요.

    권한과 그룹~

    동작 필요한 권한
    화면 열기, 목록 보기 설정 보기
    장치의 연결된 생태계 보기 설정 보기, 그리고 내가 조작할 수 있는 그룹의 장치
    추가(공유·새 장치), AoT 장치 만들기, 다시 읽기, 제거 설정 편집 그리고 컨트롤러 편집
    이 장치 공유, 공유 닫기, 연동 해제, 펌웨어 확인·업데이트 설정 편집 그리고 컨트롤러 편집, 그리고 내가 조작할 수 있는 그룹의 장치

    그룹을 쓰고 있으면, 특정 장치에 대한 동작(연결 보기·공유·연동 해제·펌웨어)은 그 AoT 장치의 그룹으로 검사합니다. AoT 장치가 없는 장치는 어느 그룹에도 속하지 않으므로 그룹에 제한되지 않는 사용자("모든 그룹 접근" 역할)만 다룰 수 있습니다. 검사를 할 수 없으면 동작은 거절됩니다.

    백업~

    Matter fabric은 matter_data 볼륨에 있으며 AoT 백업에 들어갑니다. 여기에는 fabric의 루트 CA 개인키가 있습니다. 이를 가진 사람은 같은 네트워크 안에서 AoT에 추가된 모든 Matter 장치를 제어할 수 있고, 잃으면 모든 장치를 다시 공유해야 합니다. 업그레이드·백업·복원을 보세요. 백업 파일을 보호하고, 웹 화면의 복원은 matter_data 를 복원하지 않는다는 점에 유의하세요.

    처음 시작한 뒤에는 벤더 ID와 fabric ID를 바꾸지 마세요. 기존 장치가 모두 고아가 됩니다.

    문제 해결~

    추가에 실패하면 AoT가 이유를 알려 줍니다. 원인은 다음과 같이 나뉩니다.

    메시지 할 일
    Matter 서버에 닿지 않음 matter_server 와 matter_socket 컨테이너가 실행 중인지, COMPOSE_PROFILES=matter 가 설정돼 있는지 확인
    페어링 코드가 올바르지 않음 숫자를 확인하고 다시 시도
    장치가 코드를 받아들이지 않음 공유 창이 닫혔을 수 있습니다. 다시 공유해 새 코드를 입력하세요. 새 장치라면 장치나 상자의 코드를 확인
    네트워크에서 장치를 찾지 못함 장치가 AoT와 같은 네트워크에 있고 공유 창이 열려 있어야 합니다. aot/scripts/check_matter_host.sh 실행. 새 장치라면 서버 가까이에서 페어링 모드로 두고 --ble 로 Bluetooth 점검
    장치가 제때 연결을 마치지 못함 다른 앱에서 다시 공유(새 장치는 다시 페어링 모드로)하고 재시도
    Matter 서버가 네트워크 정보를 받아들이지 않음 (network_rejected) Wi-Fi 이름·비밀번호 또는 Thread 데이터셋 확인
    Matter 서버가 Bluetooth를 쓸 수 없음 (ble_unavailable) check_matter_host.sh --ble 를 실행하고 docker-compose.matter-ble.yml 로 서버 시작
    장치가 Wi-Fi에 연결하지 못함 (wifi_failed) 이름·비밀번호 확인, 장치가 필요로 하면 2.4 GHz 네트워크 사용
    장치가 Thread 네트워크에 연결하지 못함 (thread_failed) Thread 데이터셋과 Thread 경계 라우터 동작 확인
    장치에 다른 생태계를 위한 빈 자리가 없음 그 앱에서 장치의 다른 연결 하나를 제거한 뒤 다시 공유
    장치가 인증됐음을 증명하지 못함 AoT 서버가 CSA 기기 원장에 인터넷으로 닿아야 합니다. 개발·시험용 장치는 MATTER_TEST_DCL=true 필요

    알아 둘 점:

    • 값이 들어오지 않는데 장치가 응답 중으로 보이면 연결된 생태계의 쫓겨남 경우를 보세요. 다른 앱에서 장치를 확인하세요.
    • Thread 경계 라우터나 메시 Wi-Fi를 바꾼 뒤에는 장치가 한동안 응답하지 않을 수 있습니다. 호스트 점검을 다시 실행하세요.
