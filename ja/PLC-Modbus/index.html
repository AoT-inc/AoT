    PLC (Modbus TCP)~

    AoT は Modbus TCP で PLC、リレーボード、ゲートウェイ、計量器と通信します。読み取りは Modbus TCP (PLC) 入力、制御は On/Off: Modbus TCP Coil (PLC) 出力で行います。 どちらも標準搭載のため、追加インストールは不要です。

    Modbus には認証も暗号化もありません

    ネットワーク上で装置に到達できる者は誰でも、すべてのレジスタを読み書きできます。 PLC は必ず隔離されたネットワーク（VLAN またはファイアウォールの許可リスト）に置き、 インターネットには公開しないでください。

    始める前に~

    ベンダーのドキュメントからレジスタマップを入手してください。扱いたい値ごとに次の情報が 必要です。

    • どのテーブルにあるか — coil、discrete input、holding register、input register
    • アドレス
    • 16 ビットを超える値の場合はデータ型とワード順

    初回接続でほとんどの人がつまずく点が 2 つあります。

    • アドレスの基準。 ベンダー文書は 1 から数えるアドレスを使うことが多くあります （40001 が holding register 0、00001 が coil 0）。AoT は実際の通信で使われる 0 から数えるアドレスを使います。
    • ワード順。 32 ビット値では、上位ワードを先に置くベンダーと下位ワードを先に置く ベンダーがあります。アドレスは正しいのに値がおかしい場合、原因はほぼこれです。 ワード順オプションを逆にして読み直してください。

    値の読み取り~

    Modbus TCP (PLC) 入力を追加し、次を設定します。

    オプション 説明
    ホスト / ポート 装置のアドレス。標準ポートは 502 です
    Unit ID 装置を直接指定する場合は通常 1、シリアルゲートウェイ経由ならそのスレーブアドレス
    タイムアウト / リトライ 遅い装置でなければ 1.0 秒・1 回のままにしてください。タイミング を参照
    周期 ポーリング間隔（秒）。1〜5 秒から始め、PLC の負荷を見て調整してください

    測定数を読み取るレジスタの数だけ指定し、チャンネルごとに次を設定します。

    チャンネルオプション 説明
    レジスタ種別 Coil と Discrete Input はビット、Holding・Input Register は 16 ビットワードです
    レジスタアドレス そのテーブル内で 0 から数えるアドレス
    データ型 コイル・接点は Bit、レジスタは int16/uint16/int32/uint32/float32
    ワード順 32 ビット型のみ該当。値がおかしければ逆にしてください
    倍率 生の値に掛けます。0.1 単位で報告する装置なら 0.1

    ビットは 1.0/0.0 として保存されるため、他の測定値と同じようにグラフ表示や関数での 利用ができます。

    読み取りに失敗した場合、そのチャンネルには 何も保存しません。その沈黙こそが装置の 途絶を示す信号であり、仮の値を入れると途絶を隠してしまいます。あるチャンネルが失敗しても、 残りのチャンネルの読み取りは続行されます。

    コイルの制御~

    On/Off: Modbus TCP Coil (PLC) 出力を追加します。ホスト・ポート・Unit ID・タイムアウト・ リトライの意味は入力と同じです。チャンネル数 を制御するコイルの数だけ指定して保存すると コイルごとに 1 行が現れ、各行には コイルアドレス だけを設定します。

    AoT はコマンドのたびにコイルへ書き込み、直後に読み戻します。この読み戻しが確認になります。

    • 読み戻した値がコマンドと一致すれば、チャンネルの状態は推測ではなく 装置が確認した値 になります。
    • 一致しない場合はコマンドを失敗として報告します。多くは PLC のプログラムがそのコイルを 制御しているか、アドレスが誤っている場合です。
    • 装置に到達できない場合、コマンドは失敗しチャンネルは 直前の状態を保ちます。PLC が 受け付けていない状態が画面に出ることはありません。

    読み戻しはレジスタの確認であり、リレーの確認ではありません

    コイルを読み戻すことは、PLC が値を受け付けたことの証明です。リレーが実際に動いたか、 配線が健全かは証明できません。そこまで確認するには、フィードバック接点を配線して別の 入力として読み取り、比較する必要があります。

    起動時の状態 と 終了時の状態 は他の出力と同じように動作します。PLC では起動時の状態を 「何もしない」にしておくのが適切な場合が多いです。そうすると AoT はコイルを読み取り、PLC が すでに持っている状態をそのまま受け入れ、上書きしません。

    デーモンの起動直後、チャンネルは一時的に「確認不可」と表示されます。AoT がバックグラウンドで 実際の状態を読み取っている間であり、読み取れていないコイルをオフだと決めつけないための意図的な 動作です。

    接続の共有~

    同じホストとポートを指す入力と出力は、自動的に 1 本の TCP 接続を共有し、その上の要求は 順番に処理されます。設定は不要で、これにより 1 台の PLC に多数の入力・出力を割り当てても、 ほとんどの装置が設けている同時接続数の上限に達しません。

    知っておくべき点が 1 つあります。タイムアウトとリトライは装置の登録項目ごとではなく接続 ごと です。同じホスト・ポートを共有するもののうち、最初に有効化されたものの設定が適用され ます。

    通信状態~

    PLC が応答しなくなった場合、追加設定なしでそのまま表示されます。

    • 出力 はリンクが切れた時点で、その PLC の全チャンネルが異常として表示されます。コマンドを 送っていなくても同様です。ただしフレームが 1 回失われただけでは足りず、連続 2 回の失敗で 途絶と確定します。
    • 入力 は測定値の新しさで判定します。ポーリング周期が何度も過ぎても新しい測定がなければ、 通信不可として表示されます。

    デーモンは、装置が通信異常になったとき、およびそこから復帰したときに管理者へメールも送信します。 アラート を参照してください。

    タイミング~

    1 回の要求は最大で タイムアウト × (リトライ + 1)、接続は最大で タイムアウト かかります。 既定値（1.0 秒、リトライ 1 回）なら、PLC に到達できないコマンドは約 3 秒で断念します。

    リトライを増やすと、応答のない装置が処理を占有する時間もその分だけ倍になります。制御コマンドは 同期的に実行されるため、リトライを 1 回増やすことよりも、この積がデーモンのコマンド処理の予算に 十分収まっていることの方が重要です。本当に遅い装置の場合は、リトライではなくタイムアウトを 上げてください。

    トラブルシューティング~

    症状 考えられる原因
    値が大きく外れているが安定している ワード順、またはそのレジスタに合わないデータ型
    値が 10 倍・100 倍ずれている 倍率が未設定
    読み取りはできるが書き込みで不一致エラー PLC のプログラムがそのコイルを制御中、またはコイルアドレスが誤り
    すべてタイムアウトし接続できない ホスト・ポートの誤り、またはファイアウォールが接続を破棄している
    接続はできるがすべての要求が失敗する Unit ID の誤り
    アドレスが一律に 1 つずれている ベンダー文書が 1 から数える基準 — 1 を引いてください

    入力・出力のデバッグログを有効にすると、各要求とその結果がログに記録されます。
