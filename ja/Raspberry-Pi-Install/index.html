    Raspberry Piにインストールする~

    Raspberry Pi 1台にAoTをDockerでインストールし、必要なら同じPiでMatterコントローラーまで有効にする手順です。 WindowsやMacへのDocker Desktopのインストールはインストールガイドにあります。このページはそのガイドと同じ2つのファイル(設計図docker-compose.prod.ymlと設定表.env)を使い、異なる点だけを別に書きます。

    なぜRaspberry Piなのか。 AoTは24時間動かし続けるサーバープログラムです。Raspberry Piは消費電力が少なく、電源が入ると自動で起動し、LinuxなのでMatterに必要なホストネットワークをそのまま使えます。macOSやWindowsのDocker DesktopではMatterは動作しません(Matterの要件)。

    準備~

    項目 推奨 理由
    機種 Raspberry Pi 4または5、メモリ4 GB以上(8 GB推奨) Webアプリ、デーモン、MCP、InfluxDB、Matterサーバーまで1台で動きます
    OS Raspberry Pi OS (64-bit)、Bookworm以降。画面なしで使うならLite AoTとMatterサーバーのイメージは64ビット(arm64)のみです。32ビットOSでは起動しません
    ストレージ USB 3 SSD(Pi 5ではNVMeも可)。最低32 GB 測定値のストアが書き込みを続けます。SDカードは寿命が短く遅いです
    電源 機種に合った公式電源アダプター 電圧が足りないとSSDやUSBデバイスが切断されます
    ネットワーク 有線イーサネット Matterデバイスを探すマルチキャストはWi-Fiより安定します
    Bluetooth Pi 4・5内蔵のBluetooth Matterの新規デバイスをBluetoothで初めて登録するときだけ使います。ほかのアプリから共有されるデバイスには不要です

    Matterを使う場合は、PiをMatterデバイスと同じネットワーク(同じルーター・同じVLAN)に置きます。Threadデバイスを使うには、そのネットワークにThreadボーダールーター(HomePod、Apple TV、Nest Hub、SmartThings Stationなど)がすでにある必要があります。Piはその役割を果たしません。

    1. OSを書き込む~

    別のコンピューターからRaspberry Pi ImagerでSSD(またはSDカード)にOSを書き込みます。

    1. 機種を選び、OSはRaspberry Pi OS (64-bit)(画面が不要ならRaspberry Pi OS Lite (64-bit))を選びます。
    2. 書き込む前のOSのカスタマイズ設定で次を入力します。
      • ホスト名(例: aot) — あとでaot.localで見つけられます
      • ユーザー名とパスワード — 自分で決め、ほかの人やAIには教えません
      • ロケールとタイムゾーン(例: Asia/Seoul)
      • SSHを有効にするをオン(パスワードまたは公開鍵)
    3. 書き込んだストレージをPiに挿し、LANケーブルと電源をつなぎます。初回の起動には数分かかります。

    別のコンピューターのコマンドラインから接続します(ユーザー名とホスト名は手順2で決めたもの)。

    ssh <ユーザー>@aot.local

    aot.localが見つからない場合は、ルーターの管理画面でPiのIPを調べ、ssh <ユーザー>@<IP>で接続します。以降のコマンドはすべてこのSSHウィンドウ(Piの中)で実行します。

    OSを最新にして再起動します。

    sudo apt update && sudo apt full-upgrade -y
sudo reboot

    IPを固定しておきましょう

    ブラウザーで開くアドレスが変わらないよう、ルーターの管理画面でPiに固定IP(DHCP予約)を設定しておくことをおすすめします。

    2. Dockerをインストールする~

    Docker公式のインストールスクリプトで、Docker EngineとComposeプラグインをインストールします。LinuxではDocker Desktopではなく、Docker Engineを使います。

    curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER

    最後の行は、sudoなしでdockerコマンドを使えるようにします。SSHを切断して再接続すると反映されます。再接続したら確認します。

    docker version
docker compose version

    どちらのコマンドもバージョンが表示されれば成功です。Dockerは起動時に自動で開始されます。

    3. ファイルを取得する~

    インストールガイドの手順2と同じです。<バージョン>はリリースページのLatestの番号です(先頭のvを除いた数字、例: 26.09.08)。

    mkdir -p ~/AoT/docker && cd ~/AoT/docker
curl -fsSLO https://raw.githubusercontent.com/AoT-inc/AoT/v<バージョン>/docker/docker-compose.prod.yml
curl -fsSL -o .env https://raw.githubusercontent.com/AoT-inc/AoT/v<バージョン>/docker/.env.prod.example

    Matterを使う場合は、さらに2つのファイルを取得します。ホスト点検スクリプトと、Bluetoothで新規デバイスを登録するときに重ねて使う設定です。

    curl -fsSLO https://raw.githubusercontent.com/AoT-inc/AoT/v<バージョン>/aot/scripts/check_matter_host.sh
curl -fsSLO https://raw.githubusercontent.com/AoT-inc/AoT/v<バージョン>/docker/docker-compose.matter-ble.yml

    Matterが含まれるリリースから

    Matterは実験的機能で、上の2つのファイルはMatterが含まれるリリースからあります。curl: (22) … 404と出る場合、そのバージョンにはまだMatterがありません。リリースノートでMatterに触れているバージョンを使ってください。

    ls -aで、取得したファイルがすべてあるか確認します。

    4. 設定して起動する~

    設定表を開きます。

    nano .env

    インストールガイドの手順3の4行を確認します。Raspberry PiではHARDWARE_PROFILEをLOWにします(一部のAI付加機能だけがオフになり、センサーの読み取りとデバイス制御は同じです)。

    行 Raspberry Piでの値
    AOT_IMAGE_TAG 取得したファイルと同じバージョン番号(先頭のvなし)
    AOT_PORT 8084
    TZ 現場のタイムゾーン(例: Asia/Seoul)
    HARDWARE_PROFILE LOW

    Ctrl+O、Enterで保存し、Ctrl+Xで終了します。そして起動します。

    docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps

    初回はイメージのダウンロードに数分かかります。aot-app、aot_daemon、aot_mcp、influxdbの4つがすべてUpであれば成功です。

    別のコンピューターのブラウザーでhttp://aot.local:8084(またはhttp://<PiのIP>:8084)を開きます。httpsではなくhttpです。最初の管理者アカウントの作成と動作確認は、インストールガイドの手順5〜6と同じです。

    ボリュームを削除しないでください

    停止するときはdocker compose -f docker-compose.prod.yml downだけを使います。down -vやボリュームの削除は、設定と測定値をすべて消します。

    5. 停電から復帰する~

    Raspberry Piは電源が入ると自動で起動し、Dockerは起動時に開始され、AoTのコンテナはDockerが起動すると再び立ち上がります。そのため、WindowsやMacのように別途行う設定(インストールガイドの手順7)はありません。

    インストールが終わったら、電源を抜いてから差し直して確認します。数分後にブラウザーでAoTが再び開けば成功です。

    電源をそのまま抜いて切らないでください

    停電は避けられませんが、意図的に切るときはsudo shutdown -h nowでシャットダウンしてから電源を外します。書き込み中に電源が切れると、ストレージが損傷することがあります。停電が多い場所では、UPSをおすすめします。

    6. Matterを有効にする(任意)~

    MatterデバイスをAoTに取り込むときだけ行います。詳しい動作はMatterのページにあります。このページのDockerインストールではなくネイティブ(/opt/AoT)でインストールしたPiの場合は、ネイティブインストールで起動するに従ってください。

    6-1. ホストを点検する~

    点検スクリプトは設定を読むだけで、変更しません。問題があれば、修正するコマンドも一緒に表示します。

    cd ~/AoT/docker
bash check_matter_host.sh

    各行はOK、WARN、FAILで始まります。FAILから直し、該当するWARNを直します。LANケーブルとWi-Fiの両方が接続されている場合は、Matterデバイスと同じネットワーク側を--iface eth0のように指定します。

    Raspberry Piでよくある項目:

    • IPv6がオフ、ルーター広告を受信していない: Raspberry Pi OSは標準でIPv6がオンです。オフになっている場合は、スクリプトが表示するコマンドでオンにし、再起動後も維持されるよう保存します。
    • ra_routesの警告: Threadボーダールーターのないネットワークでは正常です。Threadデバイスを使うときだけ直します。
    • mdns_5353: ほかのプログラム(例: avahi-daemon)が5353ポートを使っていても問題ありません。情報として表示されるだけです。

    6-2. Matterサーバーを起動する~

    .envで、Matterの行の先頭の#を消して有効にします。

    COMPOSE_PROFILES=matter

    MATTER_LOG_LEVELはinfoのままにします。debugに上げると、サーバーがWi-Fiのパスワードをそのままログに残します。保存して、もう一度起動します。

    docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps

    matter_serverとmatter_socketもUpであれば成功です。ブラウザーで管理 → システム管理 → 一般設定のMatterを使用(実験的)をオンにして保存します。設定メニューに表示されたMatterを開き、サーバーが接続済みと表示されるか確認します。

    6-3. Bluetoothで新規デバイスを登録する(任意)~

    ほかのアプリ(Apple Home、Google Home、SmartThingsなど)から共有されるデバイスだけを使うなら、この手順は不要です。箱から出したばかりのデバイスをAoTに直接登録するときだけ行います。

    Bluetoothサービスを有効にして点検します。

    sudo systemctl enable --now bluetooth
bash check_matter_host.sh --ble

    ble_で始まる行がOKになったら、今後は2つのファイルを一緒に使って起動します。

    docker compose -f docker-compose.prod.yml -f docker-compose.matter-ble.yml up -d

    Bluetoothを使うなら、コマンドに2つのファイルを必ず一緒に

    あとでdocker compose -f docker-compose.prod.yml up -dだけをもう一度実行すると、Bluetoothの設定が抜けたままMatterサーバーが作り直されます。アップグレードのときも2つのファイルを一緒に使います。

    6-4. デバイスを追加する~

    Matterのページのとおり、既存のアプリでデバイスを共有して受け取ったペアリングコードを、管理 → システム管理 → MatterのAdd a shared deviceに入力します。

    アップグレード~

    Dockerデプロイのアップグレードと同じです。新しいバージョンのdocker-compose.prod.ymlを取得し、.envのAOT_IMAGE_TAGを同じ番号に変えてから、pullとup -dを行います。Matterサーバーのバージョンは自動では上がらず、.envのMATTER_SERVER_TAGで決めます。

    うまくいかないとき~

    症状 原因 対処
    no matching manifest for linux/arm/v7などでイメージを取得できない 32ビットOS 64-bitのRaspberry Pi OSで書き込み直します。uname -mがaarch64である必要があります
    permission denied ... docker.sock dockerグループが反映される前 SSHを切断して再接続します
    ブラウザーが開かない アドレスやポートが違う、またはまだ起動中 psで4つがUpか、http://<PiのIP>:8084かを確認
    遅い、またはコンテナが何度も再起動する メモリ不足 free -hで確認。4 GB未満なら大きい機種を使うか、Matterをオフにします
    電源を入れ直したあとUSB SSDが見つからない 電力不足 公式電源アダプターを使い、SSDの消費電力が大きいなら、専用電源付きのUSBハブを使います
    設定 > Matterでサーバーが接続されない COMPOSE_PROFILES=matterがない、またはmatter_serverが停止 .envを確認してup -d、docker compose -f docker-compose.prod.yml logs matter_server
    デバイスが見つからない(タイムアウト) Piとデバイスが別のネットワーク、またはIPv6・マルチキャストの問題 check_matter_host.shをもう一度実行。メッシュWi-Fiのマルチキャスト最適化をオフにします
    Bluetoothでの登録が検索タイムアウトで終わる Bluetoothがオフ、または-f docker-compose.matter-ble.ymlなしで起動した check_matter_host.sh --bleを確認し、2つのファイルでup -d

    ヘルパーAI向け~

    • ユーザーはRaspberry Pi(64ビットのRaspberry Pi OS)にSSHで接続し、Docker Engineでインストールします。Docker Desktopのコマンドを案内しないでください。
    • インストールフォルダーは~/AoT/docker、composeファイルはdocker-compose.prod.ymlで、MatterのBluetoothを使う場合はdocker-compose.matter-ble.ymlを必ず一緒に使います。
    • down -v、ボリュームの削除、docker system prune --volumesを勧めないでください。
    • MATTER_LOG_LEVELをdebugに上げるよう勧めないでください(Wi-Fiのパスワードがログに残ります)。
    • ペアリングコード、Wi-Fiのパスワード、管理者パスワードを尋ねないでください。
