    注意事項~

    AoT が実際の機器を動かし始めると、ソフトウェアの小さな設定1つがそのまま現場に現れます。この章では、運用中に事故につながりやすい ポイントを1か所にまとめました。設置の前に一度、運用を始めてからもう一度読んでください。

    この章を終えると~

    • 運用中に事故につながりやすいポイントを前もって知っている
    • バックアップ、アップデート、停電に備える習慣を決めている

    始める前に~

    この章は読むだけです。各節の最後にある項目を、ご自身の現場に照らして確認してください。

    手順~

    1. バックアップ~

    • 管理 → バックアップ復元 で バックアップを作成 をクリックすると、設定データベース、アップロードしたファイル（ノート、お知らせ、施設の写真）、ユーザースクリプトが保存されます。
    • 測定の履歴は、このバックアップには含まれません。 測定値は、追加機能 → インポート エクスポート をクリックすると開く エクスポートとインポート ページで、別にエクスポートします。
    • バックアップの復元とダウンロードができるのは管理者だけです。復元の前に、AoT が現在の状態をもう一度自動でバックアップします。
    • Docker でインストールした場合は、AoT コンピューターそのものが故障したときに備えて、バックアップファイルを 別のコンピューターに ダウンロードしておいてください。

    点検：アップデートの前や、大きな設定変更の前にバックアップしましたか。ダウンロードしたバックアップを AoT コンピューターの外に保管していますか。

    2. アップデート~

    • docker/.env の AOT_IMAGE_TAG に 正確なバージョン を書いておきます。問題が起きたときは、前のバージョンに戻して起動し直せます。
    • アップデート中は制御が止まります。実行中の灌水やシーケンスは中断されます。アップデートは 機器が動いていない時間に 行ってください。
    • 自動アップデート（アップデーター）は、出力がオンになっていても延期されません。有効にする場合は、作業の予定がない時刻に設定してください。
    • アップデートの前に バックアップ を作成し、リリースノートの「アップグレード時の注意」を読みます。

    点検：バージョンを固定しましたか。アップデートの時刻は、機器の作業時間を避けていますか。

    3. 停電と再起動~

    • 出力の 起動状態 は、AoT が起動したときに適用されます。バルブやポンプは オフ に設定してください（出力の接続 手順 5）。
    • シャットダウン状態 は、AoT を正常に終了したときにだけ適用されます。突然電源が切れたときには適用されません。その場合に機器がどの状態で残るかは、 リレーやコントローラーの動作 によって決まるため、設置時に自分で確認してください。
    • 順次灌水は、再起動後に止まったところから再開します。タイマーも、動いていた周期をそのまま続けます。
    • 環境制御は、直前の判断を記憶していて、そこから制御を続けます。窓やカーテンの開度 % も記憶していますが、動いている途中で電源が切れた場合は、 記憶している値が実際と異なることがあります。再起動後に 閉じる を一度実行して、合わせ直してください。

    点検：電源を一度切ってから入れ直し、すべての機器が想定どおりの状態に戻ることを確認しましたか。

    4. 安全はハードウェアで守る~

    AoT はソフトウェアです。通信が切れたり AoT コンピューターが止まったりすると、コマンドを送れません。人がけがをしたり設備が壊れたりするおそれのある状況は、 ソフトウェアではなくハードウェアで 防いでください。

    • 窓やカーテンのモーター：終端スイッチ（リミットスイッチ）と、開く・閉じるの間の電気的インターロック
    • ポンプ：空運転を防ぐ保護装置と、圧力スイッチ
    • 暖房機：過熱遮断装置
    • 2つのリレー（開く・閉じる）で動かす設備は、ペアの出力 からだけ動かします（出力の接続 手順 4）

    点検：AoT が停止していても安全ですか。

    5. センサーの値が途切れたとき~

    • 室内のセンサーの値が途切れると、環境制御はデバイスを その位置のままにします。 屋外の雨や風の値が途切れると、窓をそれ以上開けません。 制御が止まったように見えることがあるため、モニタリング で値が途切れたセンサーを探してください。
    • 途切れたことを人が知ることができるように、メールアラート を設定してください。
    • センサーの 測定の有効期限 は、センサーが値を送る間隔に合わせて設定してください。そうすることで、途切れたことに遅れずに気付けます（センサーの接続 手順 2）。

    6. 時刻~

    • 予約、順次灌水、日の出・日の入りは、デバイス → ゾーン・サイト → システムのタイムゾーン の順で決まる時刻を使います。1つの現場だけを運用する場合は、 システムのタイムゾーンが正しければ十分です（主な設定 手順 1）。
    • 日の出と日の入りは、地図に描いた現場の位置から計算されます。地図上の位置が間違っていると、日の出の時刻も間違ったものになります。
    • グラフの時刻は、見ている人のブラウザーの時刻 で表示されることがあります。別のタイムゾーンから見るときは注意してください。

    7. 名前の付け方~

    名前は、画面、アラートのメール、AI の回答にそのまま表示されます。名前があいまいだと、人も AI も違うものを指してしまいます。

    • 既定の名前（"New Design Map"、"New site"、"Widget Name"、"Name"、"Output 1"）のままにしないでください。
    • 同じ名前を2回使わないでください。 テストのために複製した機能やコントローラーは、テストが終わったら削除します。
    • 名前には どこの何か を入れます：「環境制御：現場 B 温室」、「3-1 バルブ 1」。
    • 地図やデバイスの名前に、別の現場の名前を使い回さないでください（例：両方の現場に「育苗場」がある）。

    8. 権限と AI~

    • デバイスを操作できるのは、管理者と編集者です。見るだけの人は、モニターのロールで作成してください。
    • AI がデバイスを動かしたり日程を変更したりしようとするときは、人が AI → リクエスト の画面で承認して初めて実行されます。承認の リクエストは、15分が過ぎると消えます。
    • AI ツールに渡した API キーは、一度しか表示されません。「読み取り専用」にできる場合は、そうしてください。
    • 外部からのアクセスを許可している場合は（ネットワーク接続）、すべてのアカウントで長いパスワードを使ってください。

    9. LoRaWAN 機器~

    • 現場全体のコマンドは1つの待ち行列に並び、少なくとも 1.5 秒の間隔をあけて送信されます。複数のバルブを一度に動かすと、最後のバルブが遅れて動きます。
    • 30 秒を超えて待ったコマンドは破棄され、失敗として扱われます。
    • 省電力の機器（Class A）は、次に自分から値を送るまでコマンドを受け取れません。これには数分かかることがあります。
    • そのため、LoRaWAN のバルブで短い間隔の精密な制御は行わないでください。 分単位の灌水に向いています。

    10. 仮想の機器でテストする~

    • 新しい機能や新しい設定は、まず 仮想出力 と テスト入力 で確認してから、実際の機器に接続します（機能 手順 4）。
    • 実際の機器を初めて動かすときは、人が機器のそばにいるときに 行ってください。
    • 運用中の機器で、あれこれ操作しながらテストしないでください。

    確認~

    次の質問すべてに「はい」と答えられれば、運用を始めてかまいません。

    • 最近のバックアップを AoT コンピューターの外に保管している
    • バージョンを固定しており、アップデートの時刻が作業時間と重ならない
    • 電源を切って入れ直し、すべての機器が想定どおりの状態に戻ることを確認した
    • AoT が停止していても安全なように、ハードウェアの保護装置がある
    • センサーの値が途切れたときに、メールで知らせが届く
    • 既定の名前や重複した名前がない

    現場 A~

    • 露地のバルブは LoRaWAN を使うため、コマンドが遅れることがあります。灌水シーケンスのバルブの動作時間は、分単位で設定します。
    • 温室の区画（レタス）を収穫した後に区画を終了しないと、環境制御は最後の段階の目標値を使い続けます。収穫したら、区画も終了します。

    現場 B~

    • 現場 B は既存の制御盤のリレーを使っています。制御盤の手動スイッチで窓を動かすと、AoT が記憶している開度 % と合わなくなります。 手動で動かした場合は、AoT で 閉じる を一度実行して合わせ直します。
    • 設定を試すために環境制御器を複製した場合は、テストの後に使わないほうを削除します。同じ名前の制御器が2つあると、どちらが動いているのか分からなくなります。

    うまくいかないとき~

    実際の動作がこの章の内容と異なる場合は、バージョンを確認し（インストール）、管理 → システムログの 記録を添えてサポートにお問い合わせください。
