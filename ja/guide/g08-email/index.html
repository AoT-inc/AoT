    メールアラート~

    人がずっと画面を見続けることはできません。この章では、「温室が暑すぎる」「センサーの値が途切れた」といった ことが起きたときに、AoT からメールが届くようにします。AoT のアラートは 機能 で作ります。 条件付き機能が条件を確認し、条件が満たされたときに メール送信アクション を実行する仕組みです。 入力や出力の画面には、アラートの設定はありません。

    この章を終えると~

    • メール送信の設定をして、テストメールを受け取れる
    • 条件が満たされたときにメールが届き、同じアラートが繰り返し届かないようにできる

    始める前に~

    • 機能を作成できる AoT（機能）
    • メールを送信するアカウント。Gmail の場合は、Google アカウントの2段階認証を有効にし、「アプリ パスワード」を作成しておきます。 普段のログインパスワードでは送信できません
    • アラートを受け取るメールアドレス

    手順~

    1. メールサーバーを設定する~

    管理 → システム管理 → アラート を開きます（画面のタイトルは「アラート設定」です）。

    項目 Gmail の例 説明
    SMTPホスト smtp.gmail.com メールを送信するサーバー
    SMTPポート （空欄） 空欄の場合は、プロトコルの既定のポートを使います（SSL 465、TLS 587）
    SMTPプロトコル TLS 会社のメールサーバーの場合は、管理者に確認してください
    SMTPユーザー 送信に使う Gmail アドレス
    SMTPパスワード 16文字のアプリ パスワード 空欄のままにすると、保存済みの値がそのまま使われます
    差出人メール SMTPユーザーと同じアドレス 2つが異なると、Gmail がメールを拒否することがあります
    1時間あたりの最大メール送信数 5 1時間に送信できるメールの最大数。上限を超えたメールは 破棄されます

    保存 をクリックします。

    2. テストメールを送信する~

    同じ画面の テストメールを送信 に受信先のアドレスを入力し、ボタンをクリックします。受信トレイ（迷惑メールフォルダーも確認してください）に 「AoT Notification（コンピューター名）」という件名のメールが届けば成功です。

    テストメールは 保存済みの設定 で送信されます。項目を変更した場合は、必ず先に 保存 をクリックしてからテストしてください。 失敗した場合は、管理 → システムログの デーモン のログに実際のエラーが記録されます。

    3. アラート用の機能を作成する~

    例：温室内の温度が 35 ℃ を超えたとき、または 10 分間値が届かないときにメールを送信します。

    1. 設定 → 機能 で 条件付きコントローラ を追加します。 歯車アイコンをクリックして 条件設定 ウィンドウを開き、名前を付けます（例：「アラート：現場 B 温室 高温・途切れ」）。
    2. 周期 秒 を 60 にします。1分ごとに条件を確認します。
    3. 条件を追加 の一覧から 測定 (シングル, 最後) を選び、追加 をクリックします。新しい条件で、 測定 に温室内の温度センサーを選び、最大経過時間 秒 を 600 にして、その条件の 保存 をクリックします。 10分より古い値は「値なし」として扱われます。条件の行の下にある説明文に、self.condition("a1b2c3d4") のようなコードで使う行が表示されます。
    4. アクションを追加 の一覧から メールを送信 を選び、追加 をクリックします。受信先のアドレスを入力し（複数ある場合はカンマで区切ります）、 そのアクションの 保存 をクリックします。
    5. 実行するPythonコード の例を削除し、下のコードを貼り付けます。1行目の self.condition("…") は、3 で確認した行に置き換えます。
    temp = self.condition("a1b2c3d4")

if not hasattr(self, "alerted"):
    self.alerted = False

problem = (temp is None) or (temp > 35)

if problem and not self.alerted:
    if temp is None:
        self.message += "温室の温度の値が10分以上届いていません。\n"
    else:
        self.message += f"温室の温度は {temp:.1f} ℃ です。\n"
    self.run_all_actions()
    self.alerted = True
elif not problem:
    self.alerted = False
    1. ウィンドウ下部の 保存 をクリックし、機能を 有効化 します。保存時にコードチェック（pylint）の警告が表示されることがあります。エラーでなければ、そのままで構いません。

    コードで alerted を使う理由

    条件付き機能は、周期ごとに条件を確認します。何も対策をしないと、問題が続いている間は1分ごとにメールが届きます。 alerted は「すでに通知した」ことを表す目印です。メールは問題が起きた最初の1回だけ送信されます。値が正常に戻ると 目印が消え、次に問題が起きたときに改めて通知されます。

    4. アラートをテストする~

    実際に温室を暑くすることはできないため、条件のセンサーを一時的に テスト入力 に切り替え、 36 を入力します。1〜2分以内にメールが届き、値が 36 のままでも それ以上メールが届かなければ、テストは成功です。 25 を入力してから再び 36 を入力すると、もう1通メールが届きます。テストが終わったら、条件のセンサーを実際のセンサーに戻します。

    確認~

    条件が最初に満たされたときにメールが 1通 届き、条件が続いている間はそれ以上届かなければ完了です。

    • メール本文に、どのセンサーのどの値が原因かが書かれているか確認します。
    • アラート用の機能が複数ある場合は、すべて合わせて1時間あたりの最大メール送信数を超えないか確認します。上限を超えたメールは破棄されます。

    現場 A~

    現場 A では、露地用と温室用の2つのアラートを使います。

    • アラート：露地 土壌センサー途切れ — 3-1 と 3-2 の土壌センサーの最大経過時間をセンサーの送信間隔の3倍にし、値がないときに通知します。 LoRaWAN センサーはバッテリーが切れると前触れなく途切れるため、このアラートがもっとも役に立ちます。
    • アラート：温室 高温 — 単棟温室内の温度が 35 ℃ を超えたときに通知します。

    現場 B~

    現場 B では、まず環境制御が止まる場合に備えます。

    • アラート：温室 高温・途切れ — 手順 3 の例そのままです。
    • アラート：気象ステーション途切れ — 屋外の風速の値が途切れると、環境制御はそれ以上窓を開けません。途切れたときにすぐ分かるようにします。

    うまくいかないとき~

    症状 確認すること
    テストメールの送信に失敗する アプリ パスワードを使ったか、プロトコルとポートが正しいか、保存 してからテストしたか。管理 → システムログ → デーモン
    テストメールは届くが、アラートが届かない 機能を 有効化 したか、コード内の条件 ID を置き換えたか、メール送信アクションにアドレスを入力したか
    しばらくアラートが届いていたが、止まった 1時間あたりの最大メール送信数を超えています。設定 → 診断 → メールカウンターをリセット を実行し、繰り返し防止のコードを追加してください
    1分ごとにメールが届く 繰り返し防止のコード（alerted）がありません
    現場のネットワークでだけメールが送信されない ネットワークがメールのポートをブロックしています（ネットワーク接続）
