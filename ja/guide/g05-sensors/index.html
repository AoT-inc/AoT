    センサーの接続~

    この章では、センサーの値が AoT に入ってくるようにします。センサーごとに値を送る方式が異なるため、まず接続方式を選び、 値が届くことを確認してから、センサーを地図と施設に結び付けます。

    この章を終えると~

    • 自分のセンサーに合った接続方式を選ぶ
    • センサーの値が届くことを確認し、センサーを地図と施設に結び付ける

    始める前に~

    • 地図を構成した AoT（地図の構成）。地図を使わない場合は 手順 7 だけを飛ばします
    • センサーが値を送る方式と、その接続情報（下の手順 1 の表を参照）
    • 機器なしで先に試したい場合：何も必要ありません。テスト入力を使います（手順 6）

    手順~

    1. 接続方式を選ぶ~

    センサーが値を送る方式 AoT で追加する場所 必要なもの
    LoRaWAN 無線センサー 管理 → システム管理 → ChirpStack でまとめて登録 ChirpStack サーバーのアドレス、API キー
    MQTT で値を送る機器や既存の設備 設定 → 入力 ブローカーのアドレスとポート、トピック、メッセージ内で値がある位置
    気象（屋外の状況）API 設定 → 入力 Open-Meteo はキー不要、KMA（韓国気象庁）は無料のキー
    PLC（Modbus TCP） 設定 → 入力（Modbus TCP (PLC)） PLC のアドレス、レジスタアドレス
    Raspberry Pi に配線したセンサー（I2C、UART、1-Wire、SPI、GPIO） 設定 → 入力 センサーの型番、接続方式、アドレスまたはポート。直接インストールした AoT でのみ

    センサーはすべて入力として追加します。PLC や LoRaWAN コントローラーのように、値を読み取りながら機器も動かす機械の場合は、 値はこの章で入力として、制御は 出力の接続 で出力として別々に追加します。

    設定 → 入力 の追加一覧は メーカー: 名前 [インターフェース] の形式です。名前または測定で検索 ボックスに 「MQTT」や「温度」のように入力すると項目を探せます。

    2. LoRaWAN センサーを登録する~

    1. 管理 → システム管理 → APIキー管理 で、ChirpStack から取得した API キーを保存します。
    2. 同じメニューの ChirpStack をクリックすると、ChirpStackデバイス ページが開きます。ChirpStack接続 に、サーバーのアドレスと MQTT ブローカーのアドレスとポートを入力し、API トークン の一覧からいま保存したキーを選んで、保存 をクリックします。 一覧の横の APIキーの管理 ボタンをクリックすると、キーを保存するページに移動します。
    3. デバイスオンボーディング で登録するセンサーを選び、入力を登録 をオンにします。チャネル 欄に、値の位置を 1 行に 一つずつ書きます（センサーメーカーの資料にある値の名前を使います）。選択したデバイスを登録 をクリックします。
    4. 作成された入力の 測定の有効期限 を、センサーが値を送る間隔の 2〜3 倍に設定します。 15 分ごとに送るセンサーなら、約 2,700 秒です。

    測定の有効期限が必要な理由

    LoRaWAN や MQTT のセンサーは、AoT が問い合わせなくても自分から値を送ります。そのため、値が途絶えても接続は 正常に見えることがあります。測定の有効期限は、「この時間内に新しい値が届かなければ、センサーが途切れたものとみなす」という基準です。

    3. MQTT センサーを接続する~

    1. 設定 → 入力 で MQTT Subscribe (JSON payload) を追加します。各メッセージに数値が一つだけ入っている場合は、 MQTT Subscribe (Value payload) を選びます。
    2. ホスト、ポート、トピック を入力します。ブローカーにログインが必要な場合は ログインを使用 を、暗号化された接続の場合は TLSを使用 をオンにします。
    3. チャネルごとに、JMESPath式 の欄に値がある位置を書きます。受け取るメッセージが {"sensors":[{"temperature":24.8}]} なら、 位置は sensors[0].temperature です。
    4. チャネルごとに、実際の値に合った 測定単位 を選びます。25 前後の値で届く温度なら ℃ です。
    5. 測定の有効期限 を、機器が値を送る間隔の 2〜3 倍に設定します（手順 2 の説明と同じです）。

    単位は値に合わせてください。変換をオンにして合わせないでください

    MQTT の入力は、受け取った数値をそのまま保存し、選んだ単位をラベルとして付けるだけです。℃ の値を受け取っているのに 単位を ℉ にすると、画面には「25 ℉」と表示されます。ここで ℉→℃ の変換を追加すると、値が −3.9 に変わり、 制御がおかしくなります。正しい直し方は、単位そのものを ℃ に変えることです。

    4. 気象 API の入力を追加する~

    屋外の気温、湿度、風、雨は、換気や灌水の判断に使われます。現場に気象センサーがない場合は、インターネットの気象情報を 入力として取り込みます。多くは入力を地図上に置いた場所の気象を取得するため、追加した後、手順 7 で 現場の上に置いてください。

    一覧での名前 提供される値 キー 位置の決め方
    Open-Meteo: Open-Meteo (Coords, Hourly incl. Solar) 気温、湿度、日射、風、雨、VPD 不要 地図上の位置（または緯度・経度）
    KMA: KMA High-Resolution 500m 気温、湿度、風、気圧、雨、雪、露点 KMA API Hub のキー 地図上の位置
    KMA: KMA Station Data 気温、湿度、気圧、風 KMA API Hub のキー 気象台 の番号
    KMA: KMA Short-term Forecast 予報気温、最低・最高気温、降水確率、空の状態など 公共データポータル のキー nx・ny の格子座標
    NASA: NASA POWER (Coords, Daily incl. ET0) 蒸発散量（ET0）や日射などの日単位の値（1〜2 週間遅れて公開） 不要 地図上の位置
    OpenWeather: OpenWeatherMap (Lat/Lon, Current/Future) 気温、湿度、気圧、風 OpenWeather のキー 地図上の位置

    位置の設定：気象の入力を追加したら、歯車アイコンで入力設定を開きます。上部に小さな地図があります。地図を 現場まで動かし、地図の左側にある ラベルを現在の地図の中心に移動 ボタン（的のアイコン）をクリックしてから、保存 をクリックします。位置がないと、 システムログに「Latitude/Longitude required」と記録され、値が届きません。

    初めての場合は、Open-Meteo だけで始めてください。キーが不要なので、すぐに動きます。追加 → 位置の設定 → 測定周期 300 → 保存 → 有効化 の順に進めます。続いて入力設定の 今すぐ測定 をクリックすると、ライブ測定に気温、湿度、日射、風、雨の値がすぐに表示されます。韓国国内の現場で、より近い地点の値が必要な場合は、 KMA High-Resolution 500m も追加します。

    KMA のキーの取得

    • High-Resolution 500m と Station Data：KMA API Hub で会員登録し、使う API を申請してから、 マイページで認証キー（authKey）をコピーします。
    • Short-term Forecast：公共データポータル で KMA の短期予報照会サービス（「기상청 단기예보 조회서비스」）の利用を申請し、 一般認証キーをコピーします。新しいキーは、使えるようになるまで時間がかかることがあります。

    AoT へのキーの入力

    1. 管理 → システム管理 → APIキー管理 → 新しいAPIキーを追加 で、名前（例：「KMA API Hub」）とキーを保存します。
    2. 気象の入力の設定で、API キー欄の横にある キー ボタンから、保存したキーを選びます。

    選んだキーは、入力欄に文字列のままコピーされます。後でキーを変更した場合は、そのキーを使うすべての入力で選び直す必要があります。

    周期を長くしてください

    気象の入力の既定の周期は 15 秒です。気象情報は数分から 1 時間ごとに変わるため、測定周期 を 300 秒（5 分）以上に設定してください。KMA の API には 1 日の呼び出し回数の上限があり、Open-Meteo の無料利用は 非商用の目的に限られています。

    5. Raspberry Pi に配線したセンサーを接続する~

    温湿度、CO2、土壌のセンサーを Raspberry Pi のピンに配線して使う方法です。

    Docker でのインストールでは使えません

    Docker でインストールした AoT は、Raspberry Pi の GPIO、I2C、UART、1-Wire を使えません。配線したセンサーを使う場合は、 直接インストール を使ってください。

    1) Pi でインターフェースをオンにする

    Pi のターミナルで sudo raspi-config → Interface Options を開き、使うインターフェースをオンにして再起動します。

    インターフェース オンにするもの 注意
    I2C I2C
    UART Serial Port：ログインシェル No、シリアルハードウェア Yes ログインシェルをオンのままにすると、センサーの値に混ざります
    1-Wire 1-Wire 既定のピンは GPIO4 です
    SPI SPI

    AoT の 管理 → システム管理 → Raspberry Pi ページにも同じボタンがありますが、今は raspi-config を使ってください。

    2) センサーを追加する

    設定 → 入力 の一覧でセンサーの型番を探します。名前の末尾の角括弧が接続方式を示します。

    接続方式 一覧での名前の例 入力する欄
    I2C BOSCH: BME280 [I2C]、Sensirion: SHT31-D [I2C]、Sensirion: SCD30 [I2C]、ROHM: BH1750 [I2C] I2Cアドレス、I2Cバス（通常は 1）
    UART Winsen: MH-Z19B [UART]、CO2Meter: K30 [UART]、Atlas Scientific: Atlas pH [UART] ボーレート（センサーの説明書の値）
    1-Wire MAXIM: DS18B20 [1WIRE] 1-Wire デバイスID（一覧から選択）
    ADC（アナログセンサー） Texas Instruments: ADS1115 [I2C] I2C アドレス、チャネル
    GPIO AOSONG: DHT22 [GPIO] Pin: GPIO（BCM 番号）
    • I2C アドレスの調べ方：管理 → システム情報 の下のほうに、I2C バスごとに接続されているアドレスの表（i2cdetect の結果）が表示されます。 Pi のターミナルで i2cdetect -y 1 を実行しても確認できます。アドレスが決まっているセンサーは、一覧から選ぶだけです。
    • 1-Wire デバイスID：センサーが正しく接続されていれば、一覧に 28- で始まる ID が表示されます。「見つかりません」と表示される場合は、配線と 1-Wire がオンになっているかを確認します。
    • UART ポート：現在は /dev/ttyAMA0（Pi の既定の UART）に固定されています。USB アダプター（/dev/ttyUSB0）はまだ選べません。
    • 初めてセンサーを追加するとき、必要なプログラムがない場合は 依存関係をインストール ウィンドウが表示されます。インストール をクリックし、 「Component installation complete」と表示されるまで待ってから、センサーをもう一度追加します。インターネット接続が必要です。
    • DHT22 のように pigpio が必要なセンサーでは、Pi で pigpiod が動作している必要があります。

    3) 確認する

    有効化 をクリックし、入力設定の 今すぐ測定 で値が表示されるかを確認します。値が表示されない場合は、管理 → システムログ → デーモン を開き、 その入力のエラー（アドレスが違う、デバイスを開けない、など）を探します。

    6. 機器なしで練習する~

    AoT: Test Input: Save your own measurement value を追加します。一覧に Test: Save Value という入力が表示されます。

    1. カードの歯車アイコンをクリックして入力設定を開きます。値が複数必要な場合は、チャネル数 を増やして保存します（例：温度と湿度なら 2）。
    2. 下部の 測定値を選択(必須) で、チャネルごとに 測定単位 を選び（例：温度: 摂氏 (°C)）、その下に 名前 を入力して（例：テスト温度）、 保存 をクリックします。名前や単位が抜けていると、入力を有効化するときにエラーになります。
    3. カードの 有効化 をクリックします。
    4. 入力設定の コマンド セクションで チャネル と 値 を入力し、測定値を保存 の横にある 実行 をクリックします。その値が測定値として保存されます。
    5. 追加機能 → ライブ測定 に、いま入力した値（例：25 °C）が時刻とともに表示されれば完了です。

    テスト入力は、自分では値を作りません。そのため、値を入力してから測定周期の 2 倍（既定では 30 秒）が過ぎると、ライブ測定に 「直近 N 秒間のデータがありません」と -- が表示されます。これは故障ではありません。この動作は、メールアラート で 「センサーが途切れたとき」の通知を試すときにそのまま使います。

    この入力を使えば、実際のセンサーなしで 機能 や メールアラート を試せます。

    7. センサーを地図と施設に結び付ける~

    この手順では、各センサーをどこに置いたかを AoT に伝えます。結び付け方は 2 種類あり、用途が異なります。

    結び付け 操作する場所 使われる場面
    地図上に置く 設定 → 地図 → デバイスモード（A タブ）→ 選択一覧を 開く → 開いたウィンドウでオンにする → ドラッグして所定の位置へ ゾーンごとの値の要約、地図での表示、気象の入力の位置
    施設のセンサー枠 設定 → 施設 → 施設を選択 → 設備配置 → 種類 センサー → + 追加 → チャンネル選択 で使う値にチェック → 名前、屋内/屋外 → 施設を保存 施設の環境制御

    一つのセンサー枠では、入力の複数の値（温度と湿度、または気象の入力の温度・湿度・風速・降水量）にまとめてチェックを付けられます。 屋外の枠には、メインセンサー/バックアップセンサー を選ぶ欄が追加であります。

    施設内のセンサーは必ず施設のセンサー枠に結び付けてください

    環境制御が読み取るのは、施設のセンサー枠に結び付けられたセンサーだけです。地図上に置いただけのセンサーは、 画面には表示されても制御には使われません。

    地図でオンにしたセンサーは、いま表示している画面の中央に現れます。その場所がすべてのゾーンの外であれば、そのセンサーは どのゾーンにも属さないため、必ずドラッグして所定の位置に置いてください。

    確認~

    追加機能 → ライブ測定 に各センサーの値と時刻が表示され、時刻が更新され続けていれば完了です。

    • 入力カードに -- ではなく値が表示されることを確認します。すぐに確認したい場合は、入力設定の 今すぐ測定 をクリックします。
    • 地図上でゾーンをクリックすると、そのゾーンのセンサーの値が表示されることを確認します。
    • 施設画面のセンサー枠に、屋内と屋外のセンサーがどちらも入っていることを確認します。

    現場 A~

    現場 A では、3 つの接続方式をすべて使っています。

    センサー 方式 結び付け
    露地の温湿度（3-1 と 3-2 に 2 つずつ） LoRaWAN 地図上で各ゾーンに
    土壌水分・地温（3-1 と 3-2 に 1 つずつ） LoRaWAN 地図上で各ゾーンに
    屋外の気象 Open-Meteo、KMA 地図上でサイトの上に
    温室内の温湿度 MQTT 施設のセンサー枠（屋内、メイン）

    気象の入力は、温室の外の値です。施設のセンサー枠に入れる場合は、「屋外」の枠にする必要があります。 屋内の枠に入れると、環境制御は屋外の気象を温室内の温度とみなして動きます。

    現場 B~

    現場 B では、既存の設備がすでに集めていた値を MQTT で受け取っています。

    センサー 方式 結び付け
    温室内 5 か所の温湿度 MQTT 施設のセンサー枠（屋内）。1 か所をメイン、残りをバックアップに
    屋外の気象観測所（風速、風向、日射、降水量） MQTT 施設のセンサー枠（屋外）

    風と雨の値は、環境制御が窓を閉める根拠になります。気象観測所の値が途絶えると、窓はそれ以上開かなくなるため、 気象観測所の入力には必ず測定の有効期限を設定してください。

    うまくいかないとき~

    症状 確認すること
    入力カードに -- が表示され続ける 入力を 有効化 したか、ブローカーやサーバーのアドレスとポートが正しいか。MQTT の場合は、トピックの綴りと値の位置
    ライブ測定に「直近 N 秒間のデータがありません」と表示される 測定の有効期限がセンサーの送信間隔より短いか、センサーが実際に途切れています
    温度が異常に高い、または低い 単位を確認してください（手順 3 の警告を参照）
    ゾーンの要約でセンサーが見つからないと表示される センサーを地図上に置いていないか、ゾーンの外に置いています
    環境制御が屋内の値を読み取れない センサーを施設のセンサー枠に結び付けていません（手順 7）
