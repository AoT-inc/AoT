    AI・MCP 接続~

    AoT は、AI をつなぐ方法を2つ用意しています。主に使う方法は MCP です。すでに使っている AI アプリ （Claude Desktop、Claude Code など）を AoT に接続し、その AI に現場のセンサー値・スケジュール・地図を読ませて、機器の操作を 提案させます。MCP（Model Context Protocol）は、AI アプリが外部システムのツールを使えるようにつなぐ公開規格です。 もう1つは AoT に組み込まれている 内蔵AI で、必要なときに有効にできます。

    どちらの場合も、機器を動かしたり設定を変えたりする操作は、人が承認して初めて実行されます。

    この章を終えると~

    • AI アプリを MCP で AoT に接続し、AI に現場の状態を尋ねられる
    • AI が提案した操作を承認する方法がわかる

    始める前に~

    • 管理者アカウントでログインできる AoT（インストール）
    • MCP に対応した AI アプリ（この章では Claude Desktop と Claude Code を例にします）
    • AI アプリを AoT とは別のコンピューターで使う場合は、2台のコンピューターが互いに届くネットワーク（ネットワーク接続 の Tailscale を推奨）

    手順~

    1. 外部 AI からの接続を有効にする~

    管理 → システム管理 → 一般設定 の AIサービス の節で、外部MCPサーバーを有効化 がオンになっているか 確認します。最初はオンになっています。オフにすると、すべての MCP リクエストが拒否されます。

    Docker でインストールした場合、MCP サーバーは aot_mcp コンテナーとしてすでに動いています（ポート 5700）。

    2. 接続用のキーを作成する~

    AI アプリは、ユーザーの API キーで AoT に接続します。AI アプリごとにキーを1つずつ 作成しておくと、あとで1つのアプリだけを切断できます。

    1. 管理 → システム管理 → ユーザー一覧 で、AI が代わりを務めるユーザーを開き、APIキー の節に移ります。
    2. 権限 を選びます。フルアクセス ならロールが許す操作を提案でき、読み取り専用 なら読み取りだけを行います。
    3. AIツール を選びます。AI に見せるツールの範囲です。
    4. 運用：値の読み取り、機器の操作、スケジュール、ノートなど、毎日使うツール（最初はこちらを推奨）
    5. 運用 + 設定：入力・出力・機能・地図・ダッシュボードを作成・編集するツールまで含みます。一覧が長くなるため、AI の応答が遅くなることがあります
    6. 新しいキーを発行 の行の入力欄にアプリ名（例：Claude Desktop）を入力し、生成 をクリックします。
    7. 表示された 新しいキー を コピー します。キーが表示されるのは このとき1回だけ です。

    キーを作成できるのは、ユーザーを編集できる管理者です。

    3. MCP のアドレスを決める~

    AI アプリが どのコンピューターにあるか によって、接続方法が異なります。

    AI アプリがある場所 接続方法 この章の節
    AoT をインストールしたコンピューターと同じコンピューター AI アプリが MCP サーバーを直接実行（stdio） 手順 4
    別のコンピューター（ノートパソコンなど） ネットワークで接続（HTTP）、アドレス http://<AoT コンピューターのアドレス>:5700/mcp 手順 5

    Docker でインストールした MCP サーバーは、最初は AoT コンピューター自身からの接続だけ を受け付けます。別のコンピューターから接続するには、 docker/.env に受け付けるアドレスを書き、起動し直します。アドレスには、プライベートネットワークのアドレスか Tailscale のアドレスを使います。

    # docker/.env
AOT_MCP_BIND=100.64.0.10      # AoT コンピューターの Tailscale アドレス（例）

    docker compose -f docker/docker-compose.prod.yml up -d

    正しく開いたかどうかは、AI アプリがあるコンピューターで確認します。AoT の名前とバージョンを含む応答が返れば完了です。

    curl http://100.64.0.10:5700/mcp/info

    MCP のポートをインターネットに公開しないでください

    AOT_MCP_BIND に 0.0.0.0 を指定したり、ルーターで 5700 ポートを開放したりしないでください。MCP サーバーは暗号化されていない HTTP で動作します。プライベートネットワークか Tailscale の中だけで使ってください。

    4. 同じコンピューターから接続する（stdio）~

    AI アプリに、コンテナーの中で MCP サーバーを直接実行させます。<キー> の部分には、手順 2 でコピーしたキーを入れます。

    Claude Desktop：設定ファイル（claude_desktop_config.json）の mcpServers に追加し、Claude Desktop を再起動します。

    {
  "mcpServers": {
    "aot": {
      "command": "docker",
      "args": ["compose", "-f", "/opt/AoT/docker/docker-compose.prod.yml",
               "exec", "-T", "-e", "AOT_MCP_API_KEY=<キー>",
               "aot_mcp", "python", "aot/aot_mcp_server.py"]
    }
  }
}

    Claude Code：

    claude mcp add aot -- docker compose -f /opt/AoT/docker/docker-compose.prod.yml exec -T -e AOT_MCP_API_KEY=<キー> aot_mcp python aot/aot_mcp_server.py

    /opt/AoT は AoT をダウンロードしたフォルダーです。別の場所に置いた場合は、そのパスに置き換えます。

    5. 別のコンピューターから接続する（HTTP）~

    手順 3 のアドレスと手順 2 のキーを AI アプリに入力します。キーは X-API-KEY ヘッダーで送ります。

    Claude Code：

    claude mcp add --transport http aot http://100.64.0.10:5700/mcp --header "X-API-KEY: <キー>"

    Claude Desktop：Claude Desktop は設定ファイルからリモートサーバーに直接接続できないため、中継ツール mcp-remote を経由します （Node.js がインストールされている必要があります）。--allow-http は、暗号化されていないプライベートネットワークのアドレスに接続するときに必要です。

    {
  "mcpServers": {
    "aot": {
      "command": "npx",
      "args": ["mcp-remote", "http://100.64.0.10:5700/mcp",
               "--header", "X-API-KEY:${AOT_KEY}", "--allow-http"],
      "env": { "AOT_KEY": "<キー>" }
    }
  }
}

    MCP に対応したほかのアプリも、同じアドレスと X-API-KEY ヘッダーを入力すれば接続できます。

    接続後、AI アプリがツールを呼ぶたびに許可を求める場合は、アプリのコネクター(ツール)の権限設定で AoT の読み取り専用ツールを常に許可にしておいてください。照会のたびに確認されなくなります。装置の操作などの変更は AoT が別に承認を求めるため、ほかのツールは承認が必要のままでかまいません。

    6. 尋ねて承認する~

    1. AI アプリで「現場 B 温室の今の温度と湿度を教えて」のように尋ねます。AI が AoT のツールで値を読み取って答えます。
    2. 「側窓を 30% 開けて」のように機器を動かす依頼は、すぐには実行されず 承認待ち になります。AI は、何をしようとしているかとあわせて、 承認待ちであることを知らせます。
    3. 内容を確認し、「そのリクエストを承認して」のようにはっきり答えると、AI が承認を AoT に伝え、操作が実行されます。 承認できるのは、管理者・編集者ロールのユーザーのキーだけです。15分以内に承認しないと、リクエストは破棄されます。

    AI ができることは、キーを持つユーザーのロールと、手順 2 の権限・AIツールの範囲を超えません。

    7. 内蔵AI を有効にする（任意）~

    AoT の中で直接 AI と会話したい場合は、内蔵AI を有効にします。MCP 接続とは別に動作するため、オフのままでも MCP は使えます。

    1. 管理 → システム管理 → 一般設定 の AIサービス で AIサービスを有効化 をオンにします。画面上部に AI メニューが表示されます。
    2. AI → 接続 の 内蔵AI で エンジン（Anthropic、OpenAI、Google Gemini、ローカルの Ollama など）を選んで 追加 をクリックし、 そのサービスの APIキー と モデル を入力して 保存 し、有効化 します。

    詳しい設定は AI の概要 を参照してください。

    確認~

    AI アプリで現場の値を尋ねたときに AoT の実際の値で答え、機器の操作の依頼が承認待ちとして入ってくれば完了です。

    • AI アプリの MCP 一覧で aot が接続済みと表示されているか
    • 外部MCPサーバーを有効化 がオンになっているか
    • キーをアプリごとに別々に作成したか（発行済みキー の一覧で名前によって区別できます）

    現場 A~

    現場 A は、事務所のノートパソコンの Claude Desktop を Tailscale で AoT に接続しています（手順 5）。キーは 運用 の範囲で 作成し、AI は灌水スケジュールと土壌水分を確認してバルブの操作を提案し、担当者が承認します。

    現場 B~

    現場 B は、温室の隣の制御室にある AoT コンピューターで Claude Code を使うため、同じコンピューターからの接続（手順 4）を使います。 環境制御の設定を AI と一緒に調整するために、運用 + 設定 の範囲のキーを別に1つ用意しています。

    うまくいかないとき~

    症状 確認すること
    AI アプリが接続できない curl http://<アドレス>:5700/mcp/info が応答するか、AOT_MCP_BIND を変えたあとに起動し直したか
    すべてのリクエストが拒否される 外部MCPサーバーを有効化 がオフになっています
    認証エラーになる キーを前後の空白なしでそのまま入力したか、そのキーが 発行済みキー の一覧で失効していないか
    値は読めるが、機器の操作が提案されない キーの 権限 が 読み取り専用 か、ユーザーのロールに制御の権限がありません
    AI が設定を作成できない キーの AIツール が 運用 です。設定まで任せるには 運用 + 設定 のキーを使います
    承認した操作が実行されなかった 承認までに15分が過ぎています。もう一度依頼してください
